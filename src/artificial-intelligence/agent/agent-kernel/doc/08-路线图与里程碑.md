## 2. 评测与回归基建（每个里程碑的硬要求）

- **Provider 层**：录制真实 SSE 响应存为 fixture，测试时回放（不依赖网络与 API Key）
- **工具层**：固定工具 mock（`ToolContext` 注入 fake 实现，见 [05](05-工具系统.md)）
- **Agent 层**：断言工具调用序列 + 最终结果 + token 预算上限（任务集元数据格式见 [09 第 4 节](09-harness层设计.md)）
- **回归集**：每个 T 任务 = 一条回归用例；CI 全量跑回放，人工验收才用真实模型

## 3. v0.1 任务分解

- [ ] 包初始化：`bun init` + TS strict + oxlint/oxfmt（单包，不开 monorepo，见 [01](01-总体架构设计.md)）
- [ ] 类型与协议：`Message` / `AgentEvent`（含信封 + `onEvent`）/ `ToolCall` / `RunState`（含 `runStep` / `totalSteps` / `status` / `pendingToolCalls`）/ 错误模型（[01](01-总体架构设计.md)、[02](02-核心循环与事件系统.md)）
- [ ] 钩子管线：`compose` 洋葱 + `transformX` 串行管道 + `onEvent` 观察管线 + 观察钩子容错 + **全部钩子签名占位**（`transformToolResult` / `transformTools` 默认透传，`dispose` / `enforce` / `resume` no-op）
- [ ] Agent Loop：runLoop + `finalize` 统一收口 + 终止条件 + AbortSignal 联动 + 五个 checkpoint 保存点（内存实现）
- [ ] openai-compatible Provider：SSE 流式 + tool-call 分片聚合 + `tool-call-started` + finishReason 映射 + 错误三分类
- [ ] 工具系统：Zod 校验管线（`.strict()`）+ 错误回传 + `concurrencySafe` 分组调度 + `registerTool(AnyTool)`
- [ ] 内存 Checkpointer + 进程内 thread 锁（`ThreadBusyError`）
- [ ] **CLI 交互层**：readline 循环、threadId 多轮、`/exit`、Ctrl+C → AbortSignal（多轮验收的载体）
- [ ] 示例：天气 Agent（对齐 [项目 01](../../agent-fullstack/projects/01-weather-agent/README.md)）
- [ ] 测试基建：SSE 录制回放 fixture + 工具 mock + 钩子组合 / 终止条件单测

**v0.1 执行顺序**（每步可运行，防大爆炸集成）：

1. 定 3 个接口：`ModelProvider` / `ToolDefinition` / `AgentEvent`
2. 200 行无钩子 loop 跑通天气查询（裸 fetch + 单工具）
3. 加钩子管线，用 model-retry 插件验证洋葱组合
4. 加内存 checkpointer + thread 锁，跑通多轮
5. 套 CLI 交互层 → T0 全绿

**退出标准**：T0 通过；中断后可继续会话；并发启动同 thread 报 `ThreadBusyError`；内核满足「文件 ≤ 10、单文件 ≤ 200 行」。

## 6. 硬性度量

- **内核规模**：文件 ≤ 10、单文件 ≤ 200 行（可机械化检查；类型定义包含在内，测试与注释除外）
- **插件独立性**：smoke 脚本自动化——删除任意一个插件，其余系统可启动并跑通基础 run
- **零例外依赖**：内核 `package.json` 运行时依赖仅 `zod`
- **回归集**：每个里程碑新增的 T 任务全部进 CI 回放
- 每个设计文档的「开放问题」清零（或标 `[待评估]` 且有理由）方可宣称对应里程碑完成

## 7. 文档回写机制

- 每个里程碑退出前，对照「实现 vs 设计」逐篇回写差异，`> **状态**` 行更新版本号
- 设计变更走文档先行：先改对应文档的开放问题 → 定稿 → 再动代码
- 产出对照笔记放 `notes/`，回答三问：

1. LangChain 对应设计（见各文档对照表）与我实现的差异在哪？
2. 它为什么那样设计？（结合其源码与生态约束）
3. 我的设计在什么场景下会输给它的设计？

> 💡 这三问才是本项目的核心产出——代码是学习载体，设计判断力才是资产。
