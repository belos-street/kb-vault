## 1. 沙箱分级

| 级别 | 形态 | 隔离强度 | 版本 |
| --- | --- | --- | --- |
| L0 | 进程内直接执行 | 无（仅限完全可信代码） | 开发调试 |
| L1 | Bun 子进程 + cwd + 超时 + 最小 env | 进程级 | v0.2 |
| L1.5 | L1 + 文件系统白名单（仅指定临时/项目目录） | 进程级 + 路径约束 | v0.2 可选加固 |
| L2 | 容器 / 微 VM（Docker、云沙箱如 E2B） | 系统级 | v1.0+ |

v0.2 目标是 L1：够用、零依赖、贴合 Bun 技术栈。

## 2. Sandbox 接口

```ts
interface Sandbox {
  // 代码解释器：写临时入口文件后执行（如 Bun 代码）
  execCode(code: string, opts: SandboxOptions): Promise<ExecResult>
  // 命令执行：bash 工具走这条；cmd / args / shell 显式声明
  execCommand(command: CommandSpec, opts: SandboxOptions): Promise<ExecResult>
}

interface CommandSpec {
  cmd: string
  args?: string[]
  shell?: 'bash' | 'sh' | 'powershell' | 'pwsh'  // 显式声明，避免 Windows 默认 shell 歧义
  stdin?: string
}

interface SandboxOptions {
  cwd: string                // 必填：coding agent 场景必须在项目目录执行
  timeoutMs: number          // 必填，无默认值
  signal?: AbortSignal       // run 中止联动
  env?: Record<string, string>
  maxOutputBytes?: number    // 输出截断阈值
  killTree?: boolean         // 默认 true：超时 / abort 时杀进程树，而非只杀直接子进程
  // 流式输出：bash 工具通过 ctx.emitOutput() 转成 tool-output-delta
  onStdout?: (chunk: string) => void
  onStderr?: (chunk: string) => void
}

interface ExecResult {
  exitCode: number | null    // null = 被 signal 杀死
  stdout: string             // 全量聚合（受 maxOutputBytes 截断）
  stderr: string
  durationMs: number
  timedOut: boolean          // 超时被 kill
  killed: boolean            // timedOut || aborted（≠ 业务失败）
}
```

> ⚠️ `killed` 的语义修正（评审指出）：**正常失败命令（exitCode 1）不是被 kill**。`killed = timedOut || aborted`，与业务成败（`exitCode`）正交——bash 工具靠 `exitCode` 判断命令成败，靠 `killed` 判断是否被系统强制终止，两者混淆会污染模型对执行结果的判断。

> 💡 设计决策：**沙箱是插件提供的服务，不是内核特性**。内核只知道接口；「代码解释器」用 `execCode`，「bash 工具」用 `execCommand`，两者都是工具插件 + 从 `ctx.services` 取 sandbox。工具与沙箱零耦合，换沙箱实现（如未来换云沙箱）不动工具代码。

## 3. L1 实现要点（Bun 子进程）

```ts
// 伪代码：execCode 核心流程，省略错误归一；注意 stdout 流式转发
const minimalEnv = {
  PATH: process.env.PATH,          // 缺 PATH 会让 bun / bash 直接找不到
  HOME: process.env.HOME,
  TMPDIR: process.env.TMPDIR,
  SystemRoot: process.env.SystemRoot,  // Windows 必需
}
// 只保留运行必需变量；API Key / 业务密钥一律不透传

async function execCode(code: string, opts: SandboxOptions): Promise<ExecResult> {
  const started = performance.now()
  const cwd = await resolveWithinRoot(opts.cwd)   // 必须是 workspaceRoot 内的真实路径，拒绝 ../ 与符号链接逃逸

  // 代码写临时文件再执行（不要 stdin + entry 文件混用）；随机文件名 + 用后即删
  const entry = await writeTempSandboxFile(code)
  let timer: ReturnType<typeof setTimeout> | undefined
  let aborted = false
  let proc: Bun.Subprocess | undefined

  const onAbort = () => {
    aborted = true
    if (proc !== undefined) killProcess(proc, opts.killTree ?? true)
  }
  opts.signal?.addEventListener('abort', onAbort)

  try {
    proc = Bun.spawn(['bun', entry], {
      cwd,                             // 已校验的项目目录
      stdout: 'pipe',
      stderr: 'pipe',
      env: { ...minimalEnv, ...opts.env },
    })

    let timerFired = false
    timer = setTimeout(() => {
      timerFired = true                // 标志位判定，避免时间比较的边界歧义
      killProcess(proc!, opts.killTree ?? true)  // 先 SIGTERM，宽限后 SIGKILL；杀进程树
    }, opts.timeoutMs)
    if (aborted) onAbort()

    // 两个流必须并行消费：串行 await 会在 stdout 未 EOF 时饿死 stderr，
    // 管道缓冲写满 → 子进程阻塞 → 死锁
    const [collectedStdout, collectedStderr] = await Promise.all([
      pipeStream(proc.stdout, opts.onStdout, opts.maxOutputBytes),
      pipeStream(proc.stderr, opts.onStderr, opts.maxOutputBytes),
    ])

    const exitCode = await proc.exited
    return {
      exitCode,
      stdout: collectedStdout,          // 已聚合（受 maxOutputBytes 截断）
      stderr: collectedStderr,
      durationMs: performance.now() - started,
      timedOut: timerFired,
      killed: timerFired || aborted,
    }
  } finally {
    // 三条清理必须在 finally：正常返回 / 超时 / abort / pipe 抛错都要执行
    if (timer !== undefined) clearTimeout(timer)
    opts.signal?.removeEventListener('abort', onAbort)
    await removeTempFile(entry)
  }
}
```

`execCommand` 的实现差异：

- `cmd / args / shell` 显式声明；不依赖宿主默认 shell；
- `killTree: true` 时必须杀进程组 / 进程树，`proc.kill()` 只杀直接子进程，超时「强制回收」不成立；
- Windows 的 shell 选择（Git Bash / WSL / PowerShell）与信号行为必须在实现时验证；接口用 `shell` 字段把差异显式化，不藏默认值。

**边界校验（定稿）**：

- `cwd` 必须是 `RuntimeOptions.workspaceRoot` 内的真实路径；解析符号链接后仍须在根内，拒绝 `..` 逃逸。越界抛 `SandboxPathError`，由工具归一为 `ToolResult(ok:false, code:'SANDBOX_PATH_DENIED')`，不中止 run。
- `minimalEnv` 至少保留 `PATH` / `HOME` / `TMPDIR`（Windows 追加 `SystemRoot` / `TEMP`）；只删除密钥类变量，不做全量清空。
- abort listener 与临时文件清理一律放 `finally`，避免「每次调用泄漏一个 listener / 一个临时文件」。

L1 已知边界（如实记录，不夸大隔离性）：

- ✅ 隔离：崩溃隔离、超时强制回收、最小 env 防宿主 API Key 泄露、cwd 边界
- ⚠️ 不隔离：网络（子进程默认可访问）、文件系统（L1.5 白名单可部分收紧）；**cwd 内的 `.env` 仍对子进程可读**——最小 env 不是仓库密钥保护，敏感文件读取需走审批 / 路径拒绝
- ⚠️ L1 只防事故不防恶意代码，恶意代码场景必须 L2

## 4. 可观测性设计

### 4.1 采集：telemetry 插件经 onEvent 观察钩子

内核不感知任何观测系统——telemetry 插件经 **`onEvent` 观察钩子**逐事件接收（位于 `transformEvent` 之后，与消费者看到同一份**脱敏后最终形态**；采集通道定稿见 [03](03-插件系统与钩子设计.md)），按 `spanId` 字段构建 span 树：

```
run span（run-started → run-finished/error）
└── turn span（每轮）
    ├── model-call span（含模型名、token 用量）
    └── tool-call span × n（含工具名、成败、耗时）
```

**span 建树不靠全局栈**（评审指出：并发工具下 `tool-call-started` / `tool-call-completed` 交错，全局栈父子关系必乱）。定稿方案：[02 事件信封](02-核心循环与事件系统.md) 的 `spanId` / `parentSpanId` 字段由内核在产出事件时填好，telemetry 插件按字段建树——显式、无并发问题、可回放。

| AgentEvent | 动作 |
| --- | --- |
| `run-started` / `run-resumed` / `run-finished` / `run-aborted` / `error` | 建立 / 恢复树根，关闭 |
| `turn-started` / `turn-finished` | 建 / 关 turn span |
| `tool-call-started` / `tool-call-completed` | 建 / 关 tool span（带属性） |
| `tool-call-retrying` | 记录幂等重试的 attempt 切换，不新建执行 span |
| `tool-call-cancelled` | 关闭审批拒绝 / 过期 / abort 的 tool span，不建执行 span |
| `text-delta` | 不建 span（太碎），聚合文本统计即可 |

### 4.2 导出：OpenTelemetry 为中心

```mermaid
graph LR
    EB[事件流（onEvent 钩子）] --> TP[plugin-otel<br/>按 spanId 建树]
    TP --> OT[OTel SDK]
    OT --> LF[Langfuse 自托管<br/>默认]
    OT --> LS[LangSmith<br/>可选]
    OT --> JG[Jaeger / Grafana<br/>自选后端]
```

- 属性命名**直接对齐 OTel GenAI 语义约定**（`gen_ai.usage.input_tokens` 等）——自造命名会导致 Langfuse 等后端解析缺失（评审定稿，不再作为开放问题）
- 转储取舍：`text-delta` **不逐条落 trace**，只存聚合文本（本地存储体积与隐私兼顾）
- Langfuse（自托管、数据主权）默认，LangSmith（托管、开箱即用）可选对照——同一份 OTel 数据，切换零成本（详见 agent-fullstack 7.1）

### 4.3 日志约定

- 结构化 JSON lines，非文本拼接
- 必带字段：`ts` / `level` / `threadId` / `runId` / `plugin`（或 `module`）
- 禁止在日志中输出完整消息历史（体积 + 脱敏风险），仅输出事件摘要与用量

### 4.4 成本观测

- `usage` 事件累计到 run span 属性（`gen_ai.usage.*`：input / output / cached tokens）
- 单价表放 telemetry 插件配置（模型单价经常变，不进内核）
- 输出：每 run 成本估算 + 会话累计（usage 口径见 [01 术语表](01-总体架构设计.md)）
