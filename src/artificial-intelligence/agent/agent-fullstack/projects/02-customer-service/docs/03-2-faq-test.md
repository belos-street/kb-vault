# 03-2 FAQ 检索的三路径单测

> 对应 todo §3.2 `test/faq.test.ts`。承接 [03-1](./03-1-faq-search.md)。
> 运行：`bun test test/faq.test.ts`（纯函数测试，不依赖数据库与模型）。

## 1. 为什么三路径刚好够

一次检索只有三种结局，测试就只写三种：

| 路径     | 断言目标                     | 用例                    |
| -------- | ---------------------------- | ----------------------- |
| 命中     | 条目正确 + 答案/出处真实存在 | 验收主路径 + 五类各一例 |
| 阈值边界 | 分数卡在 0.35 两侧的行为     | 1/4 词 vs 2/4 词        |
| 未命中   | 返回 null 而不是猜一个答案   | 闲聊 / 空串 / 纯英文    |

「边界测试」的核心手法：**用真实词表构造卡点分数**。`faq-refund-7day` 词表 4 词：

```text
「退货」     → 只打中 1 词 → 1/4 = 0.25 < 0.35 → null
「退货退款」 → 打中 2 词   → 2/4 = 0.50 ≥ 0.35 → 命中，且 score === 0.5
```

同一数据、同一阈值，只挪动一个词——行为翻转点被精确定位。这比 mock 一堆假条目更能防回归（阈值或词表一改，这条测试立刻红）。

## 2. extractKeywords 的三个不变量

窗口函数单独拉出来测，断言三个**不变量**（性质而非具体值，比逐字断言稳）：

1. 所有产出长度 ≥ 2（单字不进窗口）
2. 非中文字符不产出（`/^[\u4e00-\u9fff]+$/` 全量校验）
3. 纯停用词输入产出为空（`'什么'` → `[]`）

> 📷 教学花絮：初版测试写的是 `extractKeywords('你好') → []`，跑挂了——「你好」根本不在 01 的停用词清单里（清单滤的是「什么/怎么」这类万能碎片）。真实原因是闲聊碎片与政策词表**零重叠**才未命中。已同步修正测试与 03-1 文档——单测跑出文档表述不准，这正是先测后写的价值。

## 3. 命中路径断言什么

不只断言 `id`，还断言答案内容（`toContain('7 天')`）与出处（`toContain('售后服务政策')`）：

- id 对 = 检索排序对
- 内容对 = 数据契约对（answer/source 字段真实承载事实）

五类政策（退款/物流/会员/账号/发票）各抽一例，防止「只调好了退款类」的局部过拟合——这正是上一轮词表调参的真实教训。
