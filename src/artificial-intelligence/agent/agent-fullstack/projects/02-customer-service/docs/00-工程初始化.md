## 关键设计逐个看

### 1. tsconfig 的两个路径别名

```json
"paths": {
  "@/*": ["./src/*"],
  "@kb/*": ["./kb/*"]
}
```

- `@/` → 源码常规别名；
- `@kb/` → `kb/` 目录的**专属别名**：`policy-faq.json` 是数据资产不是源码，
  与代码分开命名空间，第四章换向量检索时数据层的归属一目了然。

### 2. `.oxlintrc.json` / `.oxfmtrc.jsonc` 落项目根

配置放在本项目根目录（`02-customer-service/`），与 `package.json` 同级——
`bun run lint` / `bun run format` 的脚本在项目目录里执行，oxlint / oxfmt 从当前目录
向上找配置文件即可命中。新项目初始化时从这里复制这两份配置
（`agents.md` §5.6 的约定：项目内副本即参考配置）。
代码风格由 oxfmt 决定：单引号、无分号、无尾逗号、2 空格、行宽 80。

### 3. config.ts：环境变量的唯一入口

```typescript
const envSchema = z.object({
  DEFAULT_MODEL: z.string().default('deepseek-v4-flash'),
  CLASSIFIER_MODEL: z.string().optional(), // 分类/摘要/judge 的可选覆盖位
  DATABASE_URL: z.string().default('postgres://...'),
  CHECKPOINTER: z.enum(['memory', 'postgres']).default('postgres'),
  // 中间件参数、trace/评估输出目录……
})
```

三个设计点：

1. **Zod 校验 + fail-fast**：环境变量缺失/非法在启动瞬间报错并 `process.exit(1)`，
   而不是跑到一半在业务代码里炸出 `undefined`；
2. **模型分层保留在配置上**：全链路单模型（成本敏感档）是当前决策，但 `CLASSIFIER_MODEL`
   覆盖位把 1.1 的「主力 / mini 分层」可能性留住——未来接多档模型只改配置不动代码；
3. **模型串归一化**：`normalizeModel` 给无 provider 前缀的模型名补 `openai:`，
   对齐 `initChatModel` 的 `provider:model` 语法。
