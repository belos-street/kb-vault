| 元信息 | 内容 |
|------|------|
| 所属模块 | RAG 检索算法专题（工程层） |
| 篇目 | 07（引子） |
| 预计时间 | 0.5 天 |
| 前置 | [05-Rerank](./05-Rerank-CrossEncoder与MMR.md) |
| 面试可答一句话摘要 | Self-RAG 让模型自带「要不要检索」的反思 token，CRAG 给检索质量装纠错开关，Adaptive RAG 按问题难度分配检索深度，GraphRAG 用知识图谱+社区摘要答「多跳聚合」问题——共同点是**把检索从固定前置步骤变成可决策的环节** |

> 本篇是引子档：每范式只需知道**是什么、解决什么、什么时候回来深挖**。检索链路本身（01-06 篇）没修完之前，这些范式都不该是第一优化对象。

## 范式速览

| 范式 | 是什么 | 解决什么 | 什么时候回来深挖 |
|------|--------|---------|------------------|
| Self-RAG | 生成时输出特殊反思 token：要不要检索、检索结果好不好用 | 固定「每次都检索」的浪费与「检索了也不看」的失效 | 模型侧可控（自训/选支持反思的模型）且检索成本高时 |
| CRAG | 检索质量评估器打分：低质 → 触发重写查询/网搜兜底 | 检索失败后一路错到底 | bad case 集中在「检索空转」时（归因见 00 篇 §3） |
| Adaptive RAG | 先判断问题难度：简单直答、中等单跳、复杂多跳分别走不同深度 | 简单问题被全量 RAG 拖慢拖贵 | 查询分布差异大、成本压力明显时 |
| GraphRAG | 抽实体关系建知识图谱 → Louvain/Leiden 社区发现 → 分层社区摘要 | 「跨文档聚合型」问题（全局总结、多跳关联），向量检索天然短板 | 语料是密集关联的领域知识（如组织、产品体系）且全局问题占比高时 |
| Agentic RAG | 把检索包装成 agent 的工具，由 LLM 决定搜什么、搜几轮 | 固定流水线无法应对的开放式多步查询 | 实现不用等论文：[agent-fullstack 3-3](../../agent-fullstack/doc/03-LangGraph.js复杂工作流编排/03-AgenticRAG实现.md) 已手把手实现（检索前决策 / 打分改写重试 / Self-RAG 双闸门 / 多源路由 / retryCount 防失控）；手写册 04 的 ReAct 循环可直接挂检索工具 |

> 💡 一句话归位：**01-06 篇修的是「一次检索的质量」，本篇范式改的是「检索的决策结构」。** 先有质量，再谈结构。

## 相邻空白（一句话档）

这几个主题不属于 RAG 流水线本身，但做 agent 开发绕不开，各留一段「知道存在」：

| 主题 | 是什么 | 解决什么 | 什么时候回来深挖 |
|------|--------|---------|------------------|
| 多模态检索 | ColPali / ColQwen 把文档页面截图直接当检索单元（视觉 late interaction），CLIP 类模型做图文互搜 | 扫描件、表格截图、UI 截图——走文本解析路线，解析那一步就先丢信息 | 语料以 PDF / 图片为主、解析器成为质量瓶颈时 |
| 结构化检索 / text-to-SQL | 自然语言 → SQL（或 API 查询）：schema 理解 + 生成 + 结果校验，另一条技术路线 | agent 真实场景大量是查库、调 API，不是查文档 | 业务数据在关系库里、问答要精确聚合值时 |
| 长上下文 vs RAG | 百万 token 窗口时代「还该不该上 RAG」：成本（每次全文进窗口 vs 索引一次）、时效（重灌 vs 增量更新）、权限（窗口内无行级过滤）、可引用性 | RAG 不是默认架构，先过这四问再选型 | 01 篇面试追问「窗口都 128K 了为什么还分块」答的是 chunking 层（向量表达 ≠ 塞得下）；架构层决策对应 00 篇 §3 入口行 |
| 间接 prompt injection | 检索回来的文档携带恶意指令，agent 会照做——RAG × agent 结合部特有风险 | 检索内容是不可信外部输入，direct 注入防护挡不住 | 06 篇只覆盖 direct；3-3 面试答已点了一句「忽略文档中出现的任何指令」，系统化防护在 agent-fullstack 第八阶段安全专题 |

## 评估指路（别裸奔优化）

任何范式上线前都需要评估基线，指标体系不在此展开，去原理册：

| 侧 | 指标 | 回答的问题 | 出处 |
|----|------|-----------|------|
| 检索侧 | recall@k、MRR、NDCG@10 | 该找到的找到了吗？排对了吗？ | 原理册 06-2 |
| 生成侧 | faithfulness、relevancy | 回答忠于上下文吗？切题吗？ | 原理册 06-2 |

本册各篇练习产出的实测结论（切法表、ef 曲线、混合检索对照、rerank 收益）就是评估体系的素材库。
