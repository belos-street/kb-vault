## 🚧 边界声明：这是什么，不是什么

在开始之前，先明确这条学习路线的**边界**。这不是一份通用的机器学习教程，而是一份为**全栈程序员**定制的、**以 AI 应用优化为导向**的原理层学习指南。

| 维度 | ✅ 这是 | ❌ 这不是 |
|------|---------|----------|
| 学习目标 | 懂原理的 AI 应用架构师 | 算法工程师 |
| 学习导向 | 理解原理 → 解释 AI 现象 → 优化 RAG/Agent → 做技术选型 | 训练模型 → 调参 → 发论文 |
| Python 定位 | 跑极简案例验证原理的工具（10 行代码跑通 Embedding） | 深入算法开发的主力语言 |
| 数学要求 | 按需补直觉（线性代数、概率），够用即止 | 系统学数学、推导公式 |
| 模型训练 | 理解训练过程的概念（前向传播、反向传播、损失函数） | 手撸模型、自训大模型、调超参 |
| 每个知识点 | 锚定核心场景：RAG / Agent / AI 应用 / 向量检索 | 脱离场景的纯理论学习 |
| 遇到瓶颈 | 2 天搞不懂就跳过，继续前进 | 死磕一个原理直到彻底推导清楚 |

**一句话总结**：只学「能帮你解释 AI 现象、优化 RAG/Agent、做技术选型」的核心内容，其余一概不碰。

## 🧭 三大核心学习原则

这是贯穿整个学习过程的三条铁律，每个知识点都必须遵守：

### 原则 1：学「是什么 + 为什么 + 和我的 AI 应用有啥关系」

不学公式推导，不手撸模型。每个概念只回答三个问题：
- 它是什么？（直觉理解）
- 它为什么有效？（不推公式，用类比解释）
- 它和我的 RAG / Agent / AI 应用有什么关系？（落地到具体场景）

### 原则 2：用「最小案例验证原理」

每个概念都用最短的代码跑通，而非训练复杂模型：

```python
# ✅ 最小案例：10 行验证 Embedding
import torch
import torch.nn as nn
embedding = nn.Embedding(10, 3)
word_indices = torch.tensor([1, 2, 3])
embedded = embedding(word_indices)
print(embedded.shape)  # torch.Size([3, 3])
```

```python
# ❌ 不要做的事：训练一个完整的文本分类模型
# model = TextClassifier(vocab_size=50000, ...)
# for epoch in range(100):  # 别这么做
#     train(model, dataloader, optimizer, ...)
```

### 原则 3：所有知识点都锚定核心场景

每个知识点都必须回答：**这对我优化 RAG / Agent / AI 应用有什么用？**

| 知识点 | 锚定场景 |
|--------|----------|
| Embedding 原理 | 为什么 RAG 检索不准？怎么选 Embedding 模型？ |
| 注意力机制 | 为什么大模型能理解长上下文？上下文窗口怎么影响 RAG？ |
| 向量相似度计算 | 为什么 cosine 比欧氏距离更适合文本？重排策略怎么设计？ |
| Transformer 架构 | 为什么大模型会幻觉？怎么通过 Prompt 控制输出？ |
| 分类 / 聚类 | Agent 怎么判断用哪个工具？用户意图怎么分类？ |
| 微调 vs Prompt Engineering | 什么时候该微调，什么时候用 Prompt 就够了？ |

## 📐 学习深度边界

以下是每个模块的**学 vs 不学**边界，越界时提醒自己：**我是 AI 应用架构师，不是算法工程师。**

| 学到什么程度 | 不学什么 |
|-------------|---------|
| Embedding 为什么有效，如何影响检索质量 | Word2Vec 的数学推导、负采样的实现细节 |
| Transformer 的注意力机制概念（直觉理解） | Multi-Head Attention 的矩阵运算细节 |
| CNN/RNN/LSTM 的适用场景和局限性 | 反向传播的链式法则推导、梯度消失的数学证明 |
| 大模型幻觉的原因和缓解策略 | RLHF 的训练细节、PPO 算法实现 |
| 向量检索的相似度计算原理 | ANN 算法的实现优化（HNSW、IVF 的底层细节） |
| 什么时候该微调，什么时候用 Prompt 就够 | LoRA/QLoRA 的实现原理、训练流程 |
| 模型量化 / 蒸馏的概念和适用场景 | 量化算法的数学实现 |
| PyTorch 张量操作和自动微分 | 自己手写一个深度学习框架 |

**红线原则**：如果一个知识点你花了 2 天还没理解，且它无法直接帮你优化 RAG/Agent/AI 应用 —— **跳过它，继续前进。**

## 🧩 类比前端概念（快速建立直觉）

| AI 概念 | 前端类比 |
|---------|---------|
| 神经网络层 | React 组件（输入 → 处理 → 输出） |
| 前向传播 | 组件渲染树（数据从上往下流） |
| 反向传播 | Redux DevTools（从结果回溯原因） |
| 损失函数 | Lint 报错数（越少越好） |
| 训练过程 | CI/CD 流水线（反复构建直到通过） |
| Embedding | 将文本转为向量，类似将 CSS 转为 style 对象 |
| Tokenizer | 将文本拆成 Token，类似 AST 解析器将代码拆成 AST 节点 |
| 大模型推理 | Serverless 函数（按需调用，按 Token 计费） |
| 向量数据库 | 给数据加了一个"语义搜索引擎"索引层 |
