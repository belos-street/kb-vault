# 02 — 场景图与显示对象

> 对应大纲：模块 2 | 预计时间：1 天
> 面试可答：PixiJS 使用场景图（Scene Graph）管理所有显示对象，本质是一棵树——`stage` 是根节点，`Container` 和 `Sprite` 是子节点。父节点的变换（位置、旋转、缩放）会传递给所有子节点，类似 CSS 的 `transform` 继承。通过 `addChild` / `removeChild` 管理节点的添加和移除，`destroy()` 彻底销毁释放 GPU 资源。

---

## 1. 场景图（Scene Graph）概念

### 1.1 什么是场景图

场景图是一种**树状数据结构**，用于管理场景中所有可视对象的层级关系和变换继承。

```
Stage (root)
├── Container (背景层)
│   ├── Sprite (星空背景)
│   └── Sprite (地面)
├── Container (游戏层)
│   ├── Sprite (玩家)
│   ├── Container (敌机群)
│   │   ├── Sprite (敌机1)
│   │   ├── Sprite (敌机2)
│   │   └── Sprite (敌机3)
│   └── Container (子弹群)
│       ├── Sprite (子弹1)
│       └── Sprite (子弹2)
├── Container (UI层)
│   ├── Text (分数)
│   └── Text (生命值)
└── Container (弹窗层)
    └── Sprite (暂停面板)
```

### 1.2 为什么需要场景图

| 优势 | 说明 |
|------|------|
| **分组管理** | 同类对象放入同一 Container，批量操作 |
| **变换继承** | 移动父容器，子对象自动跟随 |
| **层级控制** | 树的深度决定渲染顺序（深度优先遍历） |
| **批量隐藏** | `container.visible = false` 一键隐藏整组 |
| **批量销毁** | `container.destroy({ children: true })` 级联销毁 |

### 1.3 场景图 vs DOM 树

| 对比维度 | DOM 树 | 场景图 |
|---------|--------|--------|
| 节点类型 | Element / Text / Comment | Container / Sprite / Graphics / Text |
| 根节点 | `document` | `app.stage` |
| 添加子节点 | `appendChild()` | `addChild()` |
| 移除子节点 | `removeChild()` | `removeChild()` |
| 变换继承 | CSS `transform` 不继承 | 位置/旋转/缩放全部继承 |
| 渲染方式 | 浏览器布局引擎 | PixiJS 渲染器（GPU） |
| 事件冒泡 | 支持 | 支持 |

## 2. DisplayObject 公共属性

所有可视对象（`Sprite`、`Graphics`、`Text`、`Container`）都继承自 `DisplayObject`，共享以下属性：

### 2.1 位置与尺寸

```javascript
const sprite = new Sprite(texture);

// 位置
sprite.x = 100;           // X 坐标（相对于父容器）
sprite.y = 200;           // Y 坐标（相对于父容器）
sprite.position.set(100, 200);  // 同时设置
sprite.position.x;        // 读取 X

// 尺寸
sprite.width = 100;       // 显示宽度（会改变 scale）
sprite.height = 80;       // 显示高度（会改变 scale）

// 锚点（控制旋转和定位的基准点）
sprite.anchor.set(0.5);   // 中心锚点（适用于 Sprite）
sprite.anchor.set(0, 0);  // 左上角（默认）
sprite.anchor.set(1, 1);  // 右下角

// 旋转轴心（适用于 Container 和 Graphics）
container.pivot.set(50, 50);  // 旋转中心偏移
```

### 2.2 变换

```javascript
// 缩放
sprite.scale.set(2);         // 等比放大 2 倍
sprite.scale.set(2, 1);     // 水平放大 2 倍，垂直不变
sprite.scale.x = 1.5;       // 只缩放水平方向

// 旋转（弧度制）
sprite.rotation = Math.PI / 4;  // 旋转 45°
sprite.rotation = Math.PI;      // 旋转 180°
sprite.angle = 45;              // 角度制（v8 支持）

// 透明度
sprite.alpha = 0.5;         // 半透明
sprite.alpha = 0;           // 完全透明（但仍参与事件检测）
```

### 2.3 显示控制

```javascript
// 可见性
sprite.visible = false;     // 不显示，不参与渲染，不参与事件检测

// 透明度 vs visible
sprite.alpha = 0;           // 不显示，但仍参与事件检测
sprite.visible = false;     // 不显示，不参与事件检测（性能更好）

// 排序（需在父容器中设置）
container.sortableChildren = true;  // 启用 zIndex 排序
sprite.zIndex = 10;                 // 数值越大越靠前
```

### 2.4 属性速查表

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `x` | number | 0 | X 坐标（相对于父容器） |
| `y` | number | 0 | Y 坐标（相对于父容器） |
| `scale` | Point | {x:1, y:1} | 缩放比例 |
| `rotation` | number | 0 | 旋转角度（弧度） |
| `angle` | number | 0 | 旋转角度（度） |
| `alpha` | number | 1 | 透明度（0~1） |
| `visible` | boolean | true | 是否可见 |
| `width` | number | - | 显示宽度（读取/设置） |
| `height` | number | - | 显示高度（读取/设置） |
| `anchor` | Point | {x:0, y:0} | 锚点（仅 Sprite/Text） |
| `pivot` | Point | {x:0, y:0} | 旋转轴心 |
| `skew` | Point | {x:0, y:0} | 倾斜 |
| `zIndex` | number | 0 | 排序值（需 sortableChildren） |

## 3. Container — 容器

`Container` 是场景图中最基础的节点，类似 HTML 的 `<div>`——没有视觉表现，只用于**分组和管理子对象**。

### 3.1 基本用法

```javascript
import { Container, Sprite } from 'pixi.js';

// 创建容器
const enemyGroup = new Container();
app.stage.addChild(enemyGroup);

// 向容器添加子对象
const enemy1 = new Sprite(enemyTexture);
enemy1.position.set(100, 100);
enemyGroup.addChild(enemy1);

const enemy2 = new Sprite(enemyTexture);
enemy2.position.set(200, 100);
enemyGroup.addChild(enemy2);

// 移动容器 → 子对象全部跟随
enemyGroup.x = 50;   // enemy1 和 enemy2 都向右移 50px
enemyGroup.y = 30;   // enemy1 和 enemy2 都向下移 30px

// 缩放容器 → 子对象全部缩放
enemyGroup.scale.set(0.8);

// 隐藏容器 → 子对象全部隐藏
enemyGroup.visible = false;
```

### 3.2 子对象管理

```javascript
// 添加子对象
container.addChild(sprite);
container.addChild(sprite1, sprite2, sprite3);  // 一次添加多个

// 添加到指定位置
container.addChildAt(sprite, 0);  // 添加到索引 0 的位置

// 移除子对象
container.removeChild(sprite);
container.removeChild(sprite1, sprite2);

// 移除指定索引的子对象
container.removeChildAt(0);

// 移除所有子对象
container.removeChildren();

// 获取子对象
container.children;          // 所有子对象数组
container.children.length;   // 子对象数量
container.getChildIndex(sprite);  // 获取索引

// 判断是否包含
container.children.includes(sprite);

// 排序
container.sortableChildren = true;
container.sortChildren();    // 按 zIndex 排序
```

### 3.3 父子变换继承

子对象的最终变换 = 父对象变换 × 子对象自身变换。

```javascript
const parent = new Container();
parent.position.set(100, 100);
parent.rotation = Math.PI / 6;   // 旋转 30°
parent.scale.set(2);
app.stage.addChild(parent);

const child = new Sprite(texture);
child.position.set(50, 0);       // 相对于父容器偏移 (50, 0)
parent.addChild(child);

// child 的世界坐标：
// - 位置：parent.position + child.position × parent.scale（经过旋转）
// - 旋转：parent.rotation + child.rotation
// - 缩放：parent.scale × child.scale
```

```
Stage (0,0)
│
└── Parent (100, 100) 旋转30° 缩放2x
    │
    └── Child (50, 0) 相对于 Parent
        │
        最终世界位置 ≈ (186, 150)  // 经过父级变换计算
        最终旋转 = 30°
        最终缩放 = 2x
```

## 4. 移除 vs 销毁

这是新手最容易混淆的概念，也是对象池的基础。

### 4.1 removeChild — 从场景图移除

```javascript
container.removeChild(sprite);

// 效果：
// - sprite 不再显示
// - sprite 不再参与渲染
// - sprite 的纹理和内存仍然保留
// - sprite 可以通过 addChild 重新添加
```

### 4.2 destroy — 彻底销毁

```javascript
sprite.destroy();

// 效果：
// - sprite 不再显示
// - 释放 GPU 纹理内存
// - 移除所有事件监听
// - ⚠️ 对象不可再使用！再调用会报错
```

### 4.3 destroy 级联销毁

```javascript
// 销毁容器及其所有子对象
container.destroy({ children: true });

// 只销毁容器本身，子对象保留（孤儿节点）
container.destroy();

// 销毁纹理
sprite.destroy({ texture: true });

// 销毁纹理和基础纹理
sprite.destroy({ texture: true, baseTexture: true });
```

### 4.4 对比表

| 操作 | 从场景图移除 | 释放 GPU 内存 | 移除事件监听 | 可复用 |
|------|:---:|:---:|:---:|:---:|
| `removeChild()` | ✅ | ❌ | ❌ | ✅ |
| `destroy()` | ✅ | ✅ | ✅ | ❌ |
| `visible = false` | ❌（仍占位） | ❌ | ❌ | ✅ |

### 4.5 选择指南

```
需要暂时隐藏？
├── 是 → visible = false（最轻量，适合 UI 切换）
└── 否 → 需要复用？
    ├── 是 → removeChild()（对象池模式）
    └── 否 → destroy()（彻底释放内存）
```

## 5. zIndex 排序

默认情况下，子对象按添加顺序渲染（后添加的在上面）。通过 `zIndex` 可以控制渲染顺序。

```javascript
const container = new Container();
container.sortableChildren = true;  // 必须开启

const bg = new Sprite(bgTexture);
bg.zIndex = 0;          // 最底层

const player = new Sprite(playerTexture);
player.zIndex = 10;     // 中间层

const ui = new Sprite(uiTexture);
ui.zIndex = 100;        // 最上层

container.addChild(bg, player, ui);
container.sortChildren();  // 手动排序
```

> **注意**：`sortableChildren` 开启后，每次 `addChild` / `removeChild` 不会自动排序，需要手动调用 `sortChildren()` 或在 Ticker 中调用。性能敏感场景建议手动控制添加顺序而不是依赖 zIndex。

## 6. 实战：分层游戏架构

用 Container 实现经典的游戏分层结构：

```javascript
import { Application, Container, Sprite, Text } from 'pixi.js';

async function main() {
  const app = new Application();
  await app.init({ width: 800, height: 600, background: '#0f0f23' });
  document.body.appendChild(app.canvas);

  // 创建分层容器
  const bgLayer = new Container();       // 背景层
  const gameLayer = new Container();     // 游戏层
  const bulletLayer = new Container();   // 子弹层
  const enemyLayer = new Container();    // 敌机层
  const uiLayer = new Container();       // UI 层
  const popupLayer = new Container();    // 弹窗层

  // 按顺序添加到舞台（后面的在上面）
  app.stage.addChild(bgLayer, gameLayer, bulletLayer, enemyLayer, uiLayer, popupLayer);

  // 向各层添加内容
  const player = new Sprite(playerTexture);
  player.anchor.set(0.5);
  player.position.set(400, 500);
  gameLayer.addChild(player);

  const scoreText = new Text({ text: 'Score: 0', style: { fill: '#fff', fontSize: 24 } });
  scoreText.position.set(10, 10);
  uiLayer.addChild(scoreText);

  // 批量操作
  enemyLayer.visible = false;    // 隐藏所有敌机
  popupLayer.visible = false;    // 隐藏弹窗
}
```

```
渲染顺序（从下到上）：
┌─────────────┐
│  popupLayer  │  弹窗层（最上层）
├─────────────┤
│   uiLayer    │  UI 层（分数、生命值）
├─────────────┤
│ enemyLayer   │  敌机层
├─────────────┤
│ bulletLayer  │  子弹层
├─────────────┤
│  gameLayer   │  游戏层（玩家）
├─────────────┤
│   bgLayer    │  背景层（最底层）
└─────────────┘
```

## 7. 常见问题

### 7.1 Container 没有尺寸

```javascript
const container = new Sprite(texture);
console.log(container.width);  // 有纹理尺寸

const container = new Container();
console.log(container.width);  // 0 — Container 默认没有尺寸

// 获取容器的包围盒
const bounds = container.getBounds();
console.log(bounds.width, bounds.height);
```

### 7.2 子对象位置是相对的

```javascript
container.position.set(200, 200);
const child = new Sprite(texture);
child.position.set(50, 50);
container.addChild(child);

// child 的世界坐标 = (200 + 50, 200 + 50) = (250, 250)
// 但 child.x 仍然是 50（相对坐标）
```

### 7.3 销毁后再使用报错

```javascript
sprite.destroy();
app.stage.addChild(sprite);  // ❌ 报错：Cannot add destroyed object

// ✅ 正确做法：销毁后不再引用
sprite.destroy();
sprite = null;
```

## 📝 面试回答模板

> **问：什么是场景图？PixiJS 怎么用它管理对象？**
>
> 场景图是一种树状数据结构，根节点是 `stage`（舞台），每个节点可以有子节点。PixiJS 中所有可视对象都是场景图的节点——`Container` 是纯分组节点（类似 div），`Sprite`、`Graphics`、`Text` 是叶子节点。父节点的变换会传递给子节点：移动父容器，所有子对象跟随移动；缩放父容器，所有子对象跟随缩放。渲染时按深度优先遍历，先渲染的在下面，后渲染的在上面。这种设计让复杂场景的管理变得简单——比如游戏中的背景层、游戏层、UI 层、弹窗层分别用 Container 管理，隐藏/显示/销毁都可以批量操作。

> **问：removeChild 和 destroy 有什么区别？**
>
> `removeChild()` 只是把对象从场景图中移除，不再显示和渲染，但对象的纹理和内存都保留，可以随时 `addChild` 重新使用——这是对象池的基础。`destroy()` 会彻底销毁对象，释放 GPU 纹理内存、移除事件监听，对象不可再使用。选择依据：需要复用的用 `removeChild`（子弹、敌机等频繁创建销毁的对象），不需要复用的用 `destroy`（一次性弹窗、临时特效）。

> **问：PixiJS 的父子变换继承是怎么工作的？**
>
> 子对象的最终变换 = 父对象变换 × 子对象自身变换。具体来说：位置是相对于父容器的偏移，经过父级的旋转和缩放后得到世界坐标；旋转是父子旋转角度相加；缩放是父子缩放比例相乘。这意味着移动父容器，所有子对象自动跟随；缩放父容器，所有子对象等比缩放。这就是为什么游戏中的分层架构（背景层/游戏层/UI层）用 Container 管理——隐藏一层只需 `container.visible = false`，所有子对象一起隐藏。
