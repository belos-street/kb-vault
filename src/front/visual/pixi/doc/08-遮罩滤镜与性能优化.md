# 08 — 遮罩、滤镜与性能优化

> 对应大纲：模块 8 | 预计时间：1.5 天
> 面试可答：PixiJS 的遮罩（Mask）通过一个 Graphics 或 Sprite 定义可见区域，容器只有在遮罩范围内才会被渲染，常用于视野效果、图片裁剪、进度条等。滤镜（Filter）是后处理效果，作用于整个容器或精灵，PixiJS 内置了模糊、灰度、颜色矩阵等滤镜。性能优化的核心策略包括：对象池复用、纹理图集减少 GPU 状态切换、`cacheAsBitmap` 缓存静态容器、`ParticleContainer` 批量渲染粒子、`visible = false` 跳过渲染等。

---

## 1. 遮罩（Mask）

### 1.1 什么是遮罩

遮罩定义了一个"可见区域"，只有遮罩覆盖的部分才会被渲染，其余部分被裁剪掉。类似 Photoshop 的剪贴蒙版。

### 1.2 Graphics 遮罩

用 Graphics 绘制形状作为遮罩：

```javascript
import { Graphics, Container, Sprite } from 'pixi.js';

// 创建容器和内容
const world = new Container();
const bg = new Sprite(bgTexture);
world.addChild(bg);

// 创建圆形遮罩（视野效果）
const mask = new Graphics();
mask.circle(400, 300, 150);    // 圆心 (400,300)，半径 150
mask.fill(0xffffff);           // 遮罩必须填充（颜色不重要，只看形状）

// 应用遮罩
world.mask = mask;
app.stage.addChild(world);
app.stage.addChild(mask);      // 遮罩对象也需要添加到场景图
```

### 1.3 常见遮罩形状

```javascript
// 圆形遮罩（视野/聚光灯效果）
const circleMask = new Graphics();
circleMask.circle(400, 300, 200);
circleMask.fill(0xffffff);

// 矩形遮罩（图片裁剪）
const rectMask = new Graphics();
rectMask.rect(100, 100, 300, 200);
rectMask.fill(0xffffff);

// 圆角矩形遮罩（头像裁剪）
const roundMask = new Graphics();
roundMask.roundRect(50, 50, 100, 100, 50);  // radius = 50 → 正圆形
roundMask.fill(0xffffff);

// 多边形遮罩（不规则区域）
const polyMask = new Graphics();
polyMask.poly([100, 0, 200, 80, 160, 200, 40, 200, 0, 80]);
polyMask.fill(0xffffff);
```

### 1.4 动态遮罩

遮罩也是显示对象，可以移动、缩放、旋转：

```javascript
// 跟随鼠标的视野效果
const mask = new Graphics();
mask.circle(0, 0, 150);
mask.fill(0xffffff);

world.mask = mask;

app.stage.on('pointermove', (e) => {
  mask.x = e.global.x;
  mask.y = e.global.y;
});
```

### 1.5 Sprite 遮罩

除了 Graphics，也可以用 Sprite（图片）作为遮罩：

```javascript
const photo = new Sprite(photoTexture);
const maskSprite = new Sprite(maskTexture);  // 一张渐变图

photo.mask = maskSprite;
app.stage.addChild(photo);
app.stage.addChild(maskSprite);
```

**注意**：Sprite 遮罩适合做渐变遮罩（边缘渐隐效果），Graphics 遮罩适合做硬边裁剪。

## 2. 滤镜（Filter）

### 2.1 什么是滤镜

滤镜是后处理效果，在渲染管线的最后阶段对容器或精灵的渲染结果进行像素级处理。类似 CSS 的 `filter` 属性。

### 2.2 内置滤镜

PixiJS 内置了多种常用滤镜：

```javascript
import { BlurFilter, ColorMatrixFilter, NoiseFilter } from 'pixi.js';

// 模糊滤镜
const blur = new BlurFilter();
blur.strength = 8;            // 模糊强度
blur.quality = 4;             // 质量（1-15，默认 4）

// 颜色矩阵滤镜（最灵活）
const colorMatrix = new ColorMatrixFilter();
colorMatrix.desaturate();     // 灰度效果
colorMatrix.saturate(2);      // 增加饱和度
colorMatrix.brightness(1.5);  // 增加亮度
colorMatrix.contrast(0.5);    // 增加对比度
colorMatrix.hue(90);          // 色相旋转
colorMatrix.sepia();          // 复古褐色调

// 噪声滤镜
const noise = new NoiseFilter();
noise.noise = 0.5;            // 噪声强度
```

### 2.3 应用滤镜

```javascript
// 对单个精灵应用
sprite.filters = [new BlurFilter()];

// 对整个容器应用（影响所有子对象）
container.filters = [new ColorMatrixFilter()];

// 移除滤镜
sprite.filters = [];

// 组合多个滤镜
sprite.filters = [new BlurFilter(), new ColorMatrixFilter()];
```

### 2.4 实战：游戏结束灰度效果

```javascript
// 游戏结束时，整个游戏画面变灰
const gray = new ColorMatrixFilter();
gray.desaturate();
gameContainer.filters = [gray];

// 暂停遮罩叠在上面
const overlay = new Graphics();
overlay.rect(0, 0, 800, 600);
overlay.fill({ color: 0x000000, alpha: 0.5 });
app.stage.addChild(overlay);

// 显示 "GAME OVER" 文字
const gameOverText = new Text({
  text: 'GAME OVER',
  style: { fill: '#ffffff', fontSize: 48 },
});
gameOverText.anchor.set(0.5);
gameOverText.position.set(400, 300);
app.stage.addChild(gameOverText);
```

### 2.5 滤镜常见应用场景

| 滤镜 | 典型场景 | 原理 |
|------|---------|------|
| **模糊** | 对话框弹出时背景虚化，让玩家聚焦到对话上 | 降低背景画面清晰度，突出前景 UI |
| **模糊** | 子弹/角色高速运动时加运动模糊，增强速度感 | 沿运动方向施加方向模糊 |
| **灰度** | 游戏结束/暂停画面整体变灰，视觉上宣告"非活跃状态" | 去饱和让画面失活 |
| **灰度** | 不可点击的按钮/图标变灰，表示禁用状态 | 去饱和 + 降低亮度 |
| **色相旋转** | 角色受击时画面短暂偏红/偏白，制造受伤反馈 | 快速旋转色相角度 |
| **色相旋转** | 同一套纹理生成不同颜色变种（敌机红/绿/蓝），省去多套美术资源 | 旋转不同角度得到不同配色 |
| **亮度/对比度** | 拾取闪光道具时画面瞬间提亮，模拟闪光弹效果 | `brightness()` 短暂提高 |
| **复古褐色调** | 过场动画/回忆场景用 sepia 调，营造怀旧氛围 | `sepia()` 叠加褐色 |
| **噪声** | 电视雪花/老电影胶片质感，或为纯色纹理添加有机纹理 | `NoiseFilter` 叠加随机噪点 |

> **经验法则**：滤镜是 GPU 像素级后处理，开销不小。能用静态纹理（提前 P 好颜色变种）替代就不要实时色相旋转；能在单个容器上用一个滤镜就不要对每个子对象分别用。

### 2.6 自定义滤镜（GLSL）

对于高级需求，可以用 GLSL 着色器编写自定义滤镜（PixiJS v8 基于 WebGL 2.0）：

```javascript
import { Filter } from 'pixi.js';

// WebGL 2.0 语法（v8 默认）
const fragmentShader = `
  #version 100
  precision mediump float;
  varying vec2 vTextureCoord;
  uniform sampler2D uSampler;
  uniform float uTime;

  void main() {
    vec4 color = texture2D(uSampler, vTextureCoord);
    // 简单的波浪扭曲
    float offset = sin(vTextureCoord.y * 10.0 + uTime) * 0.01;
    color = texture2D(uSampler, vTextureCoord + vec2(offset, 0.0));
    gl_FragColor = color;
  }
`;

const waveFilter = new Filter(undefined, fragmentShader, {
  uTime: 0,
});

sprite.filters = [waveFilter];

// 在 ticker 中更新时间
app.ticker.add((ticker) => {
  waveFilter.uniforms.uTime += ticker.deltaTime * 0.1;
});
```

> **WebGL 2.0 vs WebGL 1.0 语法差异**：
> - 1.0 中 `varying` / `attribute` / `gl_FragColor` 在 2.0 中分别改为 `in` / `out` 变量
> - 1.0 的 `texture2D()` 在 2.0 中简化为 `texture()`
> - PixiJS v8 自动管理版本适配，上面的 `#version 100` 写法同时兼容两者

## 3. 性能优化

### 3.1 性能优化策略总览

| 技巧 | 说明 | 性能提升 |
|------|------|:---:|
| 对象池 | 预创建子弹/敌机，回收复用 | 减少 GC 卡顿 |
| 纹理图集 | 合并小图为 sprite sheet | 减少 GPU 纹理切换 |
| `cacheAsBitmap` | 静态容器缓存为位图 | 减少重绘 |
| `ParticleContainer` | 批量渲染同类精灵 | 大幅提升粒子性能 |
| `visible = false` | 隐藏对象不参与渲染 | 比 `alpha = 0` 高效 |
| 避免频繁 `filters` | 滤镜开销大 | 减少 GPU 负担 |
| `ticker.maxFPS` | 非游戏场景限制帧率 | 省电省 CPU |
| `destroy({ children: true })` | 销毁时级联销毁 | 释放纹理和内存 |

### 3.2 cacheAsBitmap

将复杂的静态容器缓存为一张位图，避免每帧重新绘制所有子对象。

```javascript
// 一个包含 100 个子对象的 UI 面板
const panel = new Container();
for (let i = 0; i < 100; i++) {
  const icon = new Sprite(iconTexture);
  icon.position.set(i * 40, 0);
  panel.addChild(icon);
}

// 缓存为位图（只渲染一次，后续直接贴图）
panel.cacheAsBitmap = true;

// 如果需要修改内容，先关闭缓存
panel.cacheAsBitmap = false;
// 修改子对象...
panel.cacheAsBitmap = true;  // 重新缓存
```

**适用场景**：不会变化的 UI 面板、背景装饰、复杂的静态图形。

### 3.3 ParticleContainer

`ParticleContainer` 是专为大量同类精灵优化的容器，只支持基础属性（position、rotation、alpha、scale），但渲染速度比普通 Container 快很多。

```javascript
import { ParticleContainer, Sprite } from 'pixi.js';

// 创建粒子容器
const particles = new ParticleContainer(1000, {
  position: true,      // 支持位置
  rotation: true,      // 支持旋转
  alpha: true,         // 支持透明度
  scale: true,         // 支持缩放
});
app.stage.addChild(particles);

// 生成粒子纹理（先用 Graphics 绘制圆形，再生成纹理）
const particleGfx = new Graphics();
particleGfx.circle(0, 0, 3);
particleGfx.fill(0xffd93d);
const particleTex = app.renderer.generateTexture(particleGfx);

for (let i = 0; i < 1000; i++) {
  const p = new Sprite(particleTex);
  p.x = Math.random() * 800;
  p.y = Math.random() * 600;
  p.alpha = Math.random();
  particles.addChild(p);
}

// 每帧更新粒子位置（性能远优于普通 Container）
app.ticker.add((ticker) => {
  const dt = ticker.deltaTime;
  for (const p of particles.children) {
    p.y -= dt;
    if (p.y < -10) p.y = 610;
  }
});
```

**ParticleContainer 的限制**：
- 不支持嵌套（子对象只能是 Sprite）
- 不支持滤镜、遮罩
- 只支持基础属性

### 3.4 visible vs alpha = 0

```javascript
// ✅ 推荐：visible = false → 完全跳过渲染管线
sprite.visible = false;

// ❌ 不推荐：alpha = 0 → 仍然参与渲染，只是透明
sprite.alpha = 0;
```

`visible = false` 时 PixiJS 会跳过该对象及其所有子对象的渲染，性能更好。

### 3.5 destroy 与内存管理

```javascript
// 销毁单个精灵（释放纹理、事件监听）
sprite.destroy();

// 销毁容器及其所有子对象
container.destroy({ children: true });

// 销毁纹理
texture.destroy(true);  // true = 同时销毁 GPU 资源

// 检查是否已销毁
if (sprite.destroyed) {
  console.log('已被销毁');
}
```

**常见内存泄漏**：
- 销毁对象后仍被数组/变量引用 → 从数组中移除
- 事件监听未移除 → `sprite.off()` 或 `sprite.destroy()`
- 全局缓存的纹理未清理 → `texture.destroy()`

## 4. 粒子系统实战

### 4.1 简单爆炸粒子

> 以下用 Graphics 演示爆炸原理，更简单易懂。实际项目中如粒子数量较大（> 100），建议改用 3.3 节的 `ParticleContainer` + `Sprite` 方案获得更好性能。

```javascript
function createExplosion(x, y, count) {
  const particles = [];

  for (let i = 0; i < count; i++) {
    const p = new Graphics();
    p.circle(0, 0, 3 + Math.random() * 4);
    p.fill(0xffd93d);
    p.position.set(x, y);

    // 随机方向和速度
    const angle = Math.random() * Math.PI * 2;
    const speed = 2 + Math.random() * 4;
    p.vx = Math.cos(angle) * speed;
    p.vy = Math.sin(angle) * speed;
    p.life = 1;  // 生命值 0~1

    app.stage.addChild(p);
    particles.push(p);
  }

  // 更新粒子
  const update = (ticker) => {
    const dt = ticker.deltaTime;
    for (let i = particles.length - 1; i >= 0; i--) {
      const p = particles[i];
      p.x += p.vx * dt;
      p.y += p.vy * dt;
      p.life -= 0.02 * dt;
      p.alpha = p.life;

      if (p.life <= 0) {
        app.stage.removeChild(p);  // 先移除
        p.destroy();               // 再释放资源
        particles.splice(i, 1);
      }
    }

    if (particles.length === 0) {
      app.ticker.remove(update);
    }
  };

  app.ticker.add(update);
}
```

### 4.2 粒子性能对比

| 方式 | 100 粒子 | 1000 粒子 | 10000 粒子 |
|------|:---:|:---:|:---:|
| 普通 Container + Graphics | 流畅 | 卡顿 | 不可用 |
| 普通 Container + Sprite | 流畅 | 流畅 | 卡顿 |
| ParticleContainer + Sprite | 流畅 | 流畅 | 流畅 |

**结论**：大量粒子场景必须用 `ParticleContainer` + `Sprite`，避免用 `Graphics`。

## 5. 方案对比：滤镜 vs cacheAsBitmap vs ParticleContainer

| 特性 | 滤镜 | cacheAsBitmap | ParticleContainer |
|------|:---:|:---:|:---:|
| **用途** | 后处理效果 | 缓存静态内容 | 批量渲染粒子 |
| **性能开销** | 高（GPU 像素处理） | 低（一次缓存） | 极低（批量渲染） |
| **支持动画** | ✅ | ❌（静态） | ✅（基础属性） |
| **支持子对象** | ✅ | ✅ | 仅 Sprite |
| **适用场景** | 模糊、灰度、扭曲 | 静态 UI 面板 | 粒子、星星、雨滴 |

## 📝 面试回答模板

> **问：PixiJS 的遮罩怎么实现？有什么用途？**
>
> 遮罩通过 `container.mask = maskGraphics` 设置，遮罩对象定义了可见区域的形状。Graphics 可以绘制圆形、矩形、多边形等形状作为遮罩，也可以用 Sprite 做渐变遮罩。常见用途：1）视野效果（圆形遮罩跟随鼠标）；2）图片裁剪（矩形遮罩裁剪头像）；3）进度条（矩形遮罩控制显示宽度）。遮罩对象也需要添加到场景图中，否则不生效。

> **问：PixiJS 的滤镜性能开销大吗？怎么优化？**
>
> 滤镜是后处理效果，需要对渲染结果做像素级处理，性能开销较大。优化方式：1）减少滤镜数量，能不用就不用；2）静态对象用 `cacheAsBitmap` 缓存滤镜效果，避免每帧重新计算；3）降低滤镜质量（如 `blur.quality = 1`）；4）对整个容器应用一个滤镜，而不是对每个子对象分别应用。

> **问：ParticleContainer 和普通 Container 有什么区别？**
>
> `ParticleContainer` 是专为大量同类精灵优化的容器，渲染速度比普通 Container 快很多，因为它跳过了很多通用的渲染逻辑（嵌套、滤镜、遮罩等），只支持基础属性（position、rotation、alpha、scale）。适用场景：粒子效果、星星背景、雨滴等需要大量同类精灵的情况。限制是子对象只能是 Sprite，不支持嵌套和滤镜。
