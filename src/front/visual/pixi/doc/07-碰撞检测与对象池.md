# 07 — 碰撞检测与对象池

> 对应大纲：模块 7 | 预计时间：1.5 天
> 面试可答：游戏中的碰撞检测主要有两种方式——**圆形碰撞**（距离公式）和**矩形碰撞**（AABB 包围盒）。圆形碰撞通过计算两个圆心的距离是否小于半径之和来判断，适合子弹、球类等近似圆形的物体；矩形碰撞通过判断两个矩形是否有重叠区域来判断，适合 UI 面板、墙壁等矩形物体。对象池是游戏开发中减少 GC 压力的核心模式——预先创建一批对象放在"池子"里，需要时取出、用完后归还，避免反复 `new` + `destroy` 造成的内存抖动。

---

## 1. 碰撞检测基础

### 1.1 为什么需要碰撞检测

游戏中的核心交互——子弹击中敌机、角色踩到地面、拾取道具——都需要判断两个物体是否"碰到了"。PixiJS 本身没有内置碰撞检测，需要自己实现。

### 1.2 圆形碰撞（距离公式）

最常用的碰撞检测方式，计算两个圆心的距离是否小于半径之和。

```javascript
function circleCollision(a, b) {
  const dx = a.x - b.x;          // x 方向距离
  const dy = a.y - b.y;          // y 方向距离
  const distance = Math.sqrt(dx * dx + dy * dy);  // 勾股定理求实际距离
  return distance < a.radius + b.radius;           // 距离 < 半径之和 = 碰撞
}
```

**原理图解**：

```
情况 1：未碰撞（distance > r1 + r2）

    ●───── distance ─────●
   (A)                   (B)
    r1                    r2

情况 2：碰撞（distance < r1 + r2）

    ●── distance ──●
   (A)            (B)
    r1              r2
    ← r1+r2 范围重叠 →
```

**性能优化**：`Math.sqrt` 开销较大，可以改用平方比较（省去开方运算）：

```javascript
function circleCollisionFast(a, b) {
  const dx = a.x - b.x;
  const dy = a.y - b.y;
  const distSq = dx * dx + dy * dy;                    // 距离的平方
  const radiusSum = a.radius + b.radius;
  return distSq < radiusSum * radiusSum;                // 平方比较，省去 sqrt
}
```

### 1.3 矩形碰撞（AABB 包围盒）

AABB（Axis-Aligned Bounding Box）即轴对齐包围盒，判断两个矩形是否有重叠区域。

```javascript
function rectCollision(a, b) {
  // 使用 getBounds() 获取世界坐标下的包围盒（自动处理 anchor 和父级变换）
  const boundsA = a.getBounds();
  const boundsB = b.getBounds();

  return (
    boundsA.x < boundsB.x + boundsB.width &&
    boundsA.x + boundsA.width > boundsB.x &&
    boundsA.y < boundsB.y + boundsB.height &&
    boundsA.y + boundsA.height > boundsB.y
  );
}
```

> **为什么要用 getBounds() 而不是直接比较 x/y/width？**
> 如果 Sprite 设置了 `anchor`（如 `anchor.set(0.5)`），`sprite.x` 表示中心点而非左上角坐标。直接比较 `a.x < b.x + b.width` 会得到错误结果。`getBounds()` 返回的是对象在全局坐标系下的包围盒（`{ x, y, width, height }`），其中 `x, y` 始终是左上角，自动处理了 `anchor`、`pivot`、`scale` 和父级变换。**只要 Sprite 有变换（anchor、旋转、缩放），碰撞检测都应该用 `getBounds()`。**

**不使用 getBounds() 的快速版本**（适用于 anchor 为 (0,0) 且无父级变换的简单场景）：

```javascript
function rectCollisionFast(a, b) {
  // 要求：a 和 b 的 anchor 均为 (0,0)，且无父级变换
  return (
    a.x < b.x + b.width &&
    a.x + a.width > b.x &&
    a.y < b.y + b.height &&
    a.y + a.height > b.y
  );
}
```

### 1.4 PixiJS 中的碰撞检测实践

PixiJS 的 Sprite 没有内置 `radius` 属性，需要手动定义：

```javascript
const bullet = new Sprite(bulletTexture);
bullet.anchor.set(0.5);          // 锚点居中，(x, y) 就是中心点
bullet.radius = 8;               // 自定义碰撞半径

const enemy = new Sprite(enemyTexture);
enemy.anchor.set(0.5);
enemy.radius = 20;

// 在游戏循环中检测
app.ticker.add((ticker) => {
  if (circleCollision(bullet, enemy)) {
    // 碰撞！
    console.log('命中！');
  }
});
```

**注意**：`anchor.set(0.5)` 很重要——它让 `(x, y)` 表示精灵中心点，这样距离公式才能正确计算。

## 2. 碰撞检测优化

### 2.1 朴素检测的问题

如果场景中有 100 颗子弹和 50 个敌机，每帧需要检测 `100 × 50 = 5000` 次碰撞。当数量增加时，性能会急剧下降。

### 2.2 空间分区（Spatial Partitioning）

将画布划分为网格，只检测同一格子或相邻格子内的物体。

```javascript
// 简单网格分区
class SpatialGrid {
  constructor(cellSize, width, height) {
    this.cellSize = cellSize;
    this.cols = Math.ceil(width / cellSize);
    this.rows = Math.ceil(height / cellSize);
    this.cells = new Map();
  }

  // 清空所有格子（每帧开始时调用）
  clear() {
    this.cells.clear();
  }

  // 根据坐标计算格子 key
  getKey(x, y) {
    const col = Math.floor(x / this.cellSize);
    const row = Math.floor(y / this.cellSize);
    return `${col},${row}`;
  }

  // 将物体插入对应格子
  insert(obj) {
    const key = this.getKey(obj.x, obj.y);
    if (!this.cells.has(key)) {
      this.cells.set(key, []);
    }
    this.cells.get(key).push(obj);
  }

  // 获取某物体周围格子中的所有物体
  getNearby(obj) {
    const col = Math.floor(obj.x / this.cellSize);
    const row = Math.floor(obj.y / this.cellSize);
    const result = [];

    // 检查周围 9 个格子（含自身）
    for (let dc = -1; dc <= 1; dc++) {
      for (let dr = -1; dr <= 1; dr++) {
        const key = `${col + dc},${row + dr}`;
        const cell = this.cells.get(key);
        if (cell) result.push(...cell);
      }
    }
    return result;
  }
}
```

**使用方式**：

```javascript
const grid = new SpatialGrid(100, 800, 600); // 100px 格子

app.ticker.add(() => {
  grid.clear();

  // 将所有敌机插入网格
  enemies.forEach(e => grid.insert(e));

  // 每颗子弹只检测附近的敌机
  bullets.forEach(bullet => {
    const nearby = grid.getNearby(bullet);
    for (const enemy of nearby) {
      if (circleCollision(bullet, enemy)) {
        // 命中！
      }
    }
  });
});
```

### 2.3 碰撞检测方式选择

| 方式 | 时间复杂度 | 适用场景 |
|------|:---:|------|
| 朴素遍历 | O(n × m) | 物体数量少（< 100） |
| 空间网格 | O(n × k)，k 为邻近物体数 | 物体分布均匀 |
| 四叉树 | O(n log n) | 物体分布不均、需要动态调整 |

**实际项目建议**：物体数量 < 200 时，朴素遍历 + 平方比较就够了。超过 200 再考虑空间分区。

## 3. 对象池模式

### 3.1 为什么需要对象池

游戏中子弹、敌机、粒子等对象会频繁创建和销毁。每次 `new Sprite()` + `destroy()` 都会产生内存分配和垃圾回收（GC），导致卡顿。

```
❌ 不用对象池：
  每帧 new Sprite() → 飞出屏幕 → destroy()
  GC 频繁触发 → 画面卡顿

✅ 使用对象池：
  预先创建 50 个 Sprite 放入池中
  需要时 pool.get() → 使用 → 飞出屏幕 → pool.release()
  零 GC → 流畅
```

### 3.2 基础对象池实现

```javascript
class ObjectPool {
  /**
   * @param {Function} createFn - 创建对象的函数
   * @param {Function} resetFn  - 重置对象的函数
   * @param {number} maxSize    - 池最大容量
   */
  constructor(createFn, resetFn, maxSize = 50) {
    this.createFn = createFn;
    this.resetFn = resetFn;
    this.maxSize = maxSize;
    this.pool = [];          // 可用对象
    this.active = [];        // 正在使用的对象
  }

  // 从池中获取一个对象
  get() {
    let obj;
    if (this.pool.length > 0) {
      obj = this.pool.pop();       // 池中有，直接取
    } else if (this.active.length < this.maxSize) {
      obj = this.createFn();       // 池中没有，创建新的
    } else {
      return null;                 // 池已满
    }
    this.resetFn(obj);             // 重置状态
    this.active.push(obj);
    return obj;
  }

  // 归还对象到池中
  release(obj) {
    const idx = this.active.indexOf(obj);
    if (idx !== -1) {
      this.active.splice(idx, 1);
      obj.visible = false;       // 自动隐藏，避免屏幕残留
      this.pool.push(obj);
    }
  }

  // 归还所有活跃对象
  releaseAll() {
    while (this.active.length > 0) {
      this.pool.push(this.active.pop());
    }
  }
}
```

### 3.3 子弹池实战

```javascript
// 创建子弹纹理（用 Graphics 生成，无需图片文件）
const bulletGfx = new Graphics();
bulletGfx.rect(0, 0, 4, 12);
bulletGfx.fill(0xffd93d);
const bulletTexture = app.renderer.generateTexture(bulletGfx);

// 创建子弹池
const bulletPool = new ObjectPool(
  // createFn：创建子弹精灵
  () => {
    const bullet = new Sprite(bulletTexture);
    bullet.anchor.set(0.5);
    app.stage.addChild(bullet);
    return bullet;
  },
  // resetFn：重置子弹状态
  (bullet) => {
    bullet.x = 0;
    bullet.y = 0;
    bullet.visible = true;
    bullet.alpha = 1;
    bullet.rotation = 0;
  },
  50  // 最多 50 颗子弹
);

// 发射子弹
function shoot(playerX, playerY) {
  const bullet = bulletPool.get();
  if (!bullet) return;  // 池已满

  bullet.x = playerX;
  bullet.y = playerY - 20;
}

// 游戏循环：移动子弹 + 回收
app.ticker.add((ticker) => {
  const dt = ticker.deltaTime;
  const speed = 8;

  // 遍历活跃子弹
  for (let i = bulletPool.active.length - 1; i >= 0; i--) {
    const bullet = bulletPool.active[i];
    bullet.y -= speed * dt;

    // 出屏回收
    if (bullet.y < -20) {
      bullet.visible = false;
      bulletPool.release(bullet);
    }
  }
});
```

### 3.4 对象池 vs 直接创建销毁

| 方式 | 内存分配 | GC 压力 | 代码复杂度 | 适用场景 |
|------|:---:|:---:|:---:|------|
| 直接 `new` + `destroy` | 每次分配 | 高 | 低 | 对象少、创建频率低 |
| 对象池 | 预分配 | 无 | 中 | 子弹、粒子、敌机等高频对象 |

**经验法则**：每秒创建/销毁超过 10 个同类对象，就该用对象池。

## 4. 方案对比：碰撞检测实现方式

| 方式 | 精度 | 性能 | 实现难度 | 适用形状 |
|------|:---:|:---:|:---:|------|
| 圆形碰撞 | 中 | 高（只需 sqrt） | 低 | 子弹、球、角色 |
| 矩形碰撞（AABB） | 中 | 高（只需比较） | 低 | UI、墙壁、箱子 |
| 像素碰撞 | 高 | 低（需遍历像素） | 高 | 不规则形状（极少用） |
| 物理引擎（matter.js） | 高 | 中 | 中 | 复杂物理模拟 |

**选择建议**：
- 90% 的 2D 游戏 → 圆形或矩形碰撞够用
- 需要物理模拟（重力、弹性、摩擦力） → 用 matter.js 或 planck.js
- 像素级碰撞 → 性能太差，不推荐

## 📝 面试回答模板

> **问：PixiJS 中怎么做碰撞检测？**
>
> PixiJS 本身没有内置碰撞检测，需要自己实现。最常用的是**圆形碰撞**（距离公式）和**矩形碰撞**（AABB）。圆形碰撞通过勾股定理计算两个圆心距离，判断是否小于半径之和，适合子弹、球类等物体；矩形碰撞判断两个矩形是否有重叠区域，适合 UI 和墙壁。性能优化上，可以用平方比较代替 `Math.sqrt`，物体数量多时用空间网格分区减少检测次数。

> **问：什么是对象池？为什么游戏要用它？**
>
> 对象池是预先创建一批对象放在"池子"里，需要时取出、用完后归还的模式。游戏中子弹、敌机、粒子等对象会频繁创建和销毁，每次 `new` + `destroy` 都会产生内存分配和 GC（垃圾回收），导致画面卡顿。对象池通过复用对象避免了这个问题——池中对象的内存地址不变，GC 不需要扫描和回收，性能更稳定。经验法则：每秒创建/销毁超过 10 个同类对象就应该用对象池。

> **问：圆形碰撞的性能优化怎么做？**
>
> 最直接的优化是用平方比较代替 `Math.sqrt`。标准写法是 `Math.sqrt(dx*dx + dy*dy) < r1 + r2`，优化后是 `dx*dx + dy*dy < (r1+r2) * (r1+r2)`，省去了开方运算。当物体数量很多时（> 200），可以用空间网格分区（Spatial Grid）将画布划分为格子，每帧只检测同一格子或相邻格子内的物体，把 O(n²) 降到接近 O(n)。
