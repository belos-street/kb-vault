# 01 - 核心概念与初始化

> 对应大纲模块 1 | 预计时间：0.5 天
> 面试可答：Konva 采用分层架构，Stage 包含 Layer，Layer 包含 Shape。

***

## 1. Konva.js 是什么

Konva.js 是一个基于 Canvas 的 2D 图形库，它给原生 Canvas 加了一层**对象模型**：

- 所有图形都是**对象**（Rect、Circle、Line...）
- 对象可以**嵌套、分组、绑定事件、拖拽、变换**
- 分层渲染，多个 Canvas 叠加使用

### 跟原生 Canvas 对比

| 需求     | 原生 Canvas    | Konva                  |
| ------ | ------------ | ---------------------- |
| 画一个矩形  | `ctx.rect()` | `new Konva.Rect()`     |
| 点击矩形变红 | 手动算坐标命中检测    | `rect.on('click', fn)` |
| 拖拽矩形   | 手动实现         | `draggable: true`      |
| 缩放矩形   | 手动重绘         | `Transformer` 控件       |

**结论**：原生 Canvas 是"画了就忘"的像素操作，Konva 是"对象化管理"，这是面试常考的第一句话。

***

## 2. 三大核心概念

Konva 的分层架构可以用 DOM 类比来理解：

| Konva   | 类比 DOM           | 说明                     |
| ------- | ---------------- | ---------------------- |
| `Stage` | `document` / 根容器 | 最顶层，绑定到页面 DOM 元素       |
| `Layer` | 透明的 Canvas 画布    | 每个 Layer 对应一个独立 Canvas |
| `Group` | `<div>`          | 逻辑分组，可嵌套               |
| `Shape` | 实际的元素            | Rect、Circle、Text...    |

### 层级关系

```
Stage（绑定到 DOM 容器）
 └── Layer（底层 Canvas）
 │    └── Group
 │         ├── Rect
 │         └── Circle
 └── Layer（顶层 Canvas）
      └── Text
```

**为什么分层？** 每个 Layer 是一个独立的 Canvas，修改一个 Layer 里的图形不会影响另一个，性能更好。就像 Photoshop 的图层一样。

## 3. 初始化一个 Konva 应用

### 3.1 安装

```bash
npm install konva
# 或 CDN
<script src="https://unpkg.com/konva@9/konva.min.js"></script>
```

### 3.2 创建 Stage

```js
const stage = new Konva.Stage({
  container: 'root',      // DOM 容器 id
  width: window.innerWidth,
  height: window.innerHeight,
});
```

`container` 可以传 id 字符串或 DOM 元素引用。

### 3.3 创建 Layer

```js
const layer = new Konva.Layer();
stage.add(layer);
```

Layer 必须 `add` 到 Stage 上才会显示。一个 Stage 可以有多个 Layer。

### 3.4 添加图形

```js
const circle = new Konva.Circle({
  x: 200,        // 舞台上的 x 坐标
  y: 200,        // 舞台上的 y 坐标
  radius: 80,
  fill: 'tomato',
  stroke: '#333',
  strokeWidth: 4,
});

layer.add(circle);

layer.draw();
```

**渲染机制：为什么可以不用 `draw()`？**

现代 Konva（v7+）已全面自动化渲染：

| 操作 | 渲染方式 |
|------|---------|
| `stage.add(layer)` | 内部直接调用 `layer.draw()` |
| `layer.add(shape)` | 触发 `_requestDraw()` → `batchDraw()`（通过 `requestAnimationFrame` 批量优化） |
| `shape.setAttrs({...})` / `shape.fill('red')` | 同样触发 `_requestDraw()` → `batchDraw()` |

所有属性变更和 add 操作都会通过 `Konva.autoDrawEnabled`（默认 `true`）自动渲染，开发者无需手动干预。

**`draw()` 的真实角色是什么？**

`draw()` 是早期 Konva 版本的**遗留用法**。旧版中必须手动调用才能渲染；新版中它是**「强制立即渲染」**——跳过 `requestAnimationFrame` 队列，立即同步执行绘制指令。

```
layer.add(circle);          // ✅ 自动 batchDraw()——下一帧渲染
circle.setAttrs({fill:'red'}); // ✅ 自动 batchDraw()——同上

layer.draw();               // ⚠️ 强制立即渲染（极少需要）
                             //    仅用于：需要在当前帧拿到 toDataURL() 等场景
```

**结论**：日常开发中不需要写 `draw()`，Konva 会自动处理。示例代码中保留它是为了兼容习惯，以及演示「强制立即」场景。

### 3.5 完整的 Hello World

```html
<!DOCTYPE html>
<html>
<head>
  <script src="https://unpkg.com/konva@9/konva.min.js"></script>
</head>
<body>
  <div id="root" style="background:#eee;"></div>
  <script>
    const stage = new Konva.Stage({
      container: 'root',
      width: 600,
      height: 400,
    });

    const layer = new Konva.Layer();
    stage.add(layer);

    const circle = new Konva.Circle({
      x: 200,
      y: 200,
      radius: 80,
      fill: 'tomato',
      stroke: '#333',
      strokeWidth: 4,
    });

    layer.add(circle);
    layer.draw();  // 可省略——add() 已自动触发渲染；保留仅为习惯/强制立即
  </script>
</body>
</html>
```

## 4. 关键对象速查

### Stage

```js
stage.width()          // 获取宽度
stage.width(800)       // 设置宽度（会触发 resize）
stage.height(600)
stage.scale({ x: 2, y: 2 })  // 整体缩放
stage.toDataURL()      // 导出图片
stage.toJSON()         // 序列化JSON 字符串，包含所有图形的位置、尺寸、样式信息
```

### Layer

```js
layer.add(shape)       // 添加图形（自动渲染）
layer.remove(shape)    // 移除图形
layer.draw()           // 强制立即渲染（历史遗留，日常不需要）
layer.batchDraw()      // 批量渲染（自动触发，一般不需要手动调用）
layer.clear()          // 清空
```

### Shape 公共属性

```js
shape.x(100)           // 位置
shape.y(100)
shape.rotation(45)     // 旋转角度
shape.scaleX(2)        // 缩放
shape.scaleY(2)
shape.opacity(0.5)     // 透明度
shape.visible(false)   // 可见性
shape.name('box')      // 命名，便于查找
shape.id('box1')       // ID，唯一标识
```

## 5. 初学者常见问题

### Q: 图形没有显示？

1. 检查 `stage.add(layer)` 是否执行
2. 检查坐标是否在 Stage 可见区域内
3. 如果渲染仍然异常，尝试 `layer.draw()` 强制立即渲染排查（极少需要）

### Q: 为什么要手动 draw？

`draw()` 是 Konva 早期版本的**历史遗留用法**。旧版 Konva 中，添加/修改图形后必须手动调用 `layer.draw()` 才能渲染。现代 Konva（v7+）已全面自动化——`add()`、`setAttrs()`、属性修改等操作都会通过 `requestAnimationFrame` 批量优化渲染，开发者无需手动干预。

如今 `draw()` 的定位是**「强制立即渲染」**：跳过 RAF 队列，立即同步执行绘制。仅用于极少数特殊场景（如需要在当前帧立刻拿到 `toDataURL()` 的截图结果）。日常开发中**不需要**写 `draw()`。

### Q: Stage 和 Layer 的尺寸怎么确定？

- 默认不设置时，Stage 的默认宽高是 0
- 可以用 `stage.width()` / `stage.height()` 动态获取
- 通常初始化时就从 `container` 的尺寸或直接传入像素值

## 📝 面试回答模板

> **问：Konva.js 的核心架构是什么样的？**
>
> Konva 采用三层分层架构：Stage → Layer → Shape。Stage 是顶层容器，绑定到 DOM 元素；Layer 是独立的 Canvas，每个 Layer 对应一个真实的 Canvas 元素；Shape 是具体的图形对象（Rect、Circle 等）。这种设计让 Konva 能够做到对象化管理——每个图形都是一个对象，可以直接操作属性、绑定事件、拖拽变换，而不需要像原生 Canvas 那样手动管理绘制状态。
