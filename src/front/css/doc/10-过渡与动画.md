## 核心概念

### 1. 过渡（Transition）

过渡是**两个状态之间的补间动画**——当属性的计算值发生变化时，浏览器自动插值。

```css
.btn {
  background: #4f46e5;
  transform: translateY(0);
  transition: transform 0.3s ease, background 0.3s ease;
}
.btn:hover {
  background: #4338ca;
  transform: translateY(-2px); /* 状态变化 → 自动补间 */
}
```

#### 四个子属性

```css
transition:
  transition-property: transform;        /* 过渡哪些属性 */
  transition-duration: 0.3s;             /* 时长 */
  transition-timing-function: ease;      /* 缓动曲线 */
  transition-delay: 0s;                  /* 延迟 */
```

#### 缓动函数与 cubic-bezier

```css
/* 内置缓动 */
ease        /* 先快后慢（默认） */
linear      /* 匀速 */
ease-in     /* 慢入快出 */
ease-out    /* 快入慢出 */
ease-in-out /* 慢入慢出 */

/* cubic-bezier(x1, y1, x2, y2) 自定义曲线 */
/* 两个控制点决定曲线形状 */
transition-timing-function: cubic-bezier(0.68, -0.55, 0.265, 1.55); /* 回弹效果 */
```

**理解 cubic-bezier**：曲线从 (0,0) 到 (1,1)，两个控制点 (x1,y1) (x2,y2) 决定加速/减速形状。y 值超出 0-1 范围会产生"过冲/回弹"效果。

#### steps() 逐帧动画

```css
/* steps(n) 把过渡分成 n 个离散步骤（无补间） */
.typewriter {
  width: 20ch;
  white-space: nowrap;
  overflow: hidden;
  animation: typing 2s steps(20); /* 一次显示一个字符 */
}
```

#### linear() 自定义缓动（Baseline 2023）

```css
/* linear() 用折线逼近任意曲线，比 cubic-bezier 更灵活 */
/* 语法：linear(y1, y2, ..., yn)，等分时间点 */
.bounce {
  transition: transform 0.5s linear(
    0, 0.004, 0.016, 0.035, 0.063, 0.098, 0.141,
    0.191, 0.25, 0.316, 0.391, 0.473, 0.563, 0.66,
    0.766, 0.879, 1, 0.973, 0.953, 0.941, 0.938,
    0.941, 0.953, 0.973, 1
  );
}

/* 也可以指定时间点百分比 */
.ease-spring {
  animation-timing-function: linear(0, 0.5 25%, 1 50%, 0.8 75%, 1);
}
```

**linear() vs cubic-bezier**：cubic-bezier 只能表达单调或单峰曲线（最多一个过冲），linear() 可以表达任意复杂曲线（多次弹跳、弹簧效果），是 CSS 原生实现弹性动画的方式。

#### 过渡的触发与限制

```css
/* 触发条件：计算值发生变化（hover、class 切换、JS 改样式） */

/* ❌ display 不可过渡（不是连续值，是离散跳变） */
.box { display: none; transition: display 0.3s; } /* 无效 */

/* ❌ transition: all 的性能陷阱 */
.card { transition: all 0.3s; } /* 所有属性都监听 → 意外过渡 + 性能开销 */
/* ✅ 明确指定属性 */
.card { transition: transform 0.3s, box-shadow 0.3s; }
```

### 2. 动画（Animation）

动画用 `@keyframes` 定义**多关键帧**，可以循环、往返、控制填充模式，比 transition 强大。

```css
@keyframes bounce {
  0%   { transform: translateY(0); }
  50%  { transform: translateY(-30px); }
  100% { transform: translateY(0); }
}

.ball {
  animation: bounce 1s ease-in-out infinite;
}
```

#### animation 完整属性

```css
animation:
  animation-name: bounce;            /* 关键帧名称 */
  animation-duration: 1s;            /* 单次时长 */
  animation-timing-function: ease;   /* 缓动 */
  animation-delay: 0s;               /* 延迟 */
  animation-iteration-count: infinite; /* 次数（infinite / 数字） */
  animation-direction: alternate;    /* 方向 */
  animation-fill-mode: forwards;     /* 填充模式 */
  animation-play-state: paused;      /* 播放状态 */
```

#### direction 与 fill-mode

```css
/* direction：播放方向 */
normal;            /* 0% → 100%（默认） */
reverse;           /* 100% → 0% */
alternate;         /* 奇数次正向，偶数次反向（往返） */
alternate-reverse; /* 先反向再正向 */

/* fill-mode：动画结束后的状态 */
none;      /* 回到动画前状态（默认） */
forwards;  /* 保持最后一帧 */
backwards; /* 延迟期间应用第一帧 */
both;      /* forwards + backwards */
```

**面试常问**：fill-mode: forwards 和 both 的区别？

`forwards` 让动画结束后保持最后一帧；`both` 额外在延迟期间（delay）就应用第一帧。有 delay 且希望元素一开始就在动画起始位置时用 `both`。

#### transition vs animation

| 维度 | transition | animation |
|------|-----------|-----------|
| 触发 | 需要状态变化（hover/class） | 自动播放 |
| 关键帧 | 只有起点终点 | @keyframes 多关键帧 |
| 循环 | 不支持 | infinite |
| 往返 | 需双向定义 | alternate |
| 适用 | 简单交互反馈 | 复杂/循环动画 |

### 3. 性能模型：渲染流水线

```
JS → Style → Layout（重排）→ Paint（重绘）→ Composite（合成）
         ↑ 每帧从哪一步开始，决定性能

动画 left/top/width  → 触发 Layout → 最慢
动画 color/background → 触发 Paint  → 较慢
动画 transform/opacity → 仅 Composite → 最快（GPU）
```

**为什么 transform/opacity 快**：它们不改变元素的几何和绘制内容，浏览器把元素渲染成一张位图（合成层），动画时只是在 GPU 上对这张图做仿射变换/调透明度，跳过了 Layout 和 Paint。

#### 诊断工具

```
Chrome DevTools:
- Performance 面板：录制动画，看每帧耗时、是否有 Layout/Paint
- Rendering 面板 → Paint flashing：绿色高亮重绘区域
- Rendering 面板 → FPS meter：实时帧率
- Rendering 面板 → Layout Shift Regions：布局偏移区域
```

**目标**：动画每帧 < 16.7ms（60fps），避免紫色（Layout）和绿色（Paint）大块。

### 4. content-visibility 与 contain（性能优化）

#### content-visibility（Baseline 2024-09）

```css
/* 跳过视口外元素的布局和绘制，长列表首屏性能关键 */
.list-item {
  content-visibility: auto;
  contain-intrinsic-size: 0 200px; /* 预估高度，避免滚动条跳动 */
}
```

**原理**：`content-visibility: auto` 让浏览器对屏幕外的元素跳过渲染（类似懒加载，但浏览器原生实现）。`contain-intrinsic-size` 提供预估尺寸，保证滚动条准确。

#### contain 属性

```css
/* 告诉浏览器"这个元素内部的变化不影响外部"，缩小重排范围 */
.card {
  contain: layout paint;   /* 布局和绘制局限在内部 */
  contain: strict;         /* = size layout paint style */
  contain: content;        /* = layout paint style */
}
```

**contain 的价值**：浏览器知道修改 `.card` 内部不会导致外部重排，可以局部计算，大幅提升复杂页面的渲染性能。

### 5. @starting-style 与进入退出动画（Baseline 2024-08）

**痛点**：`display: none → block` 是离散跳变，transition 无法生效，所以弹窗的进入/退出动画一直需要 JS。

```css
/* @starting-style：为首次渲染/display 切换提供过渡起点 */
.dialog {
  opacity: 1;
  transform: translateY(0);
  transition: opacity 0.3s, transform 0.3s;
  transition-behavior: allow-discrete; /* 允许 display 参与过渡 */
}

/* 进入动画的起点 */
@starting-style {
  .dialog {
    opacity: 0;
    transform: translateY(20px);
  }
}

/* 退出状态 */
.dialog[hidden] {
  display: none;
}
```

#### 三态模型

```
@starting-style 状态  →  默认状态  →  [hidden] 状态
（进入起点）            （正常显示）   （退出终点）

进入：starting-style → 默认（淡入上移）
退出：默认 → hidden 前保持可见（配合 allow-discrete 延迟 display:none）
```

**`transition-behavior: allow-discrete`** 的作用：让 display 这样的离散属性也参与过渡——退出时先完成 opacity/transform 过渡，最后才真正 `display: none`。

#### 实战：popover 进入退出动画

```css
[popover] {
  opacity: 1;
  transform: scale(1);
  transition: opacity 0.3s, transform 0.3s,
              display 0.3s allow-discrete,
              overlay 0.3s allow-discrete; /* overlay 控制 top-layer 退出时机 */
}

@starting-style {
  [popover] { opacity: 0; transform: scale(0.95); }
}

[popover]:popover-open { /* 打开状态 */ }
```

### 6. Scroll-Driven Animations（渐进增强）

把动画进度**绑定到滚动位置**，零 JS 实现视差、进度条、滚动显现。

**兼容性**：Chrome 115+ / Safari 26+，Firefox 仍在 flag 后（非 Baseline）→ 必须渐进增强。

#### animation-timeline: scroll()（滚动进度）

```css
/* 阅读进度条：动画进度 = 页面滚动进度 */
@keyframes progress {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}

.progress-bar {
  position: fixed;
  top: 0; left: 0;
  width: 100%; height: 4px;
  background: #4f46e5;
  transform-origin: left;
  animation: progress linear;
  animation-timeline: scroll(); /* 绑定到文档滚动 */
}
```

#### animation-timeline: view()（元素可见性）

```css
/* 卡片滚动显现：进入视口时淡入上移 */
@keyframes reveal {
  from { opacity: 0; transform: translateY(50px); }
  to   { opacity: 1; transform: translateY(0); }
}

.card {
  animation: reveal linear both;
  animation-timeline: view();       /* 绑定到元素自身可见性 */
  animation-range: entry 0% entry 100%; /* 进入视口过程中完成 */
}
```

**`animation-range`** 控制动画在哪个滚动区间发生：`entry`（进入）、`exit`（离开）、`cover`（全程）、`contain`（完全可见期间）。

#### 渐进增强降级

```css
/* 用 @supports 检测，不支持时回退到 IntersectionObserver */
@supports (animation-timeline: view()) {
  .card {
    animation: reveal linear both;
    animation-timeline: view();
  }
}
/* 不支持的浏览器：卡片直接显示（或用 IO 加 class） */
```

### 7. View Transitions API

页面/状态切换时的**快照过渡**——浏览器对旧状态截图、对新状态截图，在两者之间做交叉淡入淡出（可自定义）。

#### Level 1：同文档（SPA 状态切换）

```js
// 用 startViewTransition 包裹 DOM 更新
document.startViewTransition(() => {
  updateDOM(); // 切换列表/详情视图
});
```

```css
/* 给元素命名，实现"共享元素"过渡（同一元素在两个视图间平滑移动） */
.list-item img { view-transition-name: hero; }
.detail img { view-transition-name: hero; } /* 同名 → 浏览器自动补间位置/尺寸 */
```

**兼容性**：Chrome / Edge / Safari 支持，Firefox 144+。

#### Level 2：跨文档（MPA 页面导航）

```css
/* 一行 CSS 启用跨页面过渡 */
@view-transition { navigation: auto; }
```

**兼容性**：Chrome 126+ / Safari 18.2+，Firefox 未支持 → 渐进增强。

**典型应用**：列表页→详情页的图片无缝放大过渡（类似原生 App 的共享元素动画）。

### 8. 无障碍：prefers-reduced-motion

```css
/* 尊重用户的"减少动态效果"设置（前庭障碍用户） */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

**原则**：不是完全移除动画，而是把装饰性动画降到瞬时，保留必要的状态反馈。

## 常见踩坑点

### 坑 1：transition: all 的意外过渡

```css
/* ❌ all 导致 width/height 等也被过渡，布局变化时卡顿 */
.card { transition: all 0.3s; }

/* ✅ 明确列出需要的属性 */
.card { transition: transform 0.3s, box-shadow 0.3s; }
```

### 坑 2：display: none 无法过渡

```css
/* ❌ display 是离散值，transition 无效 */
.modal { display: none; transition: opacity 0.3s; }
.modal.open { display: block; opacity: 1; } /* 不会淡入 */

/* ✅ 方案 1：@starting-style + allow-discrete（现代） */
/* ✅ 方案 2：用 visibility + opacity（visibility 可延迟切换） */
.modal { visibility: hidden; opacity: 0; transition: opacity 0.3s, visibility 0.3s; }
.modal.open { visibility: visible; opacity: 1; }
```

### 坑 3：动画 left/top 导致掉帧

```css
/* ❌ 每帧触发 Layout + Paint */
.slide { animation: move 1s; }
@keyframes move { to { left: 300px; } }

/* ✅ 用 transform（仅 Composite） */
@keyframes move { to { transform: translateX(300px); } }
```

### 坑 4：scroll-driven 动画没做降级

```css
/* ❌ 直接用 animation-timeline，Firefox 用户看到元素停在 opacity: 0 */
.card { opacity: 0; animation: reveal linear both; animation-timeline: view(); }

/* ✅ @supports 包裹，不支持时元素正常显示 */
@supports (animation-timeline: view()) {
  .card { opacity: 0; animation: ...; }
}
```

### 坑 5：forwards 填充导致元素无法交互

```css
/* ❌ 动画 forwards 保持了 pointer-events 或其他状态 */
/* fill-mode 保持的是"样式"，注意别把交互状态锁死 */
/* 如动画设置了 pointer-events: none 且 forwards → 元素永远点不了 */
```

## 面试高频问题

### Q1：transition 和 animation 的区别？

**答**：transition 是两态之间的补间，需要状态变化触发（hover、class 切换），只有起点终点，不能循环；animation 用 @keyframes 定义多关键帧，自动播放，支持循环（infinite）、往返（alternate）、填充模式（fill-mode）、暂停。简单交互反馈用 transition，复杂/循环/多阶段动画用 animation。

### Q2：为什么动画推荐 transform/opacity？

**答**：浏览器渲染流水线是 Layout（重排）→ Paint（重绘）→ Composite（合成）。动画 left/top/width 触发 Layout，动画颜色触发 Paint，都在主线程且开销大。transform 和 opacity 只在 Composite 阶段处理——元素已渲染成位图，动画只是 GPU 上做仿射变换，跳过 Layout 和 Paint，能稳定 60fps。诊断用 Performance 面板看每帧耗时和 Layout/Paint 占比。

### Q3：@starting-style 解决了什么问题？

**答**：解决了 display: none → block 无法过渡的问题。display 是离散值，transition 不生效，所以弹窗进入退出动画一直需要 JS。@starting-style 为首次渲染/display 切换提供过渡起点，配合 transition-behavior: allow-discrete 让 display 参与过渡（退出时先完成 opacity/transform 动画再真正隐藏）。现在纯 CSS 就能实现弹窗的淡入淡出，2024-08 已 Baseline。

### Q4：scroll-driven animations 是什么？怎么用？

**答**：把动画进度绑定到滚动位置，零 JS 实现视差、进度条、滚动显现。核心是 animation-timeline：scroll() 绑定滚动容器的滚动进度，view() 绑定元素自身的可见性，配合 animation-range 控制触发区间。注意兼容性——Chrome 115+、Safari 26+，Firefox 还在 flag 后，所以必须用 @supports 渐进增强，不支持时元素正常显示。

### Q5：View Transitions 是什么？

**答**：页面或状态切换时的快照过渡——浏览器对旧状态和新状态分别截图，在两者间做交叉过渡。Level 1 用于同文档（SPA），用 document.startViewTransition() 包裹 DOM 更新；给元素设相同的 view-transition-name 可以实现共享元素过渡（如列表图片放大到详情）。Level 2 的 @view-transition 支持跨页面导航（MPA）。Chrome/Safari 支持，Firefox Level 1 在 144 支持。

### Q6：content-visibility 怎么优化性能？

**答**：content-visibility: auto 让浏览器跳过视口外元素的布局和绘制，相当于原生懒渲染，对长列表首屏性能提升明显。要配合 contain-intrinsic-size 提供预估尺寸，否则滚动条会不准。它和 contain 属性配合——contain 告诉浏览器元素内部变化不影响外部，缩小重排范围。content-visibility 2024-09 已 Baseline。

## 面试回答模板

> **问：怎么优化 CSS 动画性能？**
>
> 三个层面。第一，选对属性——只动画 transform 和 opacity，它们走合成线程由 GPU 处理，跳过 Layout 和 Paint；动画 left/top 会每帧重排，动画颜色会每帧重绘。第二，用工具诊断——Performance 面板看每帧耗时是否超 16.7ms，Rendering 面板的 Paint flashing 看重绘区域，FPS meter 看实时帧率。第三，减少渲染范围——用 content-visibility: auto 跳过屏外元素渲染，用 contain 局限重排范围，用 will-change 提前提升合成层（但别滥用，占内存）。
>
> **追问：弹窗的进入退出动画以前为什么需要 JS？现在呢？**
>
> 因为弹窗用 display: none 隐藏，而 display 是离散值，transition 无法对它补间，所以以前要么用 visibility + opacity hack，要么靠 JS 控制时序。现在用 @starting-style 定义进入起点，配合 transition-behavior: allow-discrete 让 display 参与过渡——退出时先播完淡出动画再真正 display: none。纯 CSS 就能实现，2024 年后已 Baseline。

## 练习

### 练习 1：popover 进入退出动画

**要求**：用 @starting-style + transition-behavior: allow-discrete 实现 popover/dialog 的淡入缩放动画（进入和退出）

**提示**：定义 opacity/transform 过渡，@starting-style 设进入起点，display/overlay 加 allow-discrete

**预期效果**：点击按钮弹窗淡入并轻微放大，关闭时淡出缩小后才消失，全程零 JS 补间

```css
[popover] {
  opacity: 1;
  transform: scale(1);
  transition: opacity 0.3s ease, transform 0.3s ease,
              display 0.3s allow-discrete, overlay 0.3s allow-discrete;
}
@starting-style {
  [popover] { opacity: 0; transform: scale(0.95); }
}
```

### 练习 2：滚动进度条 + 卡片显现

**要求**：纯 CSS 实现阅读进度条（scroll()）和卡片滚动显现（view()），附 IntersectionObserver 降级

**提示**：进度条用 animation-timeline: scroll() + scaleX；显现用 view() + animation-range: entry；@supports 包裹

**预期效果**：滚动时顶部进度条同步增长，卡片进入视口时淡入上移；Firefox 中卡片正常显示（降级）

```css
@keyframes progress { from { transform: scaleX(0); } to { transform: scaleX(1); } }
.progress {
  position: fixed; top: 0; left: 0; width: 100%; height: 4px;
  background: #4f46e5; transform-origin: left;
  animation: progress linear; animation-timeline: scroll();
}
@supports (animation-timeline: view()) {
  @keyframes reveal { from { opacity: 0; transform: translateY(40px); } to { opacity: 1; transform: none; } }
  .card { animation: reveal linear both; animation-timeline: view(); animation-range: entry; }
}
```

### 练习 3：View Transitions 共享元素

**要求**：用 View Transitions 实现列表→详情的共享元素过渡（图片无缝放大）

**提示**：document.startViewTransition() 包裹视图切换，两个视图的图片设相同 view-transition-name

**预期效果**：点击列表项，图片平滑放大移动到详情位置（类似原生 App），而非生硬切换

```js
function showDetail(item) {
  document.startViewTransition(() => {
    renderDetail(item); // 切换 DOM
  });
}
```

```css
.list-item img, .detail img { view-transition-name: hero; }
```
