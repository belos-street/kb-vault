## 核心概念

### 1. 浮动（Float）

浮动的设计初衷是**文字环绕图片**，后来被滥用做布局（在 Flex/Grid 出现之前）。

```css
/* 文字环绕图片——浮动的本职工作 */
.article img {
  float: left;
  margin-right: 16px;
}
```

#### 浮动的副作用：父元素高度塌陷

浮动元素**脱离文档流**，父元素感知不到它的高度，导致高度塌陷。

```css
/* 清除浮动：给父元素创建 BFC */
.container { display: flow-root; }

/* 经典 clearfix（历史写法，了解即可） */
.clearfix::after {
  content: '';
  display: block;
  clear: both;
}
```

**现代项目中**：布局用 Flex/Grid，浮动只保留"文字环绕"这一个场景。`display: flow-root` 是清除浮动的最语义化方式。

### 2. 定位模型（Position）

五种定位方式，核心区别是**参照物（包含块）**不同。

```css
/* static：默认值，正常文档流，top/left 无效 */
.box { position: static; }

/* relative：相对"自身原位置"偏移，仍占据原文档流空间 */
.box { position: relative; top: 10px; left: 10px; }

/* absolute：相对"最近的定位祖先"（非 static）偏移，脱离文档流 */
.box { position: absolute; top: 0; right: 0; }

/* fixed：相对"视口"偏移，脱离文档流，滚动时不动 */
.box { position: fixed; bottom: 20px; right: 20px; }

/* sticky：滚动到阈值前是 relative，到达后"粘住"变 fixed */
.box { position: sticky; top: 0; }
```

#### 各定位的参照物（包含块）

| 定位 | 参照物 | 脱离文档流 |
|------|--------|-----------|
| `static` | —（正常流） | 否 |
| `relative` | 自身原位置 | 否（仍占空间） |
| `absolute` | 最近的非 static 祖先 | 是 |
| `fixed` | 视口（viewport） | 是 |
| `sticky` | 最近的滚动祖先 | 否 |

#### absolute 的关键细节

```css
/* absolute 必须配合"定位祖先"使用，否则会相对最近的已定位祖先，
   如果都没有，就相对初始包含块（≈ html） */
.parent { position: relative; } /* 给子元素提供参照 */
.child { position: absolute; top: 0; right: 0; } /* 相对 parent 右上角 */
```

**面试常问**：absolute 相对谁定位？

相对**最近的 position 不为 static 的祖先元素**；如果所有祖先都是 static，则相对**初始包含块**（大致等于 `<html>`）。所以用 absolute 时通常要给父元素加 `position: relative`。

#### sticky 的触发条件与失效场景

```css
/* sticky = relative + fixed 的混合 */
/* 滚动到 top: 0 之前是 relative（正常流），到达后粘住 */
.sticky-header {
  position: sticky;
  top: 0; /* 必须设阈值，否则不生效 */
}
```

**sticky 失效的常见原因**：

```css
/* ❌ 1. 没设 top/bottom 阈值 */
.sticky { position: sticky; } /* 无效 */

/* ❌ 2. 父元素有 overflow（hidden/auto/scroll） */
.parent { overflow: hidden; } /* sticky 子元素失效！ */
/* sticky 相对"最近的滚动祖先"，父级 overflow 会截断滚动上下文 */

/* ❌ 3. 父元素高度不够（没有滚动空间） */
.parent { height: 100px; } /* sticky 元素在父级内，父级太矮没法粘 */
```

### 3. 层叠上下文（Stacking Context）

层叠上下文是一个**三维概念**——页面由多个层叠上下文组成，每个上下文内部独立排序，上下文之间按整体比较。

#### 创建层叠上下文的条件

```css
/* 1. 根元素 <html>（根层叠上下文） */

/* 2. 定位元素 + z-index 不为 auto */
.box { position: relative; z-index: 1; }

/* 3. 以下属性即使不定位也会创建（高频考点） */
.box { transform: translateZ(0); }   /* 任何非 none 的 transform */
.box { opacity: 0.99; }              /* opacity < 1 */
.box { filter: blur(1px); }          /* 任何非 none 的 filter */
.box { backdrop-filter: blur(4px); } /* 任何非 none 的 backdrop-filter */
.box { clip-path: circle(50%); }     /* 任何非 none 的 clip-path */
.box { will-change: transform; }     /* will-change */
.box { position: fixed; }            /* fixed/sticky 本身创建 */
.box { mix-blend-mode: multiply; }   /* 非 normal 的混合模式 */
.box { isolation: isolate; }         /* 显式创建 */
.box { contain: layout paint; }      /* contain: layout/paint/strict/content */

/* 4. flex/grid 子元素 + z-index 不为 auto */
.flex-parent { display: flex; }
.flex-child { z-index: 1; }         /* flex/grid 子元素设 z-index 即创建 */
```

**这是"z-index 失效"的根因**——很多人不知道 transform/opacity 会偷偷创建层叠上下文。

#### 层叠顺序（同一层叠上下文内，从下到上）

```
7. 正 z-index 的定位元素      ← 最上
6. z-index: 0 / auto 的定位元素
5. 行内元素（inline）
4. 浮动元素（float）
3. 块级元素（block）
2. 负 z-index 的定位元素
1. 背景与边框（background/border）  ← 最下
```

#### z-index 失效的经典场景

```html
<div class="parent-a">          <!-- transform 创建了层叠上下文 -->
  <div class="child" style="z-index: 9999">我</div>
</div>
<div class="parent-b">
  <div class="other" style="z-index: 1">压在你上面</div>
</div>
```

```css
.parent-a { transform: translateX(0); } /* 创建层叠上下文 */
```

**分析**：child 的 z-index: 9999 只在 parent-a 的上下文内有效。比较发生在 **parent-a 和 parent-b 两个上下文之间**（它们 z-index 都是 auto，按 DOM 顺序 parent-b 在后 → 在上）。所以 other 压住 child，child 的 9999 无效。

**诊断方法**：Chrome DevTools → 更多工具 → Layers 面板（或 3D 视图），可以直观看到层叠上下文的层级结构。

### 4. top-layer 与声明式 overlay（Popover API，Baseline 2024-04）

传统模态框/弹层靠手堆 z-index，容易失控。**top-layer** 是浏览器提供的一个特殊层——元素被提升到文档所有层叠上下文之上，**彻底绕开 z-index**。

#### Popover API：声明式弹出

```html
<!-- 触发器 -->
<button popovertarget="my-popover">打开</button>

<!-- 弹出层：无需 JS 控制显隐 -->
<div id="my-popover" popover>
  我是一个弹出层
</div>
```

```css
/* popover 自动进入 top-layer，永远在最顶层 */
[popover] {
  padding: 16px;
  border: 1px solid #e5e7eb;
  border-radius: 8px;
  box-shadow: 0 8px 24px rgba(0,0,0,0.15);
}
```

**核心特性**：

```html
<!-- popover="auto"：light-dismiss（点击外部自动关闭），同时只显示一个 -->
<div popover="auto">点外面我会关闭</div>

<!-- popover="manual"：需要手动调用 hide() 关闭 -->
<div popover="manual">点外面我不关闭</div>
```

#### ::backdrop 遮罩层

```css
/* ::backdrop 是 top-layer 中元素背后的遮罩（Baseline Widely 2022-03） */
dialog::backdrop {
  background: rgba(0, 0, 0, 0.5);
}

[popover]::backdrop {
  background: rgba(0, 0, 0, 0.3);
}
```

#### popover vs dialog

```html
<!-- dialog：模态对话框，showModal() 打开，有 ::backdrop，阻塞交互 -->
<dialog id="modal">
  <form method="dialog">
    <p>确认删除？</p>
    <button value="cancel">取消</button>
    <button value="confirm">确认</button>
  </form>
</dialog>
<script>modal.showModal();</script>
```

| 特性 | popover | dialog (showModal) |
|------|---------|-------------------|
| 模态 | 否（auto 仅 light-dismiss） | 是（阻塞背景交互） |
| 打开方式 | 声明式（popovertarget） | JS（showModal） |
| ::backdrop | 自动（进入 top-layer 即有） | 自动 |
| 典型用途 | 提示、菜单、工具提示 | 确认框、表单弹窗 |

#### top-layer 的价值

```
传统方案：z-index: 9999 → 后来者 z-index: 99999 → 失控
top-layer：元素脱离常规层叠，永远在最上，无需 z-index
```

**面试常问**：怎么避免 z-index 大战？

优先用 top-layer——popover 和 dialog 的 showModal 都会把元素提升到 top-layer，天然在最顶层，完全不需要 z-index。只有非 top-layer 的常规元素（如下拉菜单、吸顶导航）才需要 z-index，且应建立分层规范（如 dropdown 100 / modal 200 / toast 300），而不是随手写 9999。

### 5. z-index 治理规范

```css
/* ❌ 反模式：随手写大数字 */
.dropdown { z-index: 9999; }
.modal { z-index: 99999; }

/* ✅ 分层规范：预留间隔，语义清晰 */
:root {
  --z-dropdown: 100;
  --z-sticky: 200;
  --z-modal: 300;
  --z-toast: 400;
}
.dropdown { z-index: var(--z-dropdown); }
.modal { z-index: var(--z-modal); }
```

**原则**：
1. 能用 top-layer（popover/dialog）就用 top-layer
2. 常规元素用 CSS 变量定义层级规范，预留间隔
3. 理解层叠上下文——z-index 只在同一上下文内比较

### 6. 实战：sticky 吸顶表头

```css
/* 表格吸顶表头 */
thead th {
  position: sticky;
  top: 0;
  background: white; /* 必须有背景，否则滚动时内容透出 */
  z-index: 1;        /* 盖住滚动的单元格 */
}

/* 吸顶导航 */
.nav {
  position: sticky;
  top: 0;
  z-index: var(--z-sticky);
}
```

## 常见踩坑点

### 坑 1：absolute 没有定位祖先，相对了 html

```css
/* ❌ 期望相对父元素，但父元素是 static → 相对了初始包含块 */
.parent { /* 忘了 position: relative */ }
.child { position: absolute; top: 0; }

/* ✅ 给参照父元素加 relative */
.parent { position: relative; }
```

### 坑 2：sticky 被父级 overflow 截断

```css
/* ❌ 父级 overflow: hidden 导致 sticky 失效 */
.wrapper { overflow: hidden; }
.sticky { position: sticky; top: 0; } /* 不生效 */

/* ✅ 移除父级 overflow，或让 sticky 元素的直接滚动容器正确 */
```

### 坑 3：transform 动画导致 z-index 失效

```css
/* ❌ 给元素加了 transform 动画，它的子元素 z-index 再高也出不去 */
.animated { transform: translateX(0); } /* 创建了层叠上下文 */
.animated .tooltip { z-index: 9999; } /* 被限制在 .animated 内 */

/* ✅ 方案：把 tooltip 移出该上下文，或用 popover（top-layer） */
```

### 坑 4：sticky 元素没有背景

```css
/* ❌ 吸顶表头透明，滚动时下方内容透出来 */
thead th { position: sticky; top: 0; }

/* ✅ 必须设不透明背景 */
thead th { position: sticky; top: 0; background: #fff; }
```

## 面试高频问题

### Q1：absolute 和 fixed 的区别？

**答**：两者都脱离文档流。absolute 相对最近的非 static 祖先定位，如果祖先都是 static 就相对初始包含块，会随页面滚动；fixed 相对视口定位，滚动时位置不变。fixed 有个坑：祖先有 transform 时，fixed 会退化为相对该祖先定位。

### Q2：sticky 什么时候生效？什么时候失效？

**答**：sticky 是 relative 和 fixed 的混合，滚动到设定阈值（如 top: 0）前是相对定位，到达后粘住。生效条件：必须设 top/bottom 阈值、在滚动容器内、父元素有足够高度。失效的常见原因：没设阈值、父元素有 overflow（hidden/auto/scroll）截断了滚动上下文、父元素太矮没有滚动空间。

### Q3：什么是层叠上下文？哪些属性会创建？

**答**：层叠上下文是三维的渲染层级单位，上下文内部独立排序，上下文之间按整体比较。创建条件包括：根元素、定位+z-index 非 auto、以及 transform、opacity<1、filter、will-change、fixed/sticky、mix-blend-mode、isolation: isolate 等。理解它的关键是：z-index 只在同一层叠上下文内比较，这就是 transform 元素内部 z-index 再高也出不去的原因。

### Q4：z-index 失效怎么排查？

**答**：先确认两个元素是否在同一个层叠上下文——如果它们的祖先有 transform、opacity<1、filter 等创建了新的上下文，z-index 只在各自上下文内有效，比较的是两个上下文本身。用 DevTools 的 Layers 面板或 3D 视图可以直观看到层级结构。解决方案：调整 DOM 结构、移除创建上下文的属性、或改用 top-layer（popover/dialog）。

### Q5：怎么避免 z-index 大战？

**答**：三个层面。第一，优先用 top-layer——popover 和 dialog 的 showModal 把元素提升到浏览器最顶层，完全不需要 z-index。第二，常规元素建立分层规范，用 CSS 变量定义 dropdown/sticky/modal/toast 的层级并预留间隔，不随手写 9999。第三，理解层叠上下文，很多"z-index 不够大"的问题其实是上下文隔离导致的。

### Q6：popover 和 dialog 有什么区别？

**答**：两者都进入 top-layer。popover 是非模态的，用 popovertarget 属性声明式打开（无需 JS），popover="auto" 支持 light-dismiss（点外部关闭），适合提示、菜单。dialog 的 showModal() 是模态的，阻塞背景交互，自带 ::backdrop 遮罩，适合确认框、表单弹窗。::backdrop 伪元素可以给两者加遮罩样式。

## 面试回答模板

> **问：谈谈你对层叠上下文的理解？**
>
> 层叠上下文是页面三维层级的基本单位。每个上下文内部的元素按固定顺序排列：背景和边框在最下，然后负 z-index、块级、浮动、行内、z-index 为 0 的定位元素，正 z-index 在最上。关键是 z-index 只在同一上下文内比较，上下文之间按整体比较。transform、opacity 小于 1、filter 等属性都会创建新上下文，这就是为什么一个 transform 元素内部的子元素 z-index 设再高也出不去。排查可以用 DevTools 的 Layers 面板。
>
> **追问：现代项目怎么管理层级？**
>
> 优先用 top-layer。popover 属性和 dialog 的 showModal 会把元素提升到浏览器最顶层，天然在所有层叠上下文之上，完全绕开 z-index。popover 还能声明式打开、支持点外部关闭，配合 ::backdrop 加遮罩。只有常规元素（吸顶导航、下拉菜单）才需要 z-index，用 CSS 变量建立分层规范。

## 练习

### 练习 1：复现 z-index 失效

**要求**：构造"父级 transform 创建层叠上下文导致子元素 z-index 失效"的场景，画出层叠树解释

**提示**：两个兄弟 div，第一个加 transform，其子元素 z-index: 9999；第二个兄弟 z-index: 1，观察谁在上

**预期效果**：第二个兄弟（z-index: 1）压住第一个的子元素（z-index: 9999）；能画出层叠树说明比较发生在两个父级上下文之间

```css
.parent-a { transform: translateX(0); position: relative; }
.parent-a .child { position: absolute; z-index: 9999; }
.parent-b { position: relative; z-index: 1; } /* DOM 在后，压住 parent-a */
```

### 练习 2：Anchor Positioning 自动翻转 tooltip

**要求**：用 Anchor Positioning 实现一个 tooltip，空间不足时自动翻转（附 @supports 降级）

**提示**：anchor-name 定义锚点，position-anchor + position-area 定位，position-try-fallbacks: flip-block 翻转

**预期效果**：tooltip 默认在按钮上方，按钮靠近视口顶部时自动翻转到下方（Baseline 2026-01，渐进增强）

```css
.btn { anchor-name: --tip; }
.tooltip {
  position: absolute;
  position-anchor: --tip;
  position-area: top;
  position-try-fallbacks: flip-block; /* 上方放不下就翻到下方 */
  margin-bottom: 8px;
}
/* 降级：不支持时回退到 JS 定位或普通 absolute */
```

### 练习 3：声明式 popover 弹出层

**要求**：用 popover 属性 + ::backdrop 实现一个声明式信息卡片弹出，对比 JS 控制显隐的写法

**提示**：button 加 popovertarget，div 加 popover="auto"，::backdrop 加遮罩

**预期效果**：点击按钮弹出卡片（自动在最顶层），点击外部自动关闭，零 JS；能说出相比 z-index 方案的优势

```html
<button popovertarget="info">查看详情</button>
<div id="info" popover="auto">
  <h3>标题</h3>
  <p>内容...</p>
</div>
```

```css
#info::backdrop { background: rgba(0,0,0,0.3); }
```

### 练习 4：sticky 吸顶表头 + 吸底合计

**要求**：用 sticky 实现表格吸顶表头和吸底合计行

**提示**：thead th 设 top: 0，tfoot td 设 bottom: 0，都要给不透明背景

**预期效果**：滚动表格时表头固定在顶部、合计行固定在底部

```css
thead th { position: sticky; top: 0; background: #fff; z-index: 1; }
tfoot td { position: sticky; bottom: 0; background: #f9fafb; }
```
