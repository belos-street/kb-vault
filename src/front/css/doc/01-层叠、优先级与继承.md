# 01 - 层叠、优先级与继承

## 核心概念

### 1. 层叠（Cascade）— CSS 的决策引擎

CSS 的全称是 **Cascading Style Sheets（层叠样式表）**。"层叠"指的是：当多条规则命中同一个元素的同一个属性时，浏览器按一套**固定的决策链**选出胜出者。

这套决策链（按 MDN 级联排序，**前者胜出后者**）：

```
1. 来源与重要性（Origin & Importance）
2. 上下文（Context，如 Shadow DOM）
3. 元素附加样式（Element-Attached，如 style 属性）
4. @layer 级联层
5. 优先级（Specificity）
6. 出现顺序（Order of Appearance）
```

**关键认知**：优先级（Specificity）只是决策链中的**第 5 层**，不是第一层。很多人以为"优先级高就生效"，这是不完整的——来源、@layer 都排在它前面。

### 2. 第一层：来源与重要性（Origin & Importance）

样式有三种来源，权重从低到高：

| 来源 | 说明 |
|------|------|
| 用户代理样式（User Agent） | 浏览器默认样式 |
| 用户样式（User） | 用户自定义样式（如辅助功能插件） |
| 作者样式（Author） | 你写的 CSS |

**`!important` 会反转这个顺序**：

```
用户代理样式 < 用户样式 < 作者样式
  ↓ 加 !important 后反转
作者 !important < 用户 !important < 用户代理 !important
```

```css
/* 浏览器默认 button 有背景色，但你的作者样式可以覆盖它（UA 样式不用 !important） */
button {
  background: rebeccapurple; /* 覆盖用户代理样式 */
}

/* 用户代理的 !important 优先级最高（但浏览器极少在 UA 样式中使用 !important） */
/* 用户（辅助功能）的 !important 优先级高于作者，你覆盖不了 */
```

**面试常问**：`!important` 的优先级最高吗？

不是。`!important` 只影响"来源"这一层的排序。作者的 `!important` 确实能压过一切普通样式，但**用户的 `!important`（辅助功能场景）优先级更高**——这是无障碍设计的一部分。

**滥用 `!important` 的代价**：破坏正常层叠，导致样式难以维护，只能靠更多的 `!important` 来覆盖，形成恶性循环。

### 3. 第二层：上下文（Context）

Shadow DOM 内的样式与外部隔离，形成独立的层叠上下文。Web Components 的样式封装就依赖这一点。

```js
const host = document.querySelector('#card');
const shadow = host.attachShadow({ mode: 'open' });
shadow.innerHTML = `
  <style>
    p { color: red; } /* 只影响 Shadow DOM 内部 */
  </style>
  <p>我是红色的</p>
`;
```

外部的 `p { color: blue }` 无法影响 Shadow DOM 内的段落（除非用 CSS 自定义属性穿透）。

### 4. 第三层：元素附加样式（Element-Attached）

直接挂在元素上的样式，即 HTML 的 `style` 属性：

```html
<!-- 内联样式在层叠中高于任何选择器（不含 !important） -->
<p style="color: red">我是红色</p>
```

```css
/* 即使优先级再高，也赢不过内联样式 */
#main .content p { color: blue; } /* 失败 */
```

内联样式 ≈ 优先级 `(1,0,0,0)`（比 ID 还高一档），但**仍然可以被 `!important` 覆盖**。

### 5. 第四层：@layer 级联层（Baseline 2022）

`@layer` 是解决"样式覆盖战争"的现代方案。它让你把作者样式**分组**，并显式声明组之间的优先级。

```css
/* 先声明层的顺序（优先级：先声明的 < 后声明的） */
@layer reset, components, utilities;

@layer reset {
  button { background: none; border: none; }
}

@layer components {
  .btn { background: blue; color: white; padding: 8px 16px; }
}

@layer utilities {
  .mt-4 { margin-top: 16px; }
}
```

**核心规则**：

1. **层的优先级由声明顺序决定**：后声明的层 > 先声明的层（与层内代码位置无关）
2. **未分层样式 > 所有分层样式**：不写在任何 `@layer` 里的样式优先级最高

```css
@layer a, b;

@layer b {
  p { color: red; }
}

@layer a {
  p { color: blue; } /* 虽然写在后面，但 a 层优先级低于 b 层 */
}

p { color: green; } /* 未分层，优先级最高 → 最终是绿色 */
```

**实战：治理第三方库覆盖问题**

```css
/* 声明顺序：第三方库优先级最低，业务样式最高 */
@layer third-party, base, business;

@layer third-party {
  @import 'some-ui-lib.css'; /* 第三方样式放最底层 */
}

@layer business {
  .card { padding: 24px; } /* 无需 !important 即可覆盖第三方 */
}
```

**面试常问**：@layer 和优先级是什么关系？

`@layer` 在层叠决策链中排在优先级**之前**。先比较样式属于哪个层（后声明的层胜出），只有在**同一层内**才比较优先级。这意味着：低优先级层里的 `#id` 选择器，会输给高优先级层里的 `p` 选择器。

### 6. 第五层：优先级（Specificity）

只有当前面所有层都打平时，才轮到优先级。优先级是一个**三元组** `(ID, CLASS, TAG)`，逐位比较（像版本号比较）：

| 档位 | 计入的选择器 |
|------|-------------|
| ID（最高） | `#id` |
| CLASS | `.class`、`[attr]`、`:hover` 等伪类 |
| TAG（最低） | `div`、`span` 等标签、`::before` 等伪元素 |

```css
#nav .item a        /* (1, 1, 1) */
.nav .item a:hover  /* (0, 2, 2) → 1 > 0，前者胜 */
.item a             /* (0, 1, 1) */
a                   /* (0, 0, 1) */
```

**比较方式**：先比 ID 位，ID 位大的直接胜出；ID 相同再比 CLASS 位；以此类推。**不是十进制加法**（11 个 class 不等于 1 个 ID）。

#### 现代伪类的优先级规则

```css
/* :is() / :not()：自身不计优先级，取参数中的最高值 */
:is(#a, .b) p    /* 等价于 #a p → (1, 0, 1) */
:not(.x) p       /* 等价于 .x p → (0, 1, 1) */

/* :where()：恒为 0，用于"零优先级"的默认样式 */
:where(#a) p     /* (0, 0, 1)，#a 的优先级被抹掉 */

/* :has()：同样取参数中的最高值 */
div:has(#x)      /* 等价于 div#x → (1, 0, 1) */
```

**`:where()` 的妙用**——写可被轻松覆盖的默认样式：

```css
/* 组件库的默认样式，用 :where 降为 0 优先级 */
:where(.btn) { padding: 8px 16px; background: gray; }

/* 使用者无需 !important，一个 class 就能覆盖 */
.my-btn { background: blue; } /* (0,1,0) > (0,0,0) ✅ */
```

#### 优先级的两个"超档"

```
内联样式 style=""   ≈ (1, 0, 0, 0)  高于任何 ID 组合
!important          再高一档，但进入"来源"层比较
```

### 7. 第六层：出现顺序（Order of Appearance）

如果前面所有层全部打平（同来源、同层、同优先级），**后写的覆盖先写的**。

```css
p { color: red; }
p { color: blue; } /* 同优先级，后写胜出 → 蓝色 */
```

这也是为什么 `@import` 的位置、`<link>` 的顺序会影响样式。

### 8. 继承（Inheritance）

某些属性会从父元素"流"向子元素，无需重复声明。

**会继承的**（主要是文本相关）：

```css
color、font-*（family/size/weight）、line-height、
text-align、letter-spacing、word-spacing、white-space、
visibility、cursor、direction
```

**不会继承的**（主要是盒模型与定位）：

```css
width/height、margin、padding、border、background、
display、position、flex、grid、box-shadow
```

```html
<div style="color: red; border: 1px solid black">
  <p>我的文字是红色（继承），但没有边框（不继承）</p>
</div>
```

#### 四个控制继承的关键字

```css
.child {
  /* inherit：强制继承父元素的值（即使该属性默认不继承） */
  border: inherit;

  /* initial：重置为 CSS 规范定义的初始值 */
  color: initial; /* color 的初始值是 canvastext（近似黑） */

  /* unset：智能选择——默认继承的属性用 inherit，否则用 initial */
  color: unset;   /* color 默认继承 → 等于 inherit */
  border: unset;  /* border 默认不继承 → 等于 initial */

  /* revert：回退到上一层来源的值（通常是用户代理样式） */
  margin: revert; /* 恢复浏览器默认的 margin */
}
```

**`all` 属性**——批量重置：

```css
/* 重置元素的所有属性（除 unicode-bidi 和 direction） */
.clean-slate {
  all: unset;   /* 常用于去除 button/a 的浏览器默认样式 */
}
```

**面试常问**：`all: unset` 和 `all: revert` 的区别？

- `all: unset`：继承的属性取父级值，不继承的属性取规范初始值（**完全无视浏览器默认样式**）
- `all: revert`：回退到**用户代理（浏览器）样式**，保留浏览器对该元素的默认表现

对 `<button>` 而言：`unset` 会让它失去所有按钮外观（连 display 都变 inline）；`revert` 会恢复成浏览器原生按钮的样子。

## 常见踩坑点

### 坑 1：以为优先级是十进制加法

```css
/* ❌ 错误理解：11 个 class = (0,11,0) > 1 个 ID (1,0,0) */
/* ✅ 正确：逐位比较，ID 位 1 > 0，ID 选择器永远胜出 */
#main { color: red; }
.a.b.c.d.e.f.g.h.i.j.k { color: blue; } /* 输 */
```

### 坑 2：@layer 里写了样式却不生效

```css
@layer base {
  .card { padding: 24px; }
}

/* 未分层样式优先级更高，覆盖了 layer 内的样式 */
.card { padding: 8px; } /* 这条赢 */
```

**对策**：要么把业务样式也放进 layer（并声明在更高优先级层），要么明确"未分层 = 最高优先级"的团队约定。

### 坑 3：用 !important 覆盖内联样式后无法再维护

```css
.modal { display: none !important; }
```

```html
<!-- JS 设置的内联样式被 !important 压死，弹窗永远打不开 -->
<div class="modal" style="display: block">
```

**对策**：避免 `!important` 与内联样式（JS 动态样式）混用，改用 class 切换。

### 坑 4：:is() 意外提升优先级

```css
/* 本意是写个低优先级选择器，但 :is 取了 #main 的优先级 */
:is(#main, .sidebar) p { color: red; } /* (1,0,1)，很高 */

/* 想保持低优先级，用 :where */
:where(#main, .sidebar) p { color: red; } /* (0,0,1) */
```

## 面试高频问题

### Q1：请完整描述 CSS 的层叠决策过程？

**答**：浏览器按六层决策链选出胜出样式：① 来源与重要性（用户代理 < 用户 < 作者，!important 反转）；② 上下文（Shadow DOM 隔离）；③ 元素附加样式（style 属性）；④ @layer 级联层（后声明的层胜出，未分层最高）；⑤ 优先级（ID/class/tag 三元组逐位比较）；⑥ 出现顺序（后写覆盖先写）。优先级只是第五层，不是唯一标准。

### Q2：优先级怎么计算？:is()、:where()、:has() 怎么算？

**答**：优先级是三元组 (ID, CLASS, TAG)，逐位比较而非相加。ID 选择器计第一档；类、属性、伪类计第二档；标签和伪元素计第三档。`:is()` 和 `:has()` 自身不计，取参数中的最高优先级；`:not()` 同理；`:where()` 恒为 0，适合写可被轻松覆盖的默认样式。内联样式约等于 (1,0,0,0)，!important 再高一档。

### Q3：@layer 解决了什么问题？

**答**：@layer 把"样式覆盖"从依赖优先级和书写顺序，变成显式声明的层级顺序。典型场景是治理第三方库样式：把第三方样式放进低优先级层，业务样式放进高优先级层，这样无需 !important、无需堆高优先级就能覆盖第三方。规则是后声明的层优先级更高，未分层样式高于所有层。

### Q4：inherit、initial、unset、revert 的区别？

**答**：`inherit` 强制取父元素的值；`initial` 取 CSS 规范定义的初始值；`unset` 是智能版——默认继承的属性表现为 inherit，否则表现为 initial；`revert` 回退到上一层来源（通常是浏览器默认样式）。配合 `all` 属性可以批量重置，`all: revert` 常用于恢复元素的原生外观。

### Q5：为什么不建议滥用 !important？

**答**：!important 破坏正常层叠顺序，把样式战争从"可预测的优先级比较"变成"谁的 important 多"，导致维护成本指数上升。正确做法是用 @layer 管理层级、用更合理的选择器、或重构样式结构。!important 的合理场景只有两个：覆盖第三方库且无法用 @layer 时、用户辅助功能样式。

## 面试回答模板

> **问：谈谈你对 CSS 层叠的理解？**
>
> 层叠是 CSS 解决"多条规则命中同一属性时谁生效"的机制。它不是只看优先级，而是按六层决策链逐层比较：来源与重要性、上下文、元素附加样式、@layer、优先级、出现顺序。优先级（ID/class/tag 三元组）只排第五。现代 CSS 推荐用 @layer 显式管理层级，把第三方库放低优先级层、业务样式放高优先级层，避免 !important 滥用。
>
> **追问：@layer 的优先级规则？**
>
> 层的优先级由声明顺序决定，后声明的层优先级更高；未分层样式高于所有分层样式。同一层内才比较选择器优先级。这意味着低优先级层里的 #id 选择器，会输给高优先级层里的 p 标签选择器。

## 练习

### 练习 1：优先级手算

**要求**：不借助工具，计算以下选择器的优先级三元组，并判断谁胜出（假设都命中同一元素）

```css
/* A */ #header .nav a:hover
/* B */ .header .nav .link.active
/* C */ nav a.link:hover
/* D */ :is(#header, .top) a
/* E */ :where(#header) .nav a
```

**提示**：逐个数 ID / (class+伪类+属性) / (tag+伪元素)；`:is()` 取参数最高，`:where()` 为 0

**预期效果**：

```
A: (1, 2, 2)  → #header(1) + .nav/.hover(2) + a/tag...
   实际：#header=1 ID；.nav + :hover = 2 class；a = 1 tag → (1,2,1)
B: (0, 4, 0)
C: (0, 2, 2)
D: (1, 0, 1)  → :is 取 #header
E: (0, 1, 1)  → :where 为 0，只剩 .nav 和 a
胜出：A（ID 位为 1 且 class 位最高）
```

### 练习 2：@layer 治理覆盖链

**要求**：用 `@layer` 重构一个"reset → 第三方组件 → 业务样式"的覆盖链，验证未分层样式的行为

**提示**：先声明 `@layer reset, vendor, business;`，把三组样式分别放入，再额外写一条未分层样式观察结果

**预期效果**：业务层无需 !important 即可覆盖 vendor 层；未分层样式覆盖所有层。在 DevTools Computed 面板能看到被划掉的规则及其所属层

```css
@layer reset, vendor, business;

@layer reset {
  button { background: none; border: none; padding: 0; }
}

@layer vendor {
  .btn { background: #eee; padding: 8px 16px; border-radius: 4px; }
}

@layer business {
  .btn { background: #4f46e5; color: white; } /* 无需 !important */
}

/* 未分层：优先级最高 */
.btn { outline-offset: 2px; }
```

### 练习 3：unset vs revert

**要求**：在一个 `<button>` 上分别应用 `all: unset` 和 `all: revert`，观察差异并解释

**提示**：button 有浏览器默认样式（背景、边框、内边距），思考 unset 和 revert 对"不继承属性"的处理差异

**预期效果**：`all: unset` 让按钮完全失去原生外观（变成普通行内文本）；`all: revert` 恢复成浏览器原生按钮样式。能口头解释：unset 对不继承属性取 initial（无样式），revert 取用户代理样式（原生外观）
