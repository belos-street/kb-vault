## 核心概念

### 1. 响应式设计基础

#### viewport meta（移动端必备）

```html
<!-- 没有这行，移动端会按 980px 宽度渲染再缩放 -->
<meta name="viewport" content="width=device-width, initial-scale=1">
```

#### 移动优先（Mobile First）

```css
/* ❌ 桌面优先：默认桌面样式，max-width 逐级覆盖（样式越写越多） */
.card { flex-direction: row; }
@media (max-width: 768px) { .card { flex-direction: column; } }

/* ✅ 移动优先：默认移动端样式，min-width 逐级增强（渐进增强） */
.card { flex-direction: column; }              /* 基础：移动端 */
@media (min-width: 768px) { .card { flex-direction: row; } } /* 增强：桌面 */
```

**为什么移动优先**：
- 移动端样式通常更简单，作为基础更合理
- 渐进增强（从简到繁）比渐进降级（从繁到简）代码更少
- 移动端性能受限，默认样式最轻量

#### 内容驱动断点

```css
/* ❌ 设备断点：追着具体设备型号写（设备无穷无尽） */
@media (min-width: 375px) { } /* iPhone */
@media (min-width: 390px) { } /* iPhone 14 */

/* ✅ 内容断点：布局在哪里"坏掉"就在哪里设断点 */
@media (min-width: 640px) { } /* 卡片放不下了 → 换布局 */
```

**原则**：断点应该由"内容在这个宽度下布局崩坏"决定，而不是由具体设备型号决定。

### 2. 媒体查询

#### 基础语法与范围写法

```css
/* 传统写法 */
@media (min-width: 768px) and (max-width: 1024px) { }

/* 现代范围语法（更直观） */
@media (768px <= width <= 1024px) { }
@media (width >= 768px) { }
```

#### 特性查询（用户偏好）

```css
/* 暗色模式偏好 */
@media (prefers-color-scheme: dark) {
  body { background: #1a1a1a; color: #eee; }
}

/* 减少动态效果（无障碍：前庭障碍用户） */
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}

/* 输入方式适配 */
@media (hover: hover) {
  /* 有悬停能力的设备（鼠标）才加 hover 效果 */
  .btn:hover { transform: translateY(-2px); }
}
@media (pointer: coarse) {
  /* 触屏设备：加大点击区域 */
  .btn { min-height: 44px; }
}
```

**`prefers-reduced-motion` 是可访问性必考点**——动画对前庭障碍用户可能造成眩晕，应提供降级。

### 3. 容器查询（Container Queries，Baseline 2023-02）

#### 媒体查询的局限

媒体查询基于**视口**，但组件可能被放在不同宽度的容器里（主内容区 vs 侧边栏）。同一组件在不同位置需要不同样式时，媒体查询无能为力——这就是"组件级响应式"的需求。

```css
/* ❌ 媒体查询：卡片样式取决于视口，但卡片可能在侧边栏（窄）也可能在主区（宽） */
@media (min-width: 768px) {
  .card { flex-direction: row; } /* 侧边栏里的卡片也被迫横排 → 崩坏 */
}
```

#### 容器查询语法

```css
/* 1. 声明容器（在父元素上） */
.card-container {
  container-type: inline-size;  /* 以行内方向（宽度）为查询基准 */
  container-name: card-box;     /* 可选：命名容器 */
}

/* 2. 查询容器（样式写在子元素上，但条件基于容器） */
@container (min-width: 500px) {
  .card { flex-direction: row; }  /* 容器宽 ≥500px 时横排 */
}

/* 带名字的查询 */
@container card-box (min-width: 500px) {
  .card { flex-direction: row; }
}
```

#### 容器查询 vs 媒体查询

| 维度 | 媒体查询 | 容器查询 |
|------|---------|---------|
| 基准 | 视口（viewport） | 父容器（container） |
| 粒度 | 页面级 | 组件级 |
| 复用性 | 组件与位置耦合 | 组件自适应任意位置 |
| 适用 | 整体布局、导航折叠 | 卡片、列表、表单组件 |

#### 实战：位置无关的卡片

```css
/* 容器声明 */
.slot { container-type: inline-size; }

/* 卡片基础：竖排 */
.card { display: flex; flex-direction: column; gap: 12px; }

/* 容器够宽 → 横排 */
@container (min-width: 480px) {
  .card { flex-direction: row; align-items: center; }
  .card img { width: 120px; height: 120px; }
}
```

```html
<!-- 同一份卡片代码，放在不同宽度的容器里自动适配 -->
<main class="slot">
  <div class="card">...</div>  <!-- 主区宽 → 横排 -->
</main>
<aside class="slot">
  <div class="card">...</div>  <!-- 侧栏窄 → 竖排 -->
</aside>
```

**这就是容器查询的核心价值**：组件不再关心自己在页面的哪个位置，只关心自己的容器有多宽。

#### 嵌套容器查询

```css
/* 容器可以嵌套，查询就近匹配 */
.outer { container-type: inline-size; }
.inner { container-type: inline-size; }

@container (min-width: 300px) {
  /* 匹配最近的满足条件的祖先容器 */
}
```

### 4. 流式设计

#### clamp() 流式尺寸（呼应模块 3）

```css
h1 { font-size: clamp(2rem, 1.5rem + 2.5vw, 4rem); }
.section { padding-block: clamp(2rem, 1rem + 4vw, 6rem); }
```

#### 响应式图片与防布局偏移（CLS）

```html
<!-- srcset + sizes：让浏览器选择最合适的图片尺寸 -->
<img
  src="photo-800.jpg"
  srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1200.jpg 1200w"
  sizes="(min-width: 768px) 50vw, 100vw"
  alt="示例"
>

<!-- picture：按条件切换不同图片（艺术指导） -->
<picture>
  <source media="(min-width: 768px)" srcset="wide.jpg">
  <img src="narrow.jpg" alt="示例">
</picture>
```

```css
/* aspect-ratio 预留空间，防止图片加载导致布局偏移（CLS） */
.card img {
  width: 100%;
  aspect-ratio: 16 / 9;  /* 加载前就占好位 */
  object-fit: cover;     /* 裁剪填充不变形 */
}
```

**CLS（Cumulative Layout Shift）** 是 Core Web Vitals 指标之一。图片不设宽高/宽高比，加载完成后会撑开布局导致下方内容跳动。`aspect-ratio` + `object-fit` 是标准解法。

### 5. 渐进增强：@supports

```css
/* 特性检测：支持的浏览器应用新样式，不支持的回退 */
.card { display: flex; } /* 回退 */

@supports (display: grid) {
  .card { display: grid; } /* 增强 */
}

/* 检测容器查询支持 */
@supports (container-type: inline-size) {
  .slot { container-type: inline-size; }
}
```

**@supports vs @media 的区别**：@media 查询设备/环境特征，@supports 查询浏览器是否支持某个 CSS 特性。

### 6. 暗色模式完整方案

#### 旧方案：每个颜色写两份媒体查询（繁琐）

```css
:root { --bg: #fff; --text: #333; }

@media (prefers-color-scheme: dark) {
  :root { --bg: #1a1a1a; --text: #eee; } /* 每个变量都要重写 */
}
```

#### 新方案：color-scheme + light-dark()（Baseline 2024-05）

```css
/* 1. 声明支持的配色方案（前置条件，必须） */
:root {
  color-scheme: light dark; /* 告诉浏览器：我支持明暗两套 */
}

/* 2. light-dark(亮色值, 暗色值) 一行搞定 */
:root {
  --bg: light-dark(#ffffff, #1a1a1a);
  --text: light-dark(#333333, #eeeeee);
  --border: light-dark(#e5e7eb, #374151);
}

body {
  background: var(--bg);
  color: var(--text);
}
```

**`light-dark()` 的工作原理**：根据当前生效的 `color-scheme` 自动选择第一个（亮色）或第二个（暗色）值。

#### 手动切换覆盖系统偏好

```css
/* 用户手动切换时，强制指定 color-scheme */
:root[data-theme="light"] { color-scheme: light; }
:root[data-theme="dark"] { color-scheme: dark; }
```

```js
// 切换逻辑 + localStorage 持久化
const saved = localStorage.getItem('theme');
if (saved) {
  document.documentElement.dataset.theme = saved;
}
function toggle() {
  const current = document.documentElement.dataset.theme || 'light';
  const next = current === 'dark' ? 'light' : 'dark';
  document.documentElement.dataset.theme = next;
  localStorage.setItem('theme', next);
}
```

**要点**：
- `color-scheme: light dark` 是 `light-dark()` 生效的前提
- 它还会让浏览器自动调整滚动条、表单控件等原生 UI 的配色
- 手动切换通过覆写 `color-scheme`（而非重写每个变量）实现

## 常见踩坑点

### 坑 1：忘了 viewport meta

```html
<!-- ❌ 没有 viewport，移动端按 980px 渲染，响应式全失效 -->
<!-- ✅ 必须加 -->
<meta name="viewport" content="width=device-width, initial-scale=1">
```

### 坑 2：容器查询不生效（没声明容器）

```css
/* ❌ 直接写 @container，但没有任何祖先声明 container-type */
@container (min-width: 500px) { .card { ... } } /* 不生效 */

/* ✅ 必须在祖先元素上声明容器 */
.parent { container-type: inline-size; }
```

### 坑 3：容器查询用在了容器自身

```css
/* ❌ 容器查询的是"祖先容器"，不能查询自己 */
.card { container-type: inline-size; }
@container (min-width: 500px) {
  .card { ... } /* 无效：card 不能查询自己，要查询它的祖先 */
}

/* ✅ 样式写在容器的"子元素"上 */
@container (min-width: 500px) {
  .card-inner { ... }
}
```

### 坑 4：图片加载导致布局跳动（CLS）

```css
/* ❌ 图片没设尺寸，加载完成后撑开布局 */
img { width: 100%; }

/* ✅ aspect-ratio 预留空间 */
img { width: 100%; aspect-ratio: 16 / 9; object-fit: cover; }
```

### 坑 5：light-dark() 不生效（没设 color-scheme）

```css
/* ❌ 直接用 light-dark()，但没有 color-scheme 声明 */
:root { --bg: light-dark(#fff, #000); } /* 不生效 */

/* ✅ 必须先声明 color-scheme */
:root {
  color-scheme: light dark;
  --bg: light-dark(#fff, #000);
}
```

## 面试高频问题

### Q1：媒体查询和容器查询的区别？怎么选？

**答**：媒体查询基于视口大小，是页面级的响应式；容器查询基于父容器大小，是组件级的响应式（Baseline 2023-02）。核心差异在组件复用：一个卡片组件放在主内容区和侧边栏，媒体查询无法区分（都看视口），容器查询能让卡片根据自身容器宽度自适应。选型上，整体布局、导航折叠用媒体查询，可复用组件的内部适配用容器查询。

### Q2：什么是移动优先？为什么推荐？

**答**：移动优先指默认样式写移动端（最简单的形态），然后用 min-width 媒体查询逐级增强到桌面。推荐的原因：一是移动端样式简单，作为基础代码更少；二是渐进增强比渐进降级更符合工程实践；三是移动端性能受限，默认轻量样式更友好。对应的断点用 min-width 而非 max-width。

### Q3：容器查询怎么用？有什么注意点？

**答**：两步：先在祖先元素声明 container-type: inline-size（以宽度为基准），再用 @container (min-width: Xpx) 写条件样式。注意点：容器查询的是祖先容器，不能查询元素自身，所以样式要写在容器的子元素上；可以命名容器（container-name）做精确查询；容器可以嵌套，查询就近匹配。

### Q4：怎么防止图片加载导致的布局偏移？

**答**：布局偏移（CLS）是因为图片加载前不占空间、加载后撑开布局。解法是给图片预设尺寸：用 aspect-ratio 声明宽高比（配合 object-fit: cover 裁剪填充），或直接写 width/height 属性。这样浏览器在图片加载前就预留好空间，不会跳动。CLS 是 Core Web Vitals 三大指标之一。

### Q5：怎么实现暗色模式？

**答**：现代方案用 color-scheme + light-dark()。先在根元素声明 color-scheme: light dark（这是前提），再用 light-dark(亮色值, 暗色值) 定义颜色变量，浏览器根据当前配色方案自动选值。手动切换通过覆写 color-scheme 实现（data-theme 属性），配合 localStorage 持久化。相比旧方案（每个颜色写两份媒体查询），代码量减半，且 color-scheme 还会自动适配滚动条、表单等原生 UI。

### Q6：prefers-reduced-motion 是什么？为什么要处理？

**答**：这是一个媒体查询特性，检测用户是否在系统中开启了"减少动态效果"。前庭障碍用户看到大幅动画会眩晕，所以这是无障碍（a11y）的重要部分。处理方式是在 @media (prefers-reduced-motion: reduce) 里关闭或简化动画（animation: none、transition: none），保留必要的状态变化。

## 面试回答模板

> **问：谈谈你对响应式设计的理解？**
>
> 响应式设计让同一份代码适配不同尺寸。现代方案是三层组合：第一层是流式设计，用 clamp() 做流式字号间距、用 auto-fit + minmax 做自适应网格，尽量减少断点；第二层是媒体查询，处理页面级布局变化，坚持移动优先（min-width）和内容驱动断点；第三层是容器查询，处理组件级响应式，让组件根据自身容器而非视口自适应，这是 2023 年 Baseline 后组件库的标准做法。还要注意防布局偏移（aspect-ratio）和无障碍（prefers-reduced-motion）。
>
> **追问：容器查询解决了什么痛点？**
>
> 痛点是组件复用。传统媒体查询看视口，但同一个卡片组件可能放在宽的主内容区，也可能放在窄的侧边栏，视口宽度无法反映组件实际可用空间，导致组件和放置位置耦合。容器查询让组件监听自己的容器宽度，放在哪里都能自适应，真正实现了"位置无关"的可复用组件。

## 练习

### 练习 1：位置无关的卡片组件

**要求**：实现一个卡片组件，仅用容器查询适配——放在宽容器横排、窄容器竖排，同一份代码

**提示**：父级声明 container-type: inline-size，@container 里改 flex-direction

**预期效果**：把同一卡片分别放进 600px 和 300px 的容器，自动呈现横排/竖排，无需媒体查询

```css
.slot { container-type: inline-size; }
.card { display: flex; flex-direction: column; gap: 12px; }
@container (min-width: 480px) {
  .card { flex-direction: row; align-items: center; }
}
```

### 练习 2：light-dark() 暗色模式

**要求**：用 color-scheme + light-dark() 实现暗色模式，支持系统偏好 + 手动切换 + localStorage 持久化

**提示**：根元素声明 color-scheme: light dark，颜色用 light-dark()，data-theme 覆写 color-scheme

**预期效果**：默认跟随系统，点击按钮可手动切换且刷新后保持；对比旧方案（双份媒体查询）的代码量

```css
:root {
  color-scheme: light dark;
  --bg: light-dark(#ffffff, #1a1a1a);
  --text: light-dark(#1f2937, #f3f4f6);
}
:root[data-theme="light"] { color-scheme: light; }
:root[data-theme="dark"] { color-scheme: dark; }
body { background: var(--bg); color: var(--text); }
```

### 练习 3：防布局偏移图片画廊

**要求**：用 aspect-ratio + object-fit 实现图片画廊，验证加载时无布局偏移

**提示**：Grid 网格 + aspect-ratio: 1 预留空间 + object-fit: cover

**预期效果**：图片加载前后布局完全一致，无跳动；DevTools Performance 面板看不到 layout shift

```css
.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
  gap: 12px;
}
.gallery img {
  width: 100%;
  aspect-ratio: 1;
  object-fit: cover;
  border-radius: 8px;
}
```
