# 01 — 环境搭建与项目初始化

> 对应大纲：思维层 | 预计时间：1 天
> 面试可答：RN 有两种启动方式——Expo 和 Bare Workflow，Expo 适合快速上手，Bare Workflow 适合需要深度定制原生代码的项目。

***

## 1. 开发环境搭建

React Native 需要同时支持 iOS 和 Android 两个平台的构建工具链，环境搭建是新手遇到的第一个门槛。

### 1.1 必装基础工具

| 工具 | 版本要求 | 用途 | 安装方式 |
|------|---------|------|---------|
| **Node.js** | ≥ 18.x | JavaScript 运行时、npm 包管理 | [官网](https://nodejs.org/) 或 nvm |
| **JDK** | 17（推荐） | Android 编译依赖 | Adoptium Temurin 17 |
| **Watchman**（macOS） | 最新版 | 文件监听，热重载依赖 | `brew install watchman` |
| **Git** | 最新版 | 版本控制 | [官网](https://git-scm.com/) |

**版本选择建议**：用 `nvm` 管理 Node.js 版本，避免系统级安装导致版本冲突。

```bash
# macOS / Linux
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
nvm install 18
nvm use 18

# Windows 推荐用 nvm-windows
# https://github.com/coreybutler/nvm-windows
```

### 1.2 Android 环境

需要安装 **Android Studio**，它会同时提供 Android SDK、模拟器（AVD）和 Gradle 构建工具。

**安装步骤**：

1. 下载 [Android Studio](https://developer.android.com/studio)
2. 安装时勾选 **Android SDK**、**Android SDK Platform**、**Android Virtual Device**
3. 安装完成后，打开 Android Studio → Settings → Languages & Frameworks → Android SDK：
   - SDK Platforms：勾选 **Android 14 (API 34)**
   - SDK Tools：勾选 **Android SDK Build-Tools 34.0.0**

**配置环境变量**（关键步骤，漏掉会报错）：

```bash
# ~/.bashrc 或 ~/.zshrc（macOS/Linux）
export ANDROID_HOME=$HOME/Library/Android/sdk   # macOS
export ANDROID_HOME=$HOME/Android/Sdk           # Linux
export PATH=$PATH:$ANDROID_HOME/emulator
export PATH=$PATH:$ANDROID_HOME/platform-tools
```

Windows 用户在 **系统环境变量** 中添加：
```
ANDROID_HOME = C:\Users\你的用户名\AppData\Local\Android\Sdk
Path 中追加：
  %ANDROID_HOME%\emulator
  %ANDROID_HOME%\platform-tools
```

**验证安装**：

```bash
adb --version          # 应输出 adb 版本号
emulator -list-avds    # 应列出已创建的模拟器（初始可能为空）
```

### 1.3 iOS 环境（仅 macOS）

| 工具 | 用途 | 安装方式 |
|------|------|---------|
| **Xcode** | iOS 编译器和模拟器 | Mac App Store 安装 |
| **CocoaPods** | iOS 依赖管理 | `sudo gem install cocoapods` |

**安装 Xcode 后必须做的事**：

1. 打开 Xcode → Settings → Locations → 确认 **Command Line Tools** 已选中
2. 同意 Xcode license：`sudo xcodebuild -license accept`
3. 安装 iOS 模拟器：Xcode → Settings → Platforms → 下载 iOS 17+ 模拟器

**验证安装**：

```bash
xcodebuild -version    # 应输出 Xcode 版本
pod --version          # 应输出 CocoaPods 版本
xcrun simctl list devices   # 应列出可用模拟器
```

### 1.4 常见环境问题速查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| `ANDROID_HOME is not set` | 环境变量未配置 | 重新检查并 source 配置文件 |
| `adb: command not found` | `platform-tools` 未加入 PATH | 在 PATH 中追加 `$ANDROID_HOME/platform-tools` |
| Gradle 下载极慢 | 默认走 Maven Central | Bare Workflow：在项目 `android/gradle.properties` 中配置国内镜像；Expo：Gradle 由 Expo 托管，无需手动配置 |
| CocoaPods 安装卡在 `Analyzing dependencies` | Pod 仓库索引过大 | 使用 `pod install --repo-update` |
| JDK 版本冲突 | 系统装了多个 JDK | 用 `JAVA_HOME` 明确指向 JDK 17 |

## 2. 创建第一个项目：Expo vs Bare Workflow

这是新手面临的第一个重大选择——**Expo** 还是 **Bare Workflow（裸工作流）**。

### 2.1 两者区别

| 维度 | Expo | Bare Workflow |
|------|------|--------------|
| 初始化命令 | `npx create-expo-app` | `npx react-native init` |
| 是否有 `android/` `ios/` 目录 | ❌ 默认没有（Expo 管理） | ✅ 有完整的原生代码 |
| 能否直接编辑原生代码 | ❌ 需要 `npx expo prebuild` 才生成 | ✅ 直接编辑 Java/Kotlin/Swift |
| 开发体验 | 一键启动，无需编译 | 需要原生编译，首次较慢 |
| OTA 热更新 | ✅ Expo EAS Update 原生支持 | ❌ 需要接入 CodePush 等第三方 |
| 原生模块 | 受限（只能用 Expo SDK 内置模块） | 完全自由（任意 npm 原生模块） |
| 适合人群 | 新手、MVP 验证、快速迭代 | 需要深度原生定制的成熟项目 |

**2026 年的建议**：如果你是新手或快速验证产品，**强烈推荐 Expo**。Expo 的生态已经足够成熟，绝大多数场景不需要 eject。

### 2.2 方式一：Expo 初始化（推荐）

```bash
npx create-expo-app@latest RNDemoApp --template blank-typescript
cd RNDemoApp
npx expo start
```

启动后会看到一个二维码，用 **Expo Go** App（iOS / Android 应用商店下载）扫码即可在真机上预览。

**在模拟器上运行**：

```bash
# 启动后按对应快捷键
# 按 a → 打开 Android 模拟器
# 按 i → 打开 iOS 模拟器
```

### 2.3 方式二：Bare Workflow 初始化

```bash
npx react-native@latest init HelloRN
cd HelloRN
```

**运行到 Android**：

```bash
npx react-native run-android
```

**运行到 iOS**（仅 macOS）：

```bash
cd ios && pod install && cd ..
npx react-native run-ios
```

首次构建会比较慢（Android 需要 Gradle 下载依赖，iOS 需要 CocoaPods 安装），耐心等待。

## 3. 项目目录结构

### 3.1 Expo 项目结构

```
RNDemoApp/
├── app.json            # 应用配置（名称、图标、splash、版本号）
├── App.tsx             # 入口组件（所有 UI 从这里开始）
├── babel.config.js     # Babel 配置
├── tsconfig.json       # TypeScript 配置
├── package.json
└── node_modules/
```

Expo 项目非常简洁——没有 `android/` 和 `ios/` 目录，原生代码由 Expo 管理。

### 3.2 Bare Workflow 项目结构

```
HelloRN/
├── android/            # Android 原生工程（Gradle 项目）
│   ├── app/
│   │   └── src/
│   │       └── main/
│   │           ├── java/       # Java/Kotlin 原生代码
│   │           ├── res/        # Android 资源文件
│   │           └── AndroidManifest.xml
│   └── build.gradle
├── ios/                # iOS 原生工程（Xcode 项目）
│   ├── HelloRN/
│   │   ├── AppDelegate.mm      # iOS 入口
│   │   └── Info.plist
│   └── HelloRN.xcworkspace
├── App.tsx             # ⭐ RN 入口组件
├── index.js            # 注册入口（调用 AppRegistry）
├── metro.config.js     # Metro 打包器配置
├── babel.config.js     # Babel 配置
├── tsconfig.json       # TypeScript 配置
├── package.json
└── node_modules/
```

### 3.3 关键文件说明

| 文件 | 作用 |
|------|------|
| `App.tsx` | **你 90% 的工作都在这里**（以及它的子组件）|
| `index.js` | 注册 App 组件，一般不需要改 |
| `android/` | Android 原生代码，只有需要写原生模块时才动 |
| `ios/` | iOS 原生代码，同上 |
| `metro.config.js` | Metro 打包器配置，一般不需要改 |
| `app.json` / `babel.config.js` | 应用配置和 Babel 插件配置 |

## 4. Metro Bundler：认识 RN 的打包工具

Metro 是 React Native 专属的 JavaScript 打包工具，类似 Webpack 但专为移动端优化。

### 4.1 Metro 的工作方式

```
你的 .tsx 代码
      ↓
Metro Bundler（打包 + 转译）
      ↓
一个 bundle.js 文件
      ↓
发送到设备上的 JS 引擎（Hermes / JSC）
```

Metro 的三大核心能力：

| 能力 | 说明 |
|------|------|
| **打包** | 把所有模块打包成一个 JS bundle |
| **转译** | TypeScript → JavaScript，JSX → JS，ES6+ → ES5 |
| **热重载（HMR）** | 保存文件后自动更新设备上的界面，无需重新编译原生代码 |

### 4.2 Hot Reload vs Fast Refresh

| 特性 | Fast Refresh（RN 0.61+） |
|------|------------------------|
| 修改组件代码 | ✅ 局部热更新，不丢失组件状态 |
| 修改非组件文件（工具函数等） | ✅ 自动重新执行引用它的组件 |
| 出现语法错误 | ✅ 修复后自动恢复 |
| 修改原生代码 | ❌ 需要重新编译原生项目 |

**体验**：修改 `App.tsx` 中的文字，保存后 1-2 秒内设备上就能看到变化，组件状态（如输入框的文字）不会丢失。

### 4.3 常用启动命令

```bash
# Expo 项目
npx expo start                  # 启动开发服务器
npx expo start --clear          # 清除 Metro 缓存后启动
npx expo start --android        # 直接启动 Android 模拟器
npx expo start --ios            # 直接启动 iOS 模拟器

# Bare Workflow 项目
npx react-native start          # 启动 Metro
npx react-native run-android    # 编译 + 安装到 Android
npx react-native run-ios        # 编译 + 安装到 iOS
```

## 5. Hermes：RN 专属 JS 引擎

Hermes 是 Meta 专门为 React Native 开发的 JavaScript 引擎，现在已成为默认引擎（取代了 JavaScriptCore）。

| 特性 | Hermes | 旧版 JavaScriptCore |
|------|--------|-------------------|
| 启动速度 | 预编译字节码，冷启动快 2-3 倍 | 解析 JS 源码，启动慢 |
| 内存占用 | 更低 | 较高 |
| 包体积 | 更小（编译为字节码） | 较大 |
| 调试 | 支持 Chrome DevTools | 需要 Flipper 等工具 |

**结论**：2026 年的 RN 项目默认都用 Hermes，无需额外配置。面试中如果被问到"RN 用什么 JS 引擎"，答 Hermes 就对了。

## 6. 第一次运行：从零到看到界面

### 6.1 Expo 项目快速启动

```bash
# 1. 创建项目
npx create-expo-app@latest HelloExpo --template blank-typescript

# 2. 进入目录
cd HelloExpo

# 3. 启动
npx expo start
```

启动后终端输出类似：

```
› Press a │ open Android
› Press i │ open iOS
› Press w │ open web

› Metro waiting on exp://192.168.x.x:8081
› Scan the QR code above with Expo Go (Android) or Camera (iOS)
```

- 按 `a` 打开 Android 模拟器
- 按 `i` 打开 iOS 模拟器
- 用真机扫码用 Expo Go 预览

### 6.2 验证成功

看到屏幕上显示 **"Open up App.tsx to start working on your app!"**，说明环境搭建成功。

现在打开 `App.tsx`，把内容改成：

```tsx
import { Text, View, StyleSheet } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.text}>Hello React Native!</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: 'center',
    alignItems: 'center',
    backgroundColor: '#f5f5f5',
  },
  text: {
    fontSize: 24,
    fontWeight: 'bold',
    color: '#333',
  },
});
```

保存后，设备上立刻显示 **"Hello React Native!"** —— 你的第一个 RN 应用跑起来了。

## 📝 面试回答模板

> **问：React Native 的开发环境需要哪些工具？**
>
> 需要 Node.js 作为 JS 运行时，Android Studio 提供 Android SDK 和模拟器，Xcode 提供 iOS 编译工具链（仅 macOS）。还需要配置 ANDROID_HOME 环境变量。如果用 Expo 的话，环境搭建会简单很多，只需要 Node.js 就能开发，原生编译由 Expo 云服务托管。

> **问：Expo 和 Bare Workflow 怎么选？**
>
> Expo 适合快速开发和 MVP 验证，不需要碰原生代码，有 OTA 热更新能力。Bare Workflow 适合需要深度定制原生代码的场景，比如接入特殊的原生 SDK。2026 年 Expo 的生态已经非常成熟，绝大多数常规应用（导航、网络请求、相机、地图）用 Expo 就够了。只有当 Expo SDK 不支持某个原生能力时，才需要 eject 到 Bare Workflow。

> **问：Metro 是什么？它和 Webpack 有什么区别？**
>
> Metro 是 React Native 专属的 JS 打包工具。它跟 Webpack 目标类似——模块打包和代码转译——但 Metro 专门为移动端优化，支持增量构建和快速热重载。Metro 的三大核心能力是打包、转译（TS/JSX → JS）和 HMR（文件修改后实时更新到设备上，不丢失组件状态）。

> **问：Hermes 是什么？为什么 RN 要用它而不是 V8？**
>
> Hermes 是 Meta 为 RN 专门开发的 JS 引擎，取代了早期的 JavaScriptCore。它的核心优势是支持预编译字节码——在构建阶段就把 JS 编译为字节码，运行时直接执行，冷启动速度比 JavaScriptCore 快 2-3 倍，内存占用也更低。之所以不用 V8，是因为 V8 是为浏览器场景设计的，启动时的 JIT 编译在移动端有内存和启动时间的额外开销，Hermes 的 AOT 编译更适合移动端场景。
