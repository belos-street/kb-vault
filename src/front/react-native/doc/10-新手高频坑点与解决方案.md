# 10 — 新手高频坑点与解决方案

> 对应大纲：工程层 | 预计时间：按需查阅
> 面试可答：RN 开发中的高频坑包括：样式默认值差异（flexDirection: column）、文字必须被 Text 包裹、Image 必须设宽高、键盘遮挡输入框、平台差异（阴影/字体/安全区域）、FlatList 性能问题、依赖版本冲突等。熟悉这些坑点能大幅减少排错时间。

> 本篇为速查文档，练习环节省略。建议在实际开发中遇到问题时按类别查阅对应小节。

## 1. 样式相关

### 1.1 View 里写文字不显示

```tsx
// ❌ 不会显示任何东西
<View>Hello World</View>

// ✅ 必须用 Text 包裹
<View><Text>Hello World</Text></View>
```

**原因**：`View` 是纯容器组件，不支持文字渲染。所有可见文字必须放在 `Text` 组件内。

### 1.2 默认排列方向是垂直

```tsx
// Web 开发者的预期：水平排列 A B C
<View>
  <View style={{ width: 50, height: 50, backgroundColor: 'red' }} />
  <View style={{ width: 50, height: 50, backgroundColor: 'blue' }} />
  <View style={{ width: 50, height: 50, backgroundColor: 'green' }} />
</View>
// 实际结果：垂直排列

// ✅ 加 flexDirection: 'row'
<View style={{ flexDirection: 'row' }}>
```

**原因**：RN 的 `flexDirection` 默认是 `column`，Web 默认是 `row`。

### 1.3 样式不继承

```tsx
// ❌ 子 Text 不会继承父 View 的颜色
<View style={{ color: 'red' }}>
  <Text>这段文字不是红色</Text>
</View>

// ✅ 直接给 Text 设样式
<Text style={{ color: 'red' }}>这段文字是红色</Text>

// ✅ 或者用 Text 嵌套 Text 实现继承
<Text style={{ color: 'red' }}>
  这段文字是红色
  <Text style={{ fontWeight: 'bold' }}>这段也是红色且加粗</Text>
</Text>
```

**原因**：RN 中只有 `Text` 嵌套 `Text` 时才会继承字体相关样式（color、fontSize、fontFamily 等），其他组件之间没有样式继承。

### 1.4 Image 不设宽高不显示

```tsx
// ❌ 图片不显示
<Image source={require('./photo.png')} />

// ✅ 必须设宽高
<Image source={require('./photo.png')} style={{ width: 200, height: 150 }} />
```

**原因**：RN 的 `Image` 不会自动读取图片尺寸（网络图片更是如此），必须显式指定。同时可以配合 `resizeMode` 控制图片适配方式：

```tsx
<Image
  source={{ uri: 'https://example.com/photo.jpg' }}
  style={{ width: '100%', height: 200 }}
  resizeMode="cover"  // 'cover'（裁剪填充）| 'contain'（等比缩放）| 'stretch'（拉伸）
/>
```

### 1.5 百分比宽度/高度不生效

```tsx
// ❌ 高度百分比不生效（需要父容器有明确高度）
<View style={{ height: '50%' }}>...</View>

// ✅ 父容器有固定高度时，子元素百分比才生效
<View style={{ height: 400 }}>
  <View style={{ height: '50%' }}>...</View>  // 200dp
</View>

// ✅ 或者用 flex 分配空间
<View style={{ flex: 1 }}>
  <View style={{ flex: 1 }}>一半</View>
  <View style={{ flex: 1 }}>一半</View>
</View>
```

**原因**：百分比高度需要父容器有明确的高度约束（固定值或百分比链），否则 `'50%'` 无法计算。RN 不会像浏览器那样自动撑满屏幕，需要用 `flex: 1` 告诉 View 填满可用空间。

### 1.6 圆角在 Android 上不生效

```tsx
// ❌ Android 上圆角可能不生效
<View style={{ borderRadius: 8, overflow: 'hidden' }}>
  <Image source={...} style={{ width: 100, height: 100 }} />
</View>

// ✅ 需要同时设置 overflow: 'hidden'
<View style={{ borderRadius: 8, overflow: 'hidden' }}>
```

**原因**：Android 上 `borderRadius` 不会自动裁剪子元素内容，需要 `overflow: 'hidden'` 配合。

### 1.7 文字截断（省略号）

```tsx
// ❌ 直接截断不显示省略号
<Text numberOfLines={1}>很长很长的文字...</Text>

// ✅ 需要配合 ellipsizeMode
<Text numberOfLines={1} ellipsizeMode="tail">
  这是一段很长很长很长很长很长很长很长的文字
</Text>
// 显示：这是一段很长很长很长很长...
```

## 2. 组件相关

### 2.1 FlatList 不滚动

```tsx
// ❌ FlatList 不滚动（父容器没有明确高度）
<View>
  <FlatList data={data} renderItem={renderItem} />
</View>

// ✅ 给 FlatList 或父容器设 flex: 1
<View style={{ flex: 1 }}>
  <FlatList data={data} renderItem={renderItem} />
</View>
```

**原因**：`FlatList` 需要明确的高度约束才能计算滚动区域。如果没有 `flex: 1` 或固定高度，它会尝试撑开所有内容，导致不滚动。

### 2.2 FlatList 滚动到底部不触发 onEndReached

```tsx
// ❌ 可能不触发
<FlatList
  onEndReached={loadMore}
/>

// ✅ 设置合适的阈值，并确保数据确实有更多
<FlatList
  onEndReached={loadMore}
  onEndReachedThreshold={0.3}  // 距离底部 30% 时触发
  ListFooterComponent={isLoading ? <ActivityIndicator /> : null}
/>
```

**常见原因**：
- `onEndReachedThreshold` 太小（默认 0.01，几乎到底才触发）
- 数据量太少，内容没有超出屏幕
- 请求没有返回 `hasMore` 标志，无限触发

### 2.3 TextInput 键盘遮挡

```tsx
// ❌ 输入框被键盘遮挡
<View style={{ flex: 1 }}>
  <View style={{ flex: 1 }} />
  <TextInput placeholder="输入消息..." />
</View>

// ✅ 用 KeyboardAvoidingView
import { KeyboardAvoidingView, Platform } from 'react-native';

<KeyboardAvoidingView
  style={{ flex: 1 }}
  behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
>
  <View style={{ flex: 1 }} />
  <TextInput placeholder="输入消息..." />
</KeyboardAvoidingView>
```

> **注意**：`behavior` 属性在 iOS 和 Android 上表现不同。iOS 用 `'padding'`，Android 通常用 `'height'` 或不设（Android 的 `windowSoftInputMode` 在 `AndroidManifest.xml` 中配置为 `adjustResize` 更可靠）。

### 2.4 TextInput 在 ScrollView 中键盘不自动收起

```tsx
// ✅ 点击空白区域收起键盘
<ScrollView keyboardShouldPersistTaps="handled">
  <TextInput />
  <Pressable onPress={Keyboard.dismiss}>
    <Text>空白区域</Text>
  </Pressable>
</ScrollView>
```

**关键**：`keyboardShouldPersistTaps="handled"` 让点击非输入区域时收起键盘。默认值 `"never"` 会导致每次点击都先收起键盘。

### 2.5 TouchableOpacity 在 ScrollView 中不响应

```tsx
// ❌ 点击事件可能被 ScrollView 吃掉
<ScrollView>
  <TouchableOpacity onPress={handlePress}>
    <Text>点击我</Text>
  </TouchableOpacity>
</ScrollView>

// ✅ 用 Pressable 替代（推荐），或设置 ScrollView 的 props
<ScrollView keyboardShouldPersistTaps="handled">
  <Pressable onPress={handlePress}>
    <Text>点击我</Text>
  </Pressable>
</ScrollView>
```

## 3. 平台差异

### 3.1 阴影写法不同

```tsx
// ❌ 只写一套阴影，另一端不生效
{
  shadowColor: '#000',
  shadowOffset: { width: 0, height: 2 },
  shadowOpacity: 0.1,
  shadowRadius: 4,
  // Android 上没有阴影！
}

// ✅ 两端都写
{
  // iOS
  shadowColor: '#000',
  shadowOffset: { width: 0, height: 2 },
  shadowOpacity: 0.1,
  shadowRadius: 4,
  // Android
  elevation: 3,
}
```

### 3.2 Android 上 elevation 影响层级

```tsx
// ❌ elevation 高的元素会覆盖 elevation 低的，即使 z-index 更低
<View style={{ zIndex: 999, elevation: 0 }}>会被遮挡</View>
<View style={{ zIndex: 1, elevation: 5 }}>会遮挡上面的</View>

// ✅ 确保 zIndex 和 elevation 一致
<View style={{ zIndex: 2, elevation: 2 }} />
<View style={{ zIndex: 1, elevation: 1 }} />
```

### 3.3 position: fixed 不存在

```tsx
// ❌ RN 没有 position: fixed
<View style={{ position: 'fixed', bottom: 0 }}>
  <Text>固定在底部</Text>
</View>

// ✅ 用 absolute + 屏幕高度模拟
import { useWindowDimensions } from 'react-native';

function FixedBottom() {
  const { height } = useWindowDimensions();
  return (
    <View style={{ position: 'absolute', bottom: 0, width: '100%' }}>
      <Text>固定在底部</Text>
    </View>
  );
}
```

**原因**：RN 只支持 `relative`（默认）和 `absolute` 两种定位，没有 `fixed`。要实现类似效果，用 `position: 'absolute'` 配合 `bottom: 0` 即可——因为 RN 的页面本身就是全屏的，`absolute` 相对于父容器定位的效果等同于 `fixed`。

### 3.4 SafeAreaView 行为不同

```tsx
// iOS：SafeAreaView 处理刘海和底部指示条
// Android：通常只需要处理状态栏

// ✅ 推荐用 react-native-safe-area-context
import { SafeAreaView } from 'react-native-safe-area-context';

<SafeAreaView style={{ flex: 1 }}>
  <App />
</SafeAreaView>
```

> **注意**：RN 内置的 `SafeAreaView` 只支持 iOS，Android 上不生效。推荐用 `react-native-safe-area-context`（React Navigation 的 peer dependency，大部分项目已经装了）。

### 3.5 字体不同

```tsx
// iOS 默认字体：San Francisco
// Android 默认字体：Roboto

// ✅ 需要跨端一致时，指定字体
import { Platform } from 'react-native';

const fontFamily = Platform.select({
  ios: 'Helvetica Neue',
  android: 'Roboto',
});

<Text style={{ fontFamily }}>统一字体</Text>
```

### 3.6 alert() 不可用

```tsx
// ❌ 浏览器的 alert() 在 RN 中不可用
alert('Hello');

// ✅ 用 RN 的 Alert
import { Alert } from 'react-native';

Alert.alert('标题', '内容', [
  { text: '取消', style: 'cancel' },
  { text: '确定', onPress: () => console.log('OK') },
]);
```

### 3.7 localStorage 不可用

```tsx
// ❌ 浏览器 API 不可用
localStorage.setItem('key', 'value');

// ✅ 用 AsyncStorage 或 MMKV
import AsyncStorage from '@react-native-async-storage/async-storage';
await AsyncStorage.setItem('key', 'value');
```

## 4. 导航相关

### 4.1 导航到已有的页面不会重新渲染

```tsx
// ❌ 从 Detail 页面 navigate 到另一个 Detail，不会创建新实例
navigation.navigate('Detail', { id: 2 });
// 如果当前就在 Detail 页面，只会更新 params，不会重新挂载

// ✅ 用 push 创建新实例
navigation.push('Detail', { id: 2 });
```

### 4.2 goBack() 行为不符合预期

```tsx
// 场景：Home → Detail → Settings
// 在 Settings 中 goBack()，期望回到 Home
// 实际：回到 Detail（因为 goBack 是弹出栈顶）

// ✅ 用 popTo 或 popToTop
navigation.popToTop();  // 回到栈底（Home）
navigation.popTo('Home');  // 回到指定页面
```

### 4.3 页面参数丢失

```tsx
// ❌ 直接解构可能报错（参数不存在时）
const { id } = route.params;  // 如果没有 params 会崩溃

// ✅ 安全解构
const { id } = route.params ?? {};
const id = route.params?.id;

// ✅ 或者在 Screen 配置中设置默认值
<Stack.Screen
  name="Detail"
  component={DetailScreen}
  initialParams={{ id: 0 }}
/>
```

### 4.4 页面组件重渲染问题

```tsx
// ❌ 在 render 中定义组件会导致每次重渲染创建新组件
<Stack.Screen name="Home">
  {() => <HomeScreen someProp={value} />}
</Stack.Screen>

// ✅ 用 component + initialParams
<Stack.Screen
  name="Home"
  component={HomeScreen}
  initialParams={{ someProp: value }}
/>

// ✅ 或者用 component + 路由级状态管理
<Stack.Screen name="Home" component={HomeScreen} />
// 在 HomeScreen 内部通过 route.params 或 Zustand 获取数据
```

## 6. 性能相关

### 6.1 在 renderItem 中创建新对象/函数

```tsx
// ❌ 每次渲染都创建新的 style 对象和函数
<FlatList
  renderItem={({ item }) => (
    <Pressable
      style={{ padding: 16, backgroundColor: '#fff' }}  // 每次都新对象
      onPress={() => handlePress(item.id)}               // 每次都新函数
    >
      <Text>{item.name}</Text>
    </Pressable>
  )}
/>

// ✅ 提取为独立组件 + React.memo
const ListItem = React.memo(({ item, onPress }) => (
  <Pressable style={styles.item} onPress={() => onPress(item.id)}>
    <Text>{item.name}</Text>
  </Pressable>
));

const styles = StyleSheet.create({
  item: { padding: 16, backgroundColor: '#fff' },
});

<FlatList
  data={data}
  renderItem={({ item }) => <ListItem item={item} onPress={handlePress} />}
/>
```

### 6.2 useEffect 中请求没有取消

```tsx
// ❌ 组件卸载后请求返回，setState 导致内存泄漏警告
useEffect(() => {
  fetch(`/users/${id}`)
    .then((res) => res.json())
    .then((data) => setUser(data));
}, [id]);

// ✅ 用 AbortController 取消
useEffect(() => {
  const controller = new AbortController();
  fetch(`/users/${id}`, { signal: controller.signal })
    .then((res) => res.json())
    .then((data) => setUser(data))
    .catch((err) => {
      if (err.name !== 'AbortError') throw err;
    });
  return () => controller.abort();
}, [id]);

// ✅ 或者直接用 React Query（自动处理取消）
const { data: user } = useQuery({
  queryKey: ['user', id],
  queryFn: () => api.get(`/users/${id}`),
});
```

### 6.3 图片未缓存导致重复加载

```tsx
// ❌ 每次渲染都重新请求网络图片
<Image source={{ uri: 'https://example.com/photo.jpg' }} />

// ✅ 用 FastImage 缓存
import FastImage from 'react-native-fast-image';

<FastImage
  source={{ uri: 'https://example.com/photo.jpg', priority: FastImage.priority.normal }}
  style={{ width: 100, height: 100 }}
  resizeMode={FastImage.resizeMode.cover}
/>
```

## 8. 常见报错速查

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `Invariant Violation: ... has no propType` | 组件 props 类型错误 | 检查传入的 props 类型 |
| `Cannot read property 'xxx' of undefined` | 空值访问 | 用 `?.` 安全访问 |
| `Tried to register two views with the same name` | 组件名冲突 | 检查重复注册的组件 |
| `Network request failed` | 网络不通或 URL 错误 | 检查 API 地址和网络状态 |
| `Requiring unknown module` | 模块路径错误 | 检查 import 路径 |
| `TurboModuleRegistry.getEnquiring(...)` | Native Module 未链接 | 检查是否安装了原生依赖 |
| `Style 'xxx' is not supported` | 不支持的样式属性 | 查 RN 文档确认支持的属性 |
| `Text strings must be rendered within a <Text>` | 文字未被 Text 包裹 | 检查 JSX 中的裸文字 |
| `Unable to load script` | JS Bundle 加载失败 | 检查 Metro 是否运行 |
| `Invariant Violation: ViewPropTypes has been removed` | 使用了已废弃的 API | 升级第三方库版本 |

## 9. 环境问题速查

| 问题 | 解决方案 |
|------|---------|
| Metro 端口被占用 | `lsof -i :8081` 找到进程，`kill -9 PID` |
| Android 模拟器无法启动 | Android Studio → AVD Manager → Cold Boot Now |
| iOS 编译报 `No matching provisioning profile` | Xcode → Signing → 重新选择 Team |
| `pod install` 超时 | `pod install --repo-update` |
| Gradle 下载慢 | 配置国内镜像（阿里云/腾讯云） |
| `watchman` 报错 | `watchman watch-del-all && watchman shutdown-server` |
| 真机连不上 Metro | 确认同一 WiFi，或用 USB + `adb reverse tcp:8081 tcp:8081` |

## 10. 代码规范建议

| 建议 | 说明 |
|------|------|
| 样式用 `StyleSheet.create` | 性能更好，避免内联对象 |
| 列表项用 `React.memo` | 避免 FlatList 不必要的重渲染 |
| 图片指定宽高 | 避免布局抖动 |
| 网络请求用 React Query | 自动处理缓存/重试/竞态 |
| 状态分层管理 | 服务端 → React Query，客户端 → Zustand |
| 类型用 TypeScript | 导航参数、API 响应、Store 类型全部定义 |
| 平台差异用 `Platform.select` | 集中管理，不要散落在各处 |
| 敏感信息用 SecureStore | Token/密码不要用明文存储 |

## 📝 面试回答模板

> **问：RN 开发中有哪些常见的坑？**
>
> 最高频的坑有三类。第一类是样式差异：flexDirection 默认是 column 不是 row，所有文字必须被 Text 包裹，Image 必须设宽高否则不显示，样式除了 Text 嵌套 Text 外没有继承。第二类是平台差异：阴影写法完全不同（iOS 用 shadow 属性，Android 用 elevation），SafeAreaView 只在 iOS 生效，字体默认不一样（iOS 是 San Francisco，Android 是 Roboto）。第三类是性能问题：FlatList 的 renderItem 中不要创建新对象/函数，网络请求要处理取消和竞态，图片要用 FastImage 缓存。

> **问：遇到 RN 的 Bug 该怎么排查？**
>
> 分三步。第一步，看 Metro 终端的错误信息，大部分语法错误和运行时错误都有明确的错误栈。第二步，用 React DevTools 检查组件的 Props 和 State 是否符合预期，用 Profiler 看是否有不必要的重渲染。第三步，用 Flipper 的 Network 插件检查接口请求/响应是否正确，用 Databases 插件检查本地存储数据。如果以上都查不出来，可能是原生层的问题，需要看 Xcode 或 Android Studio 的原生日志。
