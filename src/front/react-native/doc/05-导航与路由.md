# 05 — 导航与路由

> 对应大纲：应用层 | 预计时间：2 天（含练习）
> 面试可答：RN 的导航方案是 React Navigation（社区标准），核心概念是 Navigator + Screen。常用的导航器有 Stack（栈导航）、Tab（底部标签）、Drawer（侧边抽屉）。RN 的导航是"栈驱动"而非"URL 驱动"，页面切换依赖原生过渡动画，支持 Deep Link 和类型安全的参数传递。

---

## 1. 为什么 RN 的导航跟 Web 不一样

React Web 中，路由基于 **URL**——浏览器地址栏的路径决定渲染哪个组件。RN 中没有地址栏，导航基于**原生导航栈**——操作系统管理页面的进出栈。

```
React Web 路由：
URL: /profile → React Router 匹配 → 渲染 <Profile />

RN 导航：
navigation.navigate('Profile') → 入栈 → 原生动画推入 → 显示 ProfileScreen
```

| 维度 | React Web (React Router) | React Native (React Navigation) |
|------|--------------------------|--------------------------------|
| 驱动方式 | URL 路径 | 导航栈操作 |
| 页面切换 | CSS 过渡动画 | 原生 push/pop 动画 |
| 返回行为 | 浏览器后退按钮 | 物理返回键（Android）/ 手势滑动（iOS） |
| 深链接 | URL 直接访问 | Deep Link / Universal Link 配置 |
| 状态管理 | URL 即状态 | 导航状态（栈中有哪些页面） |

## 2. React Navigation 核心概念

React Navigation 是 RN 社区的导航标准方案。理解它的核心概念是学好 RN 导航的关键。

### 2.1 核心架构

```
NavigationContainer
  └── Navigator（导航器）
        ├── Screen（页面 A）
        ├── Screen（页面 B）
        └── Screen（页面 C）
```

- **NavigationContainer**：顶层容器，整个 App 只有一个，管理导航状态
- **Navigator**：导航器，决定页面切换方式（栈/标签/抽屉）
- **Screen**：页面，每个 Screen 对应一个 React 组件

### 2.2 安装

```bash
# 核心包
npm install @react-navigation/native

# 必需的 peer dependencies
npm install react-native-screens react-native-safe-area-context

# 常用导航器（按需安装）
npm install @react-navigation/native-stack    # 栈导航
npm install @react-navigation/bottom-tabs     # 底部标签
npm install @react-navigation/drawer          # 侧边抽屉
```

### 2.3 最小示例

```tsx
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { View, Text, Pressable } from 'react-native';

// 页面组件
function HomeScreen({ navigation }) {
  return (
    <View style={{ flex: 1, justifyContent: 'center', alignItems: 'center' }}>
      <Text style={{ fontSize: 24 }}>首页</Text>
      <Pressable onPress={() => navigation.navigate('Detail')}>
        <Text style={{ color: '#007AFF', marginTop: 16 }}>去详情页</Text>
      </Pressable>
    </View>
  );
}

function DetailScreen() {
  return (
    <View style={{ flex: 1, justifyContent: 'center', alignItems: 'center' }}>
      <Text style={{ fontSize: 24 }}>详情页</Text>
    </View>
  );
}

// 创建栈导航器
const Stack = createNativeStackNavigator();

export default function App() {
  return (
    <NavigationContainer>
      <Stack.Navigator>
        <Stack.Screen name="Home" component={HomeScreen} />
        <Stack.Screen name="Detail" component={DetailScreen} />
      </Stack.Navigator>
    </NavigationContainer>
  );
}
```

## 3. Stack Navigator：栈导航

栈导航是最基础的导航方式——新页面"推入"栈顶，返回时"弹出"。

### 3.1 栈的运作原理

```
操作                  栈状态                  屏幕显示
────────────────────────────────────────────────────
初始                  [Home]                  HomeScreen

navigate('Detail')   [Home, Detail]          DetailScreen
                                              （Home 在底下）

navigate('Settings')  [Home, Detail, Settings] SettingsScreen

goBack()              [Home, Detail]          DetailScreen

goBack()              [Home]                  HomeScreen
```

### 3.2 导航操作

```tsx
function HomeScreen({ navigation }) {
  // 跳转到新页面（入栈）
  navigation.navigate('Detail');

  // 跳转并传参
  navigation.navigate('Detail', { id: 42, title: '文章标题' });

  // push：总是推入新实例（navigate 如果已在栈中则跳到已有实例）
  navigation.push('Home');

  // 返回上一页（出栈）
  navigation.goBack();

  // 返回到栈中第一个页面
  navigation.popToTop();

  // 返回到指定页面
  navigation.popTo('Home');
}
```

### 3.3 navigate vs push

| 方法 | 行为 | 场景 |
|------|------|------|
| `navigate('Name')` | 如果栈中已有该页面，跳到它；否则推入新页面 | 大多数跳转 |
| `push('Name')` | 总是推入一个新实例，即使栈中已有 | 需要多个同类页面（如文章详情→相关文章→详情） |

```tsx
// 场景：文章列表 → 文章详情 → 相关文章 → 又一篇详情
// 用 navigate：只会跳到栈中第一个 Detail
// 用 push：每次都是新的 Detail 页面

navigation.push('Detail', { id: article.id });
```

### 3.4 页面配置

```tsx
<Stack.Navigator
  screenOptions={{
    headerStyle: { backgroundColor: '#007AFF' },
    headerTintColor: '#fff',
    headerTitleStyle: { fontWeight: 'bold' },
  }}
>
  {/* 全局配置对所有页面生效 */}

  <Stack.Screen
    name="Home"
    component={HomeScreen}
    options={{
      title: '首页',                    // 标题文字
      headerShown: true,                // 是否显示导航栏
    }}
  />

  <Stack.Screen
    name="Detail"
    component={DetailScreen}
    options={({ route }) => ({
      title: route.params?.title ?? '详情',  // 动态标题
      headerBackTitle: '返回',               // iOS 返回按钮文字
    })}
  />

  <Stack.Screen
    name="Settings"
    component={SettingsScreen}
    options={{
      headerShown: false,               // 隐藏导航栏（全屏页面）
    }}
  />
</Stack.Navigator>
```

## 4. 参数传递

### 4.1 传递参数

```tsx
// 发送方
navigation.navigate('Profile', {
  userId: '123',
  userName: 'Alice',
});

// 接收方
function ProfileScreen({ route }) {
  const { userId, userName } = route.params;
  return <Text>用户: {userName} (ID: {userId})</Text>;
}
```

### 4.2 动态读取参数

```tsx
function ProfileScreen({ route, navigation }) {
  const { userId } = route.params;

  // 设置动态标题
  useEffect(() => {
    navigation.setOptions({ title: `用户 ${userId}` });
  }, [navigation, userId]);

  return <Text>用户 ID: {userId}</Text>;
}
```

### 4.3 TypeScript 类型安全

```tsx
import { createNativeStackNavigator, NativeStackScreenProps } from '@react-navigation/native-stack';

// 定义导航参数类型
type RootStackParamList = {
  Home: undefined;
  Detail: { id: number; title: string };
  Profile: { userId: string };
};

const Stack = createNativeStackNavigator<RootStackParamList>();

// 页面组件的 props 类型
type DetailProps = NativeStackScreenProps<RootStackParamList, 'Detail'>;

function DetailScreen({ route, navigation }: DetailProps) {
  const { id, title } = route.params; // ✅ 类型安全
  return <Text>{title} (ID: {id})</Text>;
}

// navigate 也有类型提示
navigation.navigate('Detail', { id: 42, title: '文章' }); // ✅ 类型安全
navigation.navigate('Detail', { id: '42' }); // ❌ 类型错误
```

> **建议**：在项目根目录创建 `types/navigation.ts`，统一管理所有导航参数类型。随着页面增多，类型安全能避免大量低级错误。

## 5. Tab Navigator：底部标签导航

### 5.1 基本用法

```tsx
import { createBottomTabNavigator } from '@react-navigation/bottom-tabs';
import { Text } from 'react-native';

const Tab = createBottomTabNavigator();

function HomeTab()    { return <Text>首页</Text>; }
function SearchTab()  { return <Text>搜索</Text>; }
function ProfileTab() { return <Text>我的</Text>; }

export default function MainTabs() {
  return (
    <Tab.Navigator
      screenOptions={{
        tabBarActiveTintColor: '#007AFF',
        tabBarInactiveTintColor: '#999',
        headerShown: false,
      }}
    >
      <Tab.Screen
        name="Home"
        component={HomeTab}
        options={{
          tabBarLabel: '首页',
          tabBarIcon: ({ color, size }) => (
            <Text style={{ color, fontSize: size }}>🏠</Text>
          ),
        }}
      />
      <Tab.Screen
        name="Search"
        component={SearchTab}
        options={{
          tabBarLabel: '搜索',
          tabBarIcon: ({ color, size }) => (
            <Text style={{ color, fontSize: size }}>🔍</Text>
          ),
        }}
      />
      <Tab.Screen
        name="Profile"
        component={ProfileTab}
        options={{
          tabBarLabel: '我的',
          tabBarIcon: ({ color, size }) => (
            <Text style={{ color, fontSize: size }}>👤</Text>
          ),
        }}
      />
    </Tab.Navigator>
  );
}
```

### 5.2 Tab 内嵌套 Stack

实际项目中，每个 Tab 页内部通常都有自己的页面栈：

```tsx
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { createBottomTabNavigator } from '@react-navigation/bottom-tabs';

// Home 栈
const HomeStack = createNativeStackNavigator();
function HomeStackScreen() {
  return (
    <HomeStack.Navigator>
      <HomeStack.Screen name="HomeList" component={HomeScreen} />
      <HomeStack.Screen name="Detail" component={DetailScreen} />
    </HomeStack.Navigator>
  );
}

// Search 栈
const SearchStack = createNativeStackNavigator();
function SearchStackScreen() {
  return (
    <SearchStack.Navigator>
      <SearchStack.Screen name="SearchMain" component={SearchScreen} />
      <SearchStack.Screen name="Result" component={ResultScreen} />
    </SearchStack.Navigator>
  );
}

// Tab
const Tab = createBottomTabNavigator();
export default function App() {
  return (
    <NavigationContainer>
      <Tab.Navigator>
        <Tab.Screen
          name="HomeTab"
          component={HomeStackScreen}
          options={{ headerShown: false, tabBarLabel: '首页' }}
        />
        <Tab.Screen
          name="SearchTab"
          component={SearchStackScreen}
          options={{ headerShown: false, tabBarLabel: '搜索' }}
        />
      </Tab.Navigator>
    </NavigationContainer>
  );
}
```

```
最终结构：
Tab Navigator
├── HomeTab → HomeStack
│   ├── HomeList
│   └── Detail
├── SearchTab → SearchStack
│   ├── SearchMain
│   └── Result
└── ProfileTab → ProfileStack
    └── ProfileMain
```

## 6. Drawer Navigator：侧边抽屉导航

### 6.1 基本用法

```bash
npm install @react-navigation/drawer react-native-gesture-handler react-native-reanimated
```

```tsx
import { createDrawerNavigator } from '@react-navigation/drawer';

const Drawer = createDrawerNavigator();

export default function App() {
  return (
    <NavigationContainer>
      <Drawer.Navigator>
        <Drawer.Screen name="Home" component={HomeScreen} />
        <Drawer.Screen name="Settings" component={SettingsScreen} />
        <Drawer.Screen name="About" component={AboutScreen} />
      </Drawer.Navigator>
    </NavigationContainer>
  );
}

// 打开/关闭抽屉
function HomeScreen({ navigation }) {
  return (
    <View>
      <Pressable onPress={() => navigation.openDrawer()}>
        <Text>打开菜单</Text>
      </Pressable>
    </View>
  );
}
```

### 6.2 自定义抽屉内容

```tsx
import { DrawerContentScrollView, DrawerItemList } from '@react-navigation/drawer';

function CustomDrawerContent(props) {
  return (
    <DrawerContentScrollView {...props}>
      <View style={{ padding: 16, borderBottomWidth: 1, borderBottomColor: '#eee' }}>
        <Text style={{ fontSize: 18, fontWeight: 'bold' }}>用户名</Text>
        <Text style={{ color: '#666' }}>user@example.com</Text>
      </View>
      <DrawerItemList {...props} />
    </DrawerContentScrollView>
  );
}

<Drawer.Navigator drawerContent={(props) => <CustomDrawerContent {...props} />}>
  {/* ... */}
</Drawer.Navigator>
```

### 6.3 Drawer 配置选项

```tsx
<Drawer.Navigator
  screenOptions={{
    drawerType: 'front',           // 'front'（覆盖）| 'back'（推挤）| 'slide'（滑动）
    drawerPosition: 'left',        // 左侧或右侧
    drawerStyle: {
      width: 280,
      backgroundColor: '#fff',
    },
    drawerLabelStyle: {
      fontSize: 16,
    },
    drawerActiveTintColor: '#007AFF',
    drawerInactiveTintColor: '#333',
  }}
>
  <Drawer.Screen name="Home" component={HomeScreen} />
</Drawer.Navigator>
```

| `drawerType` | 效果 | 场景 |
|-------------|------|------|
| `'front'`（默认） | 抽屉覆盖在内容上方 | 内容不需移动 |
| `'back'` | 内容被推挤到右侧 | 视觉反馈更强 |
| `'slide'` | 抽屉和内容一起滑动 | Material Design 风格 |

```tsx
// 关闭/切换抽屉
navigation.closeDrawer();
navigation.toggleDrawer();
```

## 7. 导航生命周期

### 7.1 页面生命周期事件

```tsx
function DetailScreen({ navigation }) {
  // 页面获得焦点时触发（进入、从其他 Tab 切回）
  useEffect(() => {
    const unsubscribe = navigation.addListener('focus', () => {
      console.log('页面获得焦点');
      // 适合刷新数据
    });
    return unsubscribe;
  }, [navigation]);

  // 页面失去焦点时触发
  useEffect(() => {
    const unsubscribe = navigation.addListener('blur', () => {
      console.log('页面失去焦点');
      // 适合清理定时器
    });
    return unsubscribe;
  }, [navigation]);

  return <Text>详情页</Text>;
}
```

### 7.2 useFocusEffect

`useFocusEffect` 是更方便的焦点回调 Hook：

```tsx
import { useFocusEffect } from '@react-navigation/native';
import { useCallback } from 'react';

function ProfileScreen() {
  const [data, setData] = useState(null);

  // 每次页面获得焦点时重新获取数据
  useFocusEffect(
    useCallback(() => {
      fetchProfile().then(setData);
    }, [])
  );

  return <Text>{data?.name}</Text>;
}
```

> **注意**：`useFocusEffect` 内部用的是 `useCallback`，不是 `useEffect`。回调函数在页面失焦时不会自动清理，如果需要清理，返回一个清理函数。

## 8. Deep Link：深链接

Deep Link 让用户可以通过 URL 直接打开 App 的特定页面（如从浏览器链接、推送通知跳转到 App 内的某个页面）。

### 8.1 配置

```tsx
const linking = {
  prefixes: ['myapp://', 'https://myapp.com'],
  config: {
    screens: {
      Home: 'home',
      Detail: 'detail/:id',     // :id 是动态参数
      Profile: 'user/:userId',
    },
  },
};

export default function App() {
  return (
    <NavigationContainer linking={linking}>
      <Stack.Navigator>
        {/* ... */}
      </Stack.Navigator>
    </NavigationContainer>
  );
}
```

### 8.2 URL 与页面的映射

```
myapp://home              → HomeScreen
myapp://detail/42         → DetailScreen (params: { id: '42' })
myapp://user/abc          → ProfileScreen (params: { userId: 'abc' })
https://myapp.com/detail/42 → 同上（Universal Link）
```

### 8.3 从 Deep Link 获取参数

```tsx
function DetailScreen({ route }) {
  const { id } = route.params;
  // 无论是 navigate 还是 Deep Link 进入，参数都在 route.params 中
  return <Text>文章 ID: {id}</Text>;
}
```

## 9. 导航最佳实践

### 9.1 项目结构推荐

```
src/
├── navigation/
│   ├── index.tsx              # NavigationContainer + linking 配置
│   ├── types.ts               # 全局导航参数类型定义
│   ├── MainStack.tsx          # 主栈导航器
│   ├── MainTabs.tsx           # 底部标签导航器
│   └── HomeStack.tsx          # 各 Tab 内的子栈
├── screens/
│   ├── Home/
│   │   ├── HomeScreen.tsx
│   │   └── DetailScreen.tsx
│   ├── Search/
│   │   └── SearchScreen.tsx
│   └── Profile/
│       └── ProfileScreen.tsx
└── components/
    └── ...
```

### 9.2 导航参数类型集中管理

```tsx
// navigation/types.ts
export type RootStackParamList = {
  MainTabs: undefined;
  Detail: { id: number; title?: string };
  Settings: undefined;
};

export type MainTabParamList = {
  HomeTab: undefined;
  SearchTab: undefined;
  ProfileTab: undefined;
};

export type HomeStackParamList = {
  HomeList: undefined;
  Detail: { id: number };
};

// 使用时
import type { NativeStackScreenProps } from '@react-navigation/native-stack';
import type { RootStackParamList } from '../navigation/types';

type Props = NativeStackScreenProps<RootStackParamList, 'Detail'>;
```

### 9.3 常见模式

| 模式 | 实现方式 |
|------|---------|
| 登录后进入主页 | 条件渲染：未登录显示 AuthStack，已登录显示 MainStack |
| 欢迎页/引导页 | 首次启动显示 Onboarding，之后直接进主页 |
| Modal 弹窗页面 | 用 `<Stack.Group screenOptions={{ presentation: 'modal' }}>` |
| 全屏页面（无导航栏） | `headerShown: false` |

```tsx
// 登录状态切换
function App() {
  const [isLoggedIn, setIsLoggedIn] = useState(false);

            <Stack.Screen name="MainTabs" component={MainTabs} options={{ headerShown: false }} />
            <Stack.Screen name="Detail" component={DetailScreen} />
          </>
        ) : (
          <>
            <Stack.Screen name="Login" component={LoginScreen} />
            <Stack.Screen name="Register" component={RegisterScreen} />
          </>
        )}
      </Stack.Navigator>
    </NavigationContainer>
  );
}
```

```tsx
// Modal 页面
<Stack.Group screenOptions={{ presentation: 'modal' }}>
```

## 10. 导航状态管理

### 10.1 reset：重置导航栈

有时需要清空导航栈（如登出后跳到登录页，不允许返回）：

```tsx
import { CommonActions } from '@react-navigation/native';

// 登出后跳到登录页，清空栈
navigation.dispatch(
  CommonActions.reset({
    index: 0,
    routes: [{ name: 'Login' }],
  })
);
```

### 10.2 navigate 的局限性

`navigate` 只能在当前 Navigator 内部跳转。跨 Navigator 跳转需要用 `navigation.getParent()` 或将 navigator 嵌套：

```tsx
// 从 Tab 内的子页面跳到另一个 Tab
// 方式一：使用 navigation.getParent()
navigation.getParent()?.navigate('SearchTab');

// 方式二：在子 Stack 中配置 initialParams 指向目标 Tab
```

## 📝 面试回答模板

> **问：RN 的导航方案是什么？跟 React Router 有什么区别？**
>
> RN 的社区标准导航方案是 React Navigation。跟 React Router 的核心区别在于驱动方式——React Router 基于 URL 路径匹配组件，React Navigation 基于原生导航栈操作。React Navigation 的页面切换动画是原生的 push/pop，支持 iOS 手势滑动返回和 Android 物理返回键。它提供了三种核心导航器：Stack（栈导航，最常用）、Tab（底部标签，主流 App 的标配）、Drawer（侧边抽屉）。

> **问：navigate 和 push 有什么区别？**
>
> navigate 会检查目标页面是否已经在栈中，如果在就跳到已有的实例，如果不在就推入新实例。push 总是推入一个新的实例。实际场景中，大多数跳转用 navigate 就够了，只有在需要同一个页面存在多个实例时（比如文章详情 → 相关文章 → 又一个详情）才用 push。

> **问：RN 中怎么做 Tab + Stack 的嵌套导航？**
>
> 实际项目中，底部每个 Tab 内部都有自己的 Stack Navigator。结构是 Tab Navigator 套多个 Stack Navigator，每个 Stack 内部有自己的页面栈。这样从首页 Tab 跳到详情页时，详情页覆盖在首页上方，而底部 Tab 栏还在。如果要进全屏详情（隐藏 Tab 栏），可以在 Stack.Screen 的 options 中设置 tabBarStyle: { display: 'none' }。

> **问：Deep Link 怎么配置？**
>
> React Navigation 的 Deep Link 通过 linking 配置项实现。在 NavigationContainer 上传入 linking 对象，其中 prefixes 定义 URL scheme（如 myapp://），config.screens 定义路径到页面的映射（如 detail/:id 映射到 DetailScreen 并提取 id 参数）。配置后，无论是自定义 scheme 还是 Universal Link，系统都会自动打开 App 并导航到对应页面，参数通过 route.params 获取。
