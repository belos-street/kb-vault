# 08 — 设备能力与原生模块

> 对应大纲：应用层 | 预计时间：2 天（含练习）
> 面试可答：RN 通过第三方库或 Expo SDK 调用设备能力（相机/定位/推送/文件系统等）。权限管理用 react-native-permissions（Bare）或 expo-permissions（Expo）。当社区库无法满足需求时，可以通过 Native Module 桥接原生代码（Java/Kotlin/Swift）。Expo 项目的原生模块通过 Config Plugin 扩展。

## 1. 权限管理

调用任何设备能力之前，必须先请求权限。iOS 和 Android 的权限模型不同，需要分别处理。

### 1.1 权限模型差异

| 维度 | iOS | Android |
|------|-----|---------|
| 请求时机 | 首次使用时弹窗 | 安装时声明 + 运行时请求 |
| 权限粒度 | 精细（如"允许访问选中的照片" vs "允许访问所有照片"） | 较粗（READ_MEDIA_IMAGES） |
| 用户拒绝后 | 设置中手动开启 | 勾选"不再询问"后需要引导去设置 |
| 后台权限 | 需要额外声明 "Always" | 需要额外声明后台服务 |

### 1.2 Bare Workflow：react-native-permissions

```bash
npm install react-native-permissions
```

```tsx
import { check, request, PERMISSIONS, RESULTS } from 'react-native-permissions';
import { Platform } from 'react-native';

async function requestCameraPermission() {
  const permission = Platform.select({
    ios: PERMISSIONS.IOS.CAMERA,
    android: PERMISSIONS.ANDROID.CAMERA,
  });

  // 先检查当前状态
  const status = await check(permission);

  switch (status) {
    case RESULTS.GRANTED:
      return true;

    case RESULTS.DENIED:
      // 首次请求
      const result = await request(permission);
      return result === RESULTS.GRANTED;

    case RESULTS.BLOCKED:
      // 用户拒绝且勾选了"不再询问"，需要引导去设置
      Alert.alert(
        '需要相机权限',
        '请在设置中开启相机权限',
        [
          { text: '取消', style: 'cancel' },
          { text: '去设置', onPress: () => Linking.openSettings() },
        ]
      );
      return false;

    case RESULTS.UNAVAILABLE:
      Alert.alert('设备不支持此功能');
      return false;

    default:
      return false;
  }
}
```

### 1.3 Expo：expo-camera / expo-location 内置权限

Expo 的库自带权限管理，不需要额外安装权限库（以 expo-camera 的新版 Hook API 为例）：

```tsx
import { useCameraPermissions } from 'expo-camera';

function useCameraPermission() {
  const [permission, requestPermission] = useCameraPermissions();

  return {
    loading: !permission,          // 还在查询权限状态
    granted: permission?.granted ?? false,
    request: requestPermission,    // 弹窗请求权限
  };
}
```

### 1.4 通用权限请求模式

```tsx
import { Alert, Linking } from 'react-native';

async function requestWithPrompt(
  requestFn: () => Promise<boolean>,
  featureName: string
): Promise<boolean> {
  const granted = await requestFn();

  if (!granted) {
    Alert.alert(
      `${featureName}权限被拒绝`,
      `请在设置中开启${featureName}权限以使用此功能`,
      [
        { text: '取消', style: 'cancel' },
        { text: '去设置', onPress: () => Linking.openSettings() },
      ]
    );
  }

  return granted;
}

// 使用
const granted = await requestWithPrompt(
  requestCameraPermission,
  '相机'
);
```

## 2. 相机与图片选择

### 2.1 Expo 方案

```bash
npx expo install expo-camera expo-image-picker
```

```tsx
import { CameraView, useCameraPermissions } from 'expo-camera';
import * as ImagePicker from 'expo-image-picker';
import { useState, useRef } from 'react';
import { View, Text, Pressable, Image } from 'react-native';

// 拍照
function CameraScreen() {
  const [permission, requestPermission] = useCameraPermissions();
  const cameraRef = useRef<CameraView>(null);
  const [photo, setPhoto] = useState<string | null>(null);

  if (!permission) return <View />;
  if (!permission.granted) {
    return (
      <View style={{ flex: 1, justifyContent: 'center', alignItems: 'center' }}>
        <Text>需要相机权限</Text>
        <Pressable onPress={requestPermission}>
          <Text style={{ color: '#007AFF' }}>授予权限</Text>
        </Pressable>
      </View>
    );
  }

  const takePicture = async () => {
    const result = await cameraRef.current?.takePictureAsync();
    if (result) setPhoto(result.uri);
  };

  return (
    <View style={{ flex: 1 }}>
      {photo ? (
        <View style={{ flex: 1 }}>
          <Image source={{ uri: photo }} style={{ flex: 1 }} />
          <Pressable onPress={() => setPhoto(null)}>
            <Text>重拍</Text>
          </Pressable>
        </View>
      ) : (
        <CameraView style={{ flex: 1 }} ref={cameraRef}>
          <Pressable onPress={takePicture}>
            <Text style={{ color: '#fff' }}>拍照</Text>
          </Pressable>
        </CameraView>
      )}
    </View>
  );
}

// 从相册选择
async function pickImage() {
  const result = await ImagePicker.launchImageLibraryAsync({
    // 注意：MediaTypeOptions（如 MediaTypeOptions.Images）已弃用，
    // 官方要求改用 MediaType 数组
    mediaTypes: [ImagePicker.MediaType.Images],
    allowsEditing: true,
    aspect: [4, 3],
    quality: 0.8,
  });

  if (!result.canceled && result.assets[0]) {
    return result.assets[0].uri;
  }
  return null;
}

// 拍照（Expo 方式）
async function takePhoto() {
  const result = await ImagePicker.launchCameraAsync({
    allowsEditing: true,
    aspect: [4, 3],
    quality: 0.8,
  });

  if (!result.canceled && result.assets[0]) {
    return result.assets[0].uri;
  }
  return null;
}

// 选择图片或拍照
async function getImageOrCamera() {
  return new Promise((resolve) => {
    Alert.alert('选择图片来源', '', [
      { text: '拍照', onPress: async () => resolve(await takePhoto()) },
      { text: '相册', onPress: async () => resolve(await pickImage()) },
      { text: '取消', style: 'cancel', onPress: () => resolve(null) },
    ]);
  });
}
```

## 3. 定位

### 3.1 Expo 方案

```bash
npx expo install expo-location
```

```tsx
import * as Location from 'expo-location';
import { useEffect, useState } from 'react';

function useCurrentLocation() {
  const [location, setLocation] = useState<Location.LocationObject | null>(null);
  const [error, setError] = useState<string | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    (async () => {
      const { status } = await Location.requestForegroundPermissionsAsync();
      if (status !== 'granted') {
        setError('定位权限被拒绝');
        setLoading(false);
        return;
      }

      const loc = await Location.getCurrentPositionAsync({
        accuracy: Location.Accuracy.High,
      });
      setLocation(loc);
      setLoading(false);
    })();
  }, []);

  return { location, error, loading };
}

// 使用
function MapScreen() {
  const { location, error, loading } = useCurrentLocation();

  if (loading) return <ActivityIndicator />;
  if (error) return <Text>{error}</Text>;

  return (
    <Text>
      经度: {location?.coords.longitude}, 纬度: {location?.coords.latitude}
    </Text>
  );
}
```

### 3.2 持续定位（后台定位）

```tsx
import * as Location from 'expo-location';

async function startTracking() {
  const { status } = await Location.requestBackgroundPermissionsAsync();
  if (status !== 'granted') return;

  await Location.watchPositionAsync(
    {
      accuracy: Location.Accuracy.High,
      distanceInterval: 10,   // 移动 10 米更新一次
      timeInterval: 5000,     // 或 5 秒更新一次
    },
    (loc) => {
      console.log('新位置:', loc.coords.latitude, loc.coords.longitude);
    }
  );
}
```

### 3.3 地理编码（坐标 ↔ 地址）

```tsx
import * as Location from 'expo-location';

// 坐标 → 地址
const [address] = await Location.reverseGeocodeAsync({
  latitude: 39.9042,
  longitude: 116.4074,
});
console.log(address.city, address.street); // 北京市 XX路

// 地址 → 坐标
const [geocode] = await Location.geocodeAsync('北京市天安门广场');
console.log(geocode.latitude, geocode.longitude);
```

## 4. 推送通知

### 4.1 Expo 方案

```bash
npx expo install expo-notifications
```

```tsx
import * as Notifications from 'expo-notifications';
import { useEffect, useRef } from 'react';

// 配置通知行为（shouldShowAlert 已弃用，改用 shouldShowBanner / shouldShowList）
Notifications.setNotificationHandler({
  handleNotification: async () => ({
    shouldShowBanner: true,   // 前台横幅展示
    shouldShowList: true,     // 进入通知列表
    shouldPlaySound: true,
    shouldSetBadge: true,
  }),
});

function useNotifications() {
  const responseListener = useRef<Notifications.Subscription>();

  useEffect(() => {
    // 请求权限
    registerForPushNotifications();

    // 监听通知响应（用户点击通知时）
    responseListener.current = Notifications.addNotificationResponseReceivedListener(
      (response) => {
        const { screen, id } = response.notification.request.content.data;
        // 跳转到对应页面
        navigation.navigate(screen, { id });
      }
    );

    return () => {
      // 新版 SDK 已移除 removeNotificationSubscription，直接调用订阅对象的 remove()
      responseListener.current?.remove();
    };
  }, []);
}

async function registerForPushNotifications() {
  const { status } = await Notifications.requestPermissionsAsync();
  if (status !== 'granted') return;

  const token = await Notifications.getExpoPushTokenAsync();
  console.log('Push Token:', token.data);
  // 发送 token 到服务端保存
}

// 发送本地通知
async function sendLocalNotification() {
  await Notifications.scheduleNotificationAsync({
    content: {
      title: '提醒',
      body: '你有一条新消息',
      data: { screen: 'Messages', id: '123' },
    },
    trigger: { seconds: 5 },  // 5 秒后发送
  });
}
```

### 4.2 推送通知架构

```
App 启动
  ↓
获取 Expo Push Token
  ↓
发送 Token 到你的服务端
  ↓
服务端存储 Token（与用户关联）
  ↓
需要推送时，服务端调用 Expo Push API
  ↓
Expo Push Service → APNs / FCM → 设备
```

## 5. 文件系统

### 5.1 Expo 方案

```bash
npx expo install expo-file-system
```

```tsx
import * as FileSystem from 'expo-file-system';

// 下载文件
const downloadResumable = FileSystem.createDownloadResumable(
  'https://example.com/file.pdf',
  FileSystem.documentDirectory + 'file.pdf'
);
const result = await downloadResumable.downloadAsync();
console.log('下载完成:', result?.uri);

// 读取文件
const content = await FileSystem.readAsStringAsync(
  FileSystem.documentDirectory + 'data.json'
);

// 写入文件
await FileSystem.writeAsStringAsync(
  FileSystem.documentDirectory + 'data.json',
  JSON.stringify({ name: 'Alice' })
);

// 获取文件信息
const info = await FileSystem.getInfoAsync(
  FileSystem.documentDirectory + 'file.pdf'
);
console.log(info.exists, info.size);

// 删除文件
await FileSystem.deleteAsync(FileSystem.documentDirectory + 'file.pdf');
```

### 5.2 目录说明

| 目录 | 说明 | 会被清除 |
|------|------|---------|
| `FileSystem.documentDirectory` | 应用文档目录（用户数据） | 不会 |
| `FileSystem.cacheDirectory` | 缓存目录 | 系统可能清除 |
| `FileSystem.bundleDirectory` | 应用内置资源（只读） | 不会 |

### 5.3 下载进度

```tsx
const downloadResumable = FileSystem.createDownloadResumable(
  url,
  localPath,
  {},
  (downloadProgress) => {
    const progress = downloadProgress.totalBytesWritten /
      downloadProgress.totalBytesExpectedToWrite;
    setProgress(progress);
  }
);

await downloadResumable.downloadAsync();
```

## 8. 生物识别（Face ID / 指纹）

### 8.1 Expo 方案

```bash
npx expo install expo-local-authentication
```

```tsx
import * as LocalAuthentication from 'expo-local-authentication';

async function authenticate() {
  // 检查设备是否支持
  const hasHardware = await LocalAuthentication.hasHardwareAsync();
  if (!hasHardware) {
    Alert.alert('设备不支持生物识别');
    return false;
  }

  // 检查是否已录入生物信息
  const isEnrolled = await LocalAuthentication.isEnrolledAsync();
  if (!isEnrolled) {
    Alert.alert('未设置 Face ID / 指纹');
    return false;
  }

  // 发起认证
  const result = await LocalAuthentication.authenticateAsync({
    promptMessage: '验证身份',
    cancelLabel: '取消',
    disableDeviceFallback: false,  // 允许降级到密码
  });

  return result.success;
}

// 使用
const success = await authenticate();
if (success) {
  // 解锁敏感操作
  navigation.navigate('SecretScreen');
}
```

## 9. Native Module：桥接原生代码

当社区库无法满足需求时，可以自己编写原生模块桥接 iOS/Android 代码。

### 9.1 何时需要 Native Module

| 场景 | 说明 |
|------|------|
| 特殊硬件 SDK | 指南针校准、无人机控制、医疗设备 |
| 平台专属功能 | Android 通知渠道管理、iOS Widget |
| 性能关键路径 | 图像处理、音视频编解码 |
| 已有原生 SDK | 集成第三方原生 SDK（如支付、地图） |

### 9.2 TurboModule（新架构）

新架构的原生模块通过 **Codegen** 编写：JS 端先声明类型规范（Spec），构建时 Codegen 自动生成双端的接口（Android 抽象类 / iOS 协议），原生端实现接口即可。完整流程分 5 步。

**① 配置 Codegen（package.json）**

```json
// package.json
{
  "codegenConfig": {
    "name": "AppNativeModules",
    "type": "modules",
    "jsSrcsDir": "src/native-modules",
    "android": {
      "javaPackageName": "com.myapp.nativemodules"
    }
  }
}
```

**② JS 类型规范（文件按约定命名为 `Native<ModuleName>.ts`）**

```typescript
// src/native-modules/NativeDeviceSpec.ts
import { TurboModuleRegistry, type TurboModule } from 'react-native';

export interface Spec extends TurboModule {
  getDeviceName(): Promise<string>;
  getBatteryLevel(): Promise<number>;
}

// 注册名必须与原生端的模块名一致（见下文）
export default TurboModuleRegistry.getEnforcing<Spec>('DeviceSpec');
```

**③ Android 实现（继承 Codegen 生成的抽象类）**

Codegen 在构建时会生成抽象类 `NativeDeviceSpecSpec`（规范文件名 + `Spec` 后缀）：

```kotlin
// android/app/src/main/java/com/myapp/DeviceSpecModule.kt
package com.myapp

import android.content.Context
import android.os.BatteryManager
import android.os.Build
import com.facebook.react.bridge.Promise
import com.facebook.react.bridge.ReactApplicationContext
// Codegen 生成的抽象类（包名对应 codegenConfig.android.javaPackageName）
import com.myapp.nativemodules.NativeDeviceSpecSpec

class DeviceSpecModule(reactContext: ReactApplicationContext) :
    NativeDeviceSpecSpec(reactContext) {

    override fun getName() = "DeviceSpec"

    override fun getDeviceName(promise: Promise) {
        promise.resolve(Build.MODEL)
    }

    override fun getBatteryLevel(promise: Promise) {
        val bm = reactApplicationContext
            .getSystemService(Context.BATTERY_SERVICE) as BatteryManager
        promise.resolve(bm.getIntProperty(BatteryManager.BATTERY_PROPERTY_CAPACITY).toDouble())
    }
}
```

**④ Android 注册（TurboReactPackage + MainApplication）**

```kotlin
// android/app/src/main/java/com/myapp/DeviceSpecPackage.kt
package com.myapp

import com.facebook.react.TurboReactPackage
import com.facebook.react.bridge.NativeModule
import com.facebook.react.bridge.ReactApplicationContext
import com.facebook.react.module.model.ReactModuleInfo
import com.facebook.react.module.model.ReactModuleInfoProvider

class DeviceSpecPackage : TurboReactPackage {

    override fun getModule(name: String, reactContext: ReactApplicationContext): NativeModule? =
        if (name == "DeviceSpec") DeviceSpecModule(reactContext) else null

    override fun getReactModuleInfoProvider(): ReactModuleInfoProvider =
        ReactModuleInfoProvider {
            mapOf("DeviceSpec" to ReactModuleInfo(
                "DeviceSpec",  // name
                "DeviceSpec",  // className
                false,         // canOverrideExistingModule
                false,         // needsEagerInit
                false,         // isCxxModule
                true           // isTurboModule
            ))
        }
}
```

```kotlin
// MainApplication.kt：在 getPackages() 中注册
override fun getPackages(): List<ReactPackage> =
    PackageList(this).packages.apply {
        add(DeviceSpecPackage())
    }
```

**⑤ iOS 实现（ObjC++，实现 Codegen 生成的协议）**

```objc
// ios/DeviceSpecModule.mm
#import <React/RCTBridgeModule.h>
#import <UIKit/UIKit.h>
// Codegen 生成的头文件（名字对应 codegenConfig.name）
#import <AppNativeModules/AppNativeModules.h>

@interface DeviceSpecModule : NSObject <NativeDeviceSpecSpec>
@end

@implementation DeviceSpecModule

// 注册名必须与 TurboModuleRegistry.getEnforcing('DeviceSpec') 一致
RCT_EXPORT_MODULE(DeviceSpec)

- (void)getDeviceName:(RCTPromiseResolveBlock)resolve
               reject:(RCTPromiseRejectBlock)reject {
  resolve(UIDevice.currentDevice.name);
}

- (void)getBatteryLevel:(RCTPromiseResolveBlock)resolve
                 reject:(RCTPromiseRejectBlock)reject {
  UIDevice.currentDevice.batteryMonitoringEnabled = YES;
  resolve(@(UIDevice.currentDevice.batteryLevel * 100));
}

@end
```

**JS 端使用**

```typescript
import DeviceSpec from '../native-modules/NativeDeviceSpec';

const name = await DeviceSpec.getDeviceName();
const battery = await DeviceSpec.getBatteryLevel();
```

> 💡 要点：Codegen 在构建时自动运行（Android 在 gradle 构建时、iOS 在 `pod install` 时），无需手动生成代码。注意三处命名必须一致——规范文件名 `NativeDeviceSpec.ts`、JS 注册名 `'DeviceSpec'`、原生的 `getName()` / `RCT_EXPORT_MODULE` 名。

### 9.3 Expo Config Plugin

```javascript
// plugins/withCustomConfig.js
const { withAppDelegate } = require('expo/config-plugins');

module.exports = function withCustomConfig(config) {

    config.modResults.contents = config.modResults.contents.replace(
      'didFinishLaunchingWithOptions',
      '// Custom init code here\ndidFinishLaunchingWithOptions'
    );
    return config;
  });
};
```

## 📝 面试回答模板

> **问：RN 怎么调用设备能力（相机/定位等）？**
>
> 两种主要方式。Expo 项目用 Expo SDK 内置的库，比如 expo-camera、expo-location，这些库封装了权限请求和原生 API 调用，用法简洁且自动处理跨端差异。Bare Workflow 项目用社区库，比如 react-native-image-picker、react-native-geolocation。当社区库无法满足需求时，可以写 Native Module 桥接原生代码——通过 TurboModule（新架构）或 Bridge Module（旧架构）暴露原生方法给 JS 调用。

> **问：RN 中怎么做权限管理？**
>
> iOS 和 Android 的权限模型不同。iOS 在首次使用时弹窗请求，用户拒绝后只能去设置手动开启。Android 在运行时请求，如果用户勾选了"不再询问"，后续请求会直接拒绝。代码层面，Bare Workflow 用 react-native-permissions 库统一处理，它提供了 check、request 和 RESULTS 三种 API。Expo 的库内置了权限管理，比如 expo-camera 的 useCameraPermissions Hook。关键是要处理 BLOCKED 状态——当权限被永久拒绝时，引导用户跳转到系统设置页面手动开启。

> **问：什么时候需要写 Native Module？**
>
> 当现有社区库无法满足需求时。常见的场景有：集成特殊的硬件 SDK（如医疗设备、无人机）、使用平台专属功能（如 Android 通知渠道、iOS Widget）、性能关键路径（如实时图像处理），或者需要桥接已有的原生第三方 SDK。新架构下用 TurboModule 实现，JS 端通过 TurboModuleRegistry 调用，性能比旧 Bridge 好很多。Expo 项目可以通过 Config Plugin 扩展原生能力而不需要 eject。
