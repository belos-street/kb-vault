# 07 — 状态管理与本地存储

> 对应大纲：应用层 | 预计时间：2 天（含练习）
> 面试可答：RN 的状态管理跟 Web React 完全一样——useState/useContext 管组件状态，Zustand 或 Redux Toolkit 管全局状态。本地存储推荐 MMKV（同步 KV，性能是 AsyncStorage 的 30 倍），敏感信息用 expo-secure-store。核心区分：服务端状态用 React Query，客户端状态用 Zustand。

---

## 1. 状态分类：服务端状态 vs 客户端状态

在选择状态管理方案之前，先区分两种状态：

| 类型 | 定义 | 例子 | 管理方案 |
|------|------|------|---------|
| **服务端状态** | 从 API 获取的数据 | 用户列表、文章详情、订单 | React Query |
| **客户端状态** | 纯前端的状态 | 主题色、登录态、表单草稿、UI 开关 | useState / Zustand / Redux |

> **关键判断标准**：这个状态的"源头"在哪里？如果源头在服务端（API），用 React Query。如果源头在客户端（用户操作、本地配置），用状态管理库。

很多新手把所有状态都塞进 Redux，导致服务端数据在 Redux 和缓存中各存一份，维护成本很高。2026 年的最佳实践是：**React Query 管服务端状态，Zustand 管客户端状态**。

## 2. 组件内状态：useState / useReducer

### 2.1 useState

最基础的状态管理，跟 Web React 完全一样：

```tsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <Pressable onPress={() => setCount((c) => c + 1)}>
      <Text>点击了 {count} 次</Text>
    </Pressable>
  );
}
```

### 2.2 useReducer

复杂状态逻辑时用 `useReducer`：

```tsx
import { useReducer } from 'react';

type State = { items: string[]; loading: boolean; error: string | null };
type Action =
  | { type: 'LOAD' }
  | { type: 'SUCCESS'; payload: string[] }
  | { type: 'ERROR'; payload: string };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'LOAD':
      return { ...state, loading: true, error: null };
    case 'SUCCESS':
      return { items: action.payload, loading: false, error: null };
    case 'ERROR':
      return { ...state, loading: false, error: action.payload };
  }
}

function TodoList() {
  const [state, dispatch] = useReducer(reducer, {
    items: [],
    loading: false,
    error: null,
  });
  // ...
}
```

**何时用 useReducer**：状态逻辑涉及多个子值、下一个状态依赖前一个状态、状态转换逻辑复杂时。

## 3. 跨组件状态：Context

### 3.1 基本用法

```tsx
import { createContext, useContext, useState } from 'react';

// 创建 Context
const ThemeContext = createContext({
  theme: 'light',
  toggleTheme: () => {},
});

// Provider
function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');
  const toggleTheme = () => setTheme((t) => (t === 'light' ? 'dark' : 'light'));

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

// 使用
function Header() {
  const { theme, toggleTheme } = useContext(ThemeContext);
  return (
    <View style={{ backgroundColor: theme === 'light' ? '#fff' : '#333' }}>
      <Pressable onPress={toggleTheme}>
        <Text>切换主题</Text>
      </Pressable>
    </View>
  );
}

// 入口
<ThemeProvider>
  <App />
</ThemeProvider>
```

### 3.2 Context 的性能问题

Context 的问题是：**任何一个值变化，所有消费者都会重渲染**。

```tsx
// ❌ 问题：user 和 theme 放在同一个 Context
// 任何一方变化，所有消费者都重渲染
const AppContext = createContext({ user: null, theme: 'light', locale: 'zh' });

// ✅ 拆分：按关注点分离
const UserContext = createContext(null);
const ThemeContext = createContext('light');
const LocaleContext = createContext('zh');
```

### 3.3 Context 适用场景

| 场景 | 适合用 Context |
|------|---------------|
| 主题切换 | 变化频率低，消费者多 |
| 语言切换 | 同上 |
| 当前登录用户 | 登录/登出时切换 |
| 路由（React Navigation 已内置） | 不需要自己实现 |

| 场景 | 不适合用 Context |
|------|----------------|
| 频繁变化的状态（如输入框文字） | 会导致大量重渲染 |
| 深层嵌套的更新 | 需要逐层传递 |
| 复杂的状态逻辑 | useReducer 嵌套 Context 会很臃肿 |

## 4. Zustand：推荐的全局状态方案

Zustand 是 2026 年 RN 社区最流行的客户端状态管理库，API 极简，性能优秀。

### 4.1 安装

```bash
npm install zustand
```

### 4.2 创建 Store

```tsx
// stores/useAuthStore.ts
import { create } from 'zustand';

interface AuthState {
  user: { id: string; name: string; avatar: string } | null;
  token: string | null;
  isLoggedIn: boolean;
  login: (user: AuthState['user'], token: string) => void;
  logout: () => void;
}

export const useAuthStore = create<AuthState>((set) => ({
  user: null,
  token: null,
  isLoggedIn: false,
  login: (user, token) => set({ user, token, isLoggedIn: true }),
  logout: () => set({ user: null, token: null, isLoggedIn: false }),
}));
```

### 4.3 使用

```tsx
import { useAuthStore } from '../stores/useAuthStore';

function ProfileScreen() {
  // 选择性订阅（只有 user 变化时才重渲染）
  const user = useAuthStore((s) => s.user);
  const logout = useAuthStore((s) => s.logout);

  if (!user) return <Text>未登录</Text>;

  return (
    <View>
      <Text>{user.name}</Text>
      <Pressable onPress={logout}>
        <Text>退出登录</Text>
      </Pressable>
    </View>
  );
}
```

### 4.4 Zustand 的核心优势

| 特性 | 说明 |
|------|------|
| 极简 API | 不需要 Provider、不需要 Reducer、不需要 Action Type |
| 选择性订阅 | `useStore(s => s.count)` 只在 count 变化时重渲染 |
| 可以在组件外使用 | `useAuthStore.getState()` 不需要 Hook 上下文 |
| 中间件 | persist（持久化）、devtools（调试）、immer（不可变更新） |
| TypeScript 友好 | 类型推导自然 |

### 4.5 多个 Store

```tsx
// stores/useCartStore.ts
import { create } from 'zustand';

interface CartItem {
  id: string;
  name: string;
  price: number;
  quantity: number;
}

interface CartState {
  items: CartItem[];
  addItem: (item: Omit<CartItem, 'quantity'>) => void;
  removeItem: (id: string) => void;
  updateQuantity: (id: string, quantity: number) => void;
  clearCart: () => void;
  total: () => number;
}

export const useCartStore = create<CartState>((set, get) => ({
  items: [],
  addItem: (item) =>
    set((state) => {
      const existing = state.items.find((i) => i.id === item.id);
      if (existing) {
        return {
          items: state.items.map((i) =>
            i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i
          ),
        };
      }
      return { items: [...state.items, { ...item, quantity: 1 }] };
    }),
  removeItem: (id) =>
    set((state) => ({ items: state.items.filter((i) => i.id !== id) })),
  updateQuantity: (id, quantity) =>
    set((state) => ({
      items: state.items.map((i) => (i.id === id ? { ...i, quantity } : i)),
    })),
  clearCart: () => set({ items: [] }),
  total: () =>
    get().items.reduce((sum, item) => sum + item.price * item.quantity, 0),
}));
```

### 4.6 Zustand 持久化

```tsx
// stores/useAuthStore.ts
import { create } from 'zustand';
import { persist, createJSONStorage } from 'zustand/middleware';
import AsyncStorage from '@react-native-async-storage/async-storage';

export const useAuthStore = create(
  persist(
    (set) => ({
      user: null,
      token: null,
      isLoggedIn: false,
      login: (user, token) => set({ user, token, isLoggedIn: true }),
      logout: () => set({ user: null, token: null, isLoggedIn: false }),
    }),
    {
      name: 'auth-storage',         // 存储的 key
      storage: createJSONStorage(() => AsyncStorage),
    }
  )
);
```

> 推荐用 MMKV 替代 AsyncStorage 做 Zustand 持久化（见下文第 6 节），性能差距 30 倍。

## 5. Redux Toolkit（备选方案）

如果团队已有 Redux 经验或项目规模很大，Redux Toolkit 仍然是可靠的选择。

### 5.1 安装

```bash
npm install @reduxjs/toolkit react-redux
```

### 5.2 创建 Slice

```tsx
// stores/counterSlice.ts
import { createSlice, PayloadAction } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: (state) => { state.value += 1; },  // Immer 允许直接修改
    decrement: (state) => { state.value -= 1; },
    addBy: (state, action: PayloadAction<number>) => { state.value += action.payload; },
  },
});

export const { increment, decrement, addBy } = counterSlice.actions;
export default counterSlice.reducer;
```

### 5.3 配置 Store

```tsx
// stores/store.ts
import { configureStore } from '@reduxjs/toolkit';
import counterReducer from './counterSlice';

export const store = configureStore({
  reducer: {
    counter: counterReducer,
  },
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

### 5.4 使用

```tsx
// App.tsx
import { Provider } from 'react-redux';
import { store } from './stores/store';

<Provider store={store}>
  <App />
</Provider>

// 组件中
import { useSelector, useDispatch } from 'react-redux';
import { increment } from './stores/counterSlice';

function Counter() {
  const count = useSelector((state: RootState) => state.counter.value);
  const dispatch = useDispatch();
  return (
    <Pressable onPress={() => dispatch(increment())}>
      <Text>{count}</Text>
    </Pressable>
  );
}
```

### 5.5 Zustand vs Redux Toolkit

| 维度 | Zustand | Redux Toolkit |
|------|---------|--------------|
| API 复杂度 | 极简（无 Provider/Reducer/Action） | 较多概念 |
| 包体积 | ~1KB | ~11KB |
| TypeScript | 自然推导 | 需要手动定义 RootState |
| 组件外使用 | 直接 `getState()` | 需要 `store.getState()` |
| 中间件生态 | persist/devtools/immer | 完整（RTK Query 集成） |
| 适用规模 | 中小项目 | 大团队/大型项目 |
| 学习曲线 | 极低 | 中等 |

**建议**：新项目首选 Zustand，已有 Redux 生态的团队继续用 Redux Toolkit。

## 6. 本地存储

### 6.1 方案对比

| 方案 | 性能 | API | 容量 | 安全性 | 推荐度 |
|------|------|-----|------|--------|--------|
| **MMKV** | 极快（同步读写） | `set/get` | ~无限制 | 不加密 | ⭐⭐⭐⭐⭐ |
| **AsyncStorage** | 慢（异步） | `await setItem` | ~6MB | 不加密 | ⭐⭐⭐ |
| **SQLite** | 快 | SQL 查询 | ~无限制 | 不加密 | ⭐⭐⭐⭐ |
| **expo-secure-store** | 中等 | `setItemAsync` | 小（~2KB/条） | 加密（Keychain/Keystore） | ⭐⭐⭐⭐ |

**选型建议**：
- 通用 KV 存储 → **MMKV**
- Token / 密码 / 敏感信息 → **expo-secure-store** 或 **react-native-keychain**
- 结构化数据 / 复杂查询 → **SQLite**

### 6.2 MMKV

```bash
npm install react-native-mmkv
```

```tsx
import { MMKV } from 'react-native-mmkv';

const storage = new MMKV();

// 写入（同步）
storage.set('user.name', 'Alice');
storage.set('user.age', 28);
storage.set('user.tags', JSON.stringify(['admin', 'editor']));

// 读取（同步，无需 await）
const name = storage.getString('user.name');   // 'Alice'
const age = storage.getNumber('user.age');     // 28
const tags = JSON.parse(storage.getString('user.tags') ?? '[]');

// 删除
storage.delete('user.name');

// 检查是否存在
storage.contains('user.name');

// 获取所有 key
const keys = storage.getAllKeys();

// 清空全部
storage.clearAll();
```

> 「比 AsyncStorage 快 ~30 倍」是 [react-native-mmkv 官方 README](https://github.com/mrousavy/react-native-mmkv) 给出的基准测试口径（特定测试机型的读写对比），面试引用时建议标注出处；实际收益在高频小读写场景最明显。

### 6.3 Zustand + MMKV 持久化

```bash
npm install zustand react-native-mmkv
```

```tsx
// stores/storage.ts
import { MMKV } from 'react-native-mmkv';
import { StateStorage } from 'zustand/middleware';

export const mmkvStorage = new MMKV();

export const zustandMMKVStorage: StateStorage = {
  setItem: (name, value) => mmkvStorage.set(name, value),
  getItem: (name) => mmkvStorage.getString(name) ?? null,
  removeItem: (name) => mmkvStorage.delete(name),
};

// stores/useAuthStore.ts
import { create } from 'zustand';
import { persist, createJSONStorage } from 'zustand/middleware';
import { zustandMMKVStorage } from './storage';

export const useAuthStore = create(
  persist(
    (set) => ({
      user: null,
      token: null,
      login: (user, token) => set({ user, token }),
      logout: () => set({ user: null, token: null }),
    }),
    {
      name: 'auth',
      storage: createJSONStorage(() => zustandMMKVStorage),
    }
  )
);
```

### 6.4 敏感信息存储

Token、密码等敏感信息**不要用 MMKV 或 AsyncStorage**，它们是明文存储。用系统级加密存储：

```tsx
// Expo 项目
import * as SecureStore from 'expo-secure-store';

// 写入（加密）
await SecureStore.setItemAsync('auth_token', 'eyJhbGciOi...');

// 读取
const token = await SecureStore.getItemAsync('auth_token');

// 删除
await SecureStore.deleteItemAsync('auth_token');
```

```tsx
// Bare Workflow 项目
import * as Keychain from 'react-native-keychain';

// 存储
await Keychain.setGenericPassword('user', 'token_value');

// 读取
const credentials = await Keychain.getGenericPassword();
if (credentials) {
  console.log(credentials.password); // token
}

// 删除
await Keychain.resetGenericPassword();
```

## 7. AsyncStorage（了解）

AsyncStorage 是 RN 社区维护的异步 KV 存储，虽然性能不如 MMKV，但在老项目中广泛使用。

```bash
npm install @react-native-async-storage/async-storage
```

```tsx
import AsyncStorage from '@react-native-async-storage/async-storage';

// 存储
await AsyncStorage.setItem('key', 'value');
await AsyncStorage.setItem('user', JSON.stringify({ name: 'Alice' }));

// 读取
const value = await AsyncStorage.getItem('key');
const user = JSON.parse(await AsyncStorage.getItem('user') ?? '{}');

// 批量操作
await AsyncStorage.multiSet([['key1', 'v1'], ['key2', 'v2']]);
const values = await AsyncStorage.multiGet(['key1', 'key2']);

// 删除
await AsyncStorage.removeItem('key');

// 清空全部
await AsyncStorage.clear();
```

> **容量限制**：Android 上默认总容量上限 6MB，单条数据 ≤ 2MB（官方 Known limits）。
>
> **版本注意**：AsyncStorage v3 对批量 API 做了 breaking change（如 `multiGet` → `getMany`），升级时留意迁移指南；默认导出的单例 API 仍然可用。

> **迁移建议**：新项目直接用 MMKV，老项目可以逐步替换。MMKV 的同步 API 比 AsyncStorage 的异步 API 更易用，官方基准测试快 ~30 倍。

## 8. 表单状态管理

### 8.1 React Hook Form

```bash
npm install react-hook-form @hookform/resolvers zod
```

```tsx
import { useForm, Controller } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';
import { TextInput, View, Text, Pressable, Alert } from 'react-native';

const schema = z.object({
  email: z.string().email('请输入有效的邮箱'),
  password: z.string().min(8, '密码至少 8 位'),
});

type FormData = z.infer<typeof schema>;

function LoginForm() {
  const { control, handleSubmit, formState: { errors } } = useForm<FormData>({
    resolver: zodResolver(schema),
    defaultValues: { email: '', password: '' },
  });

  const onSubmit = (data: FormData) => {
    Alert.alert('登录', JSON.stringify(data));
  };

  return (
    <View style={{ padding: 16 }}>
      <Controller
        control={control}
        name="email"
        render={({ field: { onChange, onBlur, value } }) => (
          <TextInput
            placeholder="邮箱"
            value={value}
            onChangeText={onChange}
            onBlur={onBlur}
            keyboardType="email-address"
            autoCapitalize="none"
            style={{ borderWidth: 1, borderColor: errors.email ? 'red' : '#ddd', padding: 12, marginBottom: 4, borderRadius: 8 }}
          />
        )}
      />
      {errors.email && <Text style={{ color: 'red', marginBottom: 8 }}>{errors.email.message}</Text>}

      <Controller
        control={control}
        name="password"
        render={({ field: { onChange, onBlur, value } }) => (
          <TextInput
            placeholder="密码"
            value={value}
            onChangeText={onChange}
            onBlur={onBlur}
            secureTextEntry
            style={{ borderWidth: 1, borderColor: errors.password ? 'red' : '#ddd', padding: 12, marginBottom: 4, borderRadius: 8 }}
          />
        )}
      />
      {errors.password && <Text style={{ color: 'red', marginBottom: 8 }}>{errors.password.message}</Text>}

      <Pressable
        onPress={handleSubmit(onSubmit)}
        style={{ backgroundColor: '#007AFF', padding: 14, borderRadius: 8, alignItems: 'center' }}
      >
        <Text style={{ color: '#fff', fontWeight: 'bold' }}>登录</Text>
      </Pressable>
    </View>
  );
}
```

### 8.2 表单状态放在哪里

| 场景 | 状态管理 |
|------|---------|
| 单个表单组件内部 | `useState` 或 `useForm` |
| 表单需要跨组件共享 | Zustand store |
| 表单草稿需要持久化 | Zustand + persist |

## 9. 状态管理决策树

```
这个状态的源头在哪里？
├── 服务端（API 数据）→ React Query
│   ├── 列表/详情 → useQuery
│   ├── 创建/更新/删除 → useMutation
│   └── 分页 → useInfiniteQuery
│
└── 客户端（用户操作/本地配置）
    ├── 只在单个组件内 → useState / useReducer
    ├── 跨组件但变化少（主题/语言）→ Context
    ├── 跨组件且频繁变化 → Zustand
    │   ├── 需要持久化 → Zustand + persist（MMKV）
    │   └── 需要加密 → Zustand + SecureStore
    └── 大团队/大型项目 → Redux Toolkit
```

### 练习 1：主题切换

用 Context 实现全局主题切换：
- 支持 light / dark 两种主题
- 主题色存储在 AsyncStorage 中（下次打开 App 恢复）

### 练习 2：购物车

用 Zustand 实现购物车状态：
- 添加商品（如果已存在则数量 +1）
- 移除商品
- 修改数量
- 清空购物车
- 计算总价（用 Zustand 的 `get` 实现）
- 购物车数据持久化到 MMKV

### 练习 3：登录态管理

结合 React Query + Zustand + SecureStore：
- 登录后将 token 存入 SecureStore
- 用户信息存在 Zustand（持久化到 MMKV）
- Axios 拦截器从 Zustand 获取 token 注入请求
- 登出时清除 SecureStore + Zustand

## 📝 面试回答模板

> **问：RN 中怎么做状态管理？有什么推荐的方案？**
>
> 核心原则是区分"服务端状态"和"客户端状态"。服务端状态（从 API 获取的数据）用 React Query，它提供缓存、重试、分页、后台刷新等能力。客户端状态（用户操作、本地配置）用 Zustand，它 API 极简、性能好、支持选择性订阅和持久化。这个组合比 Redux 简洁很多，因为 React Query 解决了 Redux 中最复杂的异步数据流部分。

> **问：Zustand 和 Redux 怎么选？**
>
> Zustand 的优势是极简——没有 Provider、没有 Reducer、没有 Action Type，一个 create 函数搞定一个 store。它的包体积只有 1KB，支持选择性订阅（只在用到的状态变化时重渲染），可以在组件外直接调用 getState()。Redux Toolkit 的优势是生态完整（RTK Query 集成数据获取）、大团队协作规范性强。新项目推荐 Zustand，已有 Redux 的大项目继续用 Redux Toolkit。

> **问：RN 的本地存储方案有哪些？怎么选？**
>
> 常见的有四种。MMKV 是微信开源的高性能 KV 存储，同步读写，性能是 AsyncStorage 的 30 倍以上，适合通用配置和缓存。AsyncStorage 是异步的，API 简单但性能差，老项目还在用。SQLite 适合结构化数据和复杂查询。SecureStore（expo-secure-store）是加密存储，适合存 token 和密码等敏感信息。我的推荐是：通用存储用 MMKV，敏感信息用 SecureStore，结构化数据用 SQLite。
