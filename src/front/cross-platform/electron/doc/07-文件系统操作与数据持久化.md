# 07 — 文件系统操作与数据持久化

> 对应大纲：应用层 | 预计时间：1 天
> 面试可答：Electron 中文件操作只能在主进程进行——渲染进程通过 IPC 发起请求，主进程使用 Node.js 的 `fs` 模块读写文件。`app.getPath` 提供了系统标准路径（userData、documents、desktop 等）。数据持久化方案有三种：`electron-store`（简单 KV 存储，适合配置和偏好设置）、`better-sqlite3`（结构化数据查询）、直接文件存储。拖放文件通过 DOM 的 drag & drop 事件实现，文件路径通过 IPC 传给主进程处理。日志系统推荐 `electron-log`。

## 1. 文件操作：安全第一

### 1.1 为什么文件操作必须在主进程中？

```mermaid
graph LR
    subgraph renderer["渲染进程（Web 页面）"]
        R1["沙箱环境"]
        R2["不能访问 fs 模块"]
        R3["用户输入可能被篡改"]
    end

    subgraph main["主进程（Node.js）"]
        M1["完整 Node.js"]
        M2["fs.readFile()"]
        M3["路径校验"]
        M4["文件读写"]
    end

    renderer -- IPC --> main
```

如果渲染进程能直接读写文件，XSS 漏洞就可能导致：
- 读取用户的 SSH 密钥、浏览器 Cookie、密码文件
- 篡改系统配置文件
- 植入恶意脚本到开机启动项

### 1.2 安全的文件操作模式

**主进程：注册安全的 IPC handler**

```typescript
import { ipcMain, app } from 'electron';
import fs from 'node:fs/promises';
import path from 'node:path';

// 路径白名单：只允许访问这些目录
const ALLOWED_DIRS = [
  app.getPath('documents'),
  app.getPath('desktop'),
  app.getPath('userData'),
];

function isPathAllowed(filePath: string): boolean {
  const resolved = path.resolve(filePath);
  // ⚠️ 必须加路径分隔符判断，仅 startsWith(dir) 有前缀绕过风险：
  // 如 /Users/x/DocumentsEvil/a.txt 能通过 /Users/x/Documents 的前缀检查
  return ALLOWED_DIRS.some(
    (dir) => resolved === dir || resolved.startsWith(dir + path.sep)
  );
}

ipcMain.handle('file:read', async (_event, filePath: string) => {
  if (!isPathAllowed(filePath)) {
    throw new Error(`访问被拒绝: 路径不在允许范围内`);
  }
  return await fs.readFile(filePath, 'utf-8');
});

ipcMain.handle('file:save', async (_event, filePath: string, content: string) => {
  if (!isPathAllowed(filePath)) {
    throw new Error(`访问被拒绝: 路径不在允许范围内`);
  }
  await fs.writeFile(filePath, content, 'utf-8');
});

ipcMain.handle('file:exists', async (_event, filePath: string) => {
  if (!isPathAllowed(filePath)) return false;
  try {
    await fs.access(filePath);
    return true;
  } catch {
    return false;
  }
});

ipcMain.handle('file:list', async (_event, dirPath: string) => {
  if (!isPathAllowed(dirPath)) {
    throw new Error(`访问被拒绝: 路径不在允许范围内`);
  }
  const entries = await fs.readdir(dirPath, { withFileTypes: true });
  return entries.map((entry) => ({
    name: entry.name,
    isDirectory: entry.isDirectory(),
    isFile: entry.isFile(),
  }));
});
```

## 2. app.getPath 系统标准路径

### 2.1 常用路径

```typescript
import { app } from 'electron';

// 用户数据目录（应用专属，自动按应用名隔离）
app.getPath('userData');
// macOS: ~/Library/Application Support/YourApp
// Windows: C:\Users\{user}\AppData\Roaming\YourApp
// Linux: ~/.config/YourApp

// 用户文档目录
app.getPath('documents');
// macOS: ~/Documents
// Windows: C:\Users\{user}\Documents

// 用户桌面
app.getPath('desktop');
// macOS: ~/Desktop
// Windows: C:\Users\{user}\Desktop

// 用户下载目录
app.getPath('downloads');

// 临时目录
app.getPath('temp');

// 应用日志目录
app.getPath('logs');
// macOS: ~/Library/Logs/YourApp
// Windows: C:\Users\{user}\AppData\Roaming\YourApp\logs

// 应用可执行文件路径
app.getPath('exe');

// 当前应用资源目录（打包后的资源文件位置）
app.getPath('resources');
```

### 2.2 完整路径表

| 路径名 | macOS | Windows | Linux |
|--------|-------|---------|-------|
| `userData` | `~/Library/Application Support/{app}` | `%APPDATA%\{app}` | `~/.config/{app}` |
| `documents` | `~/Documents` | `C:\Users\{user}\Documents` | `~/Documents` |
| `desktop` | `~/Desktop` | `C:\Users\{user}\Desktop` | `~/Desktop` |
| `downloads` | `~/Downloads` | `C:\Users\{user}\Downloads` | `~/Downloads` |
| `temp` | `/tmp` | `%TEMP%` | `/tmp` |
| `logs` | `~/Library/Logs/{app}` | `%APPDATA%\{app}\logs` | `~/.config/{app}/logs` |
| `appData` | `~/Library/Application Support` | `%APPDATA%` | `~/.config` |
| `home` | `~` | `C:\Users\{user}` | `~` |

> **最佳实践**：应用的配置文件和数据库放在 `userData` 目录下。用户创建的文档保存到 `documents` 目录。日志写入 `logs` 目录。不要把应用数据写入应用安装目录（在 macOS 上是只读的 .app 包）。

## 3. electron-store：简单 KV 存储

### 3.1 安装

```bash
npm install electron-store
```

### 3.2 基本使用

```typescript
// 主进程中
import Store from 'electron-store';

interface StoreSchema {
  window: {
    width: number;
    height: number;
    x?: number;
    y?: number;
    isMaximized: boolean;
  };
  editor: {
    fontSize: number;
    fontFamily: string;
    theme: 'light' | 'dark' | 'system';
    tabSize: number;
    wordWrap: boolean;
  };
  recentFiles: string[];
}

const store = new Store<StoreSchema>({
  defaults: {
    window: { width: 1024, height: 768, isMaximized: false },
    editor: {
      fontSize: 14,
      fontFamily: 'monospace',
      theme: 'system',
      tabSize: 2,
      wordWrap: true,
    },
    recentFiles: [],
  },
});

// 读取
const fontSize = store.get('editor.fontSize');  // 14
const theme = store.get('editor.theme');        // 'system'

// 写入
store.set('editor.fontSize', 16);
store.set('editor.theme', 'dark');

// 按路径写入嵌套属性
store.set('window.width', 1280);

// 删除
store.delete('recentFiles');

// 判断是否存在
if (store.has('editor.fontSize')) {
  // ...
}

// 获取全部配置
const all = store.store;

// 重置为默认值
store.clear();
```

### 3.3 通过 IPC 暴露给渲染进程

```typescript
// 主进程
ipcMain.handle('store:get', (_event, key: string) => {
  return store.get(key);
});

ipcMain.handle('store:set', (_event, key: string, value: unknown) => {
  store.set(key, value);
});

// preload
contextBridge.exposeInMainWorld('store', {
  get: (key: string) => ipcRenderer.invoke('store:get', key),
  set: (key: string, value: unknown) => ipcRenderer.invoke('store:set', key, value),
});
```

## 4. better-sqlite3：结构化数据存储

### 4.1 为什么用 SQLite？

| 场景 | 推荐方案 |
|------|---------|
| 应用配置、用户偏好 | `electron-store` |
| 简单的 KV 数据、最近文件列表 | `electron-store` |
| 大量结构化数据、需要查询 | `better-sqlite3` |
| 全文搜索 | `better-sqlite3`（支持 FTS5） |
| 复杂关系数据 | `better-sqlite3` |

### 4.2 基本使用

```typescript
import Database from 'better-sqlite3';
import path from 'node:path';
import { app } from 'electron';

const dbPath = path.join(app.getPath('userData'), 'notes.db');
const db = new Database(dbPath);

// 创建表
db.exec(`
  CREATE TABLE IF NOT EXISTS notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    content TEXT DEFAULT '',
    created_at TEXT DEFAULT (datetime('now')),
    updated_at TEXT DEFAULT (datetime('now'))
  )
`);

// 预编译 SQL（性能更好）
const insertNote = db.prepare('INSERT INTO notes (title, content) VALUES (?, ?)');
const getNotes = db.prepare('SELECT * FROM notes ORDER BY updated_at DESC');
const getNoteById = db.prepare('SELECT * FROM notes WHERE id = ?');
const updateNote = db.prepare('UPDATE notes SET title = ?, content = ?, updated_at = datetime(\'now\') WHERE id = ?');
const deleteNote = db.prepare('DELETE FROM notes WHERE id = ?');

// IPC handlers
ipcMain.handle('db:create-note', (_event, title: string, content: string) => {
  const result = insertNote.run(title, content);
  return { id: result.lastInsertRowid, title, content };
});

ipcMain.handle('db:get-notes', () => {
  return getNotes.all();
});

ipcMain.handle('db:get-note', (_event, id: number) => {
  return getNoteById.get(id);
});

ipcMain.handle('db:update-note', (_event, id: number, title: string, content: string) => {
  updateNote.run(title, content, id);
});

ipcMain.handle('db:delete-note', (_event, id: number) => {
  deleteNote.run(id);
});

// 应用退出时关闭数据库
app.on('before-quit', () => {
  db.close();
});
```

> **注意**：`better-sqlite3` 是原生模块，需要在打包时特别处理。第 11 篇（构建与打包）会详细讲原生模块的打包方案。

## 5. 拖放文件（Drag & Drop）

### 5.1 渲染进程中处理拖放

```typescript
// 渲染进程中
const dropZone = document.getElementById('drop-zone')!;

// 阻止默认行为（否则浏览器会直接打开文件）
dropZone.addEventListener('dragover', (e) => {
  e.preventDefault();
  e.stopPropagation();
  dropZone.classList.add('drag-over');
});

dropZone.addEventListener('dragleave', (e) => {
  e.preventDefault();
  e.stopPropagation();
  dropZone.classList.remove('drag-over');
});

dropZone.addEventListener('drop', async (e) => {
  e.preventDefault();
  e.stopPropagation();
  dropZone.classList.remove('drag-over');

  const files = Array.from(e.dataTransfer!.files);

  for (const file of files) {
    // 在沙箱模式下，file.path 可能为空。
    // webUtils 不能在渲染进程页面代码中直接 require，
    // 必须由 preload 通过 contextBridge 暴露（见下方 5.2 节）。
    const filePath = window.electronAPI.getPathForFile(file);
    console.log('拖入的文件路径:', filePath);

    // 通过 IPC 读取文件内容
    const content = await window.electronAPI.readFile(filePath);
    console.log('文件内容:', content);
  }
});
```

### 5.2 使用 webUtils 获取文件路径

在沙箱模式下，`File.path` 属性不可用。Electron 提供了 `webUtils.getPathForFile` 来获取文件的本地路径。`webUtils` 虽然是渲染进程模块，但在 context isolation 下不能在页面代码里直接访问，**必须放在 preload 中用 contextBridge 暴露**：

```typescript
// preload.ts
import { contextBridge, ipcRenderer, webUtils } from 'electron';

contextBridge.exposeInMainWorld('electronAPI', {
  getPathForFile: (file: File) => webUtils.getPathForFile(file),
  // ... 其它 API
});
```

然后渲染进程通过 `window.electronAPI.getPathForFile(file)` 调用（即 5.1 节的写法）。

> **安全提示**：`webUtils.getPathForFile` 只能获取拖放或 `<input type="file">` 选择的文件路径，JavaScript 不能直接读取本地文件路径。这是浏览器安全模型的一部分。

## 6. 日志系统：electron-log

### 6.1 安装

```bash
npm install electron-log
```

### 6.2 基本配置

```typescript
// src/main.ts
// electron-log v5：主进程使用 electron-log/main 入口
import log from 'electron-log/main';

// 初始化 renderer 端支持（注入 IPC 桥），必须在创建窗口前调用
log.initialize();

// 配置日志文件路径（默认在 app.getPath('logs') 目录下）
// macOS: ~/Library/Logs/{app}/main.log
// Windows: %APPDATA%\{app}\logs\main.log

// 设置日志级别
log.transports.file.level = 'info';  // debug / info / warn / error
log.transports.console.level = 'debug';

// 使用
log.info('应用启动');
log.warn('配置文件缺失，使用默认值');
log.error('数据库连接失败:', error);
log.debug('调试信息:', { key: 'value' });
```

### 6.3 在渲染进程 / preload 中使用

electron-log v5 架构：renderer 端不直接写文件，日志通过 IPC 发送到主进程统一落盘（写入同一个 `main.log`）。preload / 渲染进程中必须使用 `electron-log/renderer` 入口：

```typescript
// preload.ts
import log from 'electron-log/renderer';

log.info('preload 脚本加载完成');
```

```typescript
// 渲染进程代码（需打包器支持）
import log from 'electron-log/renderer';
log.info('页面加载完成');
```

### 6.4 错误捕获

```typescript
// 主进程：捕获未处理的异常和 Promise rejection
process.on('uncaughtException', (error) => {
  log.error('未捕获的异常:', error);
});

process.on('unhandledRejection', (reason) => {
  log.error('未处理的 Promise rejection:', reason);
});

// 渲染进程：通过 preload 转发
// preload.ts
window.addEventListener('error', (event) => {
  ipcRenderer.send('renderer-error', {
    message: event.message,
    filename: event.filename,
    lineno: event.lineno,
    colno: event.colno,
  });
});

window.addEventListener('unhandledrejection', (event) => {
  ipcRenderer.send('renderer-error', {
    message: event.reason?.message ?? String(event.reason),
  });
});

// 主进程：接收渲染进程的错误
ipcMain.on('renderer-error', (_event, errorInfo) => {
  log.error('渲染进程错误:', errorInfo);
});
```

### 6.5 日志文件轮转

`electron-log` 默认支持日志文件轮转，通过 `maxSize` 控制单个日志文件大小（超出后自动归档）：

```typescript
log.transports.file.maxSize = 10 * 1024 * 1024; // 单个文件最大 10MB
```

## 7. 常见文件操作模式汇总

### 7.1 读取 JSON 配置文件

```typescript
ipcMain.handle('config:read', async (_event, fileName: string) => {
  const configPath = path.join(app.getPath('userData'), fileName);
  try {
    const content = await fs.readFile(configPath, 'utf-8');
    return JSON.parse(content);
  } catch {
    return null; // 文件不存在
  }
});
```

### 7.2 保存 JSON 配置文件

```typescript
ipcMain.handle('config:save', async (_event, fileName: string, data: unknown) => {
  const configPath = path.join(app.getPath('userData'), fileName);
  await fs.writeFile(configPath, JSON.stringify(data, null, 2), 'utf-8');
});
```

### 7.3 复制文件

```typescript
ipcMain.handle('file:copy', async (_event, src: string, dest: string) => {
  await fs.copyFile(src, dest);
});
```

### 7.4 创建目录

```typescript
ipcMain.handle('dir:create', async (_event, dirPath: string) => {
  await fs.mkdir(dirPath, { recursive: true });
});
```

### 7.5 获取文件信息

```typescript
ipcMain.handle('file:stat', async (_event, filePath: string) => {
  const stat = await fs.stat(filePath);
  return {
    size: stat.size,
    createdAt: stat.birthtime.toISOString(),
    modifiedAt: stat.mtime.toISOString(),
    isDirectory: stat.isDirectory(),
    isFile: stat.isFile(),
  };
});
```

## 📝 面试回答模板

> **问：Electron 中如何安全地进行文件操作？**
>
> 文件操作必须在主进程中进行，渲染进程通过 IPC 发起请求。主进程的 IPC handler 中需要做路径校验——用 `path.resolve` 标准化路径后，检查是否在允许的目录范围内（通常是 `app.getPath('documents')` 和 `app.getPath('userData')`）。这样即使有 XSS，攻击者也只能访问白名单目录，不能读取任意文件。另外在沙箱模式下，preload 中不能直接 `require('fs')`，所有文件操作都走 IPC。

> **问：Electron 中有哪些数据持久化方案？**
>
> 主要有三种：`electron-store` 是基于 JSON 文件的简单 KV 存储，适合保存应用配置和用户偏好，API 简洁，支持 TypeScript 类型。`better-sqlite3` 是 SQLite 绑定，适合大量结构化数据、需要 SQL 查询的场景。直接文件存储适合用户创建的文档（如 Markdown 文件）。选择标准：配置用 electron-store，数据库用 SQLite，用户文档用文件系统。

> **问：app.getPath 和 __dirname 有什么区别？**
>
> `app.getPath` 返回的是系统标准路径，如 `userData`（应用数据目录）、`documents`（用户文档目录）、`desktop`（桌面）等，这些路径会根据操作系统自动适配，且会按应用名隔离。`__dirname` 是当前 JS 文件所在的目录，打包后指向 asar 压缩包内部。应用的配置文件和用户数据应该放在 `app.getPath('userData')` 下，而不是 `__dirname` 下——因为 `__dirname` 在打包后可能是只读的。
