# 12 — 性能优化与内存管理

> 对应大纲：工程层 | 预计时间：1 天
> 面试可答：Electron 的性能瓶颈通常来自三方面——启动慢（Chromium 初始化 + 页面加载）、内存高（Chromium 基础占用 80~150MB）、渲染卡顿（主线程阻塞）。优化策略包括：`show: false` + `ready-to-show` 避免白屏、按需加载窗口减少初始内存、主进程不做耗时计算（用 Worker）、禁用不需要的 Chromium 功能（如 GPU 加速不需要的场景）、合理使用 `webContents.on('console-message')` 监控渲染进程性能。

---

## 1. 启动优化

### 1.1 Electron 应用启动过程

```
main.js 加载
     │
     ▼
Chromium 初始化          ← 最耗时（通常 0.5~2s）
     │
     ▼
主进程 JS 执行           ← 应用代码
     │
     ▼
BrowserWindow 创建
     │
     ▼
页面加载（HTML/CSS/JS）   ← 第二耗时
     │
     ▼
首次渲染（ready-to-show）
     │
     ▼
用户可见
```

### 1.2 优化策略

**策略 1：先隐藏窗口，渲染完成后显示**

```typescript
const win = new BrowserWindow({
  show: false,  // 关键：先不显示
  backgroundColor: '#1e1e1e',  // 设置背景色，减少白屏感
  webPreferences: {
    preload: path.join(__dirname, 'preload.js'),
    contextIsolation: true,
    sandbox: true,
  },
});

win.loadFile('index.html');

win.once('ready-to-show', () => {
  win.show();  // 渲染完成后才显示
});
```

**策略 2：减少主进程启动时间**

```typescript
// ❌ 启动时加载所有模块
import Database from 'better-sqlite3';
import Store from 'electron-store';
import log from 'electron-log';

// ✅ 按需延迟加载
let db: Database.Database | null = null;
function getDb() {
  if (!db) {
    db = new Database(path.join(app.getPath('userData'), 'data.db'));
  }
  return db;
}
```

**策略 3：Vite 代码分割**

```typescript
// vite.config.ts
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom'],
          editor: ['@codemirror/view', '@codemirror/state'],
        },
      },
    },
  },
});
```

## 2. 内存优化

### 2.1 Electron 的基础内存占用

```
每个 Electron 应用的内存构成：
┌─────────────────────────────────────────┐
│  主进程 (Node.js)         ~30~50 MB     │
├─────────────────────────────────────────┤
│  渲染进程 1 (Chromium)    ~50~100 MB    │
├─────────────────────────────────────────┤
│  渲染进程 2 (可选)        ~50~100 MB    │
├─────────────────────────────────────────┤
│  GPU 进程                 ~20~50 MB     │
├─────────────────────────────────────────┤
│  总计                     ~150~300 MB   │
└─────────────────────────────────────────┘
```

一个空白的 Electron 应用就要占用 150MB 左右，这是 Chromium 的固有成本。

### 2.2 减少窗口数量

每个 BrowserWindow 都是一个独立的渲染进程，占用 50~100MB：

```typescript
// ❌ 为每个功能创建新窗口
function openSettings() { new BrowserWindow({ ... }); }
function openAbout() { new BrowserWindow({ ... }); }
function openHelp() { new BrowserWindow({ ... }); }

// ✅ 使用路由在同一个窗口中切换页面
function openSettings() {
  mainWindow.webContents.send('navigate', '/settings');
}
function openAbout() {
  mainWindow.webContents.send('navigate', '/about');
}
```

### 2.3 按需创建窗口

```typescript
// ❌ 启动时创建所有窗口
app.whenReady().then(() => {
  createMainWindow();
  createSettingsWindow();
  createAboutWindow();
});

// ✅ 需要时再创建
app.whenReady().then(() => {
  createMainWindow();
});

ipcMain.on('open-settings', () => {
  createSettingsWindow();  // 用户点击时才创建
});
```

### 2.4 销毁不用的窗口

```typescript
// 关闭窗口时清理资源
win.on('closed', () => {
  win = null;  // 释放引用，允许 GC 回收
});

// 或者使用 destroy() 强制销毁
win.on('close', () => {
  // 保存状态后销毁
  saveWindowState();
  win.destroy();
});
```

### 2.5 V8 内存限制与调优

```bash
# 增加主进程的 V8 堆内存上限（默认 ~1.5GB）
electron --max-old-space-size=4096 .

# 在 package.json 的 scripts 中
{
  "scripts": {
    "start": "electron --max-old-space-size=4096 ."
  }
}
```

### 2.6 监控内存使用

```typescript
// 主进程
function logMemoryUsage() {
  const usage = process.memoryUsage();
  console.log({
    rss: `${Math.round(usage.rss / 1024 / 1024)} MB`,       // 常驻内存
    heapTotal: `${Math.round(usage.heapTotal / 1024 / 1024)} MB`,  // 堆总量
    heapUsed: `${Math.round(usage.heapUsed / 1024 / 1024)} MB`,    // 堆已用
    external: `${Math.round(usage.external / 1024 / 1024)} MB`,    // 外部内存
  });
}

setInterval(logMemoryUsage, 30000); // 每 30 秒记录一次

// 渲染进程
win.webContents.on('console-message', (_event, level, message) => {
  if (message.includes('memory')) {
    log.info('[Renderer]', message);
  }
});
```

## 3. 渲染优化

### 3.1 禁用不需要的 Chromium 功能

```typescript
const win = new BrowserWindow({
  webPreferences: {
    // 禁用不需要的功能
    webgl: false,           // 不需要 3D 时
    spellcheck: false,      // 不需要拼写检查
    images: true,           // 图片通常需要
  },
});

// 禁用硬件加速（某些情况下减少 GPU 内存）
// app.disableHardwareAcceleration();
```

> 注意：早期教程常见的 `app.commandLine.appendSwitch('disable-remote-module')` 已无意义——`remote` 模块自 Electron 14 起已从内置模块中移除（由外部包 `@electron/remote` 接替，不用就是不加载）。`plugins: false` 同理属于历史遗留配置（NPAPI 插件早已从 Chromium 移除），设置它没有实际效果。

### 3.2 GPU 加速控制

```typescript
// 在某些虚拟机或远程桌面中，GPU 加速可能有问题
app.disableHardwareAcceleration();

// 或者通过命令行参数控制
app.commandLine.appendSwitch('disable-gpu');
app.commandLine.appendSwitch('disable-software-rasterizer');
```

### 3.3 禁用 Chromium 的后台节流

```typescript
// 默认情况下，不可见的渲染进程会被节流
// 如果你的应用需要后台持续运行（如音乐播放器），可以禁用：
app.commandLine.appendSwitch('disable-renderer-backgrounding');
app.commandLine.appendSwitch('disable-background-timer-throttling');
```

## 4. 主进程优化

### 4.1 避免在主进程中做耗时操作

```typescript
// ❌ 主进程中执行大量计算
ipcMain.handle('process-data', (_event, data: number[]) => {
  return data.map((x) => heavyComputation(x)); // 阻塞主进程
});

// ✅ 使用 Worker Thread
import { Worker } from 'node:worker_threads';

ipcMain.handle('process-data', async (_event, data: number[]) => {
  return new Promise((resolve, reject) => {
    const worker = new Worker(path.join(__dirname, 'workers', 'processor.js'), {
      workerData: { data },
    });
    worker.on('message', resolve);
    worker.on('error', reject);
  });
});
```

**workers/processor.js**：

```javascript
const { workerData, parentPort } = require('node:worker_threads');

const result = workerData.data.map((x) => heavyComputation(x));
parentPort.postMessage(result);
```

### 4.2 主进程 / 渲染进程职责划分

| 操作 | 放在主进程 | 放在渲染进程 |
|------|-----------|-------------|
| 文件读写 | ✅ | ❌ |
| IPC 通信 | ✅ | ✅ |
| UI 渲染 | ❌ | ✅ |
| DOM 操作 | ❌ | ✅ |
| 数据库查询 | ✅ | ❌ |
| 大量数据计算 | ✅（用 Worker） | ✅（用 Web Worker） |
| 网络请求 | ✅ | ✅ |
| 系统 API 调用 | ✅ | ❌ |

## 5. 性能监控工具

### 5.1 Chrome DevTools Performance

渲染进程的性能分析直接用 Chrome DevTools：

1. 打开 DevTools → Performance 面板
2. 点击 Record → 操作应用 → 点击 Stop
3. 分析火焰图、长任务、内存曲线

### 5.2 任务管理器

Electron 内置任务管理器（类似 Chrome 的 Shift+Esc）：

```typescript
// 打开任务管理器（查看各进程的 CPU/内存使用）
win.webContents.sendInputEvent({
  type: 'keyDown',
  keyCode: 'Escape',
  modifiers: ['shift'],
});
```

### 5.3 自定义性能监控

```typescript
// 主进程：定期检查各窗口的内存使用
function collectPerformanceMetrics() {
  const metrics = BrowserWindow.getAllWindows().map((win) => ({
    title: win.getTitle(),
    memory: win.webContents.getProcessMemoryInfo(),
    cpu: win.webContents.getCPUUsage(),
  }));

  return Promise.all(
    metrics.map(async (m) => ({
      title: m.title,
      memory: await m.memory,
      cpu: await m.cpu,
    }))
  );
}

// 每分钟收集一次
setInterval(async () => {
  const metrics = await collectPerformanceMetrics();
  log.info('性能指标:', JSON.stringify(metrics, null, 2));
}, 60000);
```

### 5.4 关键性能指标

| 指标 | 目标值 | 监控方式 |
|------|--------|---------|
| 启动时间（到 ready-to-show） | < 2s | `Date.now()` 打点 |
| 主进程内存 | < 100MB | `process.memoryUsage()` |
| 渲染进程内存 | < 200MB | `webContents.getProcessMemoryInfo()` |
| 总内存 | < 500MB | 各进程内存之和 |
| IPC 响应时间 | < 50ms | 打点计时 |
| 首屏渲染时间 | < 1s | `performance.timing` |

## ✏️ 练习

### 练习 1：测量启动时间

**要求**：
1. 在 `main.ts` 入口处记录 `startTime = Date.now()`
2. 在 `ready-to-show` 事件中计算启动耗时
3. 将启动时间输出到日志

**验收标准**：应用启动后，日志中显示启动耗时（如 "启动耗时: 1234ms"）。

### 练习 2：内存监控

**要求**：
1. 每 10 秒记录主进程的内存使用
2. 将内存信息通过 IPC 发送给渲染进程并显示
3. 观察内存是否随时间增长（可能有内存泄漏）

**验收标准**：渲染进程中实时显示内存使用图表。

### 练习 3：按需加载窗口

**要求**：
1. 启动时只创建主窗口
2. 设置窗口和关于窗口在用户请求时才创建
3. 窗口关闭后释放引用

**验收标准**：对比优化前后的启动时间和初始内存占用。

## 📝 面试回答模板

> **问：Electron 应用的性能瓶颈在哪里？如何优化？**
>
> 三个主要瓶颈：启动慢（Chromium 初始化 0.5~2s）、内存高（基础占用 150~300MB）、渲染卡顿。启动优化：`show: false` + `ready-to-show` 避免白屏、延迟加载非关键模块、Vite 代码分割。内存优化：减少窗口数量（用路由替代多窗口）、按需创建窗口、及时销毁不用的窗口。渲染优化：禁用不需要的 Chromium 功能（webgl、spellcheck）、使用 Web Worker 处理耗时计算、避免主线程长任务。主进程优化：用 Worker Thread 处理大数据计算，避免阻塞 IPC。

> **问：Electron 应用的内存占用可以降到多低？**
>
> 一个空白 Electron 应用大约 150MB（主进程 30~50MB + 渲染进程 50~100MB + GPU 进程 20~50MB），这是 Chromium 的固有成本，无法再低。优化空间在：1）减少窗口数量——每个渲染进程 50~100MB；2）禁用不需要的功能——`webgl: false`、`spellcheck: false` 可以减少几十 MB；3）使用 `app.disableHardwareAcceleration()` 可以减少 GPU 内存但可能影响渲染性能。一般来说，一个功能完善的 Electron 应用总内存控制在 300~500MB 是合理的。

> **问：主进程和渲染进程的职责怎么划分？**
>
> 核心原则：主进程管系统能力，渲染进程管 UI。文件读写、数据库查询、系统 API 调用、菜单/对话框等放在主进程。DOM 操作、UI 渲染、用户交互放在渲染进程。耗时计算两边都可以放，但都要用 Worker（主进程用 Worker Thread，渲染进程用 Web Worker），不能阻塞各自的消息循环。IPC 通信的频率要控制——高频数据可以用 `send/on` 单向推送，避免 `invoke/handle` 的往返开销。
