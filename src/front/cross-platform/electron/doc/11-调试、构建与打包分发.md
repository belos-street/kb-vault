# 11 — 调试、构建与打包分发

> 对应大纲：工程层 | 预计时间：1.5~2 天
> 面试可答：Electron 应用有两个可调试的目标——主进程用 VS Code 的 `--inspect` 参数附加调试器，渲染进程直接用 Chrome DevTools。构建打包推荐 Electron Forge（官方工具链，配置简单）或 Electron Builder（功能更丰富，社区生态更大）。代码签名和公证是发布到 macOS/Windows 的必要步骤。自动更新通过 `electron-updater` 配合 GitHub Releases 或自建服务器实现。

## 1. 主进程调试

### 1.1 VS Code 调试配置

在项目根目录创建 `.vscode/launch.json`：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug Main Process",
      "type": "node",
      "request": "launch",
      "runtimeExecutable": "${workspaceFolder}/node_modules/.bin/electron",
      "runtimeArgs": ["--remote-debugging-port=9222", "."],
      "console": "integratedTerminal",
      "sourceMaps": true
    }
  ]
}
```

也可以用 `--inspect` 参数：

```json
{
  "name": "Debug Main Process (inspect)",
  "type": "node",
  "request": "launch",
  "runtimeExecutable": "${workspaceFolder}/node_modules/.bin/electron",
  "runtimeArgs": ["--inspect=5858", "."],
  "console": "integratedTerminal"
}
```

启动后可以在 VS Code 中设置断点、查看变量、单步调试主进程代码。

### 1.2 渲染进程调试

渲染进程就是 Chrome 页面，直接用 DevTools：

```typescript
// 开发环境自动打开 DevTools
if (process.env.NODE_ENV === 'development') {
  win.webContents.openDevTools({ mode: 'right' });
}

// 或者用快捷键 Ctrl+Shift+I / Cmd+Option+I
```

### 1.3 主进程 + 渲染进程同时调试

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Electron: Main",
      "type": "node",
      "request": "launch",
      "runtimeExecutable": "${workspaceFolder}/node_modules/.bin/electron",
      "runtimeArgs": ["--remote-debugging-port=9223", "."],
      "console": "integratedTerminal",
      "sourceMaps": true
    },
    {
      "name": "Electron: Renderer",
      "type": "chrome",
      "request": "attach",
      "port": 9223,
      "webRoot": "${workspaceFolder}/src/renderer",
      "sourceMaps": true
    }
  ],
  "compounds": [
    {
      "name": "Electron: All",
      "configurations": ["Electron: Main", "Electron: Renderer"]
    }
  ]
}
```

## 3. 构建打包方案对比

### 3.1 Electron Forge vs Electron Builder

| 维度 | Electron Forge | Electron Builder |
|------|---------------|-----------------|
| **维护方** | Electron 官方 | 社区（GitHub 25k+ stars） |
| **配置方式** | `forge.config.ts` | `electron-builder.yml` / `package.json` |
| **模板支持** | Vite / Webpack / CRA | 需手动配置 |
| **插件系统** | 丰富的插件生态 | 内置功能更多 |
| **自动更新** | `update-electron-app`（基于 `electron-updater`） | `electron-updater` |
| **代码签名** | 内置支持 | 内置支持 |
| **学习曲线** | 较低 | 中等 |
| **社区生态** | 较新但增长中 | 成熟，文档丰富 |

**建议**：新项目优先选 Electron Forge（官方维护，Vite 集成好）。已有项目或需要复杂配置选 Electron Builder。

### 3.2 Electron Forge 基本使用

```bash
# 创建新项目（推荐 Vite + TypeScript 模板）
# Forge 第一方模板共 4 个：webpack / webpack-typescript / vite / vite-typescript
npm init electron-app@latest my-app -- --template=vite-typescript

# 在已有项目中添加 Forge
npm install --save-dev @electron-forge/cli
npx electron-forge import

# 打包（生成可执行文件，不分发）
npx electron-forge package

# 构建安装包（可分发）
npx electron-forge make
```

**forge.config.ts 配置示例**：

```typescript
import type { ForgeConfig } from '@electron-forge/shared-types';
import { MakerDMG } from '@electron-forge/maker-dmg';
import { MakerSquirrel } from '@electron-forge/maker-squirrel';
import { MakerDeb } from '@electron-forge/maker-deb';
import { VitePlugin } from '@electron-forge/plugin-vite';

const config: ForgeConfig = {
  packagerConfig: {
    asar: true,
    icon: './assets/icon',
    appBundleId: 'com.yourcompany.myapp',
    osxSign: {},
    osxNotarize: {
      appleId: process.env.APPLE_ID!,
      appleIdPassword: process.env.APPLE_PASSWORD!,
      teamId: process.env.APPLE_TEAM_ID!,
    },
  },
  makers: [
    new MakerDMG({}, ['darwin']),
    new MakerSquirrel({}, ['win32']),
    new MakerDeb({}, ['linux']),
  ],
  plugins: [
    new VitePlugin({
      build: [
        { entry: 'src/main.ts', config: 'vite.main.config.ts' },
        { entry: 'src/preload.ts', config: 'vite.preload.config.ts' },
      ],
      renderer: [
        { name: 'main_window', config: 'vite.renderer.config.ts' },
      ],
    }),
  ],
};

export default config;
```

### 3.3 Electron Builder 基本使用

```bash
npm install --save-dev electron-builder
```

**package.json 配置**：

```json
{
  "build": {
    "appId": "com.yourcompany.myapp",
    "productName": "MyApp",
    "directories": {
      "output": "dist"

    "files": [
      "out/**/*",
      "package.json"

    "mac": {
      "category": "public.app-category.developer-tools",
      "target": ["dmg", "zip"],

```

## 4. 代码签名与公证

### 4.1 macOS 签名与公证

未签名的 macOS 应用会显示"无法打开"警告，用户需要在"系统偏好设置 → 安全性"中手动允许。

**签名证书**：
1. 注册 Apple Developer Program（$99/年）
2. 在 Xcode 中创建 "Developer ID Application" 证书
3. 导出为 `.p12` 文件

**公证流程**（macOS 10.15+）：

```typescript
// Electron Forge 中配置公证
// forge.config.ts
{
  packagerConfig: {
    osxSign: {
      identity: 'Developer ID Application: Your Name (TEAM_ID)',
      hardenedRuntime: true,
      entitlements: 'entitlements.plist',
      'entitlements-inherit': 'entitlements.plist',
    },
    osxNotarize: {
      appleId: process.env.APPLE_ID!,
      appleIdPassword: process.env.APPLE_PASSWORD!,  // App-Specific Password
      teamId: process.env.APPLE_TEAM_ID!,
    },
  },
}
```

**entitlements.plist**：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>com.apple.security.cs.allow-jit</key>
  <true/>
  <key>com.apple.security.cs.allow-unsigned-executable-memory</key>
  <true/>
</dict>
</plist>
```

### 4.2 Windows 签名

Windows 签名需要购买代码签名证书（EV 证书更贵但不需要用户手动信任）：

```typescript
// Electron Forge 中配置 Windows 签名
// forge.config.ts
{
  packagerConfig: {
    windowsSign: {
      certificateFile: process.env.WIN_CERT_FILE,
      certificatePassword: process.env.WIN_CERT_PASSWORD,
    },
  },
}
```

### 4.3 各平台安装包格式

| 平台 | 格式 | 说明 |
|------|------|------|
| macOS | `.dmg` | 磁盘映像，拖拽安装 |
| macOS | `.zip` | 压缩包，自动更新用 |
| macOS | `.pkg` | 安装器，企业分发用 |
| Windows | `.exe` (NSIS) | 安装器，可自定义安装目录 |
| Windows | `.msi` | Windows Installer，企业分发用 |
| Windows | `.portable` | 免安装，单文件运行 |
| Linux | `.AppImage` | 免安装，单文件运行 |
| Linux | `.deb` | Debian/Ubuntu 包管理器 |
| Linux | `.snap` | Snap 包管理器 |

## 5. 自动更新

### 5.1 使用 electron-updater

```bash
npm install electron-updater
```

```typescript
// src/main.ts
import { autoUpdater } from 'electron-updater';
import log from 'electron-log';

// 配置日志
autoUpdater.logger = log;

app.whenReady().then(() => {
  createMainWindow();

  // 检查更新
  autoUpdater.checkForUpdatesAndNotify();

  // 更新事件
  autoUpdater.on('checking-for-update', () => {
    log.info('检查更新中...');
  });

  autoUpdater.on('update-available', (info) => {
    log.info('发现新版本:', info.version);
    mainWindow.webContents.send('update-available', info);
  });

  autoUpdater.on('update-not-available', () => {
    log.info('已是最新版本');
  });

  autoUpdater.on('download-progress', (progress) => {
    log.info(`下载进度: ${progress.percent.toFixed(1)}%`);
    mainWindow.webContents.send('download-progress', progress);
  });

  autoUpdater.on('update-downloaded', (info) => {
    log.info('更新下载完成:', info.version);
    mainWindow.webContents.send('update-downloaded', info);
  });

  autoUpdater.on('error', (err) => {
    log.error('更新错误:', err);
  });
});

// 渲染进程请求安装更新
ipcMain.on('install-update', () => {
  autoUpdater.quitAndInstall();
});
```

### 5.2 配置更新源

**GitHub Releases**（最简单）：

```json
// package.json
{
  "build": {
    "publish": {
      "provider": "github",
      "owner": "your-username",
      "repo": "your-repo"
    }
  }
}
```

**自建服务器**：

```json
{
  "build": {
    "publish": {
      "provider": "generic",
      "url": "https://updates.yourcompany.com/myapp/"
    }
  }
}
```

服务器上需要的文件：
```
https://updates.yourcompany.com/myapp/
├── latest.yml              # Windows 更新信息
├── latest-mac.yml          # macOS 更新信息
├── latest-linux.yml        # Linux 更新信息
├── MyApp-1.0.0.dmg         # macOS 安装包
├── MyApp-1.0.0.exe         # Windows 安装包
└── MyApp-1.0.0.AppImage    # Linux 安装包
```

### 5.3 渲染进程中的更新 UI

```typescript
// 渲染进程中
window.electronAPI.onUpdateAvailable((info) => {
  showNotification(`发现新版本 v${info.version}，正在下载...`);
});

window.electronAPI.onDownloadProgress((progress) => {
  updateProgressBar(progress.percent);
});

window.electronAPI.onUpdateDownloaded((info) => {
  showDialog({
    title: '更新就绪',
    message: `v${info.version} 已下载完成，是否立即安装？`,
    buttons: ['立即安装', '稍后'],
    onConfirm: () => window.electronAPI.installUpdate(),
  });
});
```

## 📝 面试回答模板

> **问：Electron 应用如何调试？**
>
> 两个进程需要分别调试。主进程通过 VS Code 的 launch.json 配置，用 `--inspect` 参数启动 Electron，VS Code 附加调试器后可以设置断点、查看变量、单步执行。渲染进程就是 Chrome 页面，直接用 DevTools（Ctrl+Shift+I）调试，支持 Elements、Console、Network、Performance 等所有 Chrome 开发工具。如果需要同时调试两个进程，可以在 launch.json 中配置 compound，同时启动主进程调试和渲染进程附加。

> **问：Electron Forge 和 Electron Builder 怎么选？**
>
> Electron Forge 是官方工具链，和 Vite/Webpack 深度集成，配置简洁，适合新项目。Electron Builder 社区更大，功能更丰富，配置更灵活，适合已有项目或需要复杂构建流程的场景。两者都支持 macOS/Windows/Linux 三平台打包、代码签名、自动更新。我的建议是：新项目选 Forge（官方维护，长期来看兼容性更好），已有项目或需要高度定制选 Builder。

> **问：macOS 应用的签名和公证流程是怎样的？**
>
> 两步：签名和公证。签名需要 Apple Developer 账号（$99/年）和 Developer ID Application 证书，打包时用 `codesign` 对 .app 包签名。公证（notarize）是 macOS 10.15+ 的要求——将签名后的应用上传到 Apple 的公证服务，Apple 扫描后返回公证票据（ticket），打包到应用中。公证完成后，用户打开应用时系统会显示"已验证开发者"而不是"无法打开"。在 Electron Forge 中通过 `osxSign` 和 `osxNotarize` 配置自动化完成。
