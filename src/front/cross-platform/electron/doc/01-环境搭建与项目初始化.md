# 01 — 环境搭建与项目初始化

> 对应大纲：认知层 | 预计时间：1 天
> 面试可答：Electron 项目有两种主流脚手架——Electron Forge（官方推荐）和 Electron Builder（社区主流）。项目目录分为 main（主进程）、renderer（渲染进程）、preload（桥梁脚本）三部分。开发时用 Vite 做热重载，一个 Hello World 窗口 5 分钟就能跑起来。

---

## 1. 开发环境搭建

Electron 的环境搭建比 React Native 简单得多——不需要 Android Studio、不需要 Xcode，只要 Node.js 就够了。

### 1.1 必装工具

| 工具 | 版本要求 | 用途 | 安装方式 |
|------|---------|------|---------|
| **Node.js** | ≥ 18.x | JavaScript 运行时、npm 包管理 | [官网](https://nodejs.org/) 或 nvm |
| **Git** | 最新版 | 版本控制 | [官网](https://git-scm.com/) |
| **VS Code**（推荐） | 最新版 | 代码编辑器 | [官网](https://code.visualstudio.com/) |

**版本管理建议**：用 `nvm` 管理 Node.js 版本，避免系统级安装导致版本冲突。

```bash
# macOS / Linux
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
nvm install 20
nvm use 20

# 验证
node -v    # 应输出 v20.x.x
npm -v     # 应输出 10.x.x
```

### 1.2 平台构建工具（可选，仅原生模块需要）

如果你的项目需要使用原生 Node.js 模块（如 `better-sqlite3`、`sharp`），则需要额外安装编译工具链：

**macOS**：

```bash
xcode-select --install    # 安装 Xcode Command Line Tools
```

**Windows**：

```bash
# 以管理员身份运行 PowerShell
npm install -g windows-build-tools
# 或者安装 Visual Studio Build Tools，勾选 "C++ 桌面开发" 工作负载
```

**Linux（Ubuntu/Debian）**：

```bash
sudo apt-get install -y build-essential python3
```

> **不需要现在就装**：纯 Web 代码的 Electron 项目不需要这些。等你在第 07 篇（文件系统）或第 13 篇（原生模块）用到时再装也不迟。

## 2. 项目脚手架对比

### 2.1 三种启动方式

| 维度 | Electron Forge | Electron Builder | 手动搭建 |
|------|---------------|-----------------|---------|
| 定位 | 官方推荐的全栈工具链 | 社区主流的打包工具 | 完全自定义 |
| 初始化命令 | `npm init electron-app@latest` | 需手动配置 | 从零写 `package.json` |
| 开发体验 | 内置热重载 | 需额外配置 | 需额外配置 |
| 打包能力 | 内置（Maker 体系） | 强大（多格式支持） | 需手动集成 |
| 模板支持 | TypeScript / Webpack / Vite | 需手动搭建 | 无 |
| 学习成本 | 低 | 中 | 高 |
| 适合场景 | 新项目首选 | 需要精细控制打包配置 | 学习原理、特殊需求 |

**2026 年的建议**：新手用 **Electron Forge** 起步，熟悉后再根据需要切换到 Electron Builder。本文档用 Electron Forge + Vite 模板。

### 2.2 为什么推荐 Electron Forge？

Electron Forge 是 Electron 官方维护的工具链，覆盖了从项目创建到打包发布的完整生命周期：

```
创建项目 → 开发调试 → 打包 → 签名 → 发布
   ↑           ↑         ↑      ↑      ↑
 Forge       Forge     Forge  Forge  Forge
```

而 Electron Builder 只专注于"打包"这一个环节，其他环节需要自己搭配工具。

## 3. 创建第一个项目

### 3.1 使用 Electron Forge 初始化

```bash
# 创建项目（Vite + TypeScript 模板）
npm init electron-app@latest hello-electron -- --template=vite-typescript

# 进入项目目录
cd hello-electron

# 安装依赖
npm install

# 启动应用
npm start
```

启动后你会看到一个桌面窗口，显示 Electron 的欢迎信息——你的第一个 Electron 应用跑起来了。

### 3.2 使用 Vite + 手动搭建（进阶）

如果你更喜欢手动控制，可以用 Vite 搭建一个最小化的 Electron 项目：

```bash
mkdir my-electron-app && cd my-electron-app
npm init -y
npm install electron --save-dev
npm install vite --save-dev
```

编辑 `package.json`，添加入口和脚本：

```json
{
  "name": "my-electron-app",
  "version": "1.0.0",
  "main": "src/main/index.js",
  "scripts": {
    "start": "electron .",
    "dev": "vite"
  },
  "devDependencies": {
    "electron": "^35.0.0",
    "vite": "^6.0.0"
  }
}
```

手动搭建的好处是每个文件都在你的掌控之中，适合学习 Electron 的底层原理。但日常开发建议用 Forge，省去大量配置工作。

## 4. 项目目录结构详解

以 Electron Forge + Vite TypeScript 模板为例：

```
hello-electron/
├── src/
│   ├── main.ts              # ⭐ 主进程入口
│   ├── preload.ts           # ⭐ preload 脚本（桥梁）
│   └── renderer/
│       ├── index.html       # 渲染进程的 HTML
│       └── main.ts          # 渲染进程的 JS 入口
├── forge.config.ts          # Forge 打包配置
├── vite.main.config.ts      # Vite 配置（主进程）
├── vite.preload.config.ts   # Vite 配置（preload）
├── vite.renderer.config.ts  # Vite 配置（渲染进程）
├── tsconfig.json            # TypeScript 配置
├── package.json
└── node_modules/
```

### 4.1 关键文件说明

| 文件 | 归属进程 | 作用 |
|------|---------|------|
| `src/main.ts` | 主进程 | 应用入口，创建窗口、管理生命周期、处理系统事件 |
| `src/preload.ts` | 预加载 | 在渲染进程中安全地暴露 Node.js / Electron API |
| `src/renderer/index.html` | 渲染进程 | 窗口中展示的 HTML 页面 |
| `src/renderer/main.ts` | 渲染进程 | 页面的 JS 逻辑（可以接 React/Vue/Svelte） |
| `forge.config.ts` | 构建配置 | 打包、签名、发布相关的配置 |
| `vite.*.config.ts` | 构建配置 | 三个进程各自的 Vite 构建配置 |

> **为什么有三个 Vite 配置？** 因为主进程、preload、渲染进程的运行环境不同——主进程是 Node.js 环境，preload 是特殊的沙箱环境，渲染进程是浏览器环境。Vite 需要为每个环境单独配置。

### 4.2 与 React 项目目录的对比

如果你熟悉 React Web 项目，可以这样类比：

| React Web 项目 | Electron 项目 | 区别 |
|---------------|--------------|------|
| `src/App.tsx` | `src/renderer/main.ts` | 渲染进程的 UI 代码，可以接 React |
| `public/index.html` | `src/renderer/index.html` | 入口 HTML |
| `webpack.config.js` | `vite.*.config.ts`（×3） | 三个进程各自独立构建 |
| **没有对应** | `src/main.ts` | Web 项目没有主进程，这是 Electron 独有的 |
| **没有对应** | `src/preload.ts` | Web 项目没有 preload，这是 Electron 独有的 |

## 5. Hello World：从零到看到窗口

### 5.1 主进程代码解析

打开 `src/main.ts`，这是整个应用的入口：

```typescript
import { app, BrowserWindow } from 'electron';
import path from 'node:path';

// Handle creating/removing shortcuts on Windows when installing/uninstalling.
if (require('electron-squirrel-startup')) {
  app.quit();
}

const createWindow = () => {
  const mainWindow = new BrowserWindow({
    width: 800,
    height: 600,
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
    },
  });

  mainWindow.loadFile(path.join(__dirname, 'renderer', 'index.html'));

  // 开发时打开 DevTools
  mainWindow.webContents.openDevTools();
};

// Electron 初始化完成后创建窗口
app.whenReady().then(() => {
  createWindow();

  // macOS：点击 Dock 图标时重新创建窗口
  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) {
      createWindow();
    }
  });
});

// 所有窗口关闭时退出应用（macOS 除外）
app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') {
    app.quit();
  }
});
```

逐行解读关键代码：

| 代码 | 含义 |
|------|------|
| `new BrowserWindow({ width, height })` | 创建一个 800×600 的桌面窗口 |
| `webPreferences.preload` | 指定 preload 脚本路径（安全桥梁） |
| `mainWindow.loadFile(...)` | 让窗口加载本地 HTML 文件 |
| `app.whenReady()` | 等 Electron 初始化完成后执行 |
| `app.on('activate', ...)` | macOS 特有：点击 Dock 图标时重建窗口 |
| `app.on('window-all-closed', ...)` | 所有窗口关闭时退出（macOS 除外，因为 macOS 的习惯是关闭窗口但不退出应用） |

### 5.2 preload 脚本解析

打开 `src/preload.ts`：

```typescript
import { contextBridge, ipcRenderer } from 'electron';

// 向渲染进程暴露安全的 API
contextBridge.exposeInMainWorld('electronAPI', {
  sendMessage: (message: string) => ipcRenderer.send('message', message),
  onMessage: (callback: (message: string) => void) => {
    ipcRenderer.on('message', (_event, message) => callback(message));
  },
});
```

- `contextBridge.exposeInMainWorld` 是 Electron 安全模型的核心——它在渲染进程的 `window` 对象上挂载一个安全的 API，而不是直接暴露整个 `ipcRenderer`
- 渲染进程通过 `window.electronAPI.sendMessage()` 调用，而不是直接操作 `ipcRenderer`

> preload 脚本的详细原理会在第 02 篇（双进程架构）和第 05 篇（安全基础）中深入讲解。这里先有个概念即可。

### 5.3 渲染进程代码解析

打开 `src/renderer/index.html`：

```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="UTF-8" />
    <title>Hello Electron</title>
    <meta
      http-equiv="Content-Security-Policy"
      content="default-src 'self'; script-src 'self'"
    />
  </head>
  <body>
    <h1>Hello Electron!</h1>
    <p>👋 来自渲染进程的问候</p>
    <p id="info"></p>
    <script type="module" src="./main.ts"></script>
  </body>
</html>
```

渲染进程就是普通的 HTML 页面——跟你在浏览器中写的没有任何区别。唯一的区别是它运行在 Chromium 中，而不是浏览器 Tab 中。

## 6. 开发环境热重载配置

### 6.1 Electron Forge 默认行为

Electron Forge + Vite 模板默认已经配置好了开发体验：

```bash
npm start
```

启动后：
1. Vite 先编译主进程、preload、渲染进程的代码
2. Electron 启动并加载渲染进程
3. **修改渲染进程代码**（HTML/CSS/JS）→ Vite HMR 自动热更新，无需重启应用
4. **修改主进程代码** → 需要手动重启 `npm start`

> 这是一个重要区别：渲染进程支持 HMR（热模块替换），主进程不支持——因为主进程代码在 Node.js 中运行，修改后必须重启 Electron 进程。

### 6.2 主进程自动重启（可选优化）

如果希望主进程代码修改后也自动重启，可以使用 `electron-reload`：

```bash
npm install electron-reload --save-dev
```

在 `src/main.ts` 顶部添加：

```typescript
import path from 'node:path';
import { fileURLToPath } from 'node:url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));

if (process.env.NODE_ENV === 'development') {
  const electronReload = require('electron-reload');
  electronReload(__dirname, {
    electron: path.join(__dirname, '..', 'node_modules', '.bin', 'electron'),
  });
}
```

### 6.3 常用开发命令

```bash
npm start              # 编译并启动应用
npm run lint           # 代码检查（如果配置了 ESLint）
npm run package        # 打包为可分发的应用
npm run make           # 制作安装包（dmg / exe / deb）
```

## 7. Splash Screen：启动屏实现

Electron 应用冷启动需要 2-5 秒，这段时间用户会看到空白窗口。Splash Screen（启动屏）可以改善这个体验。

### 7.1 实现思路

在主窗口加载完成前，先显示一个轻量的启动屏窗口：

```typescript
// src/main.ts
import { app, BrowserWindow } from 'electron';
import path from 'node:path';

let mainWindow: BrowserWindow | null = null;
let splashWindow: BrowserWindow | null = null;

function createSplash() {
  splashWindow = new BrowserWindow({
    width: 400,
    height: 300,
    frame: false,           // 无边框窗口
    transparent: true,      // 透明背景（可选）
    alwaysOnTop: true,
    skipTaskbar: true,      // 不在任务栏显示
    webPreferences: {
      nodeIntegration: false,
      contextIsolation: true,
    },
  });

  splashWindow.loadFile(path.join(__dirname, 'renderer', 'splash.html'));
}

function createMainWindow() {
  mainWindow = new BrowserWindow({
    width: 1024,
    height: 768,
    show: false,            // 先隐藏主窗口
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
      contextIsolation: true,
      sandbox: true,
    },
  });

  mainWindow.loadFile(path.join(__dirname, 'renderer', 'index.html'));

  // 主窗口准备好后再显示，同时关闭启动屏
  mainWindow.once('ready-to-show', () => {
    splashWindow?.close();
    splashWindow = null;
    mainWindow?.show();
  });
}

app.whenReady().then(() => {
  createSplash();
  createMainWindow();
});
```

### 7.2 启动屏 HTML

创建 `src/renderer/splash.html`：

```html
<!DOCTYPE html>
<html>
  <head>
    <style>
      body {
        margin: 0;
        display: flex;
        justify-content: center;
        align-items: center;
        height: 100vh;
        background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
        color: white;
        font-family: -apple-system, BlinkMacSystemFont, sans-serif;
      }
      .splash {
        text-align: center;
      }
      .spinner {
        width: 40px;
        height: 40px;
        border: 3px solid rgba(255,255,255,0.3);
        border-top: 3px solid white;
        border-radius: 50%;
        animation: spin 1s linear infinite;
        margin: 0 auto 16px;
      }
      @keyframes spin {
        to { transform: rotate(360deg); }
      }
    </style>
  </head>
  <body>
    <div class="splash">
      <div class="spinner"></div>
      <h2>加载中...</h2>
    </div>
  </body>
</html>
```

关键流程：

```
应用启动 → 显示 Splash → 主窗口加载 → ready-to-show → 关闭 Splash → 显示主窗口
```

## 📝 面试回答模板

> **问：Electron 项目的目录结构是怎样的？**
>
> Electron 项目的核心是三部分：主进程（main）、渲染进程（renderer）和 preload 脚本。主进程是 Node.js 环境，负责创建窗口、管理生命周期、调用系统 API；渲染进程是 Chromium 环境，负责 UI 渲染，就是普通的 HTML/CSS/JS；preload 脚本是两者之间的安全桥梁，通过 `contextBridge` 向渲染进程暴露安全的 API。另外还有打包配置文件（如 forge.config.ts）和三个独立的 Vite 配置——因为三个进程的运行环境不同，需要分别构建。

> **问：Electron Forge 和 Electron Builder 有什么区别？**
>
> Electron Forge 是官方推荐的全栈工具链，覆盖从创建项目到打包发布的完整生命周期，内置模板、开发体验好、配置简洁。Electron Builder 是社区主流的打包工具，专注于打包和分发环节，支持更多的安装包格式和更精细的配置。简单来说，Forge 是"全家桶"，Builder 是"打包专家"。新手建议用 Forge 起步，等需要更精细的打包控制时再切到 Builder。

> **问：Electron 开发时渲染进程支持热重载吗？**
>
> 支持。渲染进程本质上是 Web 页面，Vite 的 HMR（热模块替换）完全可用——修改 HTML/CSS/JS 后，页面会自动更新，不需要重启应用，组件状态也不会丢失。但主进程不支持 HMR，因为主进程代码运行在 Node.js 中，修改后必须重启 Electron 进程。可以通过 electron-reload 等工具实现主进程文件监听 + 自动重启。
