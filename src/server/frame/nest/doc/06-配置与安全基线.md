# 06 配置与安全基线

> 所属大纲：[readme.md](../readme.md) ｜ 预计：1 天 ｜ 前置：03

**一句话定位**：从「能跑」到「敢裸奔公网」的最低配置——配置校验防脏启动、helmet/CORS/限流三件安全基线、密钥不进库。

**面试可答**：@nestjs/config 支持命名空间配置，v12 起 `validationSchema` 接受 Standard Schema（Zod），启动期校验环境变量防脏配置上线；安全基线 = helmet 安全头 + CORS 白名单 + throttler 全局与路由级限流。

---

## 1. @nestjs/config：命名空间 + Zod 校验

```ts
// config/env.schema.ts —— 单一事实源
import { z } from 'zod'

export const envSchema = z.object({
  NODE_ENV: z.enum(['development', 'production', 'test']).default('development'),
  PORT: z.coerce.number().default(3000),
  DATABASE_URL: z.url(),
  REDIS_URL: z.url(),
  JWT_SECRET: z.string().min(32),
  JWT_EXPIRES_IN: z.string().default('15m'),
})
export type Env = z.infer<typeof envSchema>
```

```ts
// app.module.ts —— v12：validationSchema 接受 Standard Schema
@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      cache: true,
      validationSchema: envSchema,          // 启动期校验：脏配置直接拒启
    }),
  ],
})
export class AppModule {}
```

```ts
// 命名空间：业务模块自带配置切片，避免全局 ConfigService 变大泥球
const dbConfig = registerAs('db', () => ({
  url: process.env.DATABASE_URL,
  poolSize: Number(process.env.DB_POOL_SIZE ?? 10),
}))

@Injectable()
export class PrismaService {
  constructor(@Inject(dbConfig.KEY) private cfg: typeof dbConfig) {}
}
```

> ⚠️ **v12 变化**：`validationSchema` 从 Joi 专属改为接受任意 Standard Schema。存量 Joi schema 仍可用但有两个条件：升级 **Joi v18+**（首个实现 Standard Schema 的版本），且库专属设置迁入 `validationOptions.libraryOptions`（如 `allowUnknown` / `abortEarly`）。来源：[Migration Guide](https://docs.nestjs.com/migration-guide#config-module)。

**为什么「启动期校验」值得单独强调**：配置错误是最贵的错误——跑一半才炸的连接串、缺字段的 JWT secret，都会在生产流量上才暴露。`validationSchema` 让它们死在启动第一秒。

## 2. 安全三件套

### helmet：安全响应头

```ts
import helmet from '@fastify/helmet'
await app.register(helmet, { contentSecurityPolicy: false })  // API 场景常关 CSP
```

一行拿到的头：`Strict-Transport-Security`、`X-Content-Type-Options`、`X-Frame-Options` 等——面试答「防 XSS 点击劫持 MIME 嗅探」够了，细节查 [helmet 文档](https://github.com/fastify/fastify-helmet)。

### CORS：白名单思维

```ts
import cors from '@fastify/cors'
await app.register(cors, {
  origin: [/\.example\.com$/, 'https://app.example.com'],   // 生产白名单，禁用 '*'
  credentials: true,                                         // Cookie 场景必须
})
```

### @nestjs/throttler：全局兜底 + 路由级加严

```ts
@Module({
  imports: [
    ThrottlerModule.forRoot({
      throttlers: [{ ttl: 60_000, limit: 100 }],   // 全局：每 IP 每分钟 100 次
    }),
  ],
  providers: [{ provide: APP_GUARD, useClass: ThrottlerGuard }],
})
export class AppModule {}

// 路由级加严：登录接口按「每分钟 5 次」防爆破
@Throttle({ default: { ttl: 60_000, limit: 5 } })
@Post('login')
login() {}
```

> 💡 限流的分布式版（多实例共享计数）需要 Redis 存储的 ThrottlerStorage——10 篇接 Redis 后回来升级。限流本身是 Guard（01 篇生命周期里占「可拒绝」位）。

## 3. 敏感配置与密钥管理

- **env 分层**：`.env` 本地开发 + CI 注入变量 + 生产 secrets manager（Vault / 云 KMS）；`.env.example` 进库（字段清单无值），真实 `.env` 进 `.gitignore`
- **secrets 不进库**：代码仓库里出现任何真实密钥 = 事故；`JWT_SECRET` 长度 ≥ 32 由 env schema 强制
- 轮换前提：secret 只从 `ConfigService` 读，不散落硬编码——换 secret 改一处

```bash
# .env.example（进库）
DATABASE_URL=postgres://user:pass@localhost:5432/app
JWT_SECRET=<openssl rand -base64 32 生成>
```

## 4. ✍️ 练习：带校验的配置模块 + 全局限流

**要求**：

1. 按 1 节搭 `envSchema`（故意漏掉 `DATABASE_URL` 启动一次，确认拒启报错可读）
2. helmet + CORS 白名单 + 全局 100 次/分钟限流，`POST /login` 单独 5 次/分钟
3. 用 `curl -H "Origin: https://evil.com" -i` 验证 CORS 拒绝；连发 6 次请求验证 429

**预期效果**：缺 env 时启动即失败且错误信息指明缺哪个字段；限流超限拿到 429 与 `Retry-After` 头。

## 5. 💬 面试问答

**Q1：环境变量为什么不直接 `process.env` 而要走 ConfigService？**

三点：① 启动期 schema 校验，脏配置拒启；② 命名空间切片让配置按域聚合、类型可推；③ 统一读取口是密钥轮换与测试替换（`overrideProvider`）的前提。散落的 `process.env` 是配置驱动的隐性耦合。

**Q2：v12 的 config 校验变了什么？**

`validationSchema` 从 Joi 专属改为 Standard Schema——Zod 直接可传；存量 Joi 需 v18+ 且选项迁入 `validationOptions.libraryOptions`。趋势与路由校验一致：全框架统一到 Standard Schema 协议。

**Q3：限流怎么做分层？**

两层：全局兜底（正常用户无感）+ 敏感路由加严（登录/注册/短信）。多实例部署时内存计数失效，要换 Redis 存储的共享计数——并注意 Redis 侧用 SCAN 不用 KEYS（10 篇纪律）。
