# 15 实战：企业级单体服务

> 所属大纲：[readme.md](../readme.md) ｜ 预计：2~3 天 ｜ 前置：01~14 全部

**一句话定位**：09 阶段实战的全量版——模块化单体，把全部技术点串成一个可交付的生产级项目。

**面试可答**：模块化单体的价值在于「微服务的模块边界 + 单体的部署简单」——模块间显式依赖（03）、异步解耦走队列而非进程拆分（10）、可观测与测试全套齐备；拆分时机到了再按模块边界平滑迁移。

## 3. main.ts：全量装配（前 14 篇的汇合点）

```ts
import './instrumentation'                      // 11：OTel 必须最先
import { NestFactory } from '@nestjs/core'
import { FastifyAdapter, NestFastifyApplication } from '@nestjs/platform-fastify'
import { createApp } from './app.factory'       // 12：装配工厂，E2E 复用
import { SwaggerModule, DocumentBuilder } from '@nestjs/swagger'

async function bootstrap() {
  const app = await createApp()                 // 校验管道/全局 Guard/Filter/Interceptor 都在工厂里
  const config = new DocumentBuilder()
    .setTitle('KB API').setVersion('1.0').addBearerAuth().build()
  SwaggerModule.setup('docs', app, SwaggerModule.createDocument(app, config))
  app.setGlobalPrefix('api', { exclude: ['health'] })   // 13
  app.enableShutdownHooks()                              // 11
  await app.listen(process.env.PORT ?? 3000)
}
bootstrap()
```

## 4. 异步链路：注册欢迎邮件的 Outbox 落地

```ts
// user.service.ts —— 事务内同写 outbox（10 篇）
async register(dto: RegisterDto) {
  const user = await this.prisma.$transaction(async (tx) => {
    const u = await tx.user.create({ data: toUser(dto) })
    await tx.outboxEvent.create({
      data: { type: 'user.registered', payload: { userId: u.id }, deliveredAt: null },
    })
    return u
  })
  return user
}

// outbox/relay.service.ts —— 定时轮询投递，投完标记
@Interval(5_000)
async relay() {
  const events = await this.prisma.outboxEvent.findMany({
    where: { deliveredAt: null }, take: 50,
  })
  for (const e of events) {
    await this.mailQueue.enqueueWelcome(e.payload.userId)   // 消费侧幂等兜底
    await this.prisma.outboxEvent.update({
      where: { id: e.id }, data: { deliveredAt: new Date() },
    })
  }
}
```

## 7. 💬 复盘问答

**Q1：为什么是「模块化单体」而不是微服务？**

模块边界（显式 imports）+ 进程内调用，先拿走微服务的「边界治理」收益，不付「网络/部署/观测复杂度」的税。模块即将来的服务边界——10 篇 Outbox 与事件解耦已让模块间耦合降到可拆水平，拆分时机到了按模块迁即可。

**Q2：这个项目里哪条链路最能体现「架构约束」的价值？**

注册链路：Zod 校验（04）→ 事务 + Outbox（08/10）→ 队列消费幂等（10）→ 审计（05）→ trace 可查（11）——每一环都有框架级挂点，而不是口头约定。换 Hono 实现同链路，逻辑一样但每个挂点都要自己发明。

**Q3：如果用户量涨 10 倍，第一刀切哪里？**

读路径：Prisma 查询加 Redis 缓存（10）+ 读写分离；然后是 report 类异步任务外移（K8s CronJob）。不要第一刀就拆微服务——先让单体跑满，profile 说话。

## 📌 小结

- 模块化单体 = 微服务的边界 + 单体的部署；模块边界就是未来的服务边界
- main.ts 是全大纲的汇合点：OTel 最先、装配进工厂、Swagger、shutdown hooks
- Outbox 让「DB 成功但邮件丢了」从概率问题变成不可能问题
- 验收标准全部可演示：一键起栈、Swagger 联调、测试全绿、CI 通过、traces 可见、锁住 cron
