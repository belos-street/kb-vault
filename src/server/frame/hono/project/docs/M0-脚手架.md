# M0 脚手架

> 所属：[project](../) 实现教学 ｜ 前置：[10-实战B](../../doc/10-实战B-企业级REST-API.md) §7.2 ｜ 对应代码：`src/lib/env.ts`、`src/index.ts`、`tsconfig.json`、`package.json`

**一句话定位**：立起「项目能启动、配置缺失能立刻炸」的地基——bun 初始化、strict tsconfig、依赖清单、目录骨架、env fail-fast。

**面试可答**：配置缺失是「不可恢复错误」，晚暴露只会让故障点离原因更远；启动期 fail-fast + 点名缺失项，把排障从「运行时诡异行为」压缩成「看一眼启动日志」。

---

## 1. 初始化与约束

```bash
bun init        # package.json 确认 "type": "module"
bun add hono @prisma/client@7 @prisma/adapter-pg zod @hono/zod-openapi @scalar/hono-api-reference pino ioredis
bun add -d prisma@7 oxlint oxfmt
```

- `type: module` 是 **Prisma 7 的硬要求**（ESM-only）——漏掉它，后面的 migrate 直接报错，而报错信息不会提示你查这里
- `tsconfig.json`：`strict: true` + `module: ESNext` + `moduleResolution: bundler` + `types: ["bun"]`——strict 全家桶从第一行代码就开，后补的成本远高于起步就严
- 目录骨架一步到位：`src/{routes,middleware,lib,schemas,domain,tests}` + `prisma/`——目录是分层约定（PRD §2.1）的物理载体，先立规矩再写代码

## 2. `lib/env.ts`：fail-fast 的实现

```ts
const envSchema = z.object({
  DATABASE_URL: z.string().min(1),
  JWT_SECRET: z.string().min(32),      // 弱密钥在启动期就拦下
  REDIS_URL: z.string().min(1),
  PORT: z.coerce.number().int().positive().default(3000),
  ENABLE_DOCS: z.enum(['true', 'false']).default('true'),
})

const parsed = envSchema.safeParse(process.env)
if (!parsed.success) {
  const detail = parsed.error.issues
    .map((i) => `${i.path.join('.')}: ${i.message}`)
    .join('; ')
  console.error(`[env] 环境变量校验失败 → ${detail}`)   // 点名缺哪项
  process.exit(1)
}
export const env = parsed.data
```

设计点：**只校验一次、启动期校验**。运行期任何代码读到的 `env` 都是已收敛的类型化对象，不需要防御式判空；`min(32)` 把「弱 JWT 密钥」这类安全隐患挡在启动时。

## 3. 组装与验证

`index.ts` 先只挂 `/healthz` 占位 + `Bun.serve`，`bun run dev` 跑通即收工。env 门禁（`ENABLE_DOCS=false` 时 `/api/doc`、`/ui` 不上线）在这里顺手写好——M5 文档端点直接消费。

验证方式：清空 `JWT_SECRET` 再启动 → 进程退出码 1、stderr 点名 `JWT_SECRET`。这个行为在 M8 被固化成 spawn 自动化用例（教程 §9 验收第 7 项）。

## 4. 对比板块：配置校验的时机

| 时机 | 表现 | 后果 |
|------|------|------|
| **启动期 fail-fast（本项目）** | 进程拒绝启动并点名缺失项 | 部署流水线立刻红 |
| 运行时惰性报错 | 请求用到才炸 | 故障点离原因远，排障看运气 |
| 默认值兜底 | 静默用错误配置运行 | 最危险——错误配置无感知 |

## 5. 自测

- [ ] `envSchema.safeParse` 之外为什么不用 `envSchema.parse`（直接抛异常）？（提示：退出码与日志格式的控制权）
- [ ] 为什么 `PORT` 可以有默认值而 `DATABASE_URL` 不行？

### 自测参考

- `parse` 直接抛 `ZodError`——退出码与日志格式不受控；`safeParse` 让我们自主决定输出格式与 `exit(1)`
- `PORT` 错了最多起在奇怪端口上服务仍可用；`DATABASE_URL` 错了连不上库，且不存在「合理的默认数据库」——必须显式提供

## 📌 小结

- fail-fast = 启动期 + 点名缺失项 + 退出码非 0，三件齐全才叫「快」
- 目录骨架先于代码：分层约定是物理事实，不是注释里的话
- Prisma 7 的 `type: module` 约束要在 `bun init` 当天确认
