## Dockerfile 多阶段（教程 §8 原样 + 两处修正）

```dockerfile
FROM oven/bun:1 AS deps
WORKDIR /app
COPY package.json bun.lock ./
RUN bun install --frozen-lockfile

FROM oven/bun:1 AS build
WORKDIR /app
COPY --from=deps /app/node_modules node_modules
COPY . .
# prisma.config.ts 加载期就解析 env('DATABASE_URL')——generate 虽不连库，
# 缺该变量直接启动失败。占位值只求格式合法，真实值运行时注入
ENV DATABASE_URL=postgres://placeholder:placeholder@localhost:5432/placeholder
RUN bunx prisma generate
RUN bun build ./src/index.ts --target bun --outdir dist

FROM oven/bun:1-slim
WORKDIR /app
COPY --from=build /app/dist dist
COPY --from=build /app/prisma prisma             # 迁移目录：migrate deploy 需要
COPY --from=build /app/prisma.config.ts ./
COPY --from=build /app/node_modules node_modules # prisma CLI 已移入 dependencies
EXPOSE 3000
CMD ["bun", "dist/index.js"]
```

Prisma 7 Rust-free 的红利在这里兑现：generate 产物纯 TS、无 binary engines，`bun build` 打出 6.65MB 单文件。运行镜像需 `migrate deploy`，所以 prisma CLI 从 devDependencies 移入 dependencies。

`.dockerignore` 必须排除 `.env`（compose 显式传 env）、`node_modules`、`dist`、`src/generated`（build 阶段重新 generate）。

## 踩坑实录（本次部署最有价值的部分）

**1. sh 不转发 SIGTERM——优雅停机在容器里失效**

`command: sh -c "migrate && bun dist/index.js"` 实测 `docker compose stop` **20s 宽限耗尽 → SIGKILL(exit 137)**。8 组隔离实验定位根因：`sh -c` 让 **sh 占住 PID1**，SIGTERM 发给 sh，sh 默认死亡且不转发子进程；bun 直做 PID1 时信号处理完全正常（对照实验均过）。修复一个词：

```yaml
command: sh -c "bunx prisma migrate deploy && exec bun dist/index.js"
#                                             ^^^^ bun 接替 sh 成为 PID1
```

修复后 stop 0.4s / exit 0 / 完整停机打点链。**这是「教程当对照、项目当实测」最典型的收获。**

**2. Dockerfile 尾注释不是注释**——`COPY ... node_modules # 说明` 里的中文被当成 COPY 参数（报 `/已移入: not found`）。Dockerfile 的 `#` 只在行首生效，注释必须独立成行。

**3. 文本 `bun.lock` 从未入库**——仓库只忽略二进制 `bun.lockb`，文本 lock 只存在于本地，CI 的 `--frozen-lockfile` 会直接挂。`bun install --save-text-lockfile` 重建后提交。

## compose 与 CI

- compose：db 挂 `pg_isready` healthcheck + `depends_on: service_healthy`，防「库没就绪 migrate 先跑」的首启竞态；app 健康检查用 `bun -e fetch`（slim 镜像没有 curl）
- CI（`.github/workflows/ci.yml`）：lint → oxfmt --check → typecheck → test（PG17/Redis7 service 容器 + 测试专用 env）→ docker build；paths 过滤只盯项目目录

## 面试可答

> **问：多阶段构建每个阶段都在做什么？为什么运行镜像要 COPY node_modules？**
> deps 层只装依赖（lockfile 冻结、层缓存友好）；build 层生成 Prisma Client 并打 bundle；运行层只带 dist + prisma 迁移目录 + 配置 + node_modules。node_modules 必须带是因为运行时要跑 `prisma migrate deploy`（CLI 已移入 dependencies）——替代方案是独立 migrate 容器或 init container，换的是镜像体积与编排复杂度。
