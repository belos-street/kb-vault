# M9 部署

> 所属：[project](../) 实现教学 ｜ 前置：[M8](./M8-测试与验收.md) ｜ 对应代码：`Dockerfile`、`.dockerignore`、`docker-compose.yml`、`.github/workflows/ci.yml`

**一句话定位**：多阶段 Dockerfile + compose 一键全栈（迁移前置）+ CI 流水线；本次最有价值的收获是用 8 组隔离实验定位了「sh 不转发 SIGTERM」这个教科书级部署坑。

**面试可答**：多阶段构建把「构建期的依赖与工具」与「运行期最小产物」分开——deps 层 frozen install、build 层 generate + bundle、运行层只带 dist/迁移目录/node_modules；容器里的 PID1 决定信号行为，`sh -c` 包装会让优雅停机失效。

---

## 1. Dockerfile 多阶段

```dockerfile
FROM oven/bun:1 AS deps
WORKDIR /app
COPY package.json bun.lock ./
RUN bun install --frozen-lockfile

FROM oven/bun:1 AS build
WORKDIR /app
COPY --from=deps /app/node_modules node_modules
COPY . .
# prisma.config.ts 加载期就解析 env('DATABASE_URL')——generate 虽不连库，
# 缺该变量直接启动失败。占位值只求格式合法，真实值由运行时注入 ⭐
ENV DATABASE_URL=postgres://placeholder:placeholder@localhost:5432/placeholder
RUN bunx prisma generate
RUN bun build ./src/index.ts --target bun --outdir dist

FROM oven/bun:1-slim
WORKDIR /app
COPY --from=build /app/dist dist
COPY --from=build /app/prisma prisma              # 迁移目录：migrate deploy 需要
COPY --from=build /app/prisma.config.ts ./
COPY --from=build /app/node_modules node_modules # prisma CLI 已移入 dependencies
EXPOSE 3000
CMD ["bun", "dist/index.js"]
```

三个 M1/M9 联动点：

- **占位 DATABASE_URL ⭐**：M1 讲过 config 加载期解析 env——build 阶段没有该变量（`.dockerignore` 正确排除了 `.env`），generate 直接失败。占位值只求格式合法
- **prisma CLI 移入 dependencies**：运行镜像要跑 `migrate deploy`
- **Prisma 7 Rust-free 的红利**：无二进制引擎，`bun build` 打出 6.65MB 单文件

`.dockerignore` 排除 `.env`（防泄密）、`node_modules`、`dist`、`src/generated`（build 阶段重新 generate）。

## 2. ⭐ 优雅停机失效的完整排查（8 组实验）

**现象**：`docker compose stop` 20s 宽限耗尽 → SIGKILL（exit 137），停机打点一行都没出现。

**定位过程**（每步只改一个变量）：

| 实验 | 结果 | 排除 |
|------|------|------|
| `bun -e` 最小脚本（PID1） | 信号正常 | bun 信号机制本身 |
| `bun -e` + `Bun.serve`（PID1） | 信号正常 | Bun.serve 干扰 |
| 未打包源码 `bun src/index.ts`（PID1） | 停机链路完整 | 应用代码 |
| 最小 bundle（PID1） | 信号正常 | bun build 产物 |
| prisma/redis/pino 分别打包 | 各自正常 | 依赖图 |

最终对照：**compose 容器（失效）vs docker run 直跑镜像（正常）**——唯一差异是 compose 的启动命令：

```yaml
command: sh -c "bunx prisma migrate deploy && bun dist/index.js"
```

**根因**：`sh -c` 让 **sh 占住 PID1**——SIGTERM 发给 sh，sh 的默认处置是自己死、**不转发子进程**，bun 根本收不到信号；宽限期后编排器 SIGKILL 全场。修复一个词：

```yaml
command: sh -c "bunx prisma migrate deploy && exec bun dist/index.js"
#                                             ^^^^ bun 接替 sh 成为 PID1
```

修复后 stop 0.4s / exit 0 / 完整停机打点链。**教训**：教程的 compose 模板带这个隐患——「迁移前置」与「信号语义」互相牵制时，`exec` 是标准解法。

**次要坑**：Dockerfile 的 `#` 只在行首生效——`COPY ... # 注释` 里的中文被当成 COPY 参数（`/已移入: not found`），注释必须独立成行。

## 3. compose：防首启竞态

```yaml
db:
  image: postgres:17
  healthcheck: { test: ['CMD-SHELL', 'pg_isready -U postgres'], interval: 3s, retries: 10 }
app:
  depends_on:
    db: { condition: service_healthy }   # 库没就绪，migrate deploy 会先炸
```

app 健康检查用 `bun -e fetch`（slim 镜像没有 curl）。compose 里 `JWT_SECRET` 是教学占位值——生产必须轮换并改用 secrets 管理。

## 4. CI（.github/workflows/ci.yml）

```yaml
services:            # PG17 + Redis7 service 容器
  postgres: { image: postgres:17, ports: ['5432:5432'] }
  redis: { image: redis:7-alpine, ports: ['6379:6379'] }
steps:
  - bun install --frozen-lockfile
  - bun run lint                        # oxlint
  - bunx oxfmt --check src prisma scripts
  - bun run typecheck                   # tsc --noEmit
  - bun run test                        # test:setup（自动建库 seed）+ bun test
  - docker build -t blog-api:ci .
```

测试专用 `JWT_SECRET`（过 fail-fast）与 `DATABASE_URL_TEST`/`REDIS_URL_TEST` 指向 service 容器；paths 过滤只盯项目目录，笔记推送不跑流水线。

**踩坑**：文本 `bun.lock` 此前只存在于本地、从未入库——CI 的 `--frozen-lockfile` 直接挂。lockfile 是「必须提交的构建输入」不是本地缓存。

## 5. 对比板块：镜像构建策略

| 策略 | 镜像体积 | 构建速度 | 适用 |
|------|---------|---------|------|
| **多阶段 + bundle（本项目）** | 小（slim + dist） | 层缓存友好 | 生产部署 |
| 单阶段全量 COPY | 大（含构建工具链） | 快 | 快速验证 |
| distroless + 独立 migrate Job | 最小 | 编排复杂度高 | K8s 多副本 |

## 📌 小结

- 多阶段 = 依赖层缓存 + 构建层完整 + 运行层最小；prisma CLI 的归属跟着「谁要跑 migrate」走
- 容器 PID1 决定信号语义：`sh -c` 包装 + `exec` 是一对固定搭配
- 教程模板 ≠ 已验证：本项目最大的收获是「照抄 → 失效 → 实验 → 回写」的完整闭环
