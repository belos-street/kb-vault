# M1 数据层

> 所属：[project](../) 实现教学 ｜ 前置：[M0](./M0-脚手架.md) ｜ 对应代码：`prisma/schema.prisma`、`prisma.config.ts`、`prisma/seed.ts`、`src/lib/db.ts`

**一句话定位**：Prisma 7 新约定全落地——`prisma-client` 生成器、config 迁移、driver adapter 替代 Rust 引擎，模型在第一天就为后面的企业级技术点埋好字段。

**面试可答**：Prisma 7 的 driver adapter 把查询编译跑在 WASM、连接交给 JS 侧驱动（如 `@prisma/adapter-pg`），无二进制引擎下载、镜像更小、对 Bun 等新运行时兼容更好；`datasource url` 从 schema 挪进 `prisma.config.ts`。

---

## 1. schema：generator 与模型

```prisma
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"   // 新生成器产出纯 TS，进源码树
}

datasource db {
  provider = "postgresql"                // 不写 url——Prisma 7 挪进 config
}
```

模型设计的关键字段是后面所有技术点的载体：

- `Post.version`（乐观锁，M5）、`Post.commentCount`（评论计数事务，M6）、`Post.deletedAt`（软删，M5/M6）
- 复合索引跟着查询走：`@@index([status, deletedAt])`（列表过滤）、`@@index([postId, deletedAt])`（评论列表）

> 决策记录（ADR，写在 schema 注释里）：本版 User 不软删——email 唯一约束与「软删行继续占用 email」冲突；未来引入用户软删用 Prisma 7.4+ `partialIndexes`（`@@unique([email], where: ...)`）解锁。

## 2. `prisma.config.ts`：Prisma 7 新约定 ⭐

```ts
import 'dotenv/config'   // ⚠️ 必需——Prisma CLI 沙箱不走 Bun 的 .env 自动加载
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: { path: 'prisma/migrations', seed: 'bun prisma/seed.ts' },
  datasource: { url: env('DATABASE_URL') },
})
```

踩坑：没有 `import 'dotenv/config'` 时 CLI 报 `Cannot resolve environment variable: DATABASE_URL`。Bun 应用侧自动加载 .env，但 **Prisma CLI 的沙箱不经过 Bun 的自动加载**——config 必须自己加载 dotenv。这个「加载期即解析」的特性在 M9 还会再咬一口（Docker build 阶段没有 DATABASE_URL，generate 需要占位值）。

## 3. `lib/db.ts`：driver adapter

```ts
import { PrismaPg } from '@prisma/adapter-pg'
import { PrismaClient } from '../generated/prisma/client'

const adapter = new PrismaPg({ connectionString: env.DATABASE_URL })
export const prisma = new PrismaClient({ adapter })
```

单例导出，与 Redis 客户端同理：客户端内部维护连接池，每请求新建会耗尽连接。

## 4. 迁移与种子

```bash
bunx prisma migrate dev --name init
bun prisma/seed.ts
```

seed 建 admin×1、editor×1、reader×2——审核流与越权测试全靠这些角色。种子数据抽到 `prisma/seed-data.ts` 单一来源（M8 的测试重置共用）。

## 5. 踩坑实录

| 坑 | 原因与解法 |
|----|-----------|
| CLI 读不到 .env | Prisma CLI 沙箱不走 Bun 自动加载，config 里显式 `import 'dotenv/config'` |
| `pnpm add prisma` 拉到 rc 版 | Prisma 7 需显式 `prisma@7`，否则 CLI 与 `@prisma/client` 版本错位 |
| pnpm 11 构建脚本被静默跳过 | 批准挪到 `pnpm-workspace.yaml` 的 allowBuilds |

## 6. 对比板块：ORM 接数据库的方式

| 方式 | 引擎位置 | 部署 | 适用 |
|------|---------|------|------|
| **Prisma 7 driver adapter（本项目）** | WASM 编译 + JS 驱动 | 无二进制下载，镜像小 | Bun/边缘/容器 |
| Prisma ≤6 Rust 引擎 | 独立二进制 | 需下载 engines | 传统 Node |
| 裸 SQL（pg/kysely） | 无 | 最小 | 强 SQL 控制需求 |

## 📌 小结

- Prisma 7 三新：`prisma-client` 生成器、config 迁移、driver adapter——每一条都改变部署形态
- config 加载期即解析 env：M1 的 dotenv 补丁、M9 的占位值，是同一个特性的两次咬人
- 字段即功能预埋：version/commentCount/deletedAt 第一天就进 schema
