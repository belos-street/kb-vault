## 这一步做什么

Prisma 7 接 PostgreSQL：schema 建模（User/Post/Comment/AuditLog）、迁移、本地容器、`lib/db.ts` 接线。

## 关键决策

**1. 新版 generator：`prisma-client` + 显式 output**

```prisma
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
}
```

Prisma 7 的新 generator 产出**纯 TS**（旧 `prisma-client-js` 产 Node 脚本），生成物进源码树随版本管理。

**2. datasource 不写 url，挪进 `prisma.config.ts`**——Prisma 7 的新约定：

```ts
import 'dotenv/config'   // ⚠️ 必需：Prisma CLI 沙箱不走 Bun 的 .env 自动加载
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: { path: 'prisma/migrations', seed: 'bun prisma/seed.ts' },
  datasource: { url: env('DATABASE_URL') },
})
```

**3. driver adapter 替代 Rust 引擎**（`lib/db.ts`）：

```ts
import { PrismaPg } from '@prisma/adapter-pg'
const adapter = new PrismaPg({ connectionString: env.DATABASE_URL })
export const prisma = new PrismaClient({ adapter })
```

Rust-free 后：generate 产物纯 TS、运行时不下载 binary engines、容器镜像显著变小、`bun build` 能打进单文件。

## 模型要点

- `Post.version`（乐观锁）、`Post.commentCount`（评论计数）、`Post.deletedAt`（软删）——这三个字段是后面 M5/M6 所有「企业级技术点」的载体
- 复合索引跟着查询走：`@@index([status, deletedAt])`（列表过滤）、`@@index([postId, deletedAt])`（评论列表）

## 踩坑实录

| 坑 | 原因与解法 |
|----|-----------|
| `prisma.config.ts` 读不到 .env | Prisma CLI 沙箱不走 Bun 的 .env 自动加载，config 里必须 `import 'dotenv/config'` |
| `pnpm add prisma` 拉到 rc 版 | Prisma 7 需显式 `prisma@7`，否则 CLI 与 `@prisma/client` 版本错位 |
| pnpm 11 构建脚本被静默跳过 | 批准挪到 `pnpm-workspace.yaml` 的 allowBuilds，package.json 的 pnpm 字段不再读取 |

## 验证

`bunx prisma migrate dev --name init` + seed（admin/editor/reader ×2，服务后续审核流测试）；DoD：findMany / create / `$transaction` 各跑通一次（含回滚自清理）。

## 面试可答

> **问：Prisma 7 的 driver adapter 和旧版 Rust 引擎差在哪？**
> 旧版查询由 Rust 引擎执行，跨语言通信 + 二进制分发；7 改为 queryCompiler 跑 WASM、连接交给 JS 侧驱动（如 `@prisma/adapter-pg` 直连 pg）。收益：无二进制下载、镜像小、与 Bun 等新运行时兼容好。
