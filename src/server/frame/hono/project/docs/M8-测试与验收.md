## 这一步做什么

## 隔离方案：为什么不是「每套件事务回滚」

最初设想（也是教程初稿）是外层事务回滚——**实测不可用**：`bun test` 每个测试文件持有独立模块注册表，各自实例化 PrismaClient（独立连接池），一个文件里的 `BEGIN` 包不住别的文件/别的事务。落地方案：

1. **独立测试库**：`.env` 增加 `DATABASE_URL_TEST`（`blog_test`），`bun run test:setup` 里 `prisma db push` 自动建库 + 幂等 seed
2. **套件间 TRUNCATE**：实测 bun 1.4.2 测试文件**严格串行**（两个 1s 睡眠文件总耗时 2.0s），每套件 `beforeAll` 里 `TRUNCATE ... RESTART IDENTITY CASCADE` + 重建种子 + `flushdb` 无并发干扰
3. **独立 Redis 下标**：`REDIS_URL_TEST=redis://localhost:6379/15`，限流/缓存测试不污染 dev 键空间
4. **双保险防误伤**：bunfig preload 缺测试变量直接拒跑；`resetTestState` 再校验 URL 必须等于 `DATABASE_URL_TEST`——TRUNCATE 指错库等于清空开发数据

```ts
// src/tests/setup-env.ts（bunfig [test].preload，先于所有测试文件执行）
if (!process.env.DATABASE_URL_TEST || !process.env.REDIS_URL_TEST) {
  console.error('[test] 缺少 DATABASE_URL_TEST / REDIS_URL_TEST——拒绝执行测试')
  process.exit(1)
}
process.env.DATABASE_URL = process.env.DATABASE_URL_TEST
```

生产代码零改动：`lib/env.ts` 仍只认 `DATABASE_URL`，只是测试进程里的值被换成了测试库。

## fail-fast 自动化验收（教程 §9 第 7 项）

```ts
const cwd = mkdtempSync(join(tmpdir(), 'blog-env-'))   // 临时 cwd：脱离项目 .env
const env = { ...process.env } as Record<string, string>
delete env.JWT_SECRET
const proc = Bun.spawnSync({
  cmd: [process.execPath, join(import.meta.dir, '..', 'index.ts')],
  cwd, env, stdout: 'pipe', stderr: 'pipe',
})
expect(proc.exitCode).toBe(1)
expect(new TextDecoder().decode(proc.stderr)).toContain('JWT_SECRET')   // 点名缺失项
```

## 测试工具链约定

- `bun run test` = `test:setup`（幂等）+ `bun test`——每次全量都在干净状态上跑
- 种子数据单一来源：`prisma/seed-data.ts`，seed 脚本与测试 reset 共用
- 请求唯一 `X-Forwarded-For`（限流按 IP+路由计数，测试间互不污染）

## 面试可答

> **问：集成测试用真数据库，怎么保证套件间互不污染？**
> 三层：库级隔离（独立 DATABASE_URL_TEST）、套件级重置（TRUNCATE RESTART IDENTITY + 重建种子 + flushdb）、请求级隔离（唯一邮箱/唯一 XFF）。用事务回滚做套件隔离的前提是单一连接池，bun test 每文件独立模块注册表的模型下不成立——工具的行为决定测试架构。
