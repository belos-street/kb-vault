# 02 — 数据建模：字段类型与约束

> **本系列基于 Prisma ORM 7.x**（2026-08 编写）。

- **所属模块**：Prisma 学习大纲 · 基础层
- **预计时间**：45 min
- **面试可答**：Prisma Schema 用字段属性（`@id`/`@default`/`@unique`/`@updatedAt`）和块级属性（`@@unique`/`@@index`）表达全部约束；表名、列名的映射用 `@map`/`@@map` 控制，可做到「ORM 命名清爽、数据库命名合规」分离。

## 1. 一句话定位

上一篇把 User 建出来了，但`String`/`Int` 只是 Prisma 标量类型的冰山一角。这一篇把 `schema.prisma` 的**类型、属性、映射**讲全，让你能写出「字段该有的约束都有」的生产级表结构。

## 2. 标量类型全景

Primitive 类型（PostgreSQL 后端）：

| Prisma 类型 | PostgreSQL 映射 | 说明 |
|------------|----------------|------|
| `String` | `text` / `varchar` | 默认 `text`，可用 `@db.VarChar(n)` 收紧，会反映到索引限制 |
| `Boolean` | `boolean` | |
| `Int` | `integer` | 32 位，常规主外键够用 |
| `BigInt` | `bigint` | 自增 ID 到亿级或雪花 ID 场景用它 |
| `Float` | `double precision` | 有精度问题的浮点 |
| `Decimal` | `numeric` | **金额必用**，不踩 Float 精度坑 |
| `DateTime` | `timestamp(3)` | 默认毫秒精度，`@db.Timestamptz()` 存带时区 |
| `Json` | `jsonb` | 半结构化字段，PG 可索引 |
| `Bytes` | `bytea` | 二进制 |

**选型口诀**：ID 内部用 `Int`/`BigInt`；对外暴露的 ID 用 `String @id @default(uuid(7))`（PG 18 原生支持、时间有序，见数据库课程 01 章）；金额 `Decimal`；时间 `DateTime`；不稳定的结构 `Json`。

## 3. 字段属性：约束的主力

```prisma
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String?
  age       Int      @default(18)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

| 属性 | 含义 | 高频用法 |
|------|------|----------|
| `@id` | 主键（单字段时） | `Int @default(autoincrement())` / `String @default(uuid(7))` / `String @default(cuid())` |
| `@default()` | 默认值，写表达式 | `now()`、`autoincrement()`、`uuid(7)`、`cuid()`、字面量 `18`、`"guest"`、`[]` |
| `@unique` | 唯一约束（隐式建索引） | email、username、slug |
| `@updatedAt` | 写入时自动刷新为当前时间 | 任何"最近修改时间"字段 |
| `@map` | 映射**列名** | 让 Prisma 字段名用驼峰、数据库列名用下划线 |

> 💡 `@updatedAt` 是 Prisma 替你生成的：`update` 时自动置为 `now()`，**不需要你手动赋值**。数据库课程里你手写过 `updated_at` 的 trigger 或应用层赋值，这里 Prisma 全包了。

## 4. 枚举与数组

```prisma
enum Role {
  USER
  ADMIN
  MODERATOR
}

enum PostStatus {
  DRAFT
  PUBLISHED
  ARCHIVED
}

model Post {
  id     Int        @id @default(autoincrement())
  title  String
  status PostStatus @default(DRAFT)
  tags   String[]   // PG 原生数组，scalar list
  roles  Role[]
}
```

- **枚举**：Prisma 在 PG 上一直映射 **PostgreSQL 原生 enum**（迁移时生成 `CREATE TYPE ... AS ENUM`）；只有 **SQLite** 不支持 enum、才退化为 `text` + Check 约束——别把两者的行为记混（参考[数据库特性矩阵](https://www.prisma.io/docs/orm/v6/reference/database-features)）。
- **scalar list（数组）**：`String[]` 映射 PG 数组列，适合 tags/roles 这类「一列一串值」；一旦要按某项单独查询，就应该拆成关联表（见 03/04 篇）。

## 5. Json 字段

```prisma
model Event {
  id      Int   @id @default(autoincrement())
  type    String
  payload Json  @default("{}")
}
```

- 写：直接传 `Json` 值：`payload: { source: "web", meta: { ua: "..." } }`。
- 读：拿回来就是 JS 对象，**无需 JSON.parse**。
- PG 上映射 `jsonb`，可对内部字段建 GIN 索引（数据库课程 05 章有 `EXPLAIN` 对比）。
- 反模式提醒：`Json` 不是用来逃避规范化的——频繁按内部字段过滤/聚合计的该拆表。

## 6. 块级属性：联合约束与索引

```prisma
model Enrollment {
  studentId Int
  courseId  Int
  status    String @default("active")

  @@id([studentId, courseId])          // 联合主键：一个学生一门课只能有一行
  @@unique([studentId, courseId])      // 和联合主键效果重叠时二选一
  @@index([courseId])                  // 按 courseId 单独查也快
  @@map("enrollments")
}
```

| 块级属性 | 作用 | 备注 |
|---------|------|------|
| `@@id([a, b])` | 联合主键 | 复合自然键 |
| `@@unique([a, b])` | 联合唯一约束 | 隐式建组合索引 |
| `@@index([a, b])` | 普通索引（可复合） | 按查询条件建前缀匹配 |
| `@@map("表名")` | 映射**表名** | 见下节 |
| `@@fulltext([...])` | 全文索引 | MySQL/PG 差异大，先不碰 |

> ⚠️ **索引方向**：写 `@@index` 前先问「哪个查询用得到它」。无脑堆索引会拖慢写入（数据库课程 05 章的教训）。Prisma 的索引更多是**声明**，什么时候建、建几列复合，要用 `EXPLAIN` 说话（10 篇再展开）。

## 7. 命名规范与映射策略

一套仓库级约定，直接照抄：

| 约定 | 示例 |
|------|------|
| 模型名 **PascalCase 单数** | `User`、`Post`、`Enrollment` |
| 字段名 **camelCase** | `createdAt`、`updatedAt` |
| 枚举值 **SCREAMING_SNAKE** | `DRAFT`、`PUBLISHED` |
| Prisma 内部用驼峰，数据库用下划线 | `@map("created_at")` + `@@map("enrollments")` |

> 💡 Prisma 默认把模型名转复数小写下划线做表名（`Enrollment` → `enrollments`）、字段名保持原样。如果你不喜欢默认行为，就用 `@@map/@map` 显式声明——**同时保留了 Prisma 代码侧的顺滑命名和 DBA 侧的规范命名**，两边都不妥协。

## 8. 练习（要求 + 提示 + 预期效果）

**要求**：设计一个「社区」的 `Post` + `Comment` 两张表（暂不做表间关系，只做各自字段），必须包含以下要素：自增主键、对外暴露的 slug（唯一）、状态枚举（DRAFT/PUBLISHED/ARCHIVED）、创建/更新时间、点赞数默认 0、tags 数组、一个 `Json` 扩展字段；slug 与状态建联合索引。

**提示**：联合索引用块级属性；枚举先定义再引用；对外字段 `@map` 到数据库下划线命名。

**预期效果**：`migrate dev` 生成的 SQL 里能看到：`CREATE TYPE`（枚举）、`UNIQUE` 约束、复合索引、`DEFAULT` 子句——你能看懂迁移文件并解释每个约束来自 schema 的哪一行。

## 9. 面试问答

> **问：Int 主键和 String UUID 主键怎么选？**

**答：** 内部表（users、配角表）用 `Int autoincrement`：8 字节、索引最快、可读。需要对外暴露 ID（订单号、资源 URL）或用应用层预生成（离线导入、分布式场景）时用 UUID，且 **PG 18 的 `uuid(7)` 时间有序**，不牺牲索引性能——这是 PG 18 相对老版本的关键升级点（呼应数据库课程 01 章）。

> **追问：那 Prisma 的 `cuid()` 呢？**

**答：** `cuid()` 也是有序、应用层生成的字符串 ID，历史兼容性好；但它是 Prisma 自己的实现，**不透明、不是数据库标准**。新项目在 PG 18 上建议直接 `uuid(7)`，与数据库层的生成逻辑统一，`db pull` 反向同步也更自然。

> **问：`Json` 字段什么时候该拆表？怎么判断？**

**答：** 判断标准是「**是否会按内部字段过滤/聚合/排序列举**」。只存取、整体替换（配置、事件 payload）→ Json 合适；要能「按 `payload.source` 统计」→ 拆出独立列或关联表（配合 GIN 索引也仍是渐进方案）。反模式是拿 Json 当万能字段逃避建模，最后写出「无法查询的数据库」。

> **追问：为什么金额用 `Decimal` 而不用 `Float`？**

**答：** IEEE 754 浮点在二进制下无法精确表示 0.1 这类十进制小数，做加法会积累误差（0.1 + 0.2 !== 0.3）。`Decimal` 映射 `numeric`，是十进制精确算术，金额等一分钱都不能错的场景必须用它。这也是面试里最便宜的送分题。

## 10. 三角对比

| 维度 | **Prisma Schema** | TypeORM 实体 | raw SQL DDL |
|------|------------------|-------------|-------------|
| 声明方式 | DSL（`.prisma`） | TS 装饰器类 | SQL 语句 |
| 类型映射 | 声明式，自带默认 | 装饰器可配 | 无（数据库说了算） |
| 迁移 | `migrate dev` 自动 diff | 手动/CLI 半自动 | 手写 + 版本管理 |
| 可读性 | 高（一页看懂全表） | 中（装饰器噪音） | 中（长） |
| 与数据库对齐 | `db pull` 反推 | 需双向同步 | 天然一致 |
