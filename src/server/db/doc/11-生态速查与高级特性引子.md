## 2. 速查：一句话清单

| 项 | 一句话定位 | 何时去看 | 状态 |
|----|-----------|---------|------|
| **Prisma Postgres** | Prisma 自家的托管 PostgreSQL（含连接池/分支/Studio） | 不想自建 PG、要托管 + 集成 | 托管服务 |
| **Accelerate** | 托管连接池 + 边缘缓存，把查询提到靠近用户 | serverless / 跨区域延迟敏感 | GA |
| **Pulse** | 数据库变更事件流（订阅 Postgres 变更） | 做实时通知、买家行为流 | GA |
| **Optimize** | AI 驱动查询性能分析与建议 | 有慢查询不知道从哪下手 | GA |
| **Client Extensions**（`$extends`） | 给 Client 加自定义方法/查询钩子（`$use` 中间件已移除，v6.14+） | 横切逻辑（审计、软删除、统一计算字段） | GA |
| **TypedSQL** | 手写 SQL 也带类型（`.sql` 文件编译检查） | 对特定查询要 100% 掌控 SQL 又不丢类型 | preview |
| **Views（数据库视图）** | schema 里声明 SQL view 并可查询 | 报表/复用复杂 JOIN 成"虚拟表" | preview |
| **Partial / Expression Indexes** | 部分索引 / 表达式索引（针对查询的子集） | PG 上只给活跃行建索引 | preview（7.4+） |
| **RLS（Row-Level Security）** | 行级安全策略（在 schema/TS 里写策略） | 多租户数据隔离 | Prisma 8（RC 中） |
| **MongoDB 支持** | 手头 v7 不原生支持，需退回 v6 | 项目确实用 Mongo | v7 缺失 |

## 3. 三条常用度最高的引子

### 3.1 Client Extensions（`$extends`）—— 最该先学的"进阶但常用"

`$use` 中间件在 v6.14.0 被移除，替代者是扩展（v4.16 起 GA）。给"每次 create 自动填 createdAt/排序字段"或"软删除默认过滤"这类横切逻辑用：

```ts
import { PrismaClient } from "./generated/prisma/client"
import { PrismaPg } from "@prisma/adapter-pg"

const prisma = new PrismaClient({ adapter: new PrismaPg({ connectionString: DATABASE_URL }) })
  .$extends({
    query: {
      $allModels: {
        async create({ model, args, query }) {
          const t0 = Date.now()
          const res = await query(args)          // 调用原逻辑
          console.log(`${model} create took ${Date.now() - t0}ms`)   // 横切：打点
          return res
        },
      },
    },
  })
```

> 💡 记住概念即可：`query` 块 = 拦截操作（可包原 `query`），`model` 块 = 加模型方法，`client` 块 = 加客户端级方法。需要时再翻官方文档。

### 3.2 TypedSQL——"我想手写 SQL 还想要类型"

写 `q.sql` 文件（如 `scripts/getTopUsers.sql`），`prisma generate` 时编译检查表名/列名/类型，运行时是**类型安全的手写 SQL**：

```ts
import { getTopUsers } from "./queries"

const topUsers = await getTopUsers(prisma, { limit: 10 })
// ✓ 类型推导，编译期校验
```

**适用**：Prisma 的声明式 API 表达不了的复杂查询（CTE、窗口函数）。

### 3.3 Views——把复杂 SELECT 变成"可查询的模型"

```prisma
view RecentPosts {
  id      Int
  title   String
  authorName String
  @@sql(`SELECT p.id, p.title, u.name AS "authorName" FROM "Post" p JOIN "User" u ON u.id = p."authorId"`)
}
```

定义后 `prisma.recentPosts.findMany()` 就能查它。**视觉上像一张表，实际是预编译查询**——报表场景的"虚拟表"。

## 6. 面试问答

> **问：Prisma 和 Prisma Postgres / Accelerate 是什么关系？**

**答：** Prisma（ORM）是开源的库；Prisma Postgres 是 Prisma 提供的托管 PostgreSQL（自带池/分支），Accelerate 是它的连接优化 + 缓存服务，Pulse 是数据库事件流，Optimize 是 AI 慢查询分析。**它们是同一家的"数据库服务 + 可观测"产品线**，都是可选的——不接它们，Prisma ORM 照样跑在你自己的 PG 上。

> **追问：那面试里"Prisma 是不是很重"怎么答？**

**答：** 区分三件事：ORM 本身在 Prisma 7 后已瘦身（纯 TS、90% 体积降幅）；加不加托管服务是可选项；团队里它的"重"更多来自**团队是否接受 schema 驱动 + 生成流程**，而不是运行时开销。愿意用一局清楚干净的心智模型换掉 SQL 字符串的团队，Prisma 是轻的。

> **问：什么时候该升级用显式 SQL（TypedSQL）而不是 Prisma API？**

**答：** 当"Prisma 声明式模型"表达成本高、或性能要求必须手写 SQL 时（复杂 CTE、窗口函数、专有聚合）。TypedSQL 的价值是**在完全掌控 SQL 的同时保留编译期类型**，等于"raw SQL 的生产力 + ORM 的安全感"。判断标准：看着 Prisma API 写抽搐、或 EXPLAIN 也救不回来时，升级。

> **追问：向面试官解释 RLS 用在哪种场景？**

**答：** 行级安全策略（Row-Level Security）是数据库层"每行可见性"的强制，典型是**多租户**：租户 A 的 SQL 永远看不到租户 B 的行，即使应用层漏了 where 也兜底。Prisma 8 支持在 schema/TS 里写 RLS 策略——注意到这是**即将 GA 的能力**，目前是预览/RC 形态，涉及生产慎用。

## 7. 三角对比

| 维度 | **Prisma（含生态）** | Drizzle + 自选周边 | raw SQL + 手搓 |
|------|---------------------|--------------------|----------------|
| 托管加速 | Accelerate/Pulse 现成 | 无官方，自组 Redis | 全手写 |
| 高级能力 | extensions/TypedSQL/Views | SQL 原生表达 | 全手写 |
| 锁定制 | Prisma 平台服务绑定其生态 | 框架中立 | 完全自由 |
| 何时选 | 靠 Prisma 提升生产力 | 要 100% 控制 SQL | 极简/极致 |
