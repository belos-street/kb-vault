# 02 — 数据建模：字段类型与约束

> **本系列基于 Prisma ORM 7.x**（2026-08 编写）。

- **预计时间**：45 min ｜ **前置**：01

**一句话定位**：把 `schema.prisma` 的类型、属性、映射讲全，让你能写出「字段该有的约束都有」的生产级表结构。

**面试可答**：约束全靠字段属性（`@id/@default/@unique/@updatedAt`）与块级属性（`@@unique/@@index`）；`@map/@@map` 让 Prisma 侧命名清爽、数据库侧命名合规两不误。

---

## 1. 标量类型全景

| Prisma 类型 | PostgreSQL 映射 | 说明 |
|------------|----------------|------|
| `String` | `text` / `varchar` | 默认 `text`，可用 `@db.VarChar(n)` 收紧 |
| `Boolean` | `boolean` | |
| `Int` / `BigInt` | `integer` / `bigint` | 32 位够用；亿级 ID 或雪花 ID 用 BigInt |
| `Float` / `Decimal` | `double precision` / `numeric` | **金额必用 Decimal**，不踩 Float 精度坑 |
| `DateTime` | `timestamp(3)` | `@db.Timestamptz()` 存带时区 |
| `Json` | `jsonb` | 半结构化字段，PG 可索引 |
| `Bytes` | `bytea` | 二进制 |

**选型口诀**：内部 ID 用 `Int`；对外暴露的 ID 用 `String @id @default(uuid(7))`（Prisma v5.18+ 在 Client 侧生成、时间有序——注意与 PG 18 的 `uuidv7()` 数据库函数是两回事）；金额 `Decimal`；不稳定结构 `Json`。

## 2. 字段属性：约束的主力

```prisma
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String?
  age       Int      @default(18)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

| 属性 | 含义 | 高频用法 |
|------|------|----------|
| `@id` | 主键 | `autoincrement()` / `uuid(7)` / `cuid()` |
| `@default()` | 默认值表达式 | `now()`、`autoincrement()`、字面量、`[]` |
| `@unique` | 唯一约束（隐式建索引） | email、slug |
| `@updatedAt` | 写入时自动刷新时间 | 不需要手动赋值，Prisma 全包 |
| `@map` | 映射**列名** | 驼峰字段 ↔ 下划线列名 |

## 3. 枚举与数组

```prisma
enum PostStatus {
  DRAFT
  PUBLISHED
  ARCHIVED
}

model Post {
  id     Int        @id @default(autoincrement())
  title  String
  status PostStatus @default(DRAFT)
  tags   String[]   // PG 原生数组（scalar list）
}
```

- 枚举在 PG 上映射**原生 enum**（迁移生成 `CREATE TYPE`）；SQLite 不支持才退化为 text
- `String[]` 适合 tags 这类「一列一串值」；一旦要按某项单独查询/过滤，就该拆关联表（03 篇）

## 4. Json 字段

```prisma
model Event {
  id      Int   @id @default(autoincrement())
  type    String
  payload Json  @default("{}")
}
```

写直接传对象、读拿回来就是 JS 对象（无需 parse）；PG 上映射 `jsonb`。**反模式提醒**：Json 不是逃避规范化的工具——频繁按内部字段过滤/聚合的该拆列拆表。

## 5. 块级属性：联合约束与索引

```prisma
model Enrollment {
  studentId Int
  courseId  Int
  status    String @default("active")

  @@id([studentId, courseId])     // 联合主键：天然去重
  @@index([courseId])             // 按 courseId 单独查也快
  @@map("enrollments")
}
```

| 块级属性 | 作用 |
|---------|------|
| `@@id([a, b])` | 联合主键 |
| `@@unique([a, b])` | 联合唯一（隐式组合索引） |
| `@@index([a, b])` | 普通索引（可复合，按查询条件建前缀匹配） |
| `@@map("表名")` | 映射表名 |

> ⚠️ 建索引前先问「哪个查询用得到它」。无脑堆索引拖慢写入；Prisma 的索引是**声明**，走没走索引用 `EXPLAIN` 说话（07 篇）。

## 6. 命名规范与映射策略

| 约定 | 示例 |
|------|------|
| 模型名 PascalCase 单数 | `User`、`Post` |
| 字段名 camelCase、枚举值 SCREAMING_SNAKE | `createdAt`、`DRAFT` |
| Prisma 驼峰 ↔ 数据库下划线 | `@map("created_at")` + `@@map("enrollments")` |

> 💡 默认行为：模型名转复数小写下划线做表名（`Post` → `posts`）。不喜欢就用 `@@map/@map` 显式声明——代码侧顺滑与 DBA 侧规范两边都不妥协。

## 7. ✍️ 练习

**要求**：设计 `Post` + `Comment` 两张孤立表（不做关系），包含：自增主键、对外 slug（唯一）、状态枚举、创建/更新时间、tags 数组、Json 扩展字段、slug+状态联合索引。**提示**：联合索引用块级属性；对外字段 `@map` 到下划线。**预期效果**：`migrate dev` 的 SQL 里能看到 `CREATE TYPE`、`UNIQUE`、复合索引、`DEFAULT`——你能解释每个约束来自 schema 哪一行。

## 📌 小结

- 类型口诀：内部 `Int`、对外 `uuid(7)`、金额 `Decimal`、时间 `DateTime`、半结构化 `Json`
- `@updatedAt` 是 Prisma 全包的；`@map/@@map` 解决两侧命名分歧
- 联合主键 `@@id` 天然去重，是最便宜的「防重复」手段
