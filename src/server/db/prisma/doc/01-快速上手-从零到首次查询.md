# 01 — 快速上手：从零到首次查询

> **本系列基于 Prisma ORM 7.x**（2026-09 更新：Prisma 8 已 GA 成为 `prisma@latest`，v7 转为 `prisma@prev` 官方持续支持，本系列仍以 v7 为基线。所有代码均为 v7 写法，与网上大量 v5/v6 教程不同，注意对照）。

- **预计时间**：45 min ｜ **前置**：无

**一句话定位**：回答「为什么用 ORM、Prisma 7 换了什么、怎么选」，然后 5 分钟内建表、插一条、查回来。

**面试可答**：Prisma 用 Schema 作为唯一数据源生成类型安全的 Client；v7 是架构级换代——Rust 引擎换成 TS+WASM Query Compiler、强制 Driver Adapter、统一 `prisma.config.ts`。

---

## 1. 为什么用 ORM（30 秒版）

用原生 `pg` 驱动写查询有三个痛点：**无类型**（`res.rows` 是 `any[]`，字段拼错运行时才炸）、**SQL 字符串拼接是注入重灾区**（需求一复杂拼接就失控）、**阻抗失配**（代码里是对象结构，数据库里是表 + 外键，手工装配是纯 boilerplate）。

> 💡 ORM 的出现不是为了消灭 SQL，而是消灭这三件事。顺带正名一个经典黑点：**N+1 是「用错了」（循环里逐条查关联），不是 ORM 的错**——好的 ORM 用 `include` 一条调用解决（04 篇展开）。

## 2. Prisma 是什么

TypeScript 生态的 ORM + 数据层工具链，核心心智模型是 **Schema 单一数据源**：

```mermaid
graph LR
  A[prisma/schema.prisma] -->|prisma generate| B[Prisma Client<br/>类型安全查询]
  A -->|prisma migrate dev| C[数据库表结构]
  B -->|类型检查| D[业务代码]
  C -->|data| B
```

改表只改 Schema 一处，迁移和客户端类型同步派生——**表和代码永远不说两套话**。

### Prisma 7：架构级换代（面试必答）

| 维度 | Prisma 5/6 | Prisma 7 |
|------|-----------|----------|
| 查询引擎 | Rust 二进制 | **纯 TS + WASM Query Compiler** |
| 数据库连接 | 内置默认驱动 | **强制 Driver Adapters**（`@prisma/adapter-pg` 等） |
| 生成产物 | `@prisma/client`（写进 node_modules） | **`prisma-client` provider + 指定 `output`** |
| 配置 | package.json `prisma` key | **统一 `prisma.config.ts`** |
| 体积/冷启动 | ~14MB / 慢 | **~1.6MB（-90%）/ 明显改善** |

> ⚠️ **版本红线**：v7 不支持 MongoDB（需退回 v6），本系列全程 PostgreSQL；网上 v5/v6 教程的 `@prisma/client` + 无 adapter 写法在 v7 **照抄即错**。📎 [v7 Release Notes](https://github.com/prisma/prisma/releases/tag/7.0.0) · [v7 升级指南](https://www.prisma.io/docs/guides/upgrade-prisma-orm/v7)

## 3. 选型结论（本系列唯一一次对比）

| 维度 | **Prisma** | Drizzle ORM | raw SQL（pg） |
|------|-----------|-------------|---------------|
| 心智模型 | Schema 声明式 → 生成类型 | TS 优先、贴近 SQL | SQL 字符串 |
| 类型安全 | 强（生成式） | 强（推断式） | 无 |
| 性能 | 中（有运行时开销，已大幅优化） | **高（近零抽象）** | 最高 |
| 迁移工具 | ✅ 内置 Migrate | ✅ drizzle-kit | ❌ 手写 |
| 适用 | **产品快速开发、团队协作** | 性能敏感、要控 SQL | 极致性能/复杂 SQL |

**一句话**：日常后端 CRUD、要类型安全和迁移体系 → Prisma；性能敏感或团队 SQL 功底深 → Drizzle；raw SQL 永远是可退回的基线。

## 4. 上手：五步跑通

### 4.1 项目与数据库

```bash
mkdir prisma-demo && cd prisma-demo
bun init -y
# package.json 加 "type": "module"（Prisma 7 硬要求，ESM 发行）和 "scripts": { "dev": "bun run src/index.ts" }

docker run --name pg18 -e POSTGRES_USER=prisma -e POSTGRES_PASSWORD=prisma -e POSTGRES_DB=demo \
  -p 5432:5432 -d postgres:18

bun add @prisma/client@7 @prisma/adapter-pg
bun add -d prisma@7
echo 'DATABASE_URL="postgresql://prisma:prisma@localhost:5432/demo?schema=public"' > .env
```

### 4.2 初始化与 Schema

```bash
bunx prisma init
```

把 `prisma/schema.prisma` 改成：

```prisma
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
}

datasource db {
  provider = "postgresql"
}

model User {
  id    Int    @id @default(autoincrement())
  email String @unique
  name  String?
}
```

| 块 | 作用 | v7 注意点 |
|----|------|-----------|
| `generator client` | 声明客户端产物 | **provider 必须是 `prisma-client`**；**`output` 必填**（不再丢进 node_modules） |
| `datasource db` | 声明数据库类型 | **只剩 `provider`**——连接串已移入 `prisma.config.ts` |

`prisma.config.ts`（init 已生成，核对）：

```ts
import "dotenv/config"
import { defineConfig, env } from "prisma/config"

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: { path: "prisma/migrations" },
  datasource: { url: env("DATABASE_URL") },
})
```

> 💡 **v6 → v7 最大区别**：连接串从 schema 移到 config.ts，且**环境变量不再自动加载**（所以要 `import "dotenv/config"`）。Bun 运行应用代码会自动加载 .env；但 `prisma.config.ts` 是 Prisma CLI（Node 进程）加载的，这行 import 保留最稳。

### 4.3 建表 + 生成客户端

```bash
bunx prisma migrate dev --name init   # diff schema 与库 → 生成 SQL 迁移文件 → 执行
bunx prisma generate                  # v7 起不再自动 generate，手动补
```

> 💡 打开 `prisma/migrations/<时间戳>_init/migration.sql` 看一眼——迁移文件是人类可读的 SQL，能直接看到 `@default(autoincrement())` 翻译成了什么。

### 4.4 首次查询

```ts
// src/index.ts
import { PrismaPg } from "@prisma/adapter-pg"
import { PrismaClient } from "./generated/prisma/client"   // v7 从你配的 output 导入

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL! })
const prisma = new PrismaClient({ adapter })

async function main() {
  const user = await prisma.user.create({
    data: { email: "alice@example.com", name: "Alice" },
  })
  console.log("created:", user)
  console.log("all:", await prisma.user.findMany())
}

main()
  .catch((e) => { console.error(e); process.exit(1) })
  .finally(async () => { await prisma.$disconnect() })
```

```bash
bun run dev
# created: { id: 1, email: 'alice@example.com', name: 'Alice' }
```

> ⚠️ v6 是 `import { PrismaClient } from "@prisma/client"`；v7 **必须从 output 路径导入**。

### 4.5 零配置备选：SQLite（可选）

不起 Docker 时把 datasource 换 `sqlite`、adapter 换 `@prisma/adapter-better-sqlite3` 即可——**换数据库 ≈ 换 provider + 换 adapter**，业务代码零改动。本系列后续仍以 PostgreSQL 为主。

**要求**：给 `User` 加 `age Int?` 字段再迁一次；写入一个 `age: 30` 的用户；用 `findFirst({ where, select: { name: true } })` 查回**只含 name** 的结果。**提示**：`select` 会把返回类型收缩到只含所选字段。**预期效果**：你能复述「改字段 = 改 schema → migrate → generate」三步闭环，且看到类型精确收缩。

## 6. 💬 面试问答（本系列 4 组之一）

> **问：为什么说 Prisma 类型安全？和 Drizzle 怎么选？**

**答**：区别在「类型从哪来」——Prisma 从 Schema **生成**类型，查询入参出参都是编译期推导（字段拼错、漏必填是编译错误）；Drizzle 靠 TS **推断**，schema 就是代码。选 Prisma 的前提是认可「消耗一次生成步骤，换 Schema 声明式单一数据源」，适合团队协作结构先行；要完全掌控 SQL 选 Drizzle。

> **追问：Prisma 7 把 Rust 引擎换成 TS+WASM，性能没倒退吗？**

**答**：官方口径查询不降反升（up to 3x faster），换来 90% 体积缩减与更快冷启动，动机是 serverless 化。代价是连接管理外置给 Driver Adapter——连接池配置不再由 Prisma 兜底（pg 默认无连接超时，v6 是 5 秒），这是 v7 生产环境最常见的坑（见 07 篇）。

> **问：`migrate dev` 和 `migrate deploy` 的区别？**

**答**：`dev` 用于开发——diff schema 与库、生成迁移文件、**可能提示重置**；`deploy` 用于生产——只按顺序执行已有迁移文件，**不 diff、不重置**。一句话：`dev` 边想边写，`deploy` 照单执行（05 篇展开）。

## 📌 小结

- ORM 消灭的是：类型丢失、SQL 拼接、手工装配；N+1 是用错了不是 ORM 的错
- Schema 单一数据源：迁移与客户端类型同源派生
- v7 三件事：`prisma-client` provider + output、Driver Adapter、`prisma.config.ts`
