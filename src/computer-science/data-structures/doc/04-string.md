# 第 4 章：串

> 串在 408 里分值不高（1-2 道选择题，重要度 ⭐⭐），但 **KMP 的 next / nextval 数组手算**是每年 1 道选择题的常客，属于"会者不难、不会者无从下手"的题型。本章真正的难点只有一个——**next 数组的构造**，它是 KMP 的全部核心：匹配过程反而是简单的机械执行。串的存储和 BF 算法属于基础送分内容，扫一遍即可。本章建议花 2-3 小时，把精力集中在本章 4.4 和 4.5 的例题验算上——**所有数组结果必须自己亲手推一遍**，光看不练等于白学。

## 4.1 串的定义与基本概念

**串（String）** 是由零个或多个字符组成的**有限序列**，一般记为：

$$S = 'a_1 a_2 \ldots a_n' \quad (n \ge 0)$$

其中 $S$ 是串名，单引号括起来的字符序列是串的值， $n$ 称为串的**长度**。字符可以是字母、数字或其他字符，但 408 考题里通常就是普通可见字符。

> 串是**内容受限的线性表**：数据元素必须是字符。因此 [第 2 章（线性表）](02-linear-list.md) 中学过的顺序存储、链式存储思想在这里直接复用——只是"元素"从 int 换成了 char。这也是本章篇幅短的原因：存储结构是线性表的老套路，真正的新东西只有 KMP。

### 基本术语

| 术语 | 定义 | 例子（以 $S='ababc'$ 为例） |
|------|------|------------------------------|
| **串** | 零个或多个字符组成的有限序列 | `'ababc'` |
| **子串** | 串中**任意连续**个字符组成的子序列 | `'ab'`、`'ba'`、`'abc'` 都是子串 |
| **主串** | 包含子串的串 | `'ababc'` 是 `'abc'` 的主串 |
| **模式串** | 在主串中寻找的特定子串（目标串） | 在 `'ababc'` 中查找 `'abc'`，`'abc'` 即模式串 |
| **位置** | 字符（或子串）在主串中的**序号**，通常从 **1** 开始 | `'abc'` 在 `'ababc'` 中的位置是 3 |
| **空串** | 长度为 0 的串，记为 `''`（不含任何字符） | `''` |
| **空格串** | 只含空格字符的串，长度 $\ge 1$ | `'   '` 长度为 3 |

> 易错点：**空串 `''`（长度为 0）和空格串 `' '`（长度 $\ge 1$ ）是两回事**，选择题常在这里设坑。另外**子串必须是"连续的"**，从 `'ababc'` 中取 `'ac'`（跳过了中间的 b）不是子串——那是"子序列"，两者不要混淆。

串的基本运算：求长度 `StrLength`、求子串 `SubString`、比较 `StrCompare`、定位 `Index`（即模式匹配）等。408 考试重点在最后一个：**模式匹配**。

## 4.2 串的存储结构

### 4.2.1 定长顺序存储

用一组地址连续的存储单元存储串，类似于定长顺序表，通常用一个字符数组 `char ch[MAXLEN]` 加上长度变量实现：

```c
#define MAXLEN 255

typedef struct {
    char ch[MAXLEN];   // 字符数组，存储串值
    int length;        // 串的实际长度
} SString;             // 定长顺序串
```

> **截断问题**：定长存储的空间固定为 `MAXLEN`，一旦串的实际长度超过 `MAXLEN`，超出的字符被**截断**丢弃——这是定长存储最大的缺陷，也是它与 4.2.2 堆分配存储的本质区别。408 选择题可能问"某操作导致字符丢失的原因"，答案就是定长顺序存储。

### 4.2.2 堆分配存储

堆分配存储仍然用一组连续空间，但空间大小是**动态申请**的（按串的实际长度分配），克服了截断问题：

```c
typedef struct {
    char *ch;    // 按串长分配存储区的首地址
    int length;  // 串的长度
} HString;       // 堆分配串
```

操作时用 `malloc` / `free`（C 中）动态管理内存：插入、连接等操作先生成新的存储区、复制内容、再释放旧空间。

> 我们常写的 C 字符串（`char *` + `'\0'` 结尾）本质上就是堆分配思想的简化版，参见 [C 语言第 2 章（数组与指针）](../../../programming-languages/c/doc/02-pointers-and-arrays.md) 的 2.7 节：`strlen` 数到 `'\0'`、`strcpy` 复制含 `'\0'`，这些逐字符操作模板正是本章 KMP 逐字符比较的基础。

### 4.2.3 块链存储（了解）

用链表存储串。由于一个结点只存一个字符时存储密度太低（指针占空间远大于字符），通常**每个结点存放多个字符（一块）**，称块链结构：

```c
#define CHUNKSIZE 80

typedef struct Chunk {
    char ch[CHUNKSIZE];        // 每个结点存 80 个字符
    struct Chunk *next;        // 指向下一结点
} Chunk;

typedef struct {
    Chunk *head, *tail;        // 头指针、尾指针
    int length;                // 串长度
} LString;                     // 块链串
```

块链存储**不便于随机访问**（找第 k 个字符要顺着指针走），且最后一个结点可能不满，408 只要求"了解"级别。

### 三种存储方式对比

| 存储方式 | 空间是否固定 | 是否截断 | 随机访问 | 考纲要求 |
|----------|-------------|---------|---------|---------|
| 定长顺序存储 | 固定（`MAXLEN`） | 超长会截断 | 支持 | 掌握 |
| 堆分配存储 | 动态分配 | 不截断 | 支持 | 掌握 |
| 块链存储 | 链式、按块分配 | 不截断 | 不支持 | 了解 |

> 408 真题中串的存储直接考察较少，但"**定长存储超长截断**""**堆分配克服截断**"是 1 分选择题的高频陷阱，务必分清。

## 4.3 朴素模式匹配（BF 算法）

### 算法思想

**BF（Brute-Force，暴力匹配）** 的思路朴素直接：用模式串 $T$ 依次与主串 $S$ 中每个可能的起点对齐，逐字符比较，全部相等即匹配成功。

- 主串指针 $i$ 、模式串指针 $j$ 都从 1 开始；
- 若 $S[i] = T[j]$ ，则 $i$ 、 $j$ 同时后移一位继续比较；
- 若失配，**主串指针回溯**：本轮比较的起点是 $i-j+1$ ，该起点已和 $T[1]$ 比较失败，故 $i$ 回到起点下一位，即 $i = i-j+2$ ；**模式串指针** $j$ 回溯到 1，重新开始。

> 易错点：很多同学把失配时的回溯写成 `i = i - j + 1`，这是**错的**。 $i-j+1$ 是本轮比较的起点位置，它已经和 $T[1]$ 比较过且失败，必须再前进一位，所以代码里是 **`i = i - j + 2`**（ $j=1$ 时恰为 `i+1`）。这个 +2 的细节选择题常考。

### 完整代码

```c
// 1 起点约定：S[1..S.length]、T[1..T.length] 存放串，下标 0 不用
int Index_BF(SString S, SString T) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (S.ch[i] == T.ch[j]) {   // 字符相等：双指针后移
            ++i;
            ++j;
        } else {                    // 字符不等：主串回溯，j 回到 1
            i = i - j + 2;          // 回溯到本轮起点 i-j+1 的下一位
            j = 1;
        }
    }
    if (j > T.length)               // j 走完模式串，匹配成功
        return i - T.length;        // 返回子串在主串中的起始位置
    else
        return 0;                   // 匹配失败
}
```

### 最坏情况 $O(mn)$ 的失效推演

看经典的最坏情形：主串 $S='0000000001'$ （ $n=10$ ），模式串 $T='0001'$ （ $m=4$ ）。 $T$ 的前 3 个字符都是 0，只有最后一个字符 1 能区分"是否匹配"，于是 BF 几乎每次都在**最后一个字符**才失配：

| 起点 | 对齐的比较过程 | 结果 | 比较次数 |
|------|---------------|------|---------|
| 1 | `0000` vs `0001`，前 3 个 0 相等，第 4 位 0 vs 1 | 失配 | 4 |
| 2 | `0000` vs `0001`，前 3 个 0 相等，第 4 位 0 vs 1 | 失配 | 4 |
| 3 | `0000` vs `0001`，前 3 个 0 相等，第 4 位 0 vs 1 | 失配 | 4 |
| 4 | `0000` vs `0001`，前 3 个 0 相等，第 4 位 0 vs 1 | 失配 | 4 |
| 5 | `0000` vs `0001`，前 3 个 0 相等，第 4 位 0 vs 1 | 失配 | 4 |
| 6 | `0000` vs `0001`，前 3 个 0 相等，第 4 位 0 vs 1 | 失配 | 4 |
| 7 | `0001` vs `0001` | 全部相等，成功 | 4 |

起点共有 $n-m+1 = 7$ 个，每个起点比较 $m=4$ 次，总比较次数：

$$(n-m+1) \times m = 7 \times 4 = 28 \ \text{次}$$

当 $m \ll n$ 时约为 $mn$ ，即 **BF 最坏时间复杂度为 $O(mn)$**。

> 观察上面的推演：主串 $i$ 反复回溯（第 1 轮比较到 $i=4$ 后回到 $i=2$ 、再回到 $i=3$……），大量重复比较已经比过的字符——第 2 轮的前 3 个 0 在第 1 轮已经比过。**这个"重复劳动"正是 KMP 要消灭的东西**：如果失配时主串指针不回溯、只让模式串滑动，就不会有任何重复比较。

## 4.4 KMP 算法（本章核心）

### 4.4.1 为什么需要 KMP

BF 的浪费在于：**主串指针 $i$ 回溯**导致已比较过的字符被反复比较。KMP 的核心思想是：**主串指针 $i$ 永不回溯**，失配时只移动模式串指针 $j$ 。

但 $j$ 不能总回到 1。回想 BF 中模式串 `'abaabc'` 匹配到某处失败时：既然模式串前 $j-1$ 个字符已经和主串对应位置**相等**，那么主串这段已匹配的尾巴**已经知道了内容**——它就是模式串的前 $j-1$ 个字符。因此完全可以根据模式串自身的结构，把 $j$ 直接滑动到一个"已匹配部分的后缀能对齐前缀"的位置，跳过必然失败的比较。

这个"滑动目标"预先计算好、存进一个数组，就是 **next 数组**。

### 4.4.2 next 数组的含义

**next[j] 表示：模式串第 $j$ 个字符失配时， $j$ 应回退到的位置。** 等价地：

> next[j] = 模式串前 $j-1$ 个字符组成的子串（已匹配部分）的**最长相等前后缀长度 + 1**。

其中：

- **前缀**：除最后一个字符外，从首字符开始的所有子串；
- **后缀**：除第一个字符外，以末字符结束的所有子串；
- **相等前后缀**：某个前缀恰好等于某个后缀（长度相同且内容相同）。

边界规定：next[1] = 0（1 起点约定下，表示模式串第一个字符就失配，此时主串 $i$ 前进、 $j$ 保持 1）；next[2] = 1（前 1 个字符没有前后缀可言，最长相等前后缀长度为 0，0+1=1）。

> 易错点：**前缀不能取整个子串本身（不含最后一个字符），后缀也不能取整个子串（不含第一个字符）**，且要找的是**最长**的相等前后缀。例如 `'aba'` 的相等前后缀只有 `'a'`（长度 1），不能把整个 `'aba'` 算进去。

### 4.4.3 手算方法一：定义法（前后缀法）

按定义一步步来，适合手算和考试：

1. next[1] = 0，next[2] = 1（规定，直接写）；
2. 对 $j \ge 3$ ：看模式串前 $j-1$ 个字符，找它的**最长相等前后缀**，长度记 $k$ ，则 next[j] = $k+1$ 。

> 求某子串的最长相等前后缀：写出全部前缀、全部后缀，取"既在前缀集合中又在后缀集合中"的最长者。注意**前缀从短到长、后缀也从短到长**，肉眼即可找。

### 4.4.4 手算方法二：递推构造法（代码法）

用递推关系构造，实际是 next 数组生成算法的原理，比定义法更快、也更能应对 408 的选择题（题目常给代码让你推结果）：

```c
// 求模式串 T 的 next 数组（1 起点，T[0] 存放串长度，T[1] 起为字符）
void get_next(SString T, int next[]) {
    int i = 1, j = 0;
    next[1] = 0;                          // 规定
    while (i < T.length) {                // i 扫到模式串末尾为止
        if (j == 0 || T.ch[i] == T.ch[j]) {
            ++i;                          // 匹配成功：i、j 同时前进
            ++j;
            next[i] = j;                  // 推出 next[i]
        } else {
            j = next[j];                  // 失配：j 回溯（核心技巧）
        }
    }
}
```

> 这段代码的**核心技巧是 `j = next[j]`**：当 $T[i] \ne T[j]$ 时， $j$ 不是简单回退到 1，而是回退到 next[j]（利用已算好的、更短的相等前后缀），这正是 KMP 思想在"构造 next 数组"这件事上的递归应用——**构造 next 数组的过程本身就是一个 KMP 匹配过程**（模式串对自己匹配）。理解了这一点，整章就通了。

### 4.4.5 完整手算例题

**例：求模式串 $T='abaabcac'$ 的 next 数组（1 起点）。**

**解**：next[1]=0，next[2]=1；对 $j \ge 3$ 用定义法：

| $j$ | 前 $j-1$ 个字符 | 前缀集合 | 后缀集合 | 最长相等前后缀 | next[j] |
|-----|----------------|---------|---------|---------------|---------|
| 1 | — | — | — | — | **0**（规定） |
| 2 | `a` | — | — | 无（长度 0） | **1**（规定） |
| 3 | `ab` | {a} | {b} | 无 | 0+1 = **1** |
| 4 | `aba` | {a, ab} | {a, ba} | `a`（长 1） | 1+1 = **2** |
| 5 | `abaa` | {a, ab, aba} | {a, aa, baa} | `a`（长 1） | 1+1 = **2** |
| 6 | `abaab` | {a, ab, aba, abaa} | {b, ab, aab, baab} | `ab`（长 2） | 2+1 = **3** |
| 7 | `abaabc` | {a, ab, aba, abaa, abaab} | {c, bc, abc, aabc, baabc} | 无 | 0+1 = **1** |
| 8 | `abaabca` | {a, ab, aba, abaa, abaab, abaabc} | {a, ca, bca, abca, aabca, baabca} | `a`（长 1） | 1+1 = **2** |

**结果：next = (0, 1, 1, 2, 2, 3, 1, 2)**。

再用**递推法**核对一遍（能推出一致结果说明方法正确）：

- 初始化：i=1, j=0，next[1]=0；
- i=1,j=0 → j==0，i=2,j=1，next[2]=1；
- i=2,j=1：T[2]=b vs T[1]=a 不等 → j=next[1]=0；
- i=2,j=0 → j==0，i=3,j=1，next[3]=1；
- i=3,j=1：a=a 相等 → i=4,j=2，next[4]=2；
- i=4,j=2：a vs b 不等 → j=next[2]=1；
- i=4,j=1：a=a → i=5,j=2，next[5]=2；
- i=5,j=2：b=b → i=6,j=3，next[6]=3；
- i=6,j=3：c vs a 不等 → j=next[3]=1；c vs a 仍不等 → j=next[1]=0；
- i=6,j=0 → j==0，i=7,j=1，next[7]=1；
- i=7,j=1：a=a → i=8,j=2，next[8]=2；i=8 已达串长，结束。

**结果一致：next = (0, 1, 1, 2, 2, 3, 1, 2)** ✅

**再练一个：求 $T='ababaa'$ 的 next 数组。**

**解**：

| $j$ | 前 $j-1$ 个字符 | 最长相等前后缀 | next[j] |
|-----|----------------|---------------|---------|
| 1 | — | — | **0** |
| 2 | `a` | 无 | **1** |
| 3 | `ab` | 无 | **1** |
| 4 | `aba` | `a`（长 1） | **2** |
| 5 | `abab` | `ab`（长 2） | **3** |
| 6 | `ababa` | `aba`（长 3） | **4** |

**结果：next = (0, 1, 1, 2, 3, 4)**。

### 4.4.6 KMP 匹配过程模拟

KMP 匹配算法代码如下：

```c
// 用 next 数组进行模式匹配（1 起点），返回模式串在主串中的起始位置，失败返回 0
int Index_KMP(SString S, SString T, int next[]) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (j == 0 || S.ch[i] == T.ch[j]) {  // 注意 j==0 的特殊处理
            ++i;
            ++j;
        } else {
            j = next[j];                     // 失配：主串 i 不动，只动 j
        }
    }
    if (j > T.length)
        return i - T.length;
    else
        return 0;
}
```

> 与 BF 代码对比，KMP 只有两处不同：① 失配分支从"`i = i-j+2; j = 1;`"变成"`j = next[j];`"，**主串指针 i 完全不动**；② 循环条件多了一个 `j == 0` 的分支（当 j 回退到 0 时，说明模式串第一个字符也失配，此时 i、j 同时前进重新对齐）。

**模拟：主串 $S='ababaabcac'$ （ $n=10$ ），模式串 $T='abaabcac'$ （ $m=8$ ），next = (0,1,1,2,2,3,1,2)。**

| 轮次 | 比较前 (i, j) | 比较 S[i] vs T[j] | 结果 | 操作后 (i, j) |
|------|--------------|------------------|------|--------------|
| 1 | (1, 1) | a vs a | 相等 | (2, 2) |
| 2 | (2, 2) | b vs b | 相等 | (3, 3) |
| 3 | (3, 3) | a vs a | 相等 | (4, 4) |
| 4 | (4, 4) | b vs a | 失配 | (4, next[4]=2) |
| 5 | (4, 2) | b vs b | 相等 | (5, 3) |
| 6 | (5, 3) | a vs a | 相等 | (6, 4) |
| 7 | (6, 4) | a vs a | 相等 | (7, 5) |
| 8 | (7, 5) | b vs b | 相等 | (8, 6) |
| 9 | (8, 6) | c vs c | 相等 | (9, 7) |
| 10 | (9, 7) | a vs a | 相等 | (10, 8) |
| 11 | (10, 8) | c vs c | 相等 | (11, 9) |

第 11 轮后 $j=9 > m=8$ ，匹配成功，返回 $i-m = 11-8 = 3$ 。主串从位置 3 起 `'abaabcac'` ✅。

> 注意第 4 轮： $i$ 停在 4 **没有回溯**， $j$ 由 next 数组直接跳到 2，跳过了必然失败的比较——这就是 KMP 比 BF 快的原因。全程主串指针 $i$ 单调递增，共比较 11 次（BF 在类似输入上会多出大量回溯比较）。

### 4.4.7 时间复杂度

- 构造 next 数组：模式串 $T$ 长 $m$ ，代码中 $i$ 单调递增、 $j$ 最多回退 $m$ 次，**$O(m)$**；
- 匹配过程：主串 $S$ 长 $n$ ， $i$ 永不回溯、单调递增，**$O(n)$**；
- 总时间复杂度：**$O(m + n)$**，这是 KMP 相对 BF（ $O(mn)$ ）的核心优势。

> 易错点：KMP 是"**主串指针不回溯**"，不是"模式串不回溯"——模式串指针 $j$ 通过 next 数组照样会向前回退（甚至连续回退多次），只是主串指针 $i$ 始终只进不退。选择题若说"KMP 中模式串指针也不回溯"，判错。

## 4.5 nextval 数组（next 的优化）

### 为什么需要优化

看模式串 $T='aaaab'$ ：next = (0, 1, 2, 3, 4)。假设匹配到 $T[4]$ 时与主串失配（主串该位为 `b`，T[4]=`a`），按 next 数组 $j$ 依次跳 3、2、1、0——但 $T[3]=T[2]=T[1]='a'$ **全都等于 $T[4]$**，主串对应位置既然与 `a` 失配，跳到这些位置后必然还是失配，白白多比较 3 次。

**如果某个 next[j] 指向的字符与 T[j] 相同，那么这次回退是无效的**——可以直接把 nextval[j] 指向 next 链上第一个"字符不同"的位置，一步到位。

### 手算规则（1 起点）

1. nextval[1] = 0（规定）；
2. 对 $j \ge 2$ ：设 $k = \text{next}[j]$ ，
   - 若 **T[j] == T[k]**：nextval[j] = nextval[k]（继承优化结果）；
   - 若 **T[j] != T[k]**：nextval[j] = next[j] = $k$ （不需要优化，保留原值）。

> 一句话记忆：**"若 T[j] 与 T[next[j]] 相同，就套用 nextval[next[j]]；否则就是 next[j] 本身"**。求 nextval 前必须先求出 next 数组。

### next 与 nextval 对比

**例： $T='ababaa'$ ，next = (0,1,1,2,3,4)，求 nextval。**

| $j$ | T[j] | next[j] | T[next[j]] | 是否相同 | nextval[j] |
|-----|------|---------|-----------|---------|------------|
| 1 | a | 0（规定） | — | — | **0** |
| 2 | b | 1 | a | 否 | next[2] = **1** |
| 3 | a | 1 | a | **是** | nextval[1] = **0** |
| 4 | b | 2 | b | **是** | nextval[2] = **1** |
| 5 | a | 3 | a | **是** | nextval[3] = **0** |
| 6 | a | 4 | b | 否 | next[6] = **4** |

**结果：nextval = (0, 1, 0, 1, 0, 4)**。对比 next = (0,1,1,2,3,4)，失配时 $j$ 的回退更"一步到位"。

**再例： $T='aaaab'$ ，next = (0,1,2,3,4)，求 nextval。**

| $j$ | T[j] | next[j] | T[next[j]] | 是否相同 | nextval[j] |
|-----|------|---------|-----------|---------|------------|
| 1 | a | 0（规定） | — | — | **0** |
| 2 | a | 1 | a | **是** | nextval[1] = **0** |
| 3 | a | 2 | a | **是** | nextval[2] = **0** |
| 4 | a | 3 | a | **是** | nextval[3] = **0** |
| 5 | b | 4 | a | 否 | next[5] = **4** |

**结果：nextval = (0, 0, 0, 0, 4)**。连续重复字符的回退被一步压缩——这正是 nextval 优化的意义所在。

### 构造 nextval 的代码

```c
// 求模式串 T 的 nextval 数组（1 起点），相比 get_next 只多了一个判断
void get_nextval(SString T, int nextval[]) {
    int i = 1, j = 0;
    nextval[1] = 0;
    while (i < T.length) {
        if (j == 0 || T.ch[i] == T.ch[j]) {
            ++i;
            ++j;
            if (T.ch[i] != T.ch[j])      // 与 get_next 的唯一区别：
                nextval[i] = j;          // 不同，直接用 j
            else
                nextval[i] = nextval[j]; // 相同，继承优化结果
        } else {
            j = nextval[j];              // 注意这里也用 nextval 回溯
        }
    }
}
```

> 易错点：get_nextval 中失配回退用的是 **`j = nextval[j]`**（不是 next[j]），且"相同则继承"时是 **nextval[j]**——两处都用 nextval，不要写成 next。408 给代码让选结果的选择题常在这里设坑。

## 4.6 下标起点：从 1 开始 vs 从 0 开始

本章所有代码和例题都采用 **1 起点**（王道/严蔚敏教材风格）：`T[1]` 存第一个字符，`next[1]=0`。但 C 语言数组天然从 0 下标开始，于是出现了两种约定：

| 对比项 | 1 起点（王道/严蔚敏） | 0 起点（直接 C 数组） |
|--------|---------------------|----------------------|
| 字符存放 | T[1] 起，T[0] 存长度或不用 | T[0] 起存字符 |
| next[1] | **0** | **-1** |
| next[2] | 1 | 0 |
| next 的一般值 | 最长相等前后缀长度 + 1 | 最长相等前后缀长度 |
| 失配处理 | j = next[j]（j=0 时 i++, j=1） | j = next[j]（j=-1 时 i++, j=0） |

> **审题要点**：408 真题**题目会明确说明下标起点**（如"串从 1 开始编号"或直接给 C 代码）。做选择题时先看题目给的是哪种约定：看到 next[1]=0 就是 1 起点，看到 next[1]=-1 就是 0 起点，两者结果不能混用。**审题时第一件事就是确认这个**，否则全盘皆输。

## 4.7 典型例题

**例 1**（BF 匹配过程推演 + 比较次数统计）：主串 $S='0000000001'$ （ $n=10$ ），模式串 $T='0001'$ （ $m=4$ ）。用 BF 算法匹配，写出匹配过程并统计总比较次数。

**解**：BF 从主串位置 1 开始，每轮若失配则主串起点 +1 重试：

| 轮次 | 起点 | 对齐结果 | 结论 | 该轮比较次数 |
|------|------|---------|------|-------------|
| 1 | 1 | `0000` vs `0001`，第 4 位 0 vs 1 | 失配 | 4 |
| 2 | 2 | `0000` vs `0001`，第 4 位 0 vs 1 | 失配 | 4 |
| 3 | 3 | `0000` vs `0001`，第 4 位 0 vs 1 | 失配 | 4 |
| 4 | 4 | `0000` vs `0001`，第 4 位 0 vs 1 | 失配 | 4 |
| 5 | 5 | `0000` vs `0001`，第 4 位 0 vs 1 | 失配 | 4 |
| 6 | 6 | `0000` vs `0001`，第 4 位 0 vs 1 | 失配 | 4 |
| 7 | 7 | `0001` vs `0001`，全相等 | **匹配成功** | 4 |

第 7 轮全部相等，匹配成功，返回位置 7。总比较次数 $= 7 \times 4 = 28$ 次（每轮 3 次相等比较 + 1 次失配比较，最后一轮 4 次全相等）。

> 此题对应 BF 的最坏情况：模式串大量字符相同，每次几乎比较到最后一个字符才失配，比较次数 $(n-m+1) \times m = 28$ ，时间复杂度 $O(mn)$ 。

**例 2**（求 next / nextval 数组）：分别求 $T_1='abaabcac'$ 、 $T_2='ababaa'$ 、 $T_3='aaaab'$ 的 next 与 nextval 数组（1 起点）。

**解**：逐步推演（前 $j-1$ 个字符的最长相等前后缀长度 + 1，再用 4.5 的规则求 nextval）：

**$T_1='abaabcac'$ ：**

| $j$ | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|-----|---|---|---|---|---|---|---|---|
| T[j] | a | b | a | a | b | c | a | c |
| next[j] | 0 | 1 | 1 | 2 | 2 | 3 | 1 | 2 |
| 判定 | 规定 | b≠a | a=a→继承 | a≠b→保留 | b=b→继承 | c≠a→保留 | a=a→继承 | c≠b→保留 |
| nextval[j] | 0 | 1 | 0 | 2 | 1 | 3 | 0 | 2 |

**$T_2='ababaa'$ ：**

| $j$ | 1 | 2 | 3 | 4 | 5 | 6 |
|-----|---|---|---|---|---|---|
| T[j] | a | b | a | b | a | a |
| next[j] | 0 | 1 | 1 | 2 | 3 | 4 |
| nextval[j] | 0 | 1 | 0 | 1 | 0 | 4 |

**$T_3='aaaab'$ ：**

| $j$ | 1 | 2 | 3 | 4 | 5 |
|-----|---|---|---|---|---|
| T[j] | a | a | a | a | b |
| next[j] | 0 | 1 | 2 | 3 | 4 |
| nextval[j] | 0 | 0 | 0 | 0 | 4 |

> 三组结果均可用 4.4.4 与 4.5 的代码逐行验证。做题时建议：先写 next，再逐列套 nextval 规则，不要跳步。

**例 3**（已知 next 数组求匹配过程）：主串 $S='ababcabcacbab'$ （ $n=13$ ），模式串 $T='abcac'$ （ $m=5$ ），next = (0,1,1,1,2)。用 KMP 匹配，逐轮列出 (i, j) 并给出结果。

**解**： $T$ 的 next 为 (0,1,1,1,2)，匹配过程如下：

| 轮次 | 比较前 (i, j) | 比较 S[i] vs T[j] | 结果 | 操作后 (i, j) |
|------|--------------|------------------|------|--------------|
| 1 | (1, 1) | a vs a | 相等 | (2, 2) |
| 2 | (2, 2) | b vs b | 相等 | (3, 3) |
| 3 | (3, 3) | a vs c | 失配 | (3, next[3]=1) |
| 4 | (3, 1) | a vs a | 相等 | (4, 2) |
| 5 | (4, 2) | b vs b | 相等 | (5, 3) |
| 6 | (5, 3) | c vs c | 相等 | (6, 4) |
| 7 | (6, 4) | a vs a | 相等 | (7, 5) |
| 8 | (7, 5) | b vs c | 失配 | (7, next[5]=2) |
| 9 | (7, 2) | b vs b | 相等 | (8, 3) |
| 10 | (8, 3) | c vs c | 相等 | (9, 4) |
| 11 | (9, 4) | a vs a | 相等 | (10, 5) |
| 12 | (10, 5) | c vs c | 相等 | (11, 6) |

第 12 轮后 $j=6 > m=5$ ，匹配成功，返回 $i-m = 11-5 = 6$ 。验证：主串第 6 位起为 `'abcac'` ✅。全程共比较 12 次，主串指针 $i$ 从 1 单调递增到 11，**从未回溯**。

> 对比：若用 BF 匹配同一输入，需要 7 轮起点、多出约 20 次比较。第 3、8 轮失配时 KMP 靠 next 数组直接滑动模式串，主串一个字符都没浪费。

### 解题技巧总结

- 求 next：**先写 next[1]=0、next[2]=1，再逐位找"前 j-1 个字符的最长相等前后缀 + 1"**；熟练后可直接用递推法心算；
- 求 nextval：**看 T[j] 与 T[next[j]] 是否相同，相同继承 nextval[next[j]]，不同保留 next[j]**；
- 匹配模拟：失配时 $i$ 不动、 $j=next[j]$ ； $j=0$ 时 $i$ 、 $j$ 同时 +1；
- 比较次数统计：匹配过程**每执行一次字符比较（含失配）计 1 次**，逐轮数清即可；
- 审题先看下标起点：next[1]=0 是 1 起点，next[1]=-1 是 0 起点。

### 常见陷阱清单

1. **next[1] 的值**：1 起点为 0，0 起点为 -1，混用必错；
2. **失配后 $j$ 的移动**：`j = next[j]`，不是 `j--`，也不是回到 1；
3. **前后缀不含整个子串**：前缀不含最后一个字符、后缀不含第一个字符；
4. **相等前后缀要取最长**：如 `'ababa'` 的相等前后缀有 `'a'`（长 1）和 `'aba'`（长 3），取 3；
5. **nextval 用 nextval 回溯**：get_nextval 的失配分支和继承分支都用 nextval 数组，不是 next；
6. **KMP 是主串不回溯**：模式串指针 $j$ 会回退，主串指针 $i$ 单调递增。

## 本章小结

### 核心要点回顾

1. **串** 是内容受限的线性表（元素为字符），子串必须连续；空串与空格串不同
2. **三种存储**：定长顺序（超长截断）、堆分配（动态、不截断）、块链（了解）
3. **BF 算法**：主串指针 $i$ 回溯（ $i = i-j+2$ ）、模式串指针 $j$ 回 1，最坏 $O(mn)$
4. **KMP 核心**：主串指针 $i$ 永不回溯，失配时 $j = next[j]$
5. **next[j] 的含义**：已匹配部分（前 $j-1$ 个字符）的**最长相等前后缀长度 + 1**；next[1]=0、next[2]=1
6. **nextval 优化**： $T[j] = T[next[j]]$ 时继承 nextval[next[j]]，否则保留 next[j]，消除重复字符的无效回退
7. **复杂度**：KMP 总 $O(m+n)$ （next 构造 $O(m)$ + 匹配 $O(n)$ ）；下标 1 起点 next[1]=0、0 起点 next[1]=-1

### 考试重点排序

| 优先级 | 考点 | 题型 |
|--------|------|------|
| ⭐⭐⭐ | next / nextval 数组手算 | 选择题 |
| ⭐⭐⭐ | 已知 next 数组的 KMP 匹配过程 / 比较次数 | 选择题 |
| ⭐⭐ | BF 匹配过程与最坏复杂度 $O(mn)$ | 选择题 |
| ⭐ | 串的存储结构（截断问题）、基本概念 | 选择题 |

> 本章复习策略：**next 数组必须手推 5 个以上模式串练到手熟**（含连续重复字符的如 `'aaaab'`），匹配模拟能画逐轮表格即可。KMP 与 [第 3 章（栈和队列）](03-stack-and-queue.md) 无直接关联，但它"用空间换时间、预处理 + 线性扫描"的思想在 [第 5 章（树与二叉树）](05-tree-and-binary-tree.md) 之后的查找与排序中还会反复出现——先把本章吃透。
