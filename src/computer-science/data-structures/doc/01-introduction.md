# 第 1 章：绪论

> 本章在 408 里通常只考 1-2 道选择题，重要度 ⭐⭐，但**时间复杂度与空间复杂度分析是全书一切算法的分析工具**——后面各章的选择题（查找效率、排序比较）和综合题（第 41 题算法设计题的最后两分就是写时空复杂度）全部依赖本章的方法。本章没有记忆负担，全是分析技巧，花 2-3 小时（含例题）即可彻底掌握。学习前提是 [C 语言第 1 章](../../../programming-languages/c/doc/01-basic-syntax.md) 中的循环、数组与递归基础。

## 1.1 数据结构三要素

数据结构研究"如何组织数据"，包含三要素：**逻辑结构、存储结构、数据的运算**。

### 1.1.1 逻辑结构

逻辑结构描述**数据元素之间的逻辑关系**，与计算机无关，是抽象的数学模型：

| 逻辑结构 | 元素间关系 | 典型例子 |
|---------|-----------|---------|
| 集合 | 元素间除"同属一个集合"外无其他关系 | 并查集中的元素集合 |
| 线性结构 | 一对一 | 线性表、栈、队列、串 |
| 树形结构 | 一对多 | 树、二叉树、堆 |
| 图状结构 | 多对多 | 图（社交网络、交通网络） |

> 易错点：栈和队列属于**线性结构**（逻辑上是"一对一"），不要因为它们的操作受限就误以为不是线性结构。

### 1.1.2 存储结构（物理结构）

存储结构是逻辑结构**在计算机中的表示（映像）**，也叫物理结构，共四种：

| 存储结构 | 实现方式 | 特点 |
|---------|---------|------|
| 顺序存储 | 连续存储单元，逻辑相邻的元素物理位置也相邻 | 随机访问 $O(1)$ ，插入/删除需移动元素 |
| 链式存储 | 用指针显式表示逻辑关系，物理位置可不相邻 | 插入/删除灵活，需额外指针空间，不支持随机访问 |
| 索引存储 | 建立索引表（关键字 + 地址），索引项指向数据元素 | 查找快，但需额外空间维护索引表 |
| 散列存储 | 由关键字直接通过哈希函数计算存储地址 | 查找平均 $O(1)$ ，需处理冲突 |

### 1.1.3 数据的运算

数据的运算包括**运算的定义**与**运算的实现**两个层次：

- **定义**：针对逻辑结构，描述运算的功能，即"做什么"。如"在表中第 $i$ 个位置插入元素 $x$"。
- **实现**：针对存储结构，描述具体步骤，即"怎么做"。顺序表插入要移动元素，链表插入只改指针。

> 运算的定义与实现分离是本章的核心思想：**逻辑结构决定运算"是什么"，存储结构决定运算"怎么做"**，同一运算在不同存储结构下效率不同。

### 1.1.4 存储结构与逻辑结构的关系

- 逻辑结构独立于计算机，是"抽象的模型"；存储结构是逻辑结构在存储器中的具体实现。
- **同一逻辑结构可以采用不同的存储结构**，例如线性表既可以用顺序存储（顺序表），也可以用链式存储（链表），具体见[第 2 章（线性表）](02-linear-list.md)。
- 存储结构的选择直接影响运算实现的效率：如"取第 $i$ 个元素"，顺序存储 $O(1)$ ，链式存储 $O(n)$ 。

### 1.1.5 顺序存储 vs 链式存储

这两种存储结构是全书对比最多的考点，必须熟练掌握：

| 对比项 | 顺序存储 | 链式存储 |
|--------|---------|---------|
| 逻辑关系表示 | 依靠物理位置相邻 | 依靠指针显式表示 |
| 随机访问 | $O(1)$ （按下标直接定位） | $O(n)$ （需从头遍历） |
| 插入/删除 | 需移动元素，平均移动 $n/2$ 个， $O(n)$ | 已知位置时只需改指针， $O(1)$ |
| 存储密度 | 高（无额外开销） | 低（每个结点需额外指针域） |
| 空间分配 | 需预先分配连续空间，可能浪费或溢出 | 按需动态申请，无浪费 |
| 适用场景 | 查找为主、长度基本固定 | 频繁插入删除、长度不确定 |

> 口诀：**"顺序查找强、链表增删快"**。选择题给场景选存储结构，就看题目里"查找频繁"还是"插入删除频繁"。

## 1.2 算法的基本概念

**算法（Algorithm）** 是对特定问题求解步骤的描述，是指令的有限序列。程序 = 数据结构 + 算法。

算法具有五大特征：

| 特征  | 含义                           |
| --- | ---------------------------- |
| 有穷性 | 算法必须在执行**有限步**之后结束，不能死循环     |
| 确定性 | 每条指令含义明确、无二义性，相同输入产生相同输出     |
| 可行性 | 每条指令都能通过已实现的基本运算执行**有限次**来完成 |
| 输入  | 有**零个或多个**输入（可从外部获取）         |
| 输出  | 有**一个或多个**输出（必须产生结果）         |

> 易错点：**程序 ≠ 算法**。算法必须满足有穷性，而程序（如操作系统）可以无限运行。选择题常考"算法与程序的区别"，答案就是有穷性。

## 1.3 时间复杂度

### 1.3.1 大 O 表示法（渐进上界）

设算法执行时间关于问题规模 $n$ 的增长函数为 $T(n)$ 。若存在正常数 $c$ 和 $n_0$ ，使得当 $n \geq n_0$ 时恒有 $T(n) \leq c \cdot f(n)$ ，则记：

$$
T(n) = O(f(n))
$$

称 $f(n)$ 是 $T(n)$ 的**渐进上界**。大 O 表示法忽略常数因子与低阶项，只关心**增长的数量级**。

> 直觉理解： $O(f(n))$ 表示"当 $n$ 足够大时，算法的执行时间最多按 $f(n)$ 这个速度增长"。3 条语句和 1000 条语句（不含循环）都是 $O(1)$ ，因为执行时间不随 $n$ 变化。

### 1.3.2 常见阶排序

$$
O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)
$$

| 阶 | 名称 | 典型算法/代码 |
|----|------|---------------|
| $O(1)$ | 常数阶 | 数组随机访问、交换两个变量 |
| $O(\log n)$ | 对数阶 | 折半查找、 $i$ 每次乘 2 的循环 |
| $O(n)$ | 线性阶 | 单层循环、顺序查找 |
| $O(n \log n)$ | 线性对数阶 | 快速/归并/堆排序（平均） |
| $O(n^2)$ | 平方阶 | 双重循环、冒泡/插入/选择排序 |
| $O(n^3)$ | 立方阶 | 三重循环、Floyd 算法（见[第 6 章（图）](06-graph.md)） |
| $O(2^n)$ | 指数阶 | 朴素递归计算斐波那契数列 |
| $O(n!)$ | 阶乘阶 | 全排列枚举 |

> 该顺序必须背熟，408 常考"给定复杂度判断大小关系"或"哪个算法的复杂度更低"。注意 $O(\log n)$ 在 $n$ 很大时远比 $O(n)$ 小：当 $n = 2^{20} \approx 10^6$ 时， $\log_2 n$ 才等于 20。

### 1.3.3 分析方法：找基本操作

求时间复杂度的标准三步：

1. **找基本操作**：最深层循环体内、执行频率最高的语句
2. **算次数**：计算基本操作执行次数关于规模 $n$ 的表达式
3. **取阶**：保留最高阶项，去掉系数和低阶项，写出 $O(...)$

> 关键点：基本操作一定是"最深层循环体"里的语句。外层循环执行 1 次、内层循环执行 $n$ 次，决定复杂度的是内层那条语句。

### 1.3.4 常见循环复杂度模式

| 循环模式 | 基本操作次数 | 复杂度 |
|---------|------------|--------|
| `for (i = 1; i <= n; i++)` | $n$ | $O(n)$ |
| `while (i <= n) i = i * 2` | $\lceil \log_2 (n+1) \rceil$ | $O(\log n)$ |
| 双层循环， $i$ 、 $j$ 都从 1 到 $n$ | $n^2$ | $O(n^2)$ |
| 双层循环， $i$ 到 $n$ ， $j$ 从 1 到 $i$ | $n(n+1)/2$ | $O(n^2)$ |
| 双层循环， $i$ 到 $n$ ， $j$ 从 $i$ 到 $n$ | $n(n+1)/2$ | $O(n^2)$ |
| 双层循环， $i$ 到 $n$ ， $j$ 从 1 到 $n-i$ （即 $i + j \leq n$ ） | $n(n-1)/2$ | $O(n^2)$ |
| 外层 $n$ 次，内层 `while (j <= n) j = j * 2` | $n \cdot \log_2 n$ | $O(n \log n)$ |
| 三重循环，各从 1 到 $n$ | $n^3$ | $O(n^3)$ |

> 记法：**两层循环相乘得 $n^2$ ，外层乘对数内层得 $n \log n$**。变种题（ $j$ 从 $i$ 起、 $i + j = n$ ）次数是 $n(n+1)/2$ 或 $n(n-1)/2$ ，比 $n^2$ 少一半，但**同阶仍是 $O(n^2)$**，只有答案精确到"执行次数"时才需要区分。

### 1.3.5 最好、最坏与平均时间复杂度

以顺序查找为例（[C 语言数组](../../../programming-languages/c/doc/02-pointers-and-arrays.md) 中的相关代码）：

```c
int seq_search(int a[], int n, int key) {
    int i;
    for (i = 0; i < n; i++) {
        if (a[i] == key) {
            return i;          /* 找到立即返回 */
        }
    }
    return -1;
}
```

| 情况 | 条件 | 比较次数 | 复杂度 |
|------|------|---------|--------|
| 最好 | 目标在第一个位置 | 1 | $O(1)$ |
| 最坏 | 目标在最后一个位置，或不存在 | $n$ | $O(n)$ |
| 平均 | 目标等概率出现在任意位置 | $(n+1)/2$ | $O(n)$ |

> 区分两个概念：**"数据规模"** 指 $n$ 的大小，决定复杂度的阶；**"输入数据"** 指具体的数据分布（关键字位置、是否有序等），决定取最好、最坏还是平均。408 常设的坑：问最坏情况复杂度时拿最好情况来答，或把"复杂度与输入数据有关"误答成"与规模无关"。

## 1.4 空间复杂度

空间复杂度 $S(n)$ 衡量算法运行过程中所需的**额外存储空间**随 $n$ 增长的数量级。一般只统计算法运行所需的辅助空间（临时变量、递归栈、辅助数组），不统计输入数据本身占用的空间。

### 1.4.1 原地工作 $O(1)$

如果算法所需的辅助空间为常数，不随 $n$ 增长，称算法**原地工作（in-place）**，空间复杂度为 $O(1)$ 。例如交换两个变量的值、一趟简单选择排序的交换过程，无论 $n$ 多大都只用几个临时变量。

### 1.4.2 递归算法的空间复杂度

递归算法每调用一次，系统就要在**函数调用栈**中分配一块工作空间（保存返回地址、局部变量等）。因此：

$$
\text{空间复杂度} = \text{递归深度} \times \text{每次调用所需空间}
$$

**例：递归求阶乘**

```c
long long fact(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * fact(n - 1);
}
```

调用链为 $fact(n) \to fact(n-1) \to \cdots \to fact(1)$ ，递归深度 $n+1$ ，每次调用 $O(1)$ 空间，故空间复杂度为 $O(n)$ 。

> 易错点：**空间复杂度不等于代码长度**。上面函数只有几行，空间却是 $O(n)$ ；反之，一个 100 行的非递归函数可能只有 $O(1)$ 辅助空间。空间取决于"同时存活的变量/栈帧数量"。

**例：归并排序**的空间复杂度为 $O(n)$ ：合并阶段需要长度为 $n$ 的辅助数组 $O(n)$ ，递归调用栈深度 $O(\log n)$ ，取较大者得 $O(n)$ 。具体实现见[第 8 章（排序）](08-sorting.md)。

> 总结：**时间看循环嵌套层数，空间看递归深度和辅助数组**。"递归深度 × 每层空间"是求递归算法空间复杂度的标准方法。

## 1.5 典型例题

**例 1**（双重循环， $j$ 从 $i$ 起）：分析以下程序的时间复杂度。

```c
#include <stdio.h>

int main(void) {
    int n = 100, sum = 0, i, j;
    for (i = 1; i <= n; i++) {
        for (j = i; j <= n; j++) {
            sum++;            /* 基本操作 */
        }
    }
    printf("sum = %d\n", sum);
    return 0;
}
```

**解**：基本操作是 `sum++`。当 $i = 1$ 时执行 $n$ 次， $i = 2$ 时执行 $n-1$ 次，……， $i = n$ 时执行 1 次，总次数为：

$$
\sum_{i=1}^{n} (n - i + 1) = n + (n-1) + \cdots + 1 = \frac{n(n+1)}{2}
$$

所以 `sum++` 共执行 $n(n+1)/2$ 次（程序输出 $5050$ ），取最高阶并去掉系数，时间复杂度为 $O(n^2)$ 。

> 本题是 408 最经典的复杂度题型：**循环次数精确值是 $n(n+1)/2$ ，但复杂度仍写 $O(n^2)$**。题目若只问复杂度，不必背公式，只需判断"两层循环嵌套"。

**例 2**（ $i$ 每次乘 2）：分析以下程序的时间复杂度。

```c
#include <stdio.h>

int main(void) {
    int i = 1, n = 1000, count = 0;
    while (i <= n) {
        i = i * 2;
        count++;              /* 基本操作 */
    }
    printf("count = %d\n", count);
    return 0;
}
```

**解**： $i$ 的取值序列为 $1, 2, 4, 8, \cdots, 2^k$ ，即每次翻倍。循环停止条件是 $i > n$ ，即 $2^k > n$ ，解得 $k \approx \log_2 n$ 。循环体执行约 $\lceil \log_2 (n+1) \rceil$ 次，时间复杂度为 $O(\log n)$ 。

> 识别特征：**循环变量以"乘"的方式更新（ $i = i * 2$ 、 $i = i * 3$ 等），复杂度就是对数阶**。同理，每次减半（ $i = i / 2$ ）也收敛到 $O(\log n)$ 。

**例 3**（三重循环）：分析以下程序的时间复杂度。

```c
#include <stdio.h>

int main(void) {
    int n = 10, count = 0, i, j, k;
    for (i = 1; i <= n; i++) {
        for (j = 1; j <= i; j++) {
            for (k = 1; k <= j; k++) {
                count++;      /* 基本操作 */
            }
        }
    }
    printf("count = %d\n", count);
    return 0;
}
```

**解**：基本操作是 `count++`，执行次数为：

$$
\sum_{i=1}^{n} \sum_{j=1}^{i} j = \sum_{i=1}^{n} \frac{i(i+1)}{2} = \frac{n(n+1)(n+2)}{6}
$$

即执行 $n(n+1)(n+2)/6$ 次，取最高阶 $n^3$ 并去掉系数，时间复杂度为 $O(n^3)$ 。

> 本题说明：内层循环上界随外层变量变化时，**不能简单相乘，要先写出求和式再化简**，但最后仍取最高阶。408 中要求写出"执行次数"的精确表达式 $n(n+1)(n+2)/6$ 也属于常见考法。

**例 4**（递归斐波那契）：分析下面递归函数的时空复杂度。

```c
#include <stdio.h>

long long fib(int n) {
    if (n <= 1) {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

int main(void) {
    printf("fib(10) = %lld\n", fib(10));
    return 0;
}
```

**解**：

**时间**：设 $T(n)$ 为 $fib(n)$ 的调用代价，有递推式 $T(n) = T(n-1) + T(n-2) + O(1)$ 。递归调用形成一棵二叉递归树：深度约 $n$ ，各层结点数按 2 的幂增长，总调用次数约为 $2^n$ 数量级，故 $T(n) = O(2^n)$ 。

**空间**：递归深度最多为 $n+1$ （沿 $fib(n) \to fib(n-1) \to \cdots \to fib(1)$ 一条链），每次调用 $O(1)$ 栈空间，故空间复杂度为 $O(n)$ 。

> 重点区分：**时间是 $O(2^n)$ ，空间是 $O(n)$**。递归树的所有结点并非同时存在，调用栈在回溯时会释放，所以空间只看"最大深度"而不是"总结点数"。这一对比是 408 高频选择题。

**例 5**（比较两段代码的复杂度）：已知 $n$ 为问题规模，比较代码 A 与代码 B 的时间复杂度大小。

```c
/* 代码 A：基本操作 k++ 的执行次数 */
int k = 0;
for (i = 1; i <= n; i++) {
    for (j = 1; j <= n; j++) {
        k++;
    }
}

/* 代码 B：基本操作 m++ 的执行次数 */
int m = 0;
for (i = 1; i <= n; i++) {
    for (j = 1; j <= n; j++) {
        for (l = 1; l <= n; l++) {
            m++;
        }
    }
}
```

**解**：代码 A 中 `k++` 执行 $n^2$ 次，时间复杂度 $O(n^2)$ ；代码 B 中 `m++` 执行 $n^3$ 次，时间复杂度 $O(n^3)$ 。当 $n$ 足够大时， $O(n^3)$ 的增长远快于 $O(n^2)$ ，故**代码 B 的时间复杂度更大**。例如 $n = 100$ 时，A 执行 $10^4$ 次，B 执行 $10^6$ 次，相差 100 倍。

> 对比变种：若把代码 A 的内层改为 `for (j = 1; j <= i; j++)`，执行 $n(n+1)/2$ 次，次数约为原来的 1/2，但**同属 $O(n^2)$**，与代码 A 的复杂度相同。比较复杂度比的是"阶"，不是具体次数。

### 常见陷阱清单

1. **只看最高阶项但别丢精确计数**：大 O 只比"阶"，忽略常数与低阶项；但若题目问"基本操作的执行次数"，必须给出精确值（如 $n(n+1)/2$ 次），不能拿阶来代替。
2. **$O(1)$ 是常数量级，不是"只执行 1 次"**：只要基本操作的执行次数与问题规模 $n$ 无关，即使执行上百次也仍是 $O(1)$ 。
3. **递归程序的空间看递归栈最大深度**：空间复杂度看的是"同一时刻"占用的辅助空间，即递归栈的最大深度，而不是调用总次数或递归树的总结点数—— $fib(n)$ 时间为 $O(2^n)$ ，空间却只有 $O(n)$ 。
4. **平均复杂度有等概率前提**：顺序查找的平均情况是按"每个元素等概率 $1/n$ 被查找"推出来的，题设若改变分布假设，结论要重新推。
5. **最好/最坏/平均要分清**：快速排序平均 $O(n \log n)$ ，最坏（已有序或逆序）退化为 $O(n^2)$ ；冒泡排序最好（正序）只需 $O(n)$ ——答题先看题目问的是哪一种。
6. **内层循环依赖外层时要累加而不是相乘**：`for (i = 1; i <= n; i++) for (j = 1; j <= i; j++)` 中内层次数随外层变化，总数为 $1 + 2 + \cdots + n = n(n+1)/2$ ，是 $O(n^2)$ ；不能机械地拿两层上界相乘。

## 本章小结

### 核心要点回顾

1. **数据结构三要素**：逻辑结构（集合、线性、树形、图状）、存储结构（顺序、链式、索引、散列）、数据的运算（定义与实现分离）。
2. **顺序 vs 链式**：顺序存储随机访问 $O(1)$ 、插入/删除 $O(n)$ ；链式存储随机访问 $O(n)$ 、已知位置插入/删除 $O(1)$ 。
3. **算法五大特征**：有穷性、确定性、可行性、输入、输出；算法 ≠ 程序（区别在有穷性）。
4. **大 O 表示法**：渐进上界，忽略常数与低阶项；常见阶排序 $O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$
5. **分析方法**：找最深层循环体的基本操作 → 数执行次数 → 取最高阶。
6. **空间复杂度**：原地工作 $O(1)$ ；递归空间 = 递归深度 × 每次调用空间（ $fact(n)$ 为 $O(n)$ ）；归并排序辅助数组 $O(n)$ 。

## 自测题

1. 数据结构的三要素是什么？各举一例。
2. 算法的五大特征是什么？算法与程序的本质区别是什么？
3. 分析下列代码的时间复杂度：

```c
int i = 1;
while (i * i <= n) {
    i++;
}
```

4. 顺序存储与链式存储相比，各自的优点是什么？
5. 一个算法代码只有 5 行但含递归调用，它的空间复杂度一定是 $O(1)$ 吗？为什么？
6. 判断正误：算法的时间复杂度仅取决于问题规模 $n$ ，与输入数据的分布无关。

> **答案**：1. 逻辑结构（如线性结构）、存储结构（如顺序存储）、数据的运算（如插入运算）；2. 有穷性、确定性、可行性、输入、输出，本质区别是算法必须满足有穷性，而程序可以无限运行；3. 循环条件 $i^2 \leq n$ 即 $i \leq \sqrt{n}$ ， $i$ 从 1 增到约 $\sqrt{n}$ ，执行约 $\lceil \sqrt{n} \rceil$ 次，时间复杂度 $O(\sqrt{n})$ ；4. 顺序存储：随机访问快（ $O(1)$ ）、存储密度高；链式存储：插入/删除灵活（已知位置 $O(1)$ ）、空间按需分配无浪费；5. 不一定，递归算法每次调用都需栈空间，空间复杂度 = 递归深度 × 每次调用空间，代码短但递归深度为 $n$ 时空间仍为 $O(n)$ ；6. 错误，复杂度是规模 $n$ 的函数，但取最好、最坏还是平均取决于输入数据的分布（如查找目标的位置），例如顺序查找最好 $O(1)$ 、最坏 $O(n)$ 。
