## 1. 定位与分工（三线并存，各管各的）

| | grammar/ 讲义（现有） | **grammar-course（本方案）** | general + Lexio（现有） |
|---|---|---|---|
| 角色 | 语法**参考书**：体系课、推导链、查漏 | 语法**学习主线**：微课、语境、操练 | 词汇 + 听说读写**能力线** |
| 单位 | 讲（29 讲，1 讲一个大体系） | **课（68 课，1 课 1 个句型/语法点）** | 课文课（三册体系） |
| 体验 | 读 + 理解判分 | 课文 → 词汇 → 操练 → 产出 → 小测 | 听 → 拼 → 写 |
| 关系 | 本课程每课「深读」跳转至此 | 从 29 讲蒸馏切分，互链 | 不动 |

一句话：**讲义教「为什么」，微课练「怎么用」**；一课负担小（20~30 分钟），靠螺旋复现攒出体系。

### 1.1 学习者画像（硬前提）

**有词汇量、语法基础弱的成人**：能读简单句、认识多数常用词，但造句靠背、长句读不拆、时态 / 从句混用、写作中式直译。由此定三条内容纪律：

- 课文**生词量克制**（8~12 词/课），不拿生词难为语法学习
- 讲解中文、例句英文，**outcome 写「学完能造出什么句子」**而非术语堆砌
- 每课只上 1 个语法点，旧点在新课里螺旋复现（70/30）

### 1.2 数据源裁定：lesson.md 保留，但角色收敛为「课本」

回应「直接生成 JSON 是否更佳」——**不必三件套，但 md 留一份**：

- **md 一源双用**：Obsidian 里给人读 / 审校 + VitePress 站点自动收录成静态语法微课页（「反正都要 web 平台」恰恰让 md 多了一层价值，零额外成本）
- **审校是质量关键环节**（AI 生成 + 作者审校）：在 md 里改 150 词课文 + 词汇表，体验远好于在 JSON 里改
- **解析器会非常薄**：本课程是自产内容 + 自定严格格式（七件套固定标题 `^## N.`），不是解析任意讲义 md——grammar-play 的 md→json 解析坑已趟完，这里只做「固定模板 → lesson.json」的确定性转换
- **真正砍掉的是 Lexio 的三件套**（lesson.md + practice.md + lesson.json 并存）：收敛为 **lesson.md 单文件 → 构建期 → lesson.json（产物，不手写、不审校）**，外加 platform 端的实际消费 schema

一句话：**md = 课本（人读、审校、发站）；json = 构建产物（平台消费）**。若未来实践发现 md 审校不顺，可平滑切换为「直接产 JSON」——平台只认 JSON，这条边界是干净的。

## 2. 课程设计

### 2.1 一课的结构（新概念式七件套）

一课 = 「学（输入 4 件）+ 练（输出 3 件）」两段，20~30 分钟走完一条动线：

```mermaid
flowchart LR
    A["① 本课目标<br/>今天只学 1 个点"] --> B["② 课文<br/>100~150 词叙事"]
    B --> C["③ 词汇表<br/>8~12 词"]
    C --> D["④ 语法点精讲<br/>1 个点 · 一页讲完"]
    D --> E["⑤ 练习<br/>理解→操练→产出"]
    E --> F["⑥ 小测<br/>4~6 题入复习队列"]
    F --> G["⑦ 深读<br/>跳讲义对应小节"]
```

**逐节规格**：

| # | 环节 | 内容规格 | 判分 / 交互 | lesson.json 字段 |
|---|------|---------|------------|-----------------|
| ① | 本课目标 | 一句话：今天只学 1 个句型 / 语法点（如「一般过去时：过去的故事」） | 只读 | `goal` |
| ② | 课文 | **100~150 词叙事文**（兔子连续剧），本课语法点**高亮 3~5 处**；约 70% 旧点 + 30% 新点；段落式、首行缩进 | 逐句中英对照（TTS 后补）；高亮句可点开「为什么这么写」 | `reading: { sentences: [{en, zh, highlight?}] }` |
| ③ | 词汇表 | **8~12 词**：音标 / 词性 / 释义 / 课文例句 / 常用搭配；台账查重（新词入账唯一、旧词复现可审计） | 词卡浏览（第一版）；拼写后补 | `vocab: [{ word, phonetic, pos, meaning, example, collocations }]` |
| ④ | 语法点精讲 | **薄讲**：1 个点的规则 + 2~3 个例句，一页内讲完（不展开体系，体系归讲义） | 只读 + 例句代码块渲染 | `notes`（≥1，构建校验必含） |
| ⑤ | 练习 | **三段递进**，题量 5~7：理解 2~3 题（课文理解选择）→ 操练 2~3 题（句型替换 drill）→ 产出 1~2 题（造句 / 仿写 / 复述） | 理解/操练=**机判**（choice / fill / drill）；产出=**自判** + 参考答案；答案逐题解锁，禁一键看全 | `practice: [{ kind, ... }]`（drill 为新题型） |
| ⑥ | 小测 | **4~6 题混合**：本课点为主，混入 2 题间隔复习题（上一课 / 三课前） | 机判为主；错题进复习队列（跨课调度） | `quiz` |
| ⑦ | 深读 | 跳 grammar 讲义对应小节（subhead 锚点，如 U01L03 → G03 §2.2），外加 1 句「什么情况下值得深挖」 | 只读链接——**跳 VitePress 站点讲义静态页**（`/kb-vault/english/grammar/…`），不是 grammar-play（那是练习平台） | `deepDive: { refs, hint }` |

**lesson.json 字段契约**（§3 校验与平台共用此一套口径；Lexio 的 `notes / output / sample` 三件套映射如下，不另立第二套）：

| Lexio 继承字段 | 本课程落点 | 校验 |
|---------------|-----------|------|
| `notes` | = ④ 语法点精讲（`notes` 至少 1 项，含规则 + 例句） | 必含 |
| `output` | = ⑤ 练习的产出题段（造句 / 仿写 / 复述，`output` 至少 1 项，含 prompt + 参考） | 必含 |
| `sample` | = 产出题的参考答案样例（每道产出题 1 条 `sample`） | 必含 |
| 其余 | `goal` / `reading` / `vocab` / `practice` / `quiz` / `deepDive` 为七件套直映 | 按 §2.1 表 |

**样例（U01L03）**：目标「主 + 动：什么都不用加」→ 课文《兔子的第一天》（run / sleep 等不及物句高亮）→ 词汇 9 词 → 精讲「不及物动词 = 什么都不要，到动词即完整」+ 3 例句 → 练习「The rabbit sleeps. → The wolf \_\_\_.」替换操练 + 造句 → 小测 5 题（含 2 题 U01L01 复习）→ 深读 G03 §2.2。

### 2.2 切分原则：1 课 = 1 个句型 / 语法点（课表定稿见同目录 `syllabus.json`）

严格从 29 讲蒸馏，总量 **68 课 · 9 单元**——每课 `refs` 回链讲义（Gnn，含小节标题级对齐），只降粒度不越纲。读者画像定为「**有词汇量、语法基础弱**」：课文生词量克制（8~12 词/课）、outcome 写成「学完能造出什么句子」而非术语堆砌。

| 单元 | 课数 | 覆盖讲义 | 说明 |
|------|------|---------|------|
| U01 句子骨架 | 7 | G01/G02/G03/G09/G23 | 五大句型各 1 课；顺序 1→2→5→3→4（先易后难，L05 有顺序说明） |
| U02 名词家族 | 9 | G12/G14/G15/G21 | it 用法拆两课（虚 it+形式主语 / 形式宾语+强调预告） |
| U03 动词的时间线 | 8 | G02/G03/G04 | 16 时态只建地图，攻核心 6 个 |
| U04 修饰件 | 10 | G13/G16/G17/G18/G21 | 形容词语序课收「限定词在形容词前」 |
| U05 长句工程 | 9 | G11/G19/G23 | 含长句拆解三步法实战课；连词只讲选型，「不同时现」归 U07L59 |
| U06 非谓语与使役 | 8 | G06/G07/G10 | **被动预告**在 U06L44（最小 be+done 定义）；独立主格降为识别型拓展课 |
| U07 句法变形 | 8 | G19/G24–G28 | **被动正式课在此**（U07L52）；主谓一致、强调、倒装、省略、连词收口 |
| U08 助动词与语气 | 6 | G05/G08 | **虚拟语气压轴**（难度纪律：先变形后语气） |
| U09 综合收口 | 3 | G01/G22/G23/G29 | 写作标点、构词猜词、结课实战 |

覆盖对账：syllabus.json `coverage` 字段 = G01–G29 → 68 课映射账（refs ↔ coverage 双向零缺口）；**G20 叹词**口语向、考试权重低，明确挂起为 P2 附加课（`deferred` 字段）。

学习顺序与讲义推导链一致：**先立骨架（U01）→ 说清「什么」（U02）→ 给动词加时间（U03）→ 加修饰（U04）→ 变长句（U05）→ 动词变身（U06，含被动预告）→ 变形收口（U07，含被动正式课）→ 语气压轴（U08）→ 综合（U09）**。难度纪律：被动基础在 U07L52 正式讲、此前只预告；虚拟语气全书最难，压轴 U08。

### 2.3 螺旋复现（去「生硬」的核心机制）

- 每课课文语料 **约 70% 旧语法点 + 30% 新点**——学过的句型在新故事里自然撞见
- **复现豁免条款**：U01L01~L04 尚无「旧点」可复现，前 4 课复现率自然爬坡（可低至 0%）；**间隔复习题从 U01L05 起启用**，从 U02 起全量生效——评审确认前 5 课物理上不可能满足 70/30，按豁免执行而非硬凑
- 小测题混入 2 题「间隔复习题」（上一课 / 三课前的知识点），错题进复习队列
- 词汇台账复用 general 的口径：新词入账唯一 + 旧词复现率可审计（english-lesson-crafter 的查重流程照搬）

### 2.4 语料：兔子叙事连续剧

教程本来就是 rabbit / carrot / wolf 统一叙事（readme 设计哲学第 5 条）——微课课文直接做成**故事线连续剧**：兔子开店 → 狼来访 → 冒险展开……每课推进一点剧情。语境连续 = 复现自然 = 不生硬。

## 3. 内容生产管线（单源：lesson.md → 构建产物 lesson.json）

沿用 Lexio 已验证的流水线骨架，按 Q3 裁定收敛为**单源管线**（`[Assumption, TBD]` 内容走 **AI 生成 + 作者审校**，english-lesson-crafter 同款工作流改造）：

```text
大纲 syllabus.json（单元 → 课序 → 语法点矩阵）
  ↓ crafter：查词汇台账 → 七件套成文 → exam-item-toolkit 规范命题（B/S 分层、答案分离）
lessons/book-01/…/UxxLnn/lesson.md（唯一手写源 · 课本）
  ↓ bun run build-data（固定模板解析 → lesson.json，构建产物不手写、不审校）
  ↓ bun run validate（解析产物 schema 校验：七件套齐全 + notes/output/sample 必含 + refs 合法）
  ↓ 常驻 CI 测试（解析器 fixture + schema 不变量，构建前执行）
平台只读消费 lesson.json
```

与 §1.2 一致：**无双源对账**——lesson.json 是解析产物，validate 负责的是「解析结果 schema 校验 + 不变量断言」，不是 md↔json 内容对账（内容只在 md 里维护一份）。唯一防漂移点：解析器 + fixture 单测锁住格式契约。

内容规范硬约束（仓库既定，全部继承）：

- 练习内容 **markdown 格式**（禁 HTML 折叠标签）；题目与答案分离；选择题 `A. / B. / C. / D.` 编号行格式
- 段落式呈现、首行缩进两字符；**lesson.json 必含 `notes` / `output` / `sample`**（映射见 §2.1 字段契约表，构建时验证）
- 拼写练习含单词和句子、完全正确才推进（若第一版含拼写模块）
