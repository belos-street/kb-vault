# 生成 skill 的写作模板

按此模板写每个能力块，保证人机兼读、结构一致。

## 目录 & 命名

```
skill/
  SKILL.md                # 集合入口：使用场景 → 读哪个能力
  reference/
    <topic>.md            # 每个能力一个主题文件，如 concurrency.md
```

- 能力文件命名（`reference/*.md`）遵循仓库命名规范（`belos-street/reference/naming-conventions.md`）：短横线小写英文，如 `d3-update-pattern.md`。
- 集合入口 `skill/SKILL.md` 承担"快速定位"，各能力 `reference/*.md` 承担"会做一件事"。
- 不做 `skill/<能力>/SKILL.md` 子目录。能力分散主题文件，靠入口速查表串联。

## 单个能力 reference/<topic>.md 骨架

先写 frontmatter（`name` + `title` + `description` + `tags`，**不写 `source` 路径**）便于检索与 LLM 扫描定位：

```markdown
---
name: "<topic>"
title: "<中文主题名>"
description: "做 <一件完整的事>。当用户要 <触发场景> 时使用。<触发场景>"
tags: [<分类标签>]
---

# <中文主题名>

一句话定位：本能力能帮你完成什么。

## 什么时候用
- 触发场景 / 判据

## 怎么做（核心步骤）
1. 输入 → 处理 → 输出 的可执行调用链
2. 分步，每步给关键 API / 公式 / 参数

## 常见坑 ⚠️
| 错误做法 ❌ | 后果 | 正确做法 ✅ |
|------------|------|------------|
| ... | ... | ... |

## 决策点（多个方案时）
| 场景 | 推荐 | 理由 |
|------|------|------|
| ... | ... | ... |

## 与其他方案取舍（同一技能域内的对照，不涉及外部语言/框架时省略）
| 维度 | 本方法 | 对照方案 |
|------|--------|----------|
| ... | ... | ... |

## 参考：官方文档（核验用）🔗
| 关键点 | 官方文档 |
|--------|----------|
| ... | [名称](链接) |

## 一句话结论
- 面试/评审能直接说的关键结论
```

## 集合入口 skill/SKILL.md 骨架

```markdown
---
name: "<区名>-skills"
title: "<区名> Skill 集合"
description: "<区名> 项目落地时可执行的最佳实践：<能力清单>。当用户要 <区名> 的 <能力> 时使用。"
tags: [...]
---

# <区名> Skill 集合

本集合是自包含的实战手册，可独立搬运到任意项目使用。

## 使用场景 → 读哪个能力
| 你要做什么 | 读 |
|-----------|----|
| <场景 A> | [reference/<topic-a>.md](reference/<topic-a>.md) |
| <场景 B> | [reference/<topic-b>.md](reference/<topic-b>.md) |

## 核心原则（一页速记）
- 3~7 条该领域最关键、可跨所有能力的定论式原则（可省略）
```

## 风格红线

- 中文正文 + 适量 emoji；技术图用 Mermaid。
- 不出现教学旅程话术（"学完你会""预计 N 天""面向已有 XX 经验"）。
- **不引用 `doc/` 相对路径，不在 frontmatter/正文写任何源路径**（`metadata.source` 也不写）。
- **不绑受众**：禁止"与 XX 心智映射/面向 XX 群体"的专门章节；偶发术语类比可保留作点缀。
- 关键结论/API 写完后用官方文档交叉核验，链接在本模板"参考：官方文档"小节留档。
- 每个能力 `reference/*.md` 脱离集合/脱离教学区也能单独看明白。
