# Skill 产物质量 Review（校验篇）

doc-to-skill 产出后的**质量评审细则**：用一套针对「skill 产物」的维度，逐项核查生成的 `skill/` 集合，输出问题清单与改进建议。作为工作流「校验」步骤的可执行清单。

> 定位边界：本页评的是 **skill 产物质量**，不是教学文档质量（后者用 `doc-quality-reviewer`）。

## 怎么用

1. 逐维核查每个文件，给每维打分：**达标 ✅ / 基本达标 🟡 / 不达标 ❌**，记下证据与具体位置。
2. 命中「红线」一票否决项 → 必须先修完再交付。
3. 按下方「输出格式」产出评审报告，问题逐条带着文件名与行号定位。

## 八维评分表

| # | 维度 | 查什么 | 达标标志 | 红线（一票否决） |
|---|------|--------|----------|------------------|
| 1 | **可触发** | frontmatter `name/title/description/tags` 是否齐全；`description` 是否含「做一件什么事 + 触发场景」 | LLM 读了 description 就能判断何时命中 | description 无触发场景，无法被检索/命中 |
| 2 | **结构完整** | 是否扁平：入口 `SKILL.md` + `reference/*.md`；每个 reference 是否含固定小节（什么时候用/怎么做/坑/决策/官方文档/一句话结论） | 结构齐全且扁平 | 出现逐能力子目录 `skill/<能力>/SKILL.md`；reference 缺失关键小节 |
| 3 | **粒度自洽** | 每个能力是否「读完能独立完成一件事」 | 无碎片、无"整套硬塞一个" | 拆成 3 个 5 行碎片；或全部教程塞一个文件 |
| 4 | **独立可搬走** | 是否有 `doc/` 相对路径、篇号、教学上下文、`metadata.source` | 零 `doc/` 引用、零源路径，搬到任意项目可独立用 | 出现 `参见 doc/03`、`metadata.source` 等仓库路径依赖 |
| 5 | **解耦不绑受众** | 是否出现「与 XX 心智映射」「面向已有 XX 经验者」「本模块你将学到」等教学区专属语境 | 无专属受众对照章节；偶发术语类比仅作点缀 | 专门的「与 XX 心智映射」对照章节或受众导语 |
| 6 | **准确忠实** | 关键 API/公式/结论是否已用官方文档（WebFetch/WebSearch）交叉核验；是否误解作者定论 | 与官方定论一致，链接回填「参考：官方文档」 | 关键 API 与官方定论冲突或凭空杜撰 |
| 7 | **人机兼读** | 中文 + 适量 emoji；有可执行步骤、坑点速查、决策判据 | 人读得懂、机器能照做 | 只剩代码或纯流程，无判据/无坑点 |
| 8 | **风格对齐** | 技术图用 Mermaid；文件名 kebab-case；入口速查表无死链；`reference/` 分主题 | Mermaid、命名合规、零死链 | ASCII 目录树；命名不规范；入口出现死链 |

## 输出格式

### 问题清单
| # | 文件 | 维度 | 问题 | 建议 |
|---|------|------|------|------|
| 1 | `reference/xxx.md` | 6 准确忠实 | … | 用官方文档核验并回填链接 |

### 评分汇总
| 维度 | 得分 | 备注 |
|------|------|------|
| 可触发 | ✅ | … |

### 结论
- ✅ 可交付：八维全达标，无红线。
- ❌ 需返工：列出必须先修的项（红线优先）。

## 一句话原则

- 这份就是 doc-to-skill「校验」步骤的落地细则：**跑完这份 = 完成质量管理**，不接受"差不多就行"的产物。
- 维度 6（准确忠实）如时间有限，优先核验「面试可答 / 作者下的定论」这两类最关键结论。
